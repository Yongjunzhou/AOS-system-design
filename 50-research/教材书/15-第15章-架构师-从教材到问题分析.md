## 第 1 步 · 剖章立骨：核心内容地图

**这一章回答的问题**：架构师到底是个什么样的物种？头衔、职级、图纸都不定义架构师——十项能力才定义。怎么判断一个人是不是架构师，怎么和五个相邻角色分开，怎么长成、怎么失败、怎么被检验、怎么给两条案例线落判词。

**三幕对齐（省一步推导）**：
- **第一幕 是什么（定界）**：1.1 一句开场白（先是一个工程师）→ 1.2 底座六项三栏点名（①~⑥各带判据）→ 1.3 增量四项十项清单（⑦~⑩ + ISO 42010 三组词分工）→ 1.4~1.7 四项增量各展开一节 → 1.8 两个更锋利的差异（需求→关切；测试→评审）+ 案例进展①李工（判词初挂）—— 喂第一组·概念题（见树见林）；
- **第二幕 不是什么（磨边弧）**：2.1 不是更高级的工程师（职级≠物种）→ 2.2 不是技术负责人（管人≠管决定）→ 2.3 不是项目经理（进度≠结构）→ 2.4 不是领域专家（业务≠系统）→ 2.5 不是画图匠（图≠决定）→ 2.6 失败四式收拢 + 案例进展②老周（判词推进）—— 喂真悖论·辨边界题；
- **第三幕 往哪去（运用）**：3.1 怎么长成（判断依据升级）→ 3.2 被任命≠成为 → 3.3 三种来路三种功课 → 3.4 成长的标志（第一次"说不"）→ 3.5 再往上（从系统到组织，四条路径）→ 3.6 能力的最终体现（开发出高质量的上半棵树 + 枝梢=1:1 搬入点 + 检验句）+ 案例进展③双线判词落定—— 喂第二组·落地 / 方法时刻题（规则 15）。

### 十项能力清单（四问化：是什么 / 不是什么 / 判据）

| 能力 | 是什么（含拆解动作） | 不是什么 | 判据 | 缺了会怎样 |
|---|---|---|---|---|
| ① 科学素养（底座） | 判断"系统靠什么成功"——理论不是空的（对系统的理论的地基） | 不是背理论；不是科普义；不是长期不碰实现 | 我对这个系统的理论是什么？靠什么成功、最大压力在哪、做错什么最致命？ | 判断不了系统靠什么成功，理论是空的 |
| ② 方法论素养（底座） | 方法不靠人传人——架构不随人走 | 不是手艺；不是只有我会的方法 | 我的方法能被别人学会吗？还是只有我会？ | 靠人传人，架构随人走 |
| ③ 实践能力（底座） | 落得了地——架构不只在图上 | 不是只会画图；不是空降不落地 | 我最近一次亲手落地，是什么时候？ | 落不了地，架构停在图上；理论不落地像没有实物的建筑图 |
| ④ 职业伦理（底座） | 能力不是中性的，它定义方向 | 不是道德说教 | 压力面前，我会不会为进度悄悄牺牲可靠性？有没有让相关方知情？ | 判断越准、破坏越大——能力不是中性的 |
| ⑤ 工程判断（横切底座） | "识别后果严重的决策"不只是一句口号 | 不是"会做决定"（"先上再说"也是判断，但是坏的判断） | 冲突里，我依据什么做取舍？ | "识别后果严重的决策"只是口号 |
| ⑥ 可复现意识（元底座） | 判断换个人也接得住——不是手艺型架构师 | 不是手艺（判断绑定在人身上） | 我的判断换个人能接住吗？我写决策记录吗？ | 判断换个人就接不住，成了手艺型架构师 |
| ⑦ 识别后果严重的决策（增量） | 对不重要的事情不决策 | 不是"想得多"、不是做事谨慎 | 影响半径大、持续时间长、修改成本高的，按决策对待 | 对重要的事情不决策=架构师的第一宗罪 |
| ⑧ 对系统的理论（增量） | 靠什么成功 / 最大压力 / 做错最致命 | 不是经验、不是碰巧做对 | 我的架构有原理吗？换个上下文还成立吗？ | 没有理论支撑，换个上下文就错 |
| ⑨ 把架构说清楚（增量） | 相关方 → 关注点 → 视点 → 视图 | 不是"文档写得好" | 每个相关方的关注点，都有一张图能落吗？ | 涵义看不见，架构没法被讨论 |
| ⑩ 判断不可逆性（增量） | 高不可逆早做、低可逆晚做、该推迟的显式推迟 | 不是只看"改起来多贵" | 我认得出不可逆决策吗？该早做的早做、该推迟的显式推迟吗？ | 把不可逆决策当日常节奏，事后不可逆 |

前六项是第8章工程师的底座（收束第8章），后四项是第9、11章长出来的系统级增量（收束第9/11章）；⑤横切、⑥是元。**整张表就是"架构师是个怎样的物种"的第一层答案：一个先把六项能力背在身上、再往系统级长的人。** 两个反直觉命题：**架构师首先是一个工程师**（次序问题——没有那六项能力，"架构师"三个字只是一张名片）；**头衔不定义架构师**（职级也不定义、图纸也不定义）。

### 核心概念（角色章的"概念"= 清单 + 两把尺子 + 一个判词任务 + 一个反直觉命题）

1. **架构师**（无新档案，以清单定义）：先是一个工程师 + 增量 = 十项能力清单；头衔不定义架构师。判据：十项能力一项一项亮起来。
2. **底座六项**（第8章收束）：科学素养 / 方法论素养 / 实践能力 / 职业伦理 + 横切⑤工程判断 + 元⑥可复现意识——架构师是工程师的一个方向，不是工程师的超越。
3. **增量四项**（第9、11章收束）：⑦识别后果严重的决策 / ⑧对系统的理论 / ⑨把架构说清楚 / ⑩判断不可逆性——长在底座上，底座缺一项增量空转。
4. **两个更锋利的差异**：认知对象 需求→关切（工程师面对规定需求，架构师面对关切）；验证方式 测试→评审（架构无唯一正确解，只能对目标评审）。
5. **五个相邻角色**（更高级的工程师 / 技术负责人 / 项目经理 / 领域专家 / 画图匠）：和架构师像但不一样，一条条磨过去。
6. **失败四式**（画图匠 / 什么都管 / 不决策 / 远离代码）：每一种都能在十项能力清单里找到缺的那一项。
7. **产品数据（上半棵树）**：概要定义（枝干）+ 接口契约（枝梢）+ 架构决策（ADR）+ 架构描述（AD）+ 系统级验证方案；枝梢=1:1 搬入点（接口契约是工程师叶子落下的那根枝梢）。
8. **再往上（从系统到组织）**：四条路径（深度/宽度/组织/权威）；工具不变，棋盘变大；CTO 头衔同样不定义能力。

### 关联概念（近界 · 辨析）

- **十项能力 ↔ 第8章六项底座 + 第9/11章增量**：底座缺一块，增量全是空转（识别依赖工程判断、理论依赖科学素养、不可逆判断依赖工程判断）——一套结构，第8章立底座、第9/11章立增量、本章收成一张清单。
- **增量四项 ↔ ISO/IEC/IEEE 42010 架构定义三组词**：元素（elements）/ 关系（relationships）/ 设计准则与演进准则（design and evolution principles）——工程师的技能围绕元素（把元素做对），架构师的增量围绕关系与演化（识别决策认关系演化风险 / 理论说关系支撑成功 / 说清楚画关系 / 不可逆判演化改不动代价）。
- **两个更锋利的差异 ↔ 第7章三把尺子**：评审对目标、验证对需求、确认对用途——架构没有逐条需求可对，只能对目标（相关方关切汇聚成的"为什么要建这个系统"）；代码用测试验证，架构用评审验证。
- **⑨把架构说清楚 ↔ 第9章相关方→关注点→视点→视图链**：第一步永远是先问"谁押了注、在乎什么"；相关方关注点天然冲突，架构师不消灭冲突，给每个冲突一个可见的落点。
- **⑩判断不可逆性 ↔ 第11章三层判断 + 三个动作**：影响半径（结构/时间/组织耦合）/ 信息成本（知识深度/隐含上下文）/ 修改风险（爆炸半径/数据完整性）；高不可逆早做、低可逆晚做、该推迟的显式推迟；阿凯改走"受控导出"是完整案例。
- **产品数据（上半棵树）↔ 第6章一棵树**：枝干是概要定义（管结构、承接关系）、叶子是详细定义（管内容、可验证）；架构师负责枝干和枝梢，工程师负责叶子；枝梢=1:1 搬入点。
- **成长 ↔ 判断依据换尺度**：代码→模块→系统→架构决策（你关心的问题换了，物种就变了）；空间维度与时间维度同时扩张。
- **失败四式 ↔ 十项能力缺项**：画图匠缺⑤（没有判断）/ 什么都管缺⑦（对不重要的事情疯狂决策）/ 不决策缺⑩（把决定留给默认）/ 远离代码缺③（判断失去锚点）。
- **判词 ↔ 3.6 产品数据**：3.6 和案例进展③量的是同一把尺子（换个人拿着架构描述和决策能不能接住、继续演进）——判词把"架构师"从头衔钉成能力清单。
- **从见过到拥有（方法底座时刻）↔ 第1章**：章首李工只有"见过"（叫得出头衔、画得出图），判词把他量成"拥有"（能对着十项清单一项一项打勾、认得出自己缺什么）。
- **技术领导力 ↔ 第8章能力清单**：管理权可以任命，领导力不能任命——技术领导力在"能力"清单里不在"职位"清单里。

### 核心原理

**第一幕 · 是什么的底层机制**
1. 架构师首先是一个工程师——次序问题：先有元素级的正确，才谈得上系统级的方向；没有六项底座，"架构师"三个字只是一张名片（1.1）。
2. 增量长在底座上——识别依赖工程判断、理论依赖科学素养、不可逆判断依赖工程判断；底座缺一块，增量全是空转（1.1）。
3. 十项合起来才是完整答案——ISO 42010 三组词分工：元素是工程师的，关系与演化是架构师的（1.3）。
4. 识别后果严重的决策，不是"想得多"，是"认得出哪类决策必须按决策对待"——大多数团队把精力花在无关紧要的决策上，对真正致命的决策从不当成决策来对待（1.4）。
5. 对不重要的事情不决策，本身就是一种好的架构决策——对重要的事情不决策，是架构师的第一宗罪（1.4）。
6. 对系统的理论，就是回答三个问题：靠什么成功 / 最大压力在哪 / 做错什么最致命——同一个箱子两种理论是两种世界观（1.5）。
7. 好的架构师不是画出最漂亮架构图的人，而是对自己系统的理论最清醒的人——知道判断依据是什么，也知道在什么条件下这个判断会失效（1.5）。
8. 图是死的，视图是活的——把架构说清楚=让每个相关方的关注点都有一张图能落；冲突不可消除只能权衡，架构师给冲突一个可见的落点（1.6）。
9. 判断不可逆性，是把架构决策从"今天能不能上"的日常节奏里拎出来，放进"值不值得为它多花三周"的另一个时间尺度（1.7）。
10. 认知对象从"需求"换成"关切"——工程师面对规定需求（明示可验证有参照），架构师面对关切（可模糊可冲突没有标准格式）（1.8）。
11. 验证方式从"测试"换成"评审"——架构没有唯一正确解，无法用测试证实，只能靠评审验证 rationale；代码用测试验证，架构用评审验证（1.8）。

**第二幕 · 磨边弧的机制（不是什么）**
12. 把职级当物种——职级是组织给的位置，物种是能力决定的；职级也不定义架构师；同一个系统，工程师横着做深，架构师横着铺广（2.1）。
13. 技术负责人管人，架构师管决定——判断是技术负责人还是架构师，看他在压力下护住的是什么：护住交付，是技术负责人；护住结构，是架构师（2.2）。
14. 管理权可以任命，领导力不能任命——技术领导力在"能力"清单里不在"职位"清单里；可信度是唯一货币，只能靠"让别人因为你的判断而受益过一次"挣来（2.2）。
15. 项目经理对日历负责，架构师对演化负责——"进度 vs 结构"冲突，正是第2章价值层失守的现场（2.3）。
16. 领域专家懂业务，架构师懂系统——好的架构师不抢领域专家的活，他让领域专家的规则在系统里待得住、改得动（2.4）。
17. 画图匠画图，架构师做决定——图是决定的表达还是决定的替代；删掉图剩下的决定才是架构（2.5）。
18. 失败四式各缺一项——画图匠缺⑤工程判断（死于没有判断）/ 什么都管缺⑦（对不重要的事情疯狂决策、对重要的视而不见）/ 不决策缺⑩（把决定留给默认，默认最保守）/ 远离代码缺③（判断失去锚点、理论不落地）（2.6）。

**第三幕 · 往哪去的机制（运用）**
19. 成长的本质是判断的依据换尺度——代码→模块→系统→架构决策；你关心的问题换了，你的物种就变了（3.1）。
20. 每上升一级，空间维度与时间维度同时扩张——工程师管元素管当下，架构师管关系与演化管多年演进（3.1）。
21. 被任命只是拿到一张牌桌的入场券——成为架构师的过程=能力清单一项一项亮起来的过程（3.2）。
22. 三种来路三种功课——从开发长出来（缺⑦⑧⑩）/ 空降（缺③⑥）/ 挂名（只有头衔）；判断走哪条路，看他在补清单的哪一项（3.3）。
23. 成长的标志是第一次"说不"——拦下的不是"错的"，是"没想清楚不可逆性的"；判断不可逆性（⑩）是成长路上最后一盏灯，因为它需要前面所有能力都到位才接得住（3.4）。
24. 再往上不是更深的架构，是关注维度的扩张——系统之系统杀手特征：每个子系统都有自己的 owner 和生命周期，没有全局 owner；从元素到系统、从系统到组织是同一种升级的两次上演（工具不变，棋盘变大）；CTO 头衔同样不定义能力（3.5）。
25. 能力的最终体现是能否开发出高质量的上半棵树——枝干立结构、枝梢定承接，让工程师的叶子有地方落、落得对；能力再强，开发不出高质量的上半棵树，架构师也不成立（3.6）。
26. 枝梢=1:1 搬入点——接口契约是工程师叶子落下的那根枝梢；架构决策错，代价是结构性的：上半棵错了，整棵下半棵跟着错（3.6.1）。
27. 六项能力在架构师侧的落点——把能力从"人身上"挪到"纸面上"，不是为了考核，是为了让能力可被检验（②⑥最终都露在产品数据上）（3.6.2）。
28. 检验句：换个人，拿着你负责的架构描述和决策，能不能接住、继续演进？能，你的架构才成立；不能，再大的图也只是装饰（3.6.3）。

**从见过到拥有（方法底座时刻，显式命名）**：对"架构师"这个词，章首的李工只有"见过"——叫得出头衔、画得出图，却答不上"当选架构师意味着你现在是什么"；判词把他量成"拥有"——能对着十项清单一项一项打勾、认得出自己缺什么。**判词把"架构师"从头衔钉成了能力清单。**

### 本章判据（十把尺子 + 一把终极尺）

1. **科学素养**：我对这个系统的理论是什么？靠什么成功、最大压力在哪、做错什么最致命？
2. **方法论素养**：我的方法能被别人学会吗？还是只有我会？
3. **实践能力**：我最近一次亲手落地，是什么时候？
4. **职业伦理**：压力面前，我会不会为进度悄悄牺牲可靠性？有没有让相关方知情？
5. **工程判断**：冲突里，我依据什么做取舍？
6. **可复现意识**：我的判断换个人能接住吗？我写决策记录吗？
7. **识别后果严重的决策**：我分得清哪类决策必须按决策对待吗？我对不重要的事不决策吗？
8. **对系统的理论**：我的架构有原理吗？换个上下文还成立吗？
9. **把架构说清楚**：每个相关方的关注点，都有一张图能落吗？
10. **判断不可逆性**：我认得出不可逆决策吗？该早做的早做、该推迟的显式推迟吗？
11. **终极尺**：能力再强，也要看我能不能开发出高质量的上半棵树——换个人，拿着它，能不能接住、继续演进？

（派生判据：画图匠判据=删掉图剩下的决定才是架构；压力判据=压力下护住交付是技术负责人、护住结构是架构师；验证方式判据=代码用测试验证、架构用评审验证。）

## 第 2 步 · 量学立标：掌握清单

### 概念层（应能定义与辨析）

1. 能定义"架构师"（先是一个工程师 + 增量 = 十项能力清单；头衔不定义架构师），并能说出底座六项与增量四项及各自对应章（第8章 / 第9·11章）。
2. 能辨析 架构师 vs 更高级的工程师（职级是位置、物种是能力；两种决策域：架构设计管系统级 vs 详细设计管模块内部——同一个系统，工程师横着做深，架构师横着铺广）。
3. 能辨析 架构师 vs 技术负责人（管决定 vs 管人；看压力下护住的是什么；管理权可以任命、领导力不能任命）。
4. 能辨析 架构师 vs 项目经理（管结构 vs 管进度；对演化负责 vs 对日历负责）。
5. 能辨析 架构师 vs 领域专家（懂系统 vs 懂业务；好的架构师不抢领域专家的活）。
6. 能辨析 架构师 vs 画图匠（图是决定的表达 vs 决定的替代；删掉图剩下的决定才是架构）。
7. 能说出两个更锋利的差异（认知对象 需求→关切；验证方式 测试→评审）及与第7章三把尺子的关系。
8. 能说出增量四项的来源（ISO/IEC/IEEE 42010 元素 / 关系 / 设计准则与演进准则——元素是工程师的，关系与演化是架构师的）。
9. 能说出失败四式（画图匠 / 什么都管 / 不决策 / 远离代码）及各自缺哪一项。
10. 能说出三种来路（从开发长出来 / 空降 / 挂名）及各自功课。
11. 能说出再往上的四条路径（深度·首席架构师 / 宽度·企业架构师 / 组织·CTO / 权威·首席工程师）及"工具不变，棋盘变大"。
12. 能说出架构师的产品数据（上半棵树：概要定义 / 接口契约 / 架构决策 ADR / 架构描述 AD / 系统级验证方案）与"枝梢=1:1 搬入点"。

### 原理层（应能解释为什么）

1. 能解释为什么架构师首先是一个工程师（次序问题：先有元素级正确，才有系统级方向）。
2. 能解释为什么增量长在底座上（识别依赖工程判断、理论依赖科学素养、不可逆判断依赖工程判断——底座缺一块增量空转）。
3. 能解释为什么十项合起来才是完整答案（ISO 42010 元素工程师 / 关系与演化架构师）。
4. 能解释为什么识别后果严重的决策不是"想得多"（认得出哪类必须按决策对待；对不重要的事情不决策）。
5. 能解释为什么对系统的理论是两种世界观的分野（同一箱子两种理论是两种世界观；知道自己何时失效）。
6. 能解释为什么把架构说清楚=让每个相关方关注点有图能落（图死视图活；冲突给可见落点）。
7. 能解释为什么判断不可逆性是另一个时间尺度（从"今天能不能上"拎出来，放进"值不值得多花三周"）。
8. 能解释为什么认知对象从需求换成关切（关切比需求宽，可模糊可冲突、没有标准格式）。
9. 能解释为什么验证方式从测试换成评审（架构无唯一正确解，只能对目标评审；代码用测试验证架构用评审验证）。
10. 能解释为什么职级不定义架构师（职级是位置、物种是能力；两种决策域）。
11. 能解释为什么技术负责人管人、架构师管决定（压力下护住交付还是护住结构）。
12. 能解释为什么领导力不能任命（技术领导力在能力清单；可信度是唯一货币，积累慢消耗快）。
13. 能解释为什么项目经理对日历负责、架构师对演化负责（"进度 vs 结构"冲突是价值层失守的现场）。
14. 能解释为什么画图匠死于没有判断（团队发现图不能用来做决定，于是绕过图各做各的）。
15. 能解释失败四式各缺哪一项，以及为什么"什么都管"看起来最负责却最危险（团队失去判断能力+他成瓶颈；重要决策没精力）。
16. 能解释为什么成长=判断依据换尺度（关心的问题换了物种就变了；空间维度与时间维度同时扩张）。
17. 能解释为什么被任命≠成为（入场券 vs 能力清单一项项亮起来；能力可长，名头是时间的快照）。
18. 能解释为什么成长的标志是第一次"说不"（拦下的不是"错的"，是"没想清楚不可逆性的"；⑩是最后一盏灯）。
19. 能解释为什么再往上不是升职而是关注维度扩张（系统之系统无全局 owner；从元素到系统、从系统到组织是同一种升级的两次上演；CTO 头衔不定义能力）。
20. 能解释为什么能力最终体现在开发出高质量的上半棵树（十项抽象在人身上不可直接检验；枝干立结构、枝梢定承接；换个人接住才算数）。
21. 能解释为什么枝梢=1:1 搬入点（接口契约=工程师叶子落下的枝梢；架构决策错代价是结构性的）。
22. 能解释为什么判词和产品数据量的是同一把尺子（李工缺①④⑥ / 老周缺②⑥ 都露在产品数据上——李工四张图下没有决定、老周判断换个人做不出来）。

### 判据层（应会用）

1. **十项能力体检**：逐项自问十把尺子——三种场合（招人面试 / 团队体检 / 自己对照）各会用。
2. **画图匠判据**：删掉你所有的图，你的决定还在=架构师；删掉图什么也没剩下=画图匠。
3. **压力判据**：压力下护住的是交付=技术负责人，护住的是结构=架构师。
4. **验证方式判据**：代码用测试验证，架构用评审验证（评审对目标）。
5. **终极尺**：能力再强，也要看能否开发出高质量的上半棵树——换个人，拿着你负责的架构描述和决策，能不能接住、继续演进？
6. **工作检查单**（每次做架构决策前）：影响半径大/持续时间长/修改成本高吗？理论对不对得起它？相关方视图跟上了吗？决策记录写了吗？在做决定还是在画图/什么都管/等默认？接口契约（枝梢）改了吗？

### 纠错红线十条

1. **先表态后翻案**：先让学员说"李工当选年度架构师、图最多文档最全，当然算架构师"，再翻，不让结论先入。
2. **反转精确不造新误解**："头衔不定义架构师"别翻成"头衔没用/该取消职称"；"架构师不是画图的人"别翻成"架构师不用画图/视图不重要"（图死视图活，视图恰恰是⑨把架构说清楚的落点）；"再往上不是升职"别翻成"架构师不该往组织走"。
3. **判据配机制**：每条反转都有"为什么"（机制）和"怎么当场验证"（判据）。
4. **归责到可对照动作**："他不是架构师"落到"⑩没打勾——把高不可逆决策当日常节奏 / ⑥没打勾——判断换个人接不住 / ④没打勾——压力面前为进度让路"，不归咎"人不行"。
5. **教机制不教断言**：教"为什么什么都管最危险"（团队失去判断能力 + 他成瓶颈 + 重要决策没精力），不教"别管太多"。
6. **先立尺子再翻案**：先给十项能力体检判据 + 画图匠判据，再翻"李工四张图当全部工作"。
7. **拉开强度层次**：★★★ 常识（架构师=升职 / 画图 / 什么都管 / 被任命=成为 / 可以不会写代码）重点翻。
8. **每个纠正落到可操作动作**：讨论完给"回去做一件事"（用十项清单给团队某人打勾、落判词、过工作检查单）。
9. **单一权威不另立标准**：判据引用书（十把尺子 + 终极尺 + 画图匠判据 + 压力判据），不发明新尺子。
10. **网搜当佐证**：N1~N7 只作"这不是书里一个人的说法"佐证，药与判据全在书内。

## 第 6 步 · 化尺为用：落地工具

### 作业指南（主产出）：用十项能力清单给团队"最像架构师的人"做一次体检 + 落判词 + 反身判团队

> 目标：把十项能力清单从"背诵对象"变成"判人的尺子"——给团队里一位公认最像架构师的人做一次十项体检，落一条判词（像李工缺①④⑥还是像老周缺②⑥），再反身判自己团队，最后落到产品数据（上半棵树）与工作检查单。
> 场景：回部门落地。时长：一次 60 分钟；两周后复查。

1. **挑对象（先立枢纽）**：选团队里"公认最像架构师的人"——最像的，往往也最容易在某一项打不上勾。
2. **项目一 · 十项体检打勾**：底座六项——①科学素养（他对系统的理论是什么？靠什么成功、最大压力在哪、做错什么最致命？）②方法论素养（他的方法能被别人学会吗？还是只有他会？）③实践能力（他最近一次亲手落地是什么时候？）④职业伦理（压力面前会为进度牺牲可靠性吗？有没有让相关方知情？）⑤工程判断（冲突里他依据什么做取舍？）⑥可复现意识（他的判断换个人能接住吗？他写决策记录吗？）；增量四项——⑦识别后果严重的决策（他分得清哪类决策必须按决策对待吗？对不重要的事不决策吗？）⑧对系统的理论（他的架构有原理吗？换个上下文还成立吗？）⑨把架构说清楚（每个相关方的关注点都有一张图能落吗？）⑩判断不可逆性（他认得出不可逆决策吗？该早做的早做、该推迟的显式推迟吗？）。
3. **项目二 · 落判词**：对照两条基准线——李工有头衔缺①④⑥（被任命的架构师在补底座）、老周无头衔缺②⑥（有底座一半的架构师在补元能力）——你的对象像哪条线？缺的是哪一项？**话术**："他不是不会做，是做的能力不可复制"（像老周）/ "他不是不会画，是图下面没有决定"（像李工）。
4. **项目三 · 反身判团队 + 反身自检**：拿掉头衔和年资，用同一张清单给团队逐项打勾——谁缺哪一项？他正在长成的是哪一项？再用清单给自己打勾——你缺的那一项，正是你在"背清单"而不是"用清单"的地方（从见过到拥有：能对着清单一项一项打勾，才算拥有）。
5. **项目四 · 落到产品数据（上半棵树）**：问最后一个问题——他/你负责的上半棵树（概要定义 / 接口契约 / 架构决策 ADR / 架构描述 AD / 系统级验证方案），换个人拿着能接住、继续演进吗？②⑥两项尤其看纸面（方法写不写得成视图、判断换个人接不接得住）。
6. **项目五 · 过工作检查单六条**：下次做架构决策前，先过那六条（影响半径大/持续时间长/修改成本高？理论对不对得起它？相关方视图跟上了吗？决策记录写了吗？在做决定还是在画图/什么都管/等默认？接口契约改了吗？）——把它打印出来贴在下一个架构决策现场。
7. **出体检报告**：十项各打勾/缺项，落判词，最该先补最缺的一项；两周后复查补了什么。

**卡住怎么判断**：打不上勾的那一项就是最该补的；⑥打不上勾=手艺型架构师（判断换个人接不住）；④打不上勾=最危险（判断越准破坏越大）；⑦⑩打不上勾=把不可逆决策当日常节奏（阿凯改走受控导出 / 李工认下编号规则是正例）；价值层三问（相关方知情/评审/记录）当场打勾——"没有记录"的地方就是④可能缺席、也是①和⑥最容易现形的地方。

### 工作检查单（配套素材）

| 检查项 | 是/否 | 否 → 可讨论发现 |
|---|---|---|
| 十项能力逐项能打勾？ | □ | 打不上勾的那一项=最该补的 |
| 判断换个人能接住？（⑥可复现） | □ | 手艺型架构师——判断绑定在人身上，架构随人走 |
| 决策记录写了吗？不可逆性标注了吗？ | □ | ⑥可复现意识缺位；架构用评审验证缺了评审对象 |
| 压力面前为进度牺牲可靠性了吗？（④） | □ | 判断越准、④越缺、破坏越大 |
| 分得清哪类决策必须按决策对待吗？（⑦） | □ | 对不重要的事情疯狂决策、对重要的视而不见 |
| 在做决定，还是在画图 / 什么都管 / 等默认？ | □ | 失败四式对号入座——每种都能在清单里找到缺项 |
| 上半棵树（概要定义/接口契约/ADR/AD/系统级验证）换个人能接住吗？ | □ | 能力再强，开发不出高质量的上半棵树不成立 |
| 下次做架构决策前过工作检查单六条了吗？ | □ | 把"换个人能不能接住"收口到每次决策 |

## 第 7 步 · 淬问成题：题卡（10 题 2×5）

### 第一组 · 概念与原理（5 题）

**Q1（破题 · 见树见林① · 概念本身）**
"年度评优会上，恒信把『年度架构师』颁给了李工，颁奖词是：『全年产出架构图最多、架构文档最全。』会后 Ada 问李工：『当选架构师，意味着你现在是什么？』他答不上来。办公室三个人接话：开发说『架构师就是更高级的工程师——升职了嘛』；测试说『架构师是画架构图的人，图画得最多那个』；运维说『架构师是什么都管的人，出了事都找他』。三句话三个『架构师』，错在哪？『架构师』到底是个什么样的物种？"
追问：① 十项能力清单——底座六项（第8章）+ 增量四项（第9、11章），怎么构成一个整体？『架构师首先是一个工程师』为什么是次序问题（没有那六项底座，『架构师』三个字只是一张名片）？② 三句话分别把什么当成了判据（职级 / 画图 / 权力——都是名义或载体，不是能力）？③ 反身：你们公司颁『架构师』头衔 / 评优时，依据的是图多文档全，还是十项能力清单？

**Q2（见树见林② · 概念关系）**
"请给出 架构师 和 更高级的工程师、技术负责人、项目经理、领域专家、画图匠 这五个相邻角色的关系，并说明：为什么说『职级也不定义架构师』？增量四项（⑦⑧⑨⑩）为什么长在底座六项上，而不是一套独立的『架构师能力』？"
追问：① 每一个角色边界各是"管什么 vs 管什么"（架构师管决定 / 管结构 / 管演化 vs 技术负责人管人 / 项目经理管进度 / 领域专家懂业务 / 画图匠画图）？② 为什么增量长在底座上（识别依赖工程判断、理论依赖科学素养、不可逆判断依赖工程判断——底座缺一块，增量全是空转）？③ 反身：你们团队里"该由架构师决定却被别人抢走"的决定，抢走它的人缺的是清单里的哪一项？

**Q3（真悖论 · 头衔/任命 vs 能力）**
"李工被任命为『年度架构师』、名片换了、评优都评上了——有头衔、有职位、有舞台。可 Ada 问他『当选架构师意味着你现在是什么』，他答不上来；按十项清单自我体检，他缺①④⑥。有头衔、被任命，到底算不算架构师？什么判据能分清『头衔』和『能力』？"
追问：① 头衔是组织给的位置、职级是组织给的位置——为什么都定义不了架构师（被任命只是拿到牌桌的入场券；『头衔一路在换，背在身上的东西没有变』）？② 李工缺①④⑥各是什么证据（①科学素养——长期不碰实现、理论开始悬空 / ④职业伦理——为进度悄悄牺牲可靠性的账没还清 / ⑥可复现意识——以前不写决策记录，现在开始写）？③ 反身：你们部门有没有"头衔先于能力"的架构师？拿掉头衔，他还立得住吗？

**Q4（真悖论 · 画图 vs 架构）**
"李工的四张图挂满一面墙，图越来越漂亮、文档越来越全——评优就把『年度架构师』颁给了他。这一章却说：删掉你所有的图，你的决定还在，你是架构师；删掉图你什么也没剩下，你是画图匠。『把图画得最全』和『把架构做出来』到底差在哪？什么判据能分清『图』和『架构』？"
追问：① 图是决定的表达还是决定的替代——四张图为什么是画图匠的作品（图下面没有任何关于『决定』的字，直到 Ada 点醒他，把四张图换成一份决定清单）？② 老周的『老规矩』不是图，是一份清单（不可还原的涵义、设计准则、演进准则）——图是死的、视图是活的，为什么『让每个相关方的关注点都有一张图能落』（⑨）比图本身重要？③ 反身：你最近一次交的『架构』，删掉图还剩什么？

**Q5（真悖论 · 什么都管 vs 管得最准）**
"运维说：架构师是什么都管的人，出了事都找他——很多人也这么信，觉得架构师就该对每个接口、每行代码、每个表负责。这一章却说：管得最准，不是管得最多；对不重要的事情不决策，本身就是一种好的架构决策。哪个对？什么判据分清『该管的』和『不该管的』？"
追问：① 什么都管为什么危险（两条后果：团队失去自己判断的能力、他成了瓶颈；精力花在大量低价值决策上，真正重要的决策反而没有精力——缺⑦）？② 识别后果严重的决策的判据（影响半径大 / 持续时间长 / 修改成本高——按决策对待；对重要的事情不决策，是架构师的第一宗罪）？③ 反身：你们团队最近一次"对重要的事情不决策、对不重要的事情疯狂决策"，是哪一个？

### 第二组 · 落地与实践（5 题）

**Q6（判据运用 · 双线判词 · 十项体检）**
"用十项能力清单，给李工和老周下判词：李工有头衔缺①④⑥，老周无头衔缺②⑥。先把两条判词逐项打勾验证，再说说：两个人都是『缺』，缺的性质有什么不同？两个人都不是完整的架构师，那『两个都在长成』是什么意思？"
追问：① 李工的里子（判断还悬着、伦理的账欠着）vs 老周的面子（判断顶配但不可复制）——各自缺项露在产品数据的哪里（李工四张图下没有决定，直到开始写 ADR / 老周老规矩写在纸上，但判断换个人做不出来）？② 判词（案例进展①②③）和 3.6（产品数据：上半棵树）量的是同一把尺子（换个人接得住吗）——为什么？③ 反身：你更接近哪条线？缺的是哪一项？

**Q7（判据运用 · 失败四式 · 四宗死法）**
"失败四式——画图匠（只有视图没有判断）、什么都管（把约束管成枷锁）、不决策（把决定留给默认）、远离代码（判断失去锚点）。用十项能力清单，说出每一宗死法缺的是哪一项。哪一宗最危险？为什么？"
追问：① 画图匠为什么死于『团队发现图不能用来做决定』而不是被辞退（缺⑤工程判断——图说系统长这样，但遇到『数据放哪』没人能答，大家绕过图各做各的）？② 什么都管为什么看起来最负责、其实最危险（对不重要的事情疯狂决策、对重要的视而不见——缺⑦；他成了瓶颈）？③ 不决策为什么是把架构决策的资格交给运气和时间（不选就是选了默认，默认最保守最省事——缺⑩判断不可逆性）？④ 反身：你最近一次架构决策更接近哪一宗？缺的是清单里的哪一项？

**Q8（判据运用 · 成长 + 被任命≠成为 + 三种来路）**
"李工被任命为『年度架构师』那天，头衔换了——但 Ada 那个问题他还是答不上来。为什么『被任命』不等于『成为』？怎么判断一个人是不是真的在长成架构师（判断的依据在哪个尺度）？三种来路（从开发长出来 / 空降 / 挂名）各是什么功课？"
追问：① 成长的本质=判断的依据换尺度（代码→模块→系统→架构决策：你关心的问题换了，你的物种就变了）——你现在判断的依据在哪个尺度？② 三种来路各缺什么（从开发长出来缺⑦⑧⑩、空降缺③⑥、挂名只有头衔）——判断一个人走哪条路，看他在补清单的哪一项？③ 成长的标志=第一次"说不"——阿凯自己把直连方案划掉改走受控导出、李工认下编号规则，拦下的为什么不是『错的』而是『没想清楚不可逆性的』（⑩判断不可逆性是最后一盏灯，需要前面所有能力到位才接得住）？

**Q9（方法时刻 · 规则 15 · 从见过到拥有 + 判词变体）**
"李工有『年度架构师』头衔、老周连名片上都印着『嵌入式硬件工程师』——可这一章的方法底座时刻是『从见过到拥有』：章首的李工对『架构师』只有『见过』——叫得出头衔、画得出图，却答不上『当选架构师意味着你现在是什么』；判词把他量成了『拥有』——能对着十项清单一项一项打勾、认得出自己缺什么。**判词把『架构师』从头衔钉成了能力清单。** 把这张清单从『背诵对象』变成『判人的尺子』：先用它判李工（有头衔缺①④⑥——证据是什么？）、再判老周（无头衔缺②⑥——证据是什么？）、最后反身判你自己的团队——谁缺哪一项？用什么判据检验（不是头衔、不是感觉）？"
追问（判词变体）：① 判李工"缺①④⑥"，证据各是什么（①长期不碰实现、理论开始悬空 / ④为进度悄悄牺牲可靠性的账没还清 / ⑥以前不写决策记录，现在开始写）？判老周"缺②⑥"，证据是什么（方法是手艺的极致、不成体系 / 判断换个人做不出来、车间没有完整测试方案）？② 反身判团队：拿掉头衔和年资，用十项逐项打勾——你们团队"最像架构师的人"缺哪一项？他正在长成的是哪一项？③ 『从见过到拥有』还意味着什么——能答全十项能力的四问（各是什么、不是什么、判据是什么）、能用清单量别人量自己，才算拥有；这把尺子现在装进你手里了吗？

**Q10（落地生根 · 回部门体检 + 判词 + 工作检查单）**
"结合你们部门现状，用十项能力清单给一位『被当成架构师的人』（或你自己）做一次体检——逐项打勾，指出缺项，落一条判词（像李工缺①④⑥还是像老周缺②⑥？），给出最该先补的一项，落到一个动作。"
追问：① 十项体检 + 工作检查单六条（影响半径大 / 持续时间长 / 修改成本高？理论对不对得起它？相关方视图跟上了吗？决策记录写了吗？在做决定还是在画图 / 什么都管 / 等默认？接口契约改了吗）先查哪两项？② 你们的架构评审 / 晋升，用的是十项判据，还是"图多 / 文档全 / 头衔高"三个错判据（和章首颁奖词一模一样）？③ 两周后回来报告：谁打了勾、缺了哪项、补了哪个动作。

- **方法时刻（规则 15，每单元至少一题）**：**Q9**（从见过到拥有 · 方法底座时刻——判词把"架构师"从头衔钉成能力清单；**判词变体必启用**——用十项能力清单判李工（有头衔缺①④⑥）/老周（无头衔缺②⑥），再反身判自己团队，把清单从"背诵对象"变成"判人的尺子"）；ch15 方法底座时刻属**方法操作类**（从见过到拥有是第1章方法，非本章纯判据运用——判词要用十项判据，但"用清单判人/反身判团队/能答全四问才算拥有"是方法操作本身），故方法时刻题独立成题、不与判据运用题合并。
- **真悖论收束三处**（两端皆真、靠判据和解）：
  - Q3 有头衔被任命 vs 算不算架构师 → 判据 = 十项能力清单 + 被任命≠成为（头衔是组织给的位置、职级是组织给的位置，判断可检验的不在名片上，在十项能力清单上；能力可长，名头只是时间的快照）；
  - Q4 把图画得最全 vs 把架构做出来 → 判据 = 画图匠判据（删掉图剩下的决定才是架构）+ ⑨把架构说清楚（图死视图活——让每个相关方的关注点都有一张图能落）；
  - Q5 什么都管 vs 管得最准 → 判据 = 识别后果严重的决策三判据（影响半径大/持续时间长/修改成本高——对不重要的事情不决策，本身就是一种好的架构决策）。
- **设题九检全过**：①无直觉能秒答（每题翻案，Q1 先认同三个人再翻）；②追问链齐（机制/判据/归责/反身）；③概念锚点在导读给足（十项能力清单/五对角色边界/名义不定义/失败四式/成长/产品数据上半棵树）；④题面依据全在书内（评优会颁奖词/三句评语/李工自我体检缺①④⑥/四张图/老规矩/老周被叫架构师/失败四式/阿凯受控导出/李工认下编号规则/上半棵树/工作检查单）；⑤靶子皆"从没怀疑"的常识（架构师=升职/画图/什么都管/被任命=成为/可以不会写代码/图全=最好/经验=理论/底座增量两套）；⑥每题落回判据或动作；⑦全部"信了相反"非知识盲区；⑧前提自证（评优会细节、李工缺①④⑥画像、老周缺②⑥判词、阿凯改走受控导出、失败四式症状写进题面）；⑨三处升级为真悖论收束。
