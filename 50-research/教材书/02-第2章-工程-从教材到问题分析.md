## 第 1 步 · 剖章立骨：核心内容地图

**这一章回答的问题**：我们到底在做什么？是工程，还是用工程的外壳包装的手艺？这两个词的区别，决定了你交付的东西能不能"换个人也交得出来"。

**三幕对齐（省一步推导）**：
- **第一幕 是什么（定界）**：1.1 一句话工程 → 1.2 四要素逐个看（③④ 补展开：三可咬合 / 人造物）→ 1.3 80 年四权威收敛 → 1.4 试金石（判据前移）—— 喂第一组·概念题（见树见林）；
- **第二幕 不是什么（磨边弧）**：2.1 工程没有单一对立面（三维，艺术维度补例）→ 2.2 不是手艺（试金石第一次使用）→ 2.3 不是方法论（四层结构 + 价值层 + 三大事故）→ 2.4 不是机械化（三词辨析 + 加功能正反对照 + 乐队类比 + 系统化四特征vs即兴 + 不确定性精髓 + 自动化两反直觉）—— 喂真悖论·辨边界题；
- **第三幕 往哪去（运用）**：3.1 系统工程=元工程（补软件系统工程递归）→ 3.2 涌现属性（补成因）→ 3.3 工程系统 ⊃ 技术系统（补技术系统三特征）→ 3.4 验收参照（补 Ropohl 社会技术系统）→ 3.5 工程体检（六把尺子合起来）—— 喂第二组·落地 / 方法时刻题（规则 15）。

### 核心概念

1. **工程**（engineering）：科学原理 × 判断创造，在约束下，用系统方法，造出有用且安全的东西。判据：试金石（换个人、换团队，同等需求与约束能交付质量相当的结果——能是工程，不能是手艺）。四要素结构：科学原理=料、约束=框、系统方法=路、有用且安全=果；三可咬合（可计划/可度量/可复现）是系统方法保证的。
2. **工程系统**（engineered system）：被设计/改造的、与预期运行环境交互、达成预期目的、遵守适用约束的系统——可以包含人、流程、组织、信息（INCOSE 2019）。判据：承诺"整个社会技术系统能运转"，不是"设备跑起来"。技术系统三特征（纯人工制品 / 功能靠技术实现 / 人只是外部使用者）——工程系统的内核。
3. **系统工程**（systems engineering）：构建复杂系统的工程——把总需求分解分配给各部件工程、定义接口、做系统级集成与验证的"元工程"（工程之上的工程，不造任何部件）。判据：涌现属性——部件全对 ≠ 系统对。
4. **软件工程**（software engineering）：把工程应用于软件（IEEE 610.12）——systematic / disciplined / quantifiable 三个形容词展开为"工程化过程特征"六方面；软件系统本身是技术系统，"软件 + 用户 + 业务流程 + 运维组织"才是工程系统。
5. **技术系统**（technical system）：仅由人工技术组件（硬件、软件、机械、电气）构成的系统，人只是使用者——工程系统的内核；三个特征：纯人工制品、功能靠技术实现、人只是外部使用者。

### 对立概念（远界）

| 概念 | 对立面 | 问什么 |
|---|---|---|
| 工程 | 科学（认识论） | 发现世界 vs 创造世界 |
| 工程 | 手艺（方法论） | 可复现 vs 依赖个人 |
| 工程 | 艺术（目标） | 满足用户 vs 表达自我（梵高的画不为人"可用"，工程师造的桥要被人走） |
| 工程 | 方法论（部分 vs 全部） | 方法论只是四层之一，不是工程本身 |
| 系统化 systematic | 算法化 algorithmic | 有章法的判断 vs 确定性执行（无需判断）；"机械化"=算法化 |
| 系统化 systematic | 系统性 systemic | 做事有章法 vs 看问题有全局（不属对立，属辨析） |
| 工程系统 | 技术系统 | 整个社会技术系统 vs 设备的集合 |
| 系统化 | 即兴发挥（ad hoc） | 有结构/有章法/可重复/全覆盖 vs 无结构/无章法/不可复现/有盲区 |

### 关联概念（近界 · 辨析）

- **四要素 ↔ 四层结构（两套说法一套算盘）**：科学原理=料=第一层工程科学；系统方法=路=第二层方法论+第三层工具实践；有用且安全=果=第四层价值与伦理；约束=框（每层取舍的舞台）；判断创造=手（每层取舍的动作）。
- **试金石 ↔ 反事实检验（第1章）**：试金石是反事实检验的落地——去掉那个人，交付还成立吗。
- **约束 × 判断创造**：判断 = 在约束下做取舍；约束越多，判断的价值越大；判断不能写全成规则（纯可复现是算法）。
- **工程系统 ⊃ 技术系统 ↔ 涌现属性**：工程系统把边界画在整个运行环境上，正是为了装下"部件全对、系统未必对"的涌现行为。
- **系统工程 × 接口管理**：部件之间的接口契约、数据口径、时序依赖——"缝"才是系统工程的战场；系统工程的产品是接口契约、集成方案、系统级验证方案。
- **软件工程 × 系统工程（递归）**："系统"是递归的——软件工程=构建软件系统的工程；软件足够大（操作系统/微服务集群）时内部长出"软件系统工程"（系统架构师/接口契约/集成测试/端到端验证）=软件世界里的元工程。
- **系统化 × 乐队类比**：系统化不是"像机器一样"按固定程序走，是"像一支乐队"——每个乐手按总谱演奏、指挥根据现场调整节奏，有流程但流程里留着判断的位置。
- **系统化 × 不确定性**：系统化的目的不是消灭不确定性（需求会变、环境会变、人会犯错），是把不确定性纳入可控范围；敏捷高度系统化却一点不算法化。
- **工程系统 × 社会技术系统（Ropohl）**：很多系统是技术子系统+人的子系统+组织子系统耦合的整体——技术部分是内核，单独优化它没有意义；INCOSE 2019 把定义从 technical system 改写为 engineered system。
- **工程系统 × 生命周期**：INCOSE 定义说工程系统要被"实现、使用、退役"——要为退役做设计；软件系统不是概念系统（有运行环境、有生命周期）。
- **IEEE 610.12 定义的是软件工程不是工程本身**：它的原话是"把工程应用于软件"，把"工程"当已知概念引用——翻译伪朋友式的严谨（第1章词汇病）。
- **"上线=成功" ↔ "UAT 跑了=确认过了"**：给第8章埋下回声——把"结果当成功"的病，同一病的两种形态。

### 核心原理

**第一幕 · 是什么的底层机制**
1. 工程是应用原理，不是发现原理——科学原理回答"为什么这样能行"（1.2①）。
2. 约束是定义的一部分，不是附加项——1941 ECPD 最早定义里就同时出现"运行经济性"和"生命财产安全"两个约束（1.2②）。
3. 约束越多，判断的价值越大——没有约束就没有判断空间，无限预算无限时间的项目不需要判断（§2.2.2）。
4. 判断不能写全成规则——约束一变，写好的规则就失效；纯可复现是算法，工程是"可复现的方法 × 不可复现的判断"，判断必须留在人身上（§2.2.2）。
5. 系统方法保证"可计划、可度量、可复现"三可相互咬合——可计划才知道花多少资源、可度量才知道做没做对、可复现才谈得上"换个人也能交付"；工程交付"有用的人造物"不是灵感，所以可复现、可检验（1.2③④）。
6. 80 年、四个机构、三个领域收敛到同一组要素——科学原理/判断创造/约束权衡/造福目的/系统方法，是"工程"概念的稳定内核（§2.2.3）。
7. 试金石测的是可复制性，不是能力高低——这正是工程与手艺的分野；它是反事实检验的落地（§2.2.4）。

**第二幕 · 磨边弧的机制（不是什么）**
8. 工程没有单一对立面——取决于维度：认识论×科学、方法论×手艺、目标×艺术（§2.3.1）。
9. 工具不会自动把人从手艺变成工程，可复现才会——手艺的载体从"脑子"换成"脚本"仍是手艺（§2.3.2）。
10. 工程是四层完整的人类实践，缺一层都不是完整的工程——缺前三层是"不专业"，缺价值与伦理是"会出事"（§2.3.3）。
11. 每一次重大工程事故背后，几乎都不是方法论出错，而是价值层失守（泰坦尼克/挑战者/737 MAX）（§2.3.3）。
12. 价值层失守三条可检验标准：相关方知不知情 / 有没有评审 / 有没有记录——客观原因不会专门留记录（§2.3.3）。
13. systematic（系统化·做事有章法）/ systemic（系统性·看问题有全局）/ algorithmic（算法化·确定性执行）三词辨析——本章判据里的"机械化"=algorithmic（§2.3.4）。
14. 系统化的本质不是"多"，是可检查——每一步有输入、输出、检查点；每个决策可追溯；整个活动可复制。"加功能"正反对照：一个越加越乱、一个越加越稳。系统化像乐队不像机器——有流程但流程里留着判断的位置（§2.3.4）。
15. 系统化四特征（有结构/有章法/可重复/全覆盖）vs 即兴四特征（无结构/无章法/不可复现/有盲区）；系统化的目的不是消灭不确定性（需求会变、环境会变、人会犯错），是把不确定性纳入可控范围——敏捷高度系统化却一点不算法化（§2.3.4）。
16. 自动化把判断提纯——机器接走执行，人接住的全是最难的判断（异常处置/边界/目标变没变）（2.4反直觉一）。
17. 自动化是单向门——它消灭的不是事故，是人阻止事故的能力（权限层：系统优先于人；能力层：长期不介入失去情境意识）；工程要"错误可见"（系统化），自动化追求"零错误"（把错误掩盖掉）——方向相反；消灭判断，就是消灭工程（2.4反直觉二）。

**第三幕 · 往哪去的机制（运用）**
18. 系统工程=元工程——"系统"是递归的：软件工程=构建软件系统的工程，系统工程=构建复杂系统的工程；软件足够大（操作系统/微服务集群）时内部也长出"软件系统工程"（系统架构师/接口契约/集成测试/端到端验证）——软件世界里的元工程；接口契约、集成方案、系统级验证方案才是它的产品（§2.4.1）。
19. 涌现属性：单个部件都合格，不等于整体合格——工程把大问题拆成小问题分给许多人做，局部对不等于整体对；接口/口径/时序这些"部分之和的溢出"不属于任何部件，却决定整体成不成立（§2.4.2）。
20. 工程系统 ⊃ 技术系统——技术系统三特征（纯人工制品/功能靠技术实现/人只是外部使用者）是设备的集合；工程系统含人/流程/组织/信息，是整个社会技术系统（§2.4.3）。
21. 工程系统有生命周期——要被"实现、使用、退役"，要为"退役"做设计（安全关停、数据迁移）；软件系统不是"概念系统"（有运行环境、有生命周期），所以软件系统是工程系统（§2.4.3）。
22. 验收参照决定成败：按技术系统看"上线=成功"，按工程系统看"人会用、流程顺、组织撑得住=成功"——把技术系统误当工程系统验收，是系统工程史上最贵的教训；Ropohl 等人点破"很多系统是社会技术系统——技术子系统+人的子系统+组织子系统耦合，单独优化技术部分没有意义"（§2.4.4）。
23. 六把尺子合起来才是一份完整的工程体检——试金石测可复制、四层测完整、六方面测过程、三问测可检查、元工程测整合、工程系统测验收参照（§2.4.5）。
24. "工程师"头衔不等于"在做工程"——工程师这个角色本身，第9章专章回答（本章问题7）。

### 对立误解（喂给第 3 步误解库 / 第 4 步陷阱清单）

1. "系统上线了 = 工程成功。"（把技术系统当工程系统验收）
2. "有流程、有工具、有测试、有敏捷，就是在做工程。"
3. "用了敏捷 + CI/CD + 测试，我们就在做软件工程。"
4. "工程的对立面就是科学。"
5. "约束是工程的敌人 / 麻烦，约束越少越好做。"
6. "工程 = 写代码 / 画图纸 / 用工具。"
7. "工程 = 方法论（瀑布 / 敏捷 / CMMI）。"
8. "只讲方法论不讲伦理，也还算工程（顶多不专业）。"
9. "系统化 = 把流程固化成算法，让机器自动跑。"
10. "微服务每个都健康，系统就是健康的。"
11. "自动化程度越高，系统越安全。"
12. "判断可以全部写进规则 / 对照表。"
13. "软件部署好、服务器跑起来 = 系统成功。"
14. "老工程师经验丰富，这就是工程。"
15. "把老工程师的经验写成文档，就是工程化。"
16. "工程化 = 上 CI/CD / 上工具 / 自动化。"
17. "系统工程 = 管整体的大工程，不用管部件细节。"（把元工程当"大工程"）

### 本章判据（五把尺子）

1. **试金石**：换个团队、换个人，用同样的需求和约束，能交付质量相当的结果——能，是工程；不能，那是手艺。
2. **四层结构**：工程科学、方法论、工具实践、价值与伦理，四层同时在场才算工程；只讲方法论是"有组织的赌博"。价值层失守三条判据：相关方知不知情 / 有没有评审 / 有没有记录。
3. **系统化 ≠ 机械化**：系统化是"有章法的判断"，不是"确定性的执行"；工程靠方法，不靠算法。过程特征用六方面检验（有结构/有方法/可重复/全覆盖/受控/可验证，缺一个就是"差一点"）；当场打勾用系统化三问（输入输出/检查点/换执行者）。自动化把判断提纯、是单向门——自动化的终点是消灭判断，消灭判断就是消灭工程。
4. **系统工程 = 元工程**：整合部件、管接口、做系统级验证；涌现属性——部件全对 ≠ 系统对。
5. **工程系统 ⊃ 技术系统**：承诺的是整个社会技术系统能运转，不是设备跑起来。

## 第 2 步 · 量学立标：掌握清单

### 概念层（应能定义与辨析）

1. 能定义"工程"（四要素一句话：科学原理 × 判断创造，在约束下，用系统方法，造出有用且安全的东西），并说出四要素各司其职（料/框/路/果）与系统方法保证的三可咬合（可计划/可度量/可复现）。
2. 能辨析 工程 vs 手艺（方法论维度）/ 科学（认识论维度）/ 艺术（目标维度）——工程没有单一对立面。
3. 能辨析 工程 vs 方法论（方法论只是四层之一，不是工程本身）。
4. 能定义"工程系统"（INCOSE 2019：被设计/改造、与环境交互、有目的、守约束的系统，可含人/流程/组织/信息），并辨析 工程系统 ⊃ 技术系统，说出技术系统三特征（纯人工制品/功能靠技术实现/人只是外部使用者）。
5. 能定义"系统工程"=元工程（把部件整合成整体、不造部件、管接口、做系统级验证），并说明"系统"的递归：软件工程=构建软件系统的工程；软件足够大时内部长出"软件系统工程"。
6. 能辨析 systematic（系统化·有章法）/ systemic（系统性·有全局）/ algorithmic（算法化·确定执行）三词各回答什么问题，并说明本章判据里"机械化"= algorithmic。
7. 能说出系统化四特征（有结构/有章法/可重复/全覆盖）与即兴四特征（无结构/无章法/不可复现/有盲区）的对照，及"加功能"正反对照（一个越加越乱、一个越加越稳）；系统化像乐队不像机器。
8. 能说出 IEEE 610.12 软件工程定义（"把工程应用于软件"）及三个形容词（systematic/disciplined/quantifiable）→ 六方面——注意它定义的是软件工程不是工程本身。
9. 能说出四层结构（工程科学/方法论/工具实践/价值与伦理）及各层缺位的后果（不专业 vs 会出事）。
10. 能说出自动化两反直觉（提纯判断 / 单向门：权限层+能力层）。
11. 能说出 Ropohl 社会技术系统（技术子系统+人的子系统+组织子系统耦合的整体，单独优化技术部分没有意义）与工程系统生命周期（实现/使用/退役）。

### 原理层（应能解释为什么）

1. 能解释为什么工程是应用原理不是发现原理（科学原理回答"为什么这样能行"）。
2. 能解释为什么约束是定义的一部分不是附加项（1941 ECPD 定义里就有两个约束）。
3. 能解释为什么"约束越多，判断的价值越大"（没有约束就没有判断空间）。
4. 能解释为什么判断不能写全成规则（约束一变规则失效；纯可复现是算法；工程=可复现方法×不可复现判断）。
5. 能解释为什么三可相互咬合（可计划才知道花多少资源、可度量才知道做没做对、可复现才谈得上换个人也能交付）。
6. 能解释为什么 80 年四机构收敛到同一组要素（概念的稳定内核）。
7. 能解释为什么试金石测的是可复制性不是能力高低（反事实检验的落地）。
8. 能解释为什么工程没有单一对立面（取决于认识论/方法论/目标哪个维度）。
9. 能解释为什么工具不会自动把人从手艺变成工程（可复现才会；载体从脑子换成脚本仍是手艺）。
10. 能解释为什么价值层最致命（三大事故背后都是价值层失守而非方法论出错）。
11. 能解释价值层失守三条判据为什么成立（相关方知情/评审/记录；客观原因不会留记录）。
12. 能解释三词辨析（systematic 有章法 / systemic 有全局 / algorithmic 确定执行）。
13. 能解释为什么系统化的本质是可检查不是流程多（每一步有输入输出检查点、决策可追溯；"加功能"正反对照；像乐队不像机器）。
14. 能解释为什么系统化的目的不是消灭不确定性（需求会变、环境会变、人会犯错；把不确定性纳入可控范围；敏捷高度系统化却一点不算法化）。
15. 能解释自动化两个反直觉（提纯判断：机器接执行、人接最难判断；单向门：权限层+能力层）。
16. 能解释为什么"错误可见"（系统化）与"零错误"（自动化）方向相反，消灭判断=消灭工程。
17. 能解释为什么系统工程是元工程、软件工程有递归（软件足够大时内部长出软件系统工程）。
18. 能解释涌现属性为什么在工程里无处不在（大问题拆小分给人做，局部对≠整体对；溢出不属于任何部件）。
19. 能解释为什么工程系统边界画在整个运行环境上（INCOSE 2019 从 technical system 改写的动机；技术系统三特征）。
20. 能解释为什么"把技术系统误当工程系统验收"是系统工程史上最贵的教训（上线≠成功；Ropohl 社会技术系统）。

### 判据层（应会用）

1. **试金石**：换个人、换团队，同等需求与约束能交付同等质量——能是工程，不能是手艺；三种场合（团队交接/招聘/复盘）各会用。
2. **四层结构**：四层同时在场才算工程；缺层后果各不同（缺工程科学="只会做不知道为什么"；缺方法论="靠人传人"；缺工具实践="方法论悬空"；缺价值伦理="会出事"）。
3. **价值层失守三判据**：相关方知不知情 / 有没有评审 / 有没有记录——当场打勾。
4. **六方面检验**：有结构/有方法/可重复/全覆盖/受控/可验证，缺一个就是"差一点"（工程里"差一点"往往就是事故）。
5. **系统化三问**：每一步有明确的输入和输出吗？每一步有可检验的检查点吗？换个执行者，结果还稳定吗——三问皆"是"才是系统化。
6. **元工程判据**：系统工程整合部件、管接口、做系统级验证；涌现属性（部件全对 ≠ 系统对）；软件世界里的元工程=软件系统工程。
7. **工程系统判据**：承诺"整个社会技术系统能运转"（技术达标 + 人会用 + 流程顺 + 组织撑得住），不是"设备跑起来"。
8. **工程体检六项目**：可复制性（试金石）/ 完整性（四层）/ 过程特征（六方面）/ 可检查（三问）/ 整合度（元工程）/ 验收参照（工程系统）。

### 纠错红线十条

1. **先表态后翻案**：先让学员说"系统上线了=成功，这还用讨论吗"，再翻，不让结论先入。
2. **反转精确不造新误解**："系统化≠机械化"别翻成"不要自动化"；"约束是舞台"别翻成"约束越多越好"——要区分真实约束与官僚限制；"工程没有单一对立面"别翻成"工程无边界"；"系统工程是元工程"别翻成"系统工程不管部件"。
3. **判据配机制**：每条反转都有"为什么"（机制）和"怎么当场验证"（判据）。
4. **归责到可对照动作**："你没在做工程"落到"试金石一测就倒 / 四层缺两层 / 六方面缺三个"，不归咎"人不行"。
5. **教机制不教断言**：教"为什么价值层失守最致命"（三大事故机制），不教"讲伦理就安全"；教"为什么系统化像乐队"（有流程但流程里留着判断的位置），不教"流程没用"。
6. **先立尺子再翻案**：先给试金石/四层/工程系统判据，再翻李工"我们已经是工程化团队了"。
7. **拉开强度层次**：★★★ 常识（上线=成功 / 敏捷=软件工程 / 自动化越高越安全 / 约束是敌人）重点翻。
8. **每个纠正落到可操作动作**：讨论完给"回去做一件事"（如用试金石测一个交付、用系统化三问照一个流程）。
9. **单一权威不另立标准**：判据引用书（五把尺子），不发明新尺子。
10. **网搜当佐证**：N1~N7 只作"这不是我一个人说的"佐证，药与判据全在书内。

## 第 6 步 · 化尺为用：落地工具

### 作业指南（主产出）：给团队最近交付的一个系统做一次"工程体检"

> 目标：用本章六把尺子（书 3.5 的六个体检项目），对团队最近交付/上线的一个系统做一次完整工程体检，产出三件可执行改进。
> 场景：回部门落地。时长：一次 60 分钟；两周后复查。

1. **挑系统（先立枢纽）**：选一个"最近交付/上线、你心里最有底"的系统——最自信的，往往是四层/试金石最没打勾的。
2. **项目一 · 试金石（可复制性）**：换个团队来运维/交付这个系统，能一样跑吗？——如果靠张三的隐藏命令、李四的环境变量、王五没写进文档的部署顺序，答案就是"不能"，那是手艺。**话术**："这个人走了，交付还能维持吗？"
3. **项目二 · 四层结构（完整性）**：工程科学——"为什么这样能行"有依据吗（容量评估、压测结论）？方法论——需求→设计→实现→验证→维护齐吗？工具实践——方法论落地成工具了吗？价值伦理——压力面前会为质量让路吗？**逐层打勾**，缺层后果各不同（不专业 vs 会出事）。
4. **项目三 · 六方面（过程特征）**：有结构 / 有方法 / 可重复 / 全覆盖 / 受控 / 可验证——挨个过，**缺一个就是"差一点"**，而工程里"差一点"往往就是事故。
5. **项目四 · 系统化三问（可检查）**：每一步有明确的输入和输出吗？每一步有可检验的检查点吗？换个执行者，结果还稳定吗？三问答不上来的地方，那只是一张流程图——拿"加功能"正反对照当试运行：你们最近一次加功能，是越加越乱还是越加越稳？**话术**："你刚才说'加个功能半小时'——三问答得上吗？答不上，那是即兴，不是系统化。"
6. **项目五 · 系统工程（整合度）**：模块各自做得好，但接口、数据口径、时序依赖这些"缝"有人管吗？部件全对 ≠ 系统对，灰色地带是系统工程的地盘；微服务集群里有没有长出"软件系统工程"（接口契约/集成测试/端到端验证）？
7. **项目六 · 工程系统（验收参照）**：按技术系统看——上线了吗、跑起来了吗？按工程系统看——人会用吗、流程顺吗、组织撑得住吗？两个答案不一致，缺的就是人/流程/组织/数据那一块。**技术系统三特征当场对照**：你们这个系统里，人只是外部使用者，还是已经是系统的一部分（流程/组织/操作员）？
8. **出体检报告**：六个项目各下结论（合格/不合格/差一半），**最该先补的是最不合格的一项**；最后一条建议照书抄——先把"验收的参照"从"系统上线"换成"系统被用起来"。

**卡住怎么判断**：答不上来的那一项就是最该补的；价值层失守三判据（相关方知情/评审/记录）当场打勾——"没有记录"的地方，就是失守可能潜伏的地方。不用六项全做完，找到第一个答不出的项目就能开工。

### 工作检查单（配套素材）

| 检查项 | 是/否 | 否 → 可讨论发现 |
|---|---|---|
| 换个人能同等交付？（试金石） | □ | 手艺而非工程——可复制性不合格 |
| 四层同时在场？（工程科学/方法论/工具实践/价值伦理） | □ | 缺工程科学="只会做不知道为什么"；缺价值层="会出事" |
| 价值层三判据打勾？（相关方知情/评审/记录） | □ | 失守恰恰发生在"没有记录"的地方 |
| 六方面缺几个？（有结构/有方法/可重复/全覆盖/受控/可验证） | □ | "差一点"往往就是事故 |
| 每一步有输入输出/检查点/换执行者稳定？（系统化三问） | □ | 那只是一张流程图，不是系统化——即兴，不是系统化 |
| 加功能是越加越稳还是越加越乱？（加功能正反对照） | □ | 非系统化=想起需求直接开写→改表→没测→回滚；系统化=需求评审→影响评估→设计评审→编码+单测→集成回归→预发布→上线→记录 |
| 灰色地带有人管？（接口/数据口径/时序依赖） | □ | 涌现属性在系统的"缝"里等着；微服务集群=软件系统工程 |
| 验收参照是"上线"还是"被用起来"？（工程系统） | □ | 拿"上线"当"成功"是工程系统失败的最贵教训；技术系统三特征对照 |
| 这个系统的边界画在设备壳上还是整个运行环境？（Ropohl） | □ | 单独优化技术部分没有意义——"用不起来"往往卡在人/流程/组织那层 |

## 第 7 步 · 淬问成题：题卡（10 题 2×5）

### 第一组 · 概念与原理（5 题）

**Q1（破题 · 见树见林① · 概念本身）**
"季度会上，李工宣布：『我们敏捷转型成功了。双周迭代、CI/CD 全绿、自动化测试覆盖 80%，我们已经是工程化团队了。』Ada 只问了一句：『上个月上线那次事故，是为什么？』——李工说：『那是人手不够，临时赶工，跟工程化没关系。』这句话错在哪？工程到底是什么？用四要素给恒信的敏捷转型逐条打勾，哪一条没兑现？"
追问：① 四要素（科学原理/约束/系统方法/有用且安全）怎么构成一个整体——缺"料/框/路/果"各是什么后果？系统方法保证的三个"可"（可计划/可度量/可复现）为什么相互咬合？② 上个月的事故，为什么几乎可以肯定"不是工程"的证据，而不是"工程之外"的意外？③ 反身：你们团队上次宣布"我们工程化了"，当时用四要素打过勾吗？

**Q2（见树见林② · 概念关系）**
"请给出 工程、系统工程、软件工程、工程系统、技术系统 这五个词的关系，并说明：为什么说系统工程是『元工程』？『系统』这个词为什么是递归的——软件工程内部为什么也会长出『软件系统工程』？技术系统的三个特征是什么，为什么工程系统 ⊃ 技术系统？"
追问：① 系统工程不造任何部件，它造什么（接口契约/集成方案/系统级验证方案）？软件足够大时（操作系统/微服务集群）内部为什么长出系统工程的子集（系统架构师/接口契约/集成测试/端到端验证）？② 技术系统三特征（纯人工制品/功能靠技术实现/人只是外部使用者）——按这三条，恒信合同审批系统上线了算技术系统成功，为什么还不算工程系统成功？③ 反身：你们说的"系统"，是设备集合，还是整个社会技术系统？

**Q3（真悖论 · 有流程有工具 vs 在做工程）**
"李工说：有流程、有工具、有测试、有敏捷，就是在做工程——很多人也这么信。可这一章说：工程有四层，缺一层都不是完整的工程。哪个对？什么判据能证明『有流程』不等于『在做工程』？"
追问：① 四层结构里，缺前三层（工程科学/方法论/工具实践）和缺价值伦理，后果有什么不同（不专业 vs 会出事）？② 泰坦尼克/挑战者/737 MAX 三大事故的共同点是什么——方法论出错，还是价值层失守？③ 工程的"对立面"是什么？——为什么说工程没有单一对立面（认识论×科学 / 方法论×手艺 / 目标×艺术）？李工把"工程化"当成了哪个对立面的反面？④ 反身：你们公司有没有"只讲方法论不讲伦理"的时刻——那叫什么（有组织的赌博）？

**Q4（真悖论 · 约束是敌人还是舞台）**
"有人抱怨：约束是工程的敌人——成本紧、工期紧、风险高，束手束脚，约束越少越好做。这一章却说：约束越多，判断的价值越大，约束是工程的全部舞台。两个都对吗？什么判据分清什么时候该怎样？"
追问：① 一个没有约束的项目（无限预算/无限时间/无限耐心）还需要判断吗？还需要工程师吗？② "真实约束"（成本/工期/资源/安全红线）和"无意义的限制"（纯官僚式流程）怎么区分——哪个产生判断价值？③ 判断为什么不能写全成规则（约束一变规则就失效）？"完全可复现"为什么不是工程的极致（纯可复现是算法）？④ 反身：你们最近砍需求、砍容量评估，砍的是"真实约束下的权衡"，还是"方便自己"？

**Q5（真悖论 · 系统化 vs 机械化）**
"『系统化就是把流程固化成算法，让机器自动跑』『自动化程度越高，越接近工程、越安全』——这套说法对吗？还是『系统化是可检查的章法、机械化是确定执行』？同样给软件加一个新功能，为什么一个越加越乱、一个越加越稳？自动化程度越高，是越接近工程，还是越远离工程？"
追问：① systematic / systemic / algorithmic 三个词各回答什么问题？"机械化"指哪个？② 用系统化三问（输入输出/检查点/换执行者）照"加功能"的例子——非系统化：想起需求直接开写→写一半改数据库→顺手改表结构→没测旧功能→上线报表挂→连夜回滚→三个月后没人知道为什么多了个字段；系统化：需求写清楚并评审→评估影响范围→设计评审→编码+单元测试→集成测试回归→预发布验证→上线→记录变更。差别在哪？系统化为什么"像一支乐队"不像"像一台机器"（每个乐手按总谱演奏、指挥根据现场调整节奏——有流程但流程里留着判断的位置）？③ 系统化的目的为什么不是消灭不确定性（需求会变、环境会变、人会犯错——把不确定性纳入可控范围）？系统化四特征（有结构/有章法/可重复/全覆盖）vs 即兴四特征（无结构/无章法/不可复现/有盲区）——敏捷为什么"高度系统化却一点谈不上算法化"？④ 自动化为什么是"单向门"（权限层 + 能力层）？737 MAX 的 MCAS 怎么演示"消灭的不是事故，是人阻止事故的能力"？⑤ 反身：你手里最大的自动化，是把判断提纯了，还是把判断消灭了？

### 第二组 · 落地与实践（5 题）

**Q6（判据运用 · 试金石）**
"冰链的老周做了十五年温控产品，车间里没有一份完整测试方案，但『心里有数』——哪个批次容易出问题、哪种工况要降额、哪家供应商的电容不可靠，全在脑子里。去年他请假两周，一个批次出问题，产线没人能定位；老周回来，十分钟找出问题。用试金石测：老周是工程还是手艺？恒信那套 CI/CD 呢？工具为什么不会自动把人从手艺变成工程？"
追问：① 试金石三种场合（团队交接/招聘/复盘）各怎么用？② "把个人能力变成组织能力"——老周的手艺怎么工程化改造，第一步做什么？③ 反身：你们团队最值钱的"手艺"是什么？那个人走了，交付还能维持吗？

**Q7（判据运用 · 四层结构 · 价值层失守三判据）**
"上个月恒信合同审批系统在月末高峰宕机 40 分钟，法务财务几百个审批卡住。根因：一个新上线的接口没做容量评估——冲刺计划里排了，但『这个功能月底要上』，就砍了。砍的时候，没有评审、没有风险登记、没有负责人签字，就是李工在站会上说了一句『先上再说』。为什么说这是价值层失守，而不是『客观原因』？"
追问：① 价值层失守三判据（相关方知不知情/有没有评审/有没有记录）——客观原因为什么不会专门留记录？② 上个月的事故证明了什么——这个团队有工程的方法论和工具，但还缺哪一层？③ 反身：你们公司有没有"先上再说"？砍需求时，有没有让相关方知情？

**Q8（判据运用 · 系统工程 · 涌现属性 · 软件系统工程递归）**
"恒信的法务、财务、业务三个模块各自都做得好，但三个部门的数据口径对不齐、审批流跨部门断点没人管——集成那天，就是事故那天。为什么『单个部件都合格，不等于整体合格』？微服务每个单独健康、调用链没人管，为什么上线必出事——软件世界里的『系统工程』是谁的地盘？"
追问：① 系统工程为什么是"元工程"（整合部件、不造部件）——它造的三样东西（接口契约/集成方案/系统级验证方案）各管什么？② 软件足够大时（操作系统/微服务集群）内部为什么也会长出"软件系统工程"（系统架构师/接口契约/集成测试/端到端验证）——这解释了微服务的"灰色地带"为什么是系统工程的地盘？③ 涌现属性为什么在工程里无处不在（把大问题拆小分给许多人做，局部对≠整体对；接口/口径/时序这些"部分之和的溢出"不属于任何部件）？④ 反身：你们最近一次"部件全对、整体出事"，是哪个灰色地带没人管？

**Q9（方法时刻 · 规则 15 · 判据主义 + 跨域变体）**
"李工记住了『工程化』这个词，却从没用对过它——这就是第1章的『反记忆崇拜』：有标签，只是见过。这一章的方法底座时刻，就是反记忆崇拜 → 判据主义：不用定义背书，用判据打勾。请亲手给『工程』立一条可检验判据，再给『工程系统』立一条——当场验证：可复现吗？判断留人了吗？承诺的是设备跑起来，还是整个社会技术系统能运转？"
追问（跨域变体）：① 你给『工程系统』立的判据，换到冰链的 M3 温控箱（硬件+固件+云端+App+冷链流程+法规+操作员）还成立吗？恒信的合同审批系统呢？判据变没变——这说明了什么（概念不挑行业）？② Ropohl 当年点破"很多系统是社会技术系统——技术子系统+人的子系统+组织子系统耦合在一起，单独优化技术部分没有意义"——你立的工程系统判据，是不是正是在替"整个社会技术系统能运转"打勾？技术系统三特征（纯人工制品/功能靠技术实现/人只是外部使用者）里，哪一条提醒你别把 M3 或恒信当成纯设备集合？③ 反身：你们团队最近一次宣布"我们工程化了"，当时有没有一条可检验判据，还是只贴了"敏捷/CI/CD"的标签？——有标签是见过，有判据才算拥有。

**Q10（落地生根 · 回部门工程体检）**
"结合你们部门现状，用本章的试金石、四层结构、工程系统三个判据，给你们最近交付的一个系统做一次『工程体检』——给出最该改进的三件事，每个落到一个动作。"
追问：① 六个体检项目（可复制/完整/过程特征/可检查/整合/验收参照）先查哪两个？② 李工那句"我们已经是工程化团队了"——你们团队说过类似的话吗？当时测过哪把尺子？③ 两周后回来报告：哪个判据测出不合格、补了哪个动作？
