## 第 1 步 · 剖章立骨：核心内容地图

**这一章回答的问题**：架构师到底是个什么样的物种？头衔、职级、图纸都不定义架构师——十项能力才定义；他是工程师角色体系中的一个专门角色，对系统结构演化负专责、不对系统成败负终责。怎么判断一个人是不是架构师（十项体检 + 两把分工尺 + 一把母词尺，共十三项判据），怎么和六个相邻角色分开（含边界判据），怎么长成（抽象跃迁）、怎么失败（四式）、怎么被检验（产品数据两层）、怎么给两条案例线落判词。

**三幕对齐（省一步推导）**：
- **第一幕 是什么（定界）**：16.2.1 一句开场白（先是一个工程师，ISO 12207/15288 specialization）→ 16.2.2 底座六项三栏点名（①~⑥各带判据）→ 16.2.3 增量四项（⑦~⑩ + ISO 42010 三组词分工 + 15288 §6.4.4 生成→选择→表达）→ 16.2.4~16.2.7 四项增量各展开一节 → 16.2.8 六个更锋利的差异（决策域/认知对象/验证方式/时间尺度/能力灵魂/判断锚点）→ 16.2.9 整条链：architecting 七动词链（母词映射表 + 两套切法并行）+ 案例进展①万辉（判词初挂）—— 喂第一组·概念题（见树见林）；
- **第二幕 不是什么（磨边弧）**：16.3.1 不是更高级的工程师（职级≠物种·两种决策域·**边界判据：约束别人→架构师 / 只管自己→工程师**）→ 16.3.2 不是系统工程师（**专责≠终责·委托—协商—验收·拍板权vs理由权**）→ 16.3.3 不是技术负责人（管人≠管决定·领导力不能任命）→ 16.3.4 不是项目经理（进度≠结构）→ 16.3.5 不是领域专家（业务≠系统）→ 16.3.6 不是画图匠（图≠决定·删掉图剩下的决定）→ 16.3.7 失败四式收拢（含"什么都管=把专责当终责"）+ 案例进展②水忠（判词推进·粒度语境）—— 喂真悖论·辨边界题；
- **第三幕 往哪去（运用）**：16.4.1 怎么长成（**抽象跃迁**·系统→架构换专精轨道非升职·分叉不是阶梯·"需求翻一倍还成立吗"）→ 16.4.2 被任命≠成为 → 16.4.3 三种来路三种功课 → 16.4.4 成长的标志（第一次"说不"）→ 16.4.5 再往上（从系统到组织·四条路径·工具不变棋盘变大）→ 16.4.6 能力的最终体现（**系统级文档族 + 架构符合性把关 + 三粒度责任矩阵 + 组织级治理产出（制度层）**）→ 16.4.7 接口契约=1:1 搬入点 → 16.4.8 检验：换个人能不能接住 + 案例进展③双线判词落定—— 喂第二组·落地 / 方法时刻题（规则 15）。

### 核心概念（含根概念标注）

> 标注规则（v2.1）：按正文根概念四标准（原子性/生成性/不可替代性/递归性）标出本章档案中的**承重柱**。角色章无新概念档案，承重柱标注说明：**本章承重柱 = 第9章六项底座**——原子性（元素级正确是系统级方向的不可再归约前提）/ 生成性（增量四项全部从底座长出）/ 不可替代性（去掉底座"架构师"只是名片）/ 递归性（专责、终责、判词全部挂在底座缺项上）。架构活动链（七动词）是工序切法、非概念承重柱，与十项清单两套切法并行（§16.2.9）。

1. **架构师**（角色收束概念，无新档案）【清单定义 · 承重柱 = 底座六项】：先是一个工程师 + 增量 = 十项能力清单；头衔/职级/图纸都不定义架构师；对系统结构与演化负专责、不对系统成败负终责。判据：十项能力一项一项亮起来（§16.2.1）。
2. **底座六项**（第9章收束）【承重柱】：科学素养 / 方法论素养 / 实践能力 / 职业伦理 + 横切⑤工程判断 + 元⑥可复现意识——六项能力分属工程的四层结构（工程科学/方法论/工具实践/价值与伦理），缺一项"工程师"就不是完整的人；架构师是工程师的一个方向，不是工程师的超越（§16.2.2）。
3. **增量四项**（第10、12章收束）：⑦识别后果严重的决策 / ⑧对系统的理论 / ⑨把架构说清楚 / ⑩判断不可逆性——长在底座上，底座缺一项增量空转；对应 15288 §6.4.4 架构定义流程三件事（生成候选→选择一个→用一致视图表达）；ISO 42010 三组词：元素是工程师的、关系与演化是架构师的（§16.2.3）。
4. **专责 ≠ 终责**（§16.3.2 核心）：系统工程师对系统成败负终责（accountability，不可委托），架构师对系统结构与演化负专责（responsibility，可委托可追责）；两者是**委托—协商—验收**的回路（拍板权在系统工程师、理由权 rationale 在架构师；派生需求回流、协商理解）；"背在身上，是看在眼里，不是担在肩上"。判据：**专责尺**（判据11）。
5. **边界判据**（§16.3.1）：**凡是"约束别人"的决策，归架构师；凡是"只管自己"的决策，归工程师。** 架构师定边界、定接口、定演化原则（约束别人代码的决策）；工程师在模块内自治（内部结构、内部依赖、实现策略自己定——哪怕那已经是"模块内部架构"，第9章 §9.3.6 模块级迷你架构师）。谁在越界，一眼可辨。
6. **六个更锋利的差异**（§16.2.8）：决策域 局部可逆→全局难逆 / 认知对象 需求→关注点 / 验证方式 测试→评审 / 时间尺度 当下→跨版本演化 / 能力灵魂 契约与证据→决策与理由（rationale）/ 判断锚点 规定需求→目的（确认单立锚）——架构师与"像但不一样"角色分道扬镳的根源。
7. **架构活动链（母词）**（§16.2.9）：architecting 七动词——构思→定义→表达→记录→沟通→认证恰当实现→维护与改进；贯穿生命周期反复发生，不是串行七步；十项清单=体检切法（长什么样）、动词链=工序切法（每天做什么），两套并行不吞并；标准认活不认职位（42010 只给活动立词条，不给头衔立）。判据：**母词尺**（判据13）。
8. **六个相邻角色**：更高级的工程师 / 系统工程师 / 技术负责人 / 项目经理 / 领域专家 / 画图匠——和架构师像但不一样，一条条磨过去（§16.3.1~16.3.6）。
9. **失败四式**（§16.3.7）：画图匠（只有视图没判断）/ 什么都管（把约束管成枷锁·把专责当终责）/ 不决策（把决定留给默认）/ 远离代码（判断失去锚点）——每一种都能在十项能力清单里找到缺的那一项。
10. **产品数据两层**（§16.4.6）：系统级文档族（AD/ADR/ICD/概要定义/派生需求/权衡报告/元素分配/架构基线/演化路线图/系统级验证方案）是"作品"+ 组织级治理产出（架构原则/政策/治理指令/委员会章程/治理决策记录/合规评估报告/健康度指标）是"制度"；架构符合性把关（certifying proper implementation）；分工在层级：架构师主责系统结构 / 系统工程师主责系统级（主责兼终责）/ 模块工程师主责模块级；接口契约=1:1 搬入点；概详分离是每份方案的普遍结构、不是角色分工。
11. **抽象跃迁（成长）**（§16.4.1~16.4.5）：系统→架构换一条专精轨道（从管流程到设计结构），非升职；被任命≠成为；三种来路三种功课；成长的标志=第一次"说不"；再往上=从系统到组织（四条路径：深度/宽度/组织/权威），工具不变、棋盘变大；CTO 头衔同样不定义能力。
12. **从见过到拥有**（方法底座时刻）：章首万辉对"架构师"只有"见过"——叫得出头衔、画得出图，却答不上"当选架构师意味着你现在是什么"；判词把他量成"拥有"——能对着十项清单一项一项打勾、认得出自己缺什么。**判词把"架构师"从头衔钉成了能力清单。**

### 对立概念（远界）

| 概念 | 对立面 | 问什么 |

### 关联概念（近界 · 辨析）

- **十项能力 ↔ 第9章六项底座 + 第10、12章增量**：底座缺一块，增量全是空转（识别依赖工程判断、理论依赖科学素养、不可逆判断依赖工程判断）——一套结构，第9章立底座、第10/12章立增量、本章收成一张清单。
- **增量四项 ↔ ISO 42010 三组词 + 15288 §6.4.4**：元素（elements）/ 关系（relationships）/ 设计准则与演进准则（design and evolution principles）——元素是工程师的、关系与演化是架构师的（识别决策认关系演化风险 / 理论说关系支撑成功 / 说清楚画关系 / 不可逆判演化改不动代价）；增量四项=生成→选择→表达三件事背后要长的能力。
- **专责≠终责 ↔ 第9章粒度尺 / 三粒度责任矩阵**：第9章那把粒度尺在本章收口——架构师主责系统结构、SE 主责系统级（主责兼终责）、模块工程师主责模块级；专责可以委托可以追责，架不住底座缺一块。
- **边界判据 ↔ 第9章分形不对称（对外架构）**：模块对外边界归上层分配、内部架构归工程师自己（§9.3.6 模块级迷你架构师）；本章立成"约束别人→架构师 / 只管自己→工程师"——两个角色互不替代（没有架构师各自为政 Cowboy Coding、没有工程师架构落不了地）。
- **委托—协商—验收 ↔ 第8章三把尺子 + 系统级评审**：架构能改变需求（派生需求回流）→ 两者是持续的谈判对手（协商理解）；常态张力调和=rationale 对质 + 系统级评审（TR）由系统工程师主持、架构师是材料主笔和陈述方——把"架构的远见"和"系统的责任"焊在一起的那道缝。
- **验证方式差异 ↔ 第8章三把尺子**：评审对目标、验证对需求、确认对用途——架构没有逐条需求可对，只能对目标（相关方关注点汇聚成的"为什么要建这个系统"）；**代码用测试验证，架构用评审验证**（评审审的正是写下来的理由 rationale）。
- **⑨把架构说清楚 ↔ 第10章相关方→关注点→视点→视图链**：第一步永远是先问"谁押了注、在乎什么"；相关方关注点天然冲突，架构师不消灭冲突，给每个冲突一个可见的落点（水忠给疾控/司机/维修/监管四张视图，图是死的、视图是活的）。
- **⑩判断不可逆性 ↔ 第12章三层判断 + 三个动作**：影响半径（结构/时间/组织耦合）/ 信息成本（知识深度/隐含上下文）/ 修改风险（爆炸半径/数据完整性）；高不可逆早做、低可逆晚做、该推迟的显式推迟；董勐改走"受控导出"是完整案例（§16.2.7）。
- **架构活动链（母词）↔ 十项能力清单**：两套切法并行，不互相吞并——每一项能力都能在链上找到它管的动作；第11章用前段（构思→定义→表达）、第14章用后两个动词（认证=符合性监控、维护改进=演化治理）；整条链第一次整体摆出（§16.2.9）。
- **抽象跃迁 ↔ 第9章拓宽 / 分叉不是阶梯**：拓宽（模块→系统）把视野拉宽，抽象跃迁（系统→架构）换专精轨道；决策对象从"事实"到"本质"；管理线（技术经理→项目总监）与架构线（系统架构师→首席架构师）正交——"升不上去才走架构线"是把分叉当阶梯。
- **产品数据 ↔ 第6章一棵树 / 第9章产品数据 / 三粒度责任矩阵**：概详分离是每份方案的普遍结构（不是角色分工）；架构师主责系统结构、SE 主责系统级、模块工程师主责模块级；接口契约=1:1 搬入点（工程师部件方案落下的那根枝梢）。
- **架构符合性把关 ↔ 第8章评审 + 第9章责任矩阵**：42010 给 architecting 定义含"认证架构的恰当实现"（certifying proper implementation）——架构师不只画架构，还要查模块详细定义符不符合架构分配、技术方案有没有违背架构原则；矩阵画的是谁编制、谁批准，符合性把关是矩阵没画出来的那层——系统工程师管文档的载体（签发的那个文件），架构师管文档的内容（架构决策的来源）。
- **组织级治理产出 ↔ 第14章治理**：治理=掌舵落到架构域；方向权（目标/政策/战略）属组织层、内容权（原则/政策/指令/符合性判断/决策依据）属架构师（ISO 42020）；系统级文档族是"作品"、治理产出是"制度"；**治理决策权在架构委员会（架构师是技术核心），但系统级变更的最终裁决仍要系统工程师背书——治理是架构师的常设法庭，系统工程师是系统成败的最终责任人**。
- **成长 ↔ 判断依据换尺度**：开发问代码→模块问怎么切→系统问整棵设计树→架构决策问"哪些决策改错的代价大到不能等"（你关心的问题换了，物种就变了）；空间维度与时间维度同时扩张；终极题"如果需求翻一倍，这个架构还成立吗"。
- **失败四式 ↔ 十项能力缺项**：画图匠缺⑤（没有判断）/ 什么都管缺⑦（对不重要的事情疯狂决策、对重要的视而不见，且把专责当终责）/ 不决策缺⑩（把决定留给默认）/ 远离代码缺③（判断失去锚点、理论不落地）。
- **判词 ↔ 产品数据**：16.4.8 和案例进展③量的是同一把尺子（换个人拿着架构描述和决策能不能接住、继续演进）——判词把"架构师"从头衔钉成能力清单。
- **从见过到拥有（方法底座时刻）↔ 第1章**：章首万辉只有"见过"（叫得出头衔、画得出图），判词把他量成"拥有"（能对着十项清单一项一项打勾、认得出自己缺什么）——四问法在能力清单上的适配（各是什么、不是什么、判据是什么、往哪去）。
- **技术领导力 ↔ 第9章能力清单**：管理权可以任命，领导力不能任命——技术领导力在"能力"清单里不在"职位"清单里；可信度是唯一货币，只能靠"让别人因为你的判断而受益过一次"挣来（§16.3.3）。

### 核心原理

**第一幕 · 是什么的底层机制**
1. 架构师首先是一个工程师——次序问题：先有元素级的正确，才谈得上系统级的方向；没有六项底座，"架构师"三个字只是一张名片（§16.2.1）。
2. 增量长在底座上——识别依赖工程判断、理论依赖科学素养、不可逆判断依赖工程判断；底座缺一块，增量全是空转（§16.2.1）。
3. 十项合起来才是完整答案——ISO 42010 三组词分工：元素是工程师的、关系与演化是架构师的；增量四项对应 15288 §6.4.4 架构定义流程的生成→选择→表达（§16.2.3）。
4. 识别后果严重的决策，不是"想得多"，是"认得出哪类决策必须按决策对待"——大多数团队把精力花在无关紧要的决策上，对真正致命的决策从不当成决策来对待（§16.2.4）。
5. 对不重要的事情不决策，本身就是一种好的架构决策——对重要的事情不决策，是架构师的第一宗罪（§16.2.4）。
6. 对系统的理论，就是回答三个问题：靠什么成功 / 最大压力在哪 / 做错什么最致命——同一个箱子两种理论是两种世界观；好的架构师是对自己系统的理论最清醒的人（§16.2.5）。
7. 图是死的，视图是活的——把架构说清楚=让每个相关方的关注点都有一张图能落；冲突不可消除只能权衡，架构师给冲突一个可见的落点（§16.2.6）。
8. 判断不可逆性，是把架构决策从"今天能不能上"的日常节奏里拎出来，放进"值不值得为它多花三周"的另一个时间尺度（§16.2.7）。
9. 五维差异——决策域 局部可逆→全局难逆 / 认知对象 需求→关注点 / 验证方式 测试→评审 / 时间尺度 当下→跨版本演化 / 能力灵魂 契约与证据→决策与理由（rationale）；**代码用测试验证，架构用评审验证**（§16.2.8）。
10. 架构活动链（architecting 七动词）是能力的母词——每一项能力都能在链上找到它管的动作；十项清单=体检切法、动词链=工序切法，两套并行不吞并；标准认活不认职位（§16.2.9）。

**第二幕 · 磨边弧的机制（不是什么）**
11. 把职级当物种——职级是组织给的位置，物种是能力决定的；职级也不定义架构师；同一系统，工程师横着做深，架构师横着铺广（§16.3.1）。
12. **边界判据**——凡是"约束别人"的决策归架构师、凡是"只管自己"的决策归工程师（模块内部架构归工程师自己，§9.3.6）；谁在越界一眼可辨；两个角色互不替代（§16.3.1）。
13. **专责≠终责**——系统工程师对系统成败负终责（accountability 不可委托，出了事他兜底）；架构师对系统结构与演化负专责（responsibility 可委托可追责）；"背在身上=看在眼里不是担在肩上"；看得见整条链，和兜底整条链，是两回事（§16.3.2）。
14. **委托—协商—验收回路**——委托（SE 把架构正确性委托给架构师、架构师以架构描述回馈、SE 评审背书）；协商（架构能改变需求——派生需求回流更新规定需求，目标是"协商理解"不是"完美正确解"）；验收（拍板权在系统工程师、理由权 rationale 在架构师——你提方案+理由，我拍板+兜底）（§16.3.2）。
15. **常态张力调和**——架构师偏架构纯洁性与长远演化、系统工程师偏交付可行与当前约束；调和不是谁压过谁，是把理由摆出来对质——系统级评审（TR）由系统工程师主持、架构师是材料主笔和陈述方（§16.3.2）。
16. 技术负责人管人、架构师管决定——判断是技术负责人还是架构师，看他在压力下护住的是什么：护住交付是技术负责人、护住结构是架构师；管理权可以任命，领导力不能任命（§16.3.3）。
17. 项目经理对日历负责、架构师对演化负责——"进度 vs 结构"冲突，正是第2章价值层失守的现场（§16.3.4）。
18. 领域专家懂业务、架构师懂系统——好的架构师不抢领域专家的活，他让领域专家的规则在系统里待得住、改得动（§16.3.5）。
19. 画图匠画图、架构师做决定——图是决定的表达还是决定的替代；删掉图剩下的决定才是架构（§16.3.6）。
20. 失败四式各缺一项——画图匠缺⑤工程判断（死于没有判断）/ 什么都管缺⑦（对不重要的事情疯狂决策、对重要的视而不见，**且把专责当终责**，既僭越又失职）/ 不决策缺⑩（把决定留给默认，默认最保守）/ 远离代码缺③（判断失去锚点、理论不落地）（§16.3.7）。

**第三幕 · 往哪去的机制（运用）**
21. **抽象跃迁**——成长的本质不是"管的人变多"，是换一条专精轨道：从对"系统成败"负终责，转向对"系统的结构与演化"负专责；决策对象从"事实"（方案行不行、预算够不够）变成"本质"（什么结构能同时满足互相冲突的关注点、且未来三年还能演化）；15288 §6.4.4 给架构定义流程 purpose 的第一个词是 generate——架构师要先创造候选结构，再选择，再表达（§16.4.1）。
22. 判断的依据在抽象跃迁里升级——开发问"代码怎么写清晰"→模块设计问"模块怎么切"→系统设计问"整棵设计树怎么长"→架构决策问"哪些决策改错的代价大到不能等"；你关心的问题换了，你的物种就变了；每上升一级，空间维度与时间维度同时扩张；终极题"如果需求翻一倍，这个架构还成立吗"（§16.4.1）。
23. **分叉不是阶梯**——不是所有系统工程师都会（或该）成为架构师；管理线（技术经理→项目总监）与架构线（系统架构师→首席架构师）正交；"升不上去才走架构线"是把分叉当成了阶梯（§16.4.1）。
24. 被任命只是拿到一张牌桌的入场券——成为架构师的过程=能力清单一项一项亮起来的过程；能力可长，名头只是时间的快照（§16.4.2）。
25. 三种来路三种功课——从开发长出来（缺⑦⑧⑩）/ 空降（缺③⑥）/ 挂名（只有头衔）；判断走哪条路，看他在补清单的哪一项（§16.4.3）。
26. 成长的标志是第一次"说不"——拦下的不是"错的"，是"没想清楚不可逆性的"；判断不可逆性（⑩）是成长路上最后一盏灯，因为它需要前面所有能力都到位才接得住（§16.4.4）。
27. 再往上不是更深的架构，是关注维度的扩张——从系统到组织；系统之系统杀手特征：每个子系统都有自己的 owner 和生命周期，没有全局 owner；从元素到系统、从系统到组织是同一种升级的两次上演（工具不变，棋盘变大）；CTO 头衔同样不定义能力（§16.4.5）。
28. 能力的最终体现是能否开发出高质量的产品数据——十项能力抽象在人身上不可直接检验，面试会看走眼、领导会凭印象打分；架构师的产品数据在系统结构级（切分/连接/规矩），让每个部件的设计有地方落、落得对；能力再强，开发不出高质量的产品数据，这个架构师也不成立（§16.4.6）。
29. 架构师造的是"缝"的数据、关系与演化的数据、约束的数据——文档是载体，决策与理由（rationale）才是灵魂；**架构符合性把关**（certifying proper implementation）：架构师不只画架构，还要检查实现符不符合架构分配；系统工程师管文档的载体、架构师管文档的内容（§16.4.6）。
30. 分工在层级——架构师主责系统结构 / 系统工程师主责系统级（主责兼终责）/ 模块工程师主责模块级；概详分离是每份方案内部的普遍结构，不是角色分工（§16.4.6）。
31. **接口契约 = 1:1 搬入点**——架构师定的接口契约，就是工程师部件方案落下的那根枝梢；架构决策错，代价是结构性的：系统级错了，部件级跟着错（§16.4.7）。
32. **组织级治理产出是第二层制度**——当一个架构师管的不只是一个系统，而是所有系统的架构怎么保持一致、怎么演化、怎么被遵守，他就在做架构治理；方向权（目标/政策/战略）属组织层、内容权（原则/政策/指令/符合性判断/决策依据）属架构师（ISO 42020）；系统级文档族是"作品"、治理产出是"制度"；**治理决策权在架构委员会（架构师是技术核心），但系统级变更的最终裁决仍要系统工程师背书——治理是架构师的常设法庭，系统工程师是系统成败的最终责任人**（§16.4.6）。
33. 检验句：换个人，拿着你负责的架构描述和决策，能不能接住、继续演进？能，你的架构才成立；不能，再大的图也只是装饰（§16.4.8）。

**从见过到拥有（方法底座时刻，显式命名）**：对"架构师"这个词，章首的万辉只有"见过"——叫得出头衔、画得出图，却答不上"当选架构师意味着你现在是什么"；判词把他量成"拥有"——能对着十项清单一项一项打勾、认得出自己缺什么。**判词把"架构师"从头衔钉成了能力清单。**

### 本章判据（十三把尺子 + 终极尺 + 工作检查单）

> **架构师是一个方向，不是头衔；是一张清单，不是职级；是一份专责，不是终责。** 这十三项判据是本书的体检清单——十项能力、两把分工尺与一把母词尺，都是本书的凝练，不是任何标准的条文；标准出处（42010/15288/12207）见正文。它们都当场可检验。

十项能力体检（架构师的十把尺子，逐项自问，各配"违反即崩"）：
1. **科学素养**：我对这个系统的理论是什么？靠什么成功、最大压力在哪、做错什么最致命？**违反即崩：答不上"系统靠什么成功"，理论就是空的——万辉长期不碰实现，判断悬空（缺①，判词初挂）。**
2. **方法论素养**：我的方法能被别人学会吗？还是只有我会？**违反即崩：方法只在自己脑子里，架构随人走——水忠的判断换个人做不出来（缺②，判词）。**
3. **实践能力**：我最近一次亲手落地，是什么时候？**违反即崩：架构停在图上，判断没有锚点——远离代码的架构师，不知道系统真实的样子（失败四式第四宗，缺③）。**
4. **职业伦理**：压力面前，我会不会为进度悄悄牺牲可靠性？有没有让相关方知情？**违反即崩：为进度悄悄牺牲可靠性、还没让相关方知情——万辉的"先上再说"，第2章事故就是价值层失守（缺④）。**
5. **工程判断**：冲突里，我依据什么做取舍？**违反即崩：图下面没有"决定"的字——画图匠死于自己没有判断（失败四式第一宗，缺⑤）。**
6. **可复现意识**：我的判断换个人能接住吗？我写决策记录吗？**违反即崩：判断换个人就接不住——水忠的老规矩换个人做不出来，成了手艺型架构师（缺⑥，判词）。**
7. **识别后果严重的决策**：我认得出"影响半径大/持续时间长/修改成本高"的决策，并按决策对待吗？**违反即崩：把致命决策当普通字段改——万辉改合同编号规则，以为"今天就能改"，三个月连环三爆（§16.2.4）。**
8. **对系统的理论**：我的架构有原理吗？换个上下文还成立吗？**违反即崩：碰巧做对、却不知道为什么对，换个上下文就错——没有理论的架构，像没有原理的工程（§16.2.5）。**
9. **把架构说清楚**：每个相关方的关注点，都有一张图能落吗？**违反即崩：图是死的、视图是活的——相关方看不到自己该看的那一面，冲突被闷在各自脑子里（§16.2.6）。**
10. **判断不可逆性**：我认得出不可逆决策吗？该早做的早做、该推迟的显式推迟吗？**违反即崩：把决定留给默认——不决策的架构师，把架构决策的资格交给运气和时间（失败四式第三宗，缺⑩）。**

十把尺子之外，还有两把分工尺、一把母词尺——
11. **专责尺**：我清楚自己背的是专责（架构正确性）不是终责（系统成败）吗？我和系统工程师的分工，是委托—协商—验收吗？**违反即崩：把专责错当终责——"什么都管"的架构师越过边界背系统成败的账，既僭越又失职（§16.3.2，失败四式第二宗）。**
12. **符合性尺**：我检查过实现是否符合架构分配吗？（certifying proper implementation——认证架构的恰当实现）**违反即崩：画完架构就完了，实现符不符合不查——模块详细定义背离架构分配、技术方案违背架构原则，也没人发现（§16.4.6）。**
13. **母词尺**：我知道自己正在做七动词链里的哪个动作吗？构思想清楚了吗？定义定形了吗？认证检查了吗？**违反即崩：只做表达就以为做完了架构——链断在半路，画图匠式架构师（§16.2.9）。**

十把尺子量到最后是一句话：**能力再强，也要看我能不能开发出高质量的产品数据——换个人能不能接住。**（终极尺）

**工作检查单**（每次做架构决策前）：
- [ ] 这是不是一次"影响半径大 / 持续时间长 / 修改成本高"的决策？
- [ ] 我对这个系统的理论是什么？这次决定对不对得起它？
- [ ] 有哪几个相关方的关注点会被这次决定影响？他们的视图跟上了吗？
- [ ] 这次决策记录写了吗？不可逆性标注了吗？
- [ ] 我是在做决定，还是在画图 / 什么都管 / 等默认？
- [ ] 这次决定对应的接口契约改了吗？下游的部件方案跟着变了吗？
- [ ] 我在背专责还是终责？有没有把不该背的账揽到自己头上？

9. **失败四式**【能解释】：能定义（画图匠/什么都管/不决策/远离代码）；能辨析（≠能力不行——是缺项可补）；能溯源（第10章"管得最准不是管得最多"+ 第12章"没做架构决策=伪选项"+ 第9章可复现意识）；能致用（对号入座 + 每种都能在清单里找到缺的那一项）。
10. **抽象跃迁（成长）**【必须脱口】：能定义（系统→架构换专精轨道非升职；决策对象从"事实"到"本质"）；能辨析（≠升职、≠所有 SE 都该成为架构师——分叉不是阶梯）；能溯源（第9章拓宽的下一跳；15288 §6.4.4 generate）；能致用（判断走哪条路看补清单哪一项；三种来路三种功课；第一次"说不"；再往上四条路径——工具不变棋盘变大）。
11. **架构师文档族 + 治理产出**【能解释】：能定义（系统级文档族是"作品"+ 组织级治理产出是"制度"；架构符合性把关 certifying proper implementation；接口契约=1:1 搬入点；三粒度责任矩阵）；能辨析（≠一张架构图、≠管理层的活）；能溯源（第6章一棵树 + 第9章产品数据 + 第10章老规矩 + 第14章治理/ISO 42020）；能致用（能力的最终体现——换个人接住；符合性尺、治理决策权在委员会、最终裁决在 SE）。

### 原理层（应能解释为什么）

1. 能解释为什么架构师首先是一个工程师、增量长在底座上（次序问题：先有元素级正确，才有系统级方向；识别依赖工程判断、理论依赖科学素养、不可逆判断依赖工程判断——底座缺一项增量空转）。
2. 能解释为什么十项合起来才是完整答案（ISO 42010 元素工程师/关系与演化架构师；增量四项=15288 §6.4.4 生成→选择→表达背后要长的能力）。
3. 能解释为什么边界判据是"约束别人 vs 只管自己"（架构师定边界定接口定演化原则、工程师在模块内自治；没有架构师各自为政、没有工程师架构落不了地）。
4. 能解释为什么认知对象从需求换成关注点、验证方式从测试换成评审（关注点比需求宽、可模糊可冲突没有标准格式；架构无唯一正确解，只能对目标评审——代码用测试验证，架构用评审验证；第8章三把尺子）。
5. 能解释为什么专责≠终责（accountability 不可委托 vs responsibility 可委托可追责；"背在身上=看在眼里不是担在肩上"；拍板权在 SE、理由权 rationale 在架构师；委托—协商—验收回路；派生需求回流、协商理解；常态张力调和=rationale 对质 + SE 主持评审架构师陈述）。
6. 能解释失败四式各缺哪一项，以及为什么"什么都管"看起来最负责却最危险（团队失去判断能力+他成瓶颈；对不重要的事情疯狂决策、对重要的视而不见——缺⑦，且把专责当终责）。
7. 能解释为什么架构活动链（七动词）是能力的母词、为什么标准认活不认职位（每一项能力都能在链上找到它管的动作；42010 只给 architecting 立词条、不给架构师立——被任命只是入场券）。
8. 能解释为什么成长=抽象跃迁（系统→架构换专精轨道非升职；决策对象从"事实"到"本质"；你关心的问题换了物种就变了；分叉不是阶梯——管理线 vs 架构线正交；每上升一级空间维度与时间维度同时扩张）。
9. 能解释为什么被任命≠成为、成长的标志是第一次"说不"（入场券 vs 能力清单一项项亮起来；三种来路三种功课，判断走哪条路看他在补清单的哪一项；拦下的不是"错的"是"没想清楚不可逆性的"，⑩是最后一盏灯）。
10. 能解释为什么再往上不是升职而是关注维度扩张（系统之系统无全局 owner；从元素到系统、从系统到组织是同一种升级的两次上演；CTO 头衔不定义能力；工具不变棋盘变大）。
11. 能解释为什么能力最终体现在开发出高质量的产品数据（十项抽象在人身上不可直接检验；系统级架构设计：切分/连接/规矩；能力再强开发不出来也不成立；换个人接住才算数）。
12. 能解释为什么架构师造的是"缝/关系与演化/约束"的数据、为什么要有架构符合性把关（架构师不造部件，造让部件协同的规则；certifying proper implementation；系统工程师管载体、架构师管内容；接口契约=1:1 搬入点——架构决策错代价是结构性的）。
13. 能解释为什么组织级治理产出是产品数据的第二层制度（系统级文档族是"作品"、治理产出是"制度"；方向权属组织层、内容权属架构师——ISO 42020；治理决策权在架构委员会但系统级变更最终裁决仍要 SE 背书——常设法庭 vs 最终责任人；呼应第14章治理）。
14. 能解释为什么判词和产品数据量的是同一把尺子、为什么"从见过到拥有"是本章收束（万辉缺①④⑥ / 水忠缺②⑥ 都露在产品数据上——万辉四张图下没有决定、水忠判断换个人做不出来；判词把"架构师"从头衔钉成能力清单）。

### 判据层（应会用）

1~10. **十项能力体检**：逐项自问十把尺子（科学素养/方法论素养/实践能力/职业伦理/工程判断/可复现意识/识别后果严重的决策/对系统的理论/把架构说清楚/判断不可逆性）——三种场合（招人面试/团队体检/自己对照）各会用。
11. **专责尺**：我清楚自己背的是专责（架构正确性）不是终责（系统成败）吗？我和系统工程师的分工，是委托—协商—验收吗？（拍板权在系统工程师、理由权 rationale 在架构师；背在身上=看在眼里不是担在肩上）。
12. **符合性尺**：我检查过实现是否符合架构分配吗？（certifying proper implementation——认证架构的恰当实现）。
13. **母词尺**：我知道自己正在做七动词链里的哪个动作吗？构思想清楚了吗？定义定形了吗？认证检查了吗？（只做表达就以为做完了架构=链断在半路）。

（配套派生判据：画图匠判据=删掉图剩下的决定才是架构；压力判据=压力下护住交付是技术负责人、护住结构是架构师；验证方式判据=代码用测试验证、架构用评审验证；边界判据=约束别人的归架构师、只管自己的归工程师；终极尺=换个人拿着你的架构描述和决策能不能接住、继续演进；工作检查单七条=每次做架构决策前过一遍。）

### 纠错红线十条

1. **先表态后翻案**：先让学员说"万辉当选年度架构师、图最多文档最全，当然算架构师"，再翻，不让结论先入。
2. **反转精确不造新误解**："头衔不定义架构师"别翻成"头衔没用/该取消职称"；"架构师不是画图的人"别翻成"架构师不用画图/视图不重要"（图死视图活，视图恰恰是⑨把架构说清楚的落点）；"专责≠终责"别翻成"架构师不用负责/可以甩锅"——专责可委托可追责，架构师搞砸了追责追到架构师；"再往上不是升职"别翻成"架构师不该往组织走"；"两套切法并行"别翻成"动词链可有可无"——它是母词尺（判据13）。
3. **判据配机制**：每条反转都有"为什么"（机制）和"怎么当场验证"（判据）。
4. **归责到可对照动作**："他不是架构师"落到"⑩没打勾——把高不可逆决策当日常节奏 / ⑥没打勾——判断换个人接不住 / ④没打勾——压力面前为进度让路 / 专责尺没打勾——把终责的账揽到自己头上"，不归咎"人不行"。
5. **教机制不教断言**：教"为什么什么都管最危险"（团队失去判断能力 + 他成瓶颈 + 把专责当终责），不教"别管太多"；教"为什么委托—协商—验收"（派生需求回流、协商理解），不教"架构师别拍板"。
6. **先立尺子再翻案**：先给十项能力体检判据 + 专责尺 + 符合性尺 + 母词尺，再翻"万辉四张图当全部工作"。
7. **拉开强度层次**：★★★ 常识（架构师=升职 / 画图 / 什么都管·对系统成败负责 / 被任命=成为 / 可以不会写代码 / 画完就算交付）重点翻。
8. **每个纠正落到可操作动作**：讨论完给"回去做一件事"（用十项清单给团队某人打勾、落判词、过工作检查单七条、翻产品数据两层、对任一架构图问母词尺"我在做哪个动作"）。
9. **单一权威不另立标准**：判据引用书（十三把尺子 + 终极尺 + 画图匠判据 + 压力判据 + 验证方式判据 + 边界判据 + 工作检查单），不发明新尺子。
10. **网搜当佐证**：N1~N7 只作"这不是书里一个人的说法"佐证，药与判据全在书内。

## 第 6 步 · 化尺为用：落地工具

### 作业指南（主产出）：用十项能力清单给团队"最像架构师的人"做一次体检 + 落判词 + 反身判团队 + 过产品数据两层 + 过母词尺

> 目标：把十项能力清单从"背诵对象"变成"判人的尺子"——给团队里一位公认最像架构师的人做一次十项体检，落一条判词（像万辉缺①④⑥还是像水忠缺②⑥？），再反身判自己团队、自己，最后落到产品数据两层（系统级文档族 + 组织级治理产出）、母词尺与工作检查单七条。
> 场景：回部门落地。时长：一次 60 分钟；两周后复查。

1. **挑对象（先立枢纽）**：选团队里"公认最像架构师的人"——最像的，往往也最容易在某一项打不上勾。
2. **项目一 · 十项体检打勾**：底座六项——①科学素养（他对系统的理论是什么？靠什么成功、最大压力在哪、做错什么最致命？）②方法论素养（他的方法能被别人学会吗？还是只有他会？）③实践能力（他最近一次亲手落地是什么时候？）④职业伦理（压力面前会为进度牺牲可靠性吗？有没有让相关方知情？）⑤工程判断（冲突里他依据什么做取舍？）⑥可复现意识（他的判断换个人能接住吗？他写决策记录吗？）；增量四项——⑦识别后果严重的决策（他分得清哪类决策必须按决策对待吗？）⑧对系统的理论（他的架构有原理吗？换个上下文还成立吗？）⑨把架构说清楚（每个相关方的关注点都有一张图能落吗？）⑩判断不可逆性（他认得出不可逆决策吗？该早做的早做、该推迟的显式推迟吗？）。
3. **项目二 · 落判词（带粒度语境）**：对照两条基准线——万辉有头衔缺①④⑥（系统架构师头衔、专责缺底座：判断还悬着、伦理的账欠着）、水忠无头衔缺②⑥（模块工程师岗位做架构活：判断顶配但不可复制）——你的对象像哪条线？缺的是哪一项？**话术**："他不是不会做，是做的能力不可复制"（像水忠）/ "他不是不会画，是图下面没有决定"（像万辉）。
4. **项目三 · 反身判团队 + 反身自检**：拿掉头衔和年资，用同一张清单给团队逐项打勾——谁缺哪一项？他正在长成的是哪一项？再用清单给自己打勾——你缺的那一项，正是你在"背清单"而不是"用清单"的地方（从见过到拥有：能对着清单一项一项打勾，才算拥有）。
5. **项目四 · 过专责尺 + 符合性尺 + 边界判据**：你们最近一个项目里，"系统成败的账"（终责）在谁手里、"架构正确性的账"（专责）在谁手里——两者是不是同一个人（兼任还是失职）？分工是委托—协商—验收吗（拍板权在谁、理由权在谁）？再问符合性尺：最近一次评审，有没有查"实现是否符合架构分配"？还有边界判据：最近一次被抢走的决定，是"约束别人的"还是"只管自己的"——本该归谁？
6. **项目五 · 落到产品数据两层**：他/你负责的系统级文档族（AD/ADR/ICD/概要定义/派生需求/权衡报告/元素分配/架构基线/演化路线图/系统级验证方案），换个人拿着能接住、继续演进吗？②⑥两项尤其看纸面（方法写不写得成视图、判断换个人接不接得住）。组织级治理产出（架构原则/政策/委员会章程/合规评估/健康度指标）——这两层在你们部门有吗？（系统级文档族是"作品"、治理产出是"制度"。）
7. **项目六 · 过母词尺 + 工作检查单七条**：他现在正在做七动词链里的哪个动作（构思/定义/表达/记录/沟通/认证恰当实现/维护与改进）？链断在哪？（只做表达=画图匠；只记录不沟通=老规矩写在自己纸上）。下次做架构决策前，先过那七条（影响半径大/持续时间长/修改成本高？理论对不对得起它？相关方视图跟上了吗？决策记录写了吗？在做决定还是在画图/什么都管/等默认？接口契约改了吗？我在背专责还是终责？）——把它打印出来贴在下一个架构决策现场。
8. **出体检报告**：十项各打勾/缺项，落判词，最该先补最缺的一项；两周后复查补了什么。

**卡住怎么判断**：打不上勾的那一项就是最该补的；⑥打不上勾=手艺型架构师（判断换个人接不住）；④打不上勾=最危险（判断越准破坏越大）；⑦⑩打不上勾=把不可逆决策当日常节奏（董勐改走受控导出 / 万辉认下编号规则是正例）；专责尺打不上勾=把不该背的账揽到自己头上（什么都管）；符合性尺打不上勾=画完架构就交差（实现符不符合没人查）；母词尺打不上勾=链断在半路（画图匠式架构师）；价值层三问（相关方知情/评审/记录）当场打勾——"没有记录"的地方就是④可能缺席、也是①和⑥最容易现形的地方。

### 工作检查单（配套素材）

| 检查项 | 是/否 | 否 → 可讨论发现 |

## 第 7 步 · 淬问成题：题卡（10 题 2×5）

### 第一组 · 概念与原理（5 题）

**Q1（破题 · 见树见林① · 概念本身）**
"年度评优会上，恒信把『年度架构师』颁给了万辉，颁奖词是：『全年产出架构图最多、架构文档最全。』会后徐漾问万辉：『当选架构师，意味着你现在是什么？』他答不上来。办公室三个人接话：开发说『架构师就是更高级的工程师——升职了嘛』；测试部的同事说『架构师是画架构图的人，图画得最多那个』；运维说『架构师是什么都管的人，出了事都找他』。三句话三个『架构师』，错在哪？『架构师』到底是个什么样的物种？"
追问：① 十项能力清单——底座六项（第9章）+ 增量四项（第10、12章），怎么构成一个整体？『架构师首先是一个工程师』为什么是次序问题（没有那六项底座，『架构师』三个字只是一张名片；ISO 12207/15288 里它是工程师角色体系中的一种 specialization，不是另一个物种）？② 三句话分别把什么当成了判据（职级 / 画图 / 权力——都是名义或载体，不是能力）？③ 反身：你们公司颁『架构师』头衔 / 评优时，依据的是图多文档全，还是十项能力清单？

**Q2（见树见林② · 概念关系）**
"请给出 架构师 和 更高级的工程师、系统工程师、技术负责人、项目经理、领域专家、画图匠 这六个相邻角色的关系，并说明：为什么说『职级也不定义架构师』？『约束别人』和『只管自己』为什么是架构师和工程师的边界判据？架构师和系统工程师为什么是两个专门角色、两本账——『专责』和『终责』差在哪？增量四项（⑦⑧⑨⑩）为什么长在底座六项上，而不是一套独立的『架构师能力』？"
追问：① 边界判据：架构师定边界、定接口、定演化原则（约束别人代码的决策）；工程师在模块内自治（内部结构、内部依赖、实现策略自己定，哪怕已经是『模块内部架构』，第9章 §9.3.6 模块级迷你架构师）——谁在越界，一眼可辨；没有架构师各自为政（Cowboy Coding）、没有工程师架构落不了地，为什么？② 专责≠终责：系统工程师对系统成败负终责（accountability 不可委托），架构师对结构演化负专责（responsibility 可委托可追责）——拍板权在谁、理由权（rationale）在谁？『背在身上』为什么是『看在眼里』不是『担在肩上』？③ 六个更锋利的差异里，验证方式为什么从『测试』换成『评审』——第8章『评审对目标、验证对需求、确认对用途』，架构没有逐条需求可对，只能对什么？『代码用测试验证，架构用评审验证』的『评审』审的是什么？④ 为什么增量长在底座上（识别依赖工程判断、理论依赖科学素养、不可逆判断依赖工程判断——底座缺一块，增量全是空转）？⑤ 反身：你们团队里"该由架构师决定却被别人抢走"的决定，抢走它的人缺的是清单里的哪一项？

**Q3（真悖论 · 头衔/任命 vs 能力）**
"万辉被任命为『年度架构师』、名片换了、评优都评上了——有头衔、有职位、有舞台。可徐漾问他『当选架构师意味着你现在是什么』，他答不上来；按十项清单自我体检，他缺①④⑥。有头衔、被任命，到底算不算架构师？什么判据能分清『头衔』和『能力』？"
追问：① 头衔是组织给的位置、职级是组织给的位置——为什么都定义不了架构师（被任命只是拿到牌桌的入场券；『头衔一路在换，背在身上的东西没有变』；42010 只给架构活动立词条、不给头衔立——标准认活不认职位）？② 万辉缺①④⑥各是什么证据（①科学素养——长期不碰实现、理论开始悬空 / ④职业伦理——为进度悄悄牺牲可靠性的账没还清 / ⑥可复现意识——以前不写决策记录，现在开始写）？③ 反身：你们部门有没有"头衔先于能力"的架构师？拿掉头衔，他还立得住吗？

**Q4（真悖论 · 画图 vs 架构）**
"万辉的四张图挂满一面墙，图越来越漂亮、文档越来越全——评优就把『年度架构师』颁给了他。这一章却说：删掉你所有的图，你的决定还在，你是架构师；删掉图你什么也没剩下，你是画图匠。『把图画得最全』和『把架构做出来』到底差在哪？什么判据能分清『图』和『架构』？"
追问：① 图是决定的表达还是决定的替代——四张图为什么是画图匠的作品（图下面没有任何关于『决定』的字，直到徐漾点醒他，把四张图换成一份决定清单）？② 水忠的『老规矩』不是图，是一份清单（不可还原的涵义、设计准则、演进准则）——图是死的、视图是活的，为什么『让每个相关方的关注点都有一张图能落』（⑨）比图本身重要（给疾控看追溯链路、给司机看状态视图、给维修看结构视图、给监管看合规视图，合起来说的是同一个 M3）？③ 反身：你最近一次交的『架构』，删掉图还剩什么？

**Q5（真悖论 · 专责 vs 终责 · 什么都管 vs 管得最准）**
"运维说：架构师是什么都管的人，出了事都找他——这句话有两层意思：一是把『管太多』当负责，二是把『系统成败的账』甩给架构师。这一章却说：管得最准，不是管得最多；对不重要的事情不决策，本身就是一种好的架构决策；而『背在身上』是看在眼里，不是担在肩上——系统成败那本账，记在系统工程师头上。哪个对？什么判据分清『架构师该背的』和『不该背的』？"
追问：① 专责 vs 终责——accountability（不可委托）与 responsibility（可委托可追责）差在哪？为什么说『架构师搞砸了，追责追到架构师；对外向客户、向监管扛雷的，是系统工程师』？② 委托—协商—验收回路：系统工程师把『架构正确性』委托给架构师、架构师以架构描述回馈、SE 评审背书；拍板权在系统工程师、理由权 rationale 在架构师——为什么选了一个架构方案会带来派生需求、要回流更新规定需求？协商理解（negotiated understanding）为什么不是『完美的正确解』？③ 什么都管的两条后果（团队失去判断能力+他成瓶颈；精力花在低价值决策上、重要决策反而没精力——缺⑦）+ 识别后果严重的决策三判据（影响半径大/持续时间长/修改成本高）——对重要的事情不决策，为什么是架构师的第一宗罪？④ 反身：你们团队最近一次"对重要的事情不决策、对不重要的事情疯狂决策"，是哪一个？

### 第二组 · 落地与实践（5 题）

**Q6（判据运用 · 双线判词 · 十项体检 · 判词粒度语境）**
"用十项能力清单，给万辉和水忠下判词：万辉有头衔缺①④⑥，水忠无头衔缺②⑥。先把两条判词逐项打勾验证，再说说：两个人都是『缺』，缺的性质有什么不同？两个人都不是完整的架构师，那『两个都在长成』是什么意思？"
追问：① 判词粒度语境——万辉的名字印在『系统架构师』这一格、背的却是最需要底座的那份专责（专责缺底座）；水忠在『模块工程师』岗位上做架构的活、缺②⑥（方法是手艺的极致不成体系、判断换个人做不出来）。为什么『有头衔缺底座』和『无头衔做架构活』都不是完整的架构师？② 缺项露在产品数据的哪里（万辉四张图下没有决定，直到开始写 ADR / 水忠老规矩写在纸上但判断换个人做不出来）——判词（案例进展①②③）和 16.4.8（检验句）为什么量的是同一把尺子（换个人接得住吗）？③ 反身：你更接近哪条线？缺的是哪一项？

**Q7（判据运用 · 失败四式 · 四宗死法）**
"失败四式——画图匠（只有视图没有判断）、什么都管（把约束管成枷锁，把专责当终责）、不决策（把决定留给默认）、远离代码（判断失去锚点）。用十项能力清单，说出每一宗死法缺的是哪一项。哪一宗最危险？为什么？"
追问：① 画图匠为什么死于『团队发现图不能用来做决定』而不是被辞退（缺⑤工程判断——图说系统长这样，但遇到『数据放哪』没人能答，大家绕过图各做各的）？② 什么都管为什么看起来最负责、其实最危险（对不重要的事情疯狂决策、对重要的视而不见——缺⑦；他成了瓶颈；且把专责错当终责，既僭越又失职）？③ 不决策为什么是把架构决策的资格交给运气和时间（不选就是选了默认，默认最保守最省事——缺⑩判断不可逆性）？远离代码为什么是『判断失去锚点』（理论还在但不落任何可实现的东西——缺③实践能力）？④ 反身：你最近一次架构决策更接近哪一宗？缺的是清单里的哪一项？

**Q8（判据运用 · 抽象跃迁成长 + 被任命≠成为 + 三种来路）**
"万辉被任命为『年度架构师』那天，头衔换了——但徐漾那个问题他还是答不上来。为什么『被任命』不等于『成为』？成长为什么不是升职，而是『抽象跃迁』——从系统到架构，换一条专精轨道？怎么判断一个人是不是真的在长成架构师（判断的依据在哪个尺度）？三种来路（从开发长出来 / 空降 / 挂名）各是什么功课？"
追问：① 抽象跃迁：系统→架构=换专精轨道非升职；决策对象从『事实』（方案行不行、预算够不够）到『本质』（什么结构能同时满足互相冲突的关注点、且未来三年还能演化）；15288 §6.4.4 架构定义流程=生成→选择→表达——为什么说『你关心的问题换了，你的物种就变了』？② 分叉不是阶梯：管理线（技术经理→项目总监）与架构线（系统架构师→首席架构师）为什么正交？『升不上去才走架构线』错在哪？架构师每天想的问题=『如果需求翻一倍，这个架构还成立吗』——这句话在问什么？③ 三种来路各缺什么（从开发长出来缺⑦⑧⑩、空降缺③⑥、挂名只有头衔）——判断一个人走哪条路，看他在补清单的哪一项？④ 成长的标志=第一次『说不』——董勐自己把直连方案划掉改走受控导出、万辉认下编号规则，拦下的为什么不是『错的』而是『没想清楚不可逆性的』（⑩判断不可逆性是最后一盏灯，需要前面所有能力到位才接得住）？

**Q9（方法时刻 · 规则 15 · 从见过到拥有 + 判词变体 + 转述形态）**
"万辉有『年度架构师』头衔、水忠连名片上都印着『嵌入式硬件工程师』——可这一章的方法底座时刻是『从见过到拥有』：章首的万辉对『架构师』只有『见过』——叫得出头衔、画得出图，却答不上『当选架构师意味着你现在是什么』；判词把他量成了『拥有』——能对着十项清单一项一项打勾、认得出自己缺什么。**判词把『架构师』从头衔钉成了能力清单。** 把这张清单从『背诵对象』变成『判人的尺子』，做三件事：① 判万辉（有头衔缺①④⑥——系统架构师头衔、专责缺底座，证据是什么？）、② 判水忠（无头衔缺②⑥——模块工程师岗位做架构活，证据是什么？）、③ 反身判你自己的团队——谁缺哪一项？用什么判据检验（不是头衔、不是感觉）？最后把『架构师』用三五句话讲给一个完全外行的人听——讲到哪卡住，缺口就在哪。"
追问（判词变体 + 转述）：① 判万辉"缺①④⑥"，证据各是什么（①长期不碰实现、理论开始悬空 / ④为进度悄悄牺牲可靠性的账没还清 / ⑥以前不写决策记录，现在开始写）？判水忠"缺②⑥"，证据是什么（方法是手艺的极致、不成体系 / 判断换个人做不出来、车间没有完整测试方案）？两个人的缺项为什么都露在产品数据上（万辉四张图下没有决定、水忠老规矩写在纸上但判断不可复制）——判词和产品数据量的是同一把尺子？② 用七动词链量判词（母词尺）：水忠做到了构思、定义、表达、认证，唯独缺记录与沟通留痕——为什么正好对应缺⑥？万辉画了四张图（表达），构思、定义缺位，认证（架构符合性把关）更是他的功课——为什么缺的正是底座①④⑥？你此刻在做的架构工作，是七动词链里的哪个动作？③ 转述（压缩测试）：把『架构师』讲给一个完全外行的人，三五句话讲清——讲到『专责不是终责』卡住，还是讲到『删掉图剩下的决定』卡住？卡壳处就是结构没成型或边界没划清的地方（四问与转述，测的是同一件事）。④ 反身判团队：拿掉头衔和年资，用十项逐项打勾——你们团队"最像架构师的人"缺哪一项？他正在长成的是哪一项？『从见过到拥有』还意味着什么——能答全十项能力的四问（各是什么、不是什么、判据是什么、往哪去）、能用清单量别人量自己，才算拥有；这把尺子现在装进你手里了吗？

**Q10（落地生根 · 回部门体检 + 判词 + 产品数据两层 + 工作检查单）**
"结合你们部门现状，用十项能力清单给一位『被当成架构师的人』（或你自己）做一次体检——逐项打勾，指出缺项，落一条判词（像万辉缺①④⑥还是像水忠缺②⑥？），给出最该先补的一项，落到一个动作。"
追问：① 十项体检 + 专责尺 + 符合性尺 + 母词尺 + 工作检查单七条（影响半径大/持续时间长/修改成本高？理论对不对得起它？相关方视图跟上了吗？决策记录写了吗？在做决定还是在画图/什么都管/等默认？接口契约改了吗？我在背专责还是终责？）先查哪两项？② 产品数据两层都齐吗——系统级文档族（AD/ADR/ICD/概要定义/派生需求/权衡报告/元素分配/架构基线/演化路线图/系统级验证方案）是『作品』，组织级治理产出（架构原则/政策/委员会章程/合规评估/健康度指标）是『制度』；治理决策权在架构委员会、但系统级变更的最终裁决仍要系统工程师背书（常设法庭 vs 最终责任人）——这两层在你们部门有吗？概详分离是每份方案的普遍结构，为什么不是角色分工？接口契约为什么是工程师部件方案的 1:1 搬入点（架构决策错，代价是结构性的）？③ 你们的架构评审 / 晋升，用的是十项判据，还是"图多 / 文档全 / 头衔高"三个错判据（和章首颁奖词一模一样）？④ 两周后回来报告：谁打了勾、缺了哪项、补了哪个动作。

- **设题九检全过**：①无直觉能秒答（每题翻案，Q1 先认同三个人再翻）；②追问链齐（机制/判据/归责/反身）；③概念锚点在导读给足（十项能力清单/六对角色边界/边界判据/专责≠终责/名义不定义/五维差异/七动词链母词/失败四式/抽象跃迁/产品数据两层/母词尺/工作检查单）；④题面依据全在书内（评优会颁奖词/三句评语/万辉自我体检缺①④⑥/四张图/老规矩/四张视图/水忠被叫架构师/失败四式/董勐受控导出/万辉认下编号规则/系统成败的账/派生需求回流/产品数据两层/七动词链量判词/工作检查单七条）；⑤靶子皆"从没怀疑"的常识（架构师=升职/画图/什么都管·对系统成败负责/被任命=成为/可以不会写代码/图全=最好/经验=理论/底座增量两套/系统工程师是执行者/所有 SE 都该成架构师/十项清单=六块增量/标准认头衔）；⑥每题落回判据或动作；⑦全部"信了相反"非知识盲区；⑧前提自证（评优会细节、万辉缺①④⑥画像、水忠缺②⑥判词、粒度语境、专责终责分工、委托—协商—验收、边界判据、五维差异、七动词链量判词、董勐改走受控导出、失败四式症状、产品数据两层清单写进题面）；⑨三处升级为真悖论收束。
