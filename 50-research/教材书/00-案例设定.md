# 案例设定：全书两条贯穿案例线

> 本文件是教材书全书的"案例圣经"——两个虚构案例支撑所有章节的"误解现场"、"双域镜照"与"章末反转"。均为虚构但现实的设定，不指涉真实公司。
> 组织原则：按方法论的底座（[`00-方法论的底座.md`](00-方法论的底座.md)）组织——案例是"落实践"（五环第5环）与"概念跨域"（意义即用法）的载体；一本书不挑行业，同一概念在硬件与软件两个世界各长各的样子。
> 用法：写某章 → §三 每章案例任务卡（章节视图）定主/镜与反转 + §十 素材包取料；找某条线的完整素材 → §二 案例身份（案例视图）；核某概念的双线演示 → §四 跨域对照（概念视图）；写判词 → §五 角色画像 + §九 角色弧线；防跨章漂移 → §七 时间线 + §八 回声登记。
> 读者无需单独阅读本文件（案例随章节自然展开）。

## 一、案例总纲：为什么是这两个案例

1. 一个造"有形设备"（冰链 M3 温控箱），一个造"无形系统"（恒信合同审批）——全书最好的"工程系统 vs 技术系统"演示对（第2章）。
2. 同一套概念在两个世界各长一个样——每个概念至少一条线深度演示，另一条线做"镜照"段落（200-400 字）。
3. 团队行为模式：先因"词汇病"做错（各章章首"误解现场"），经正确概念纠正（各章"认知反转"）——读者看着团队犯自己也在犯的错。
4. **承接第1章方法论**：每个误解现场 = 一个概念"见过未拥有"，每个认知反转 = 把它推到"拥有"；每章案例在演示第1章的某一"方法底座时刻"（见 §三 对应列）。
5. **第1章误解现场用两司团队戏份（冰链·工程团队 / 恒信·设计团队）**——各开一室、都吵"架构"、各五张脸、全员出场；它演示的是"任何公司都在犯"的同词异义病，并首次示范"概念不挑行业"；案例团队自第1章起承接，后续各章用各自领域的词病继续演示同一套病。
6. **案例成员随内容推进同步成长（所有成员，2026-08-26 立）**——不止主角，**所有**贯穿出场的成员（两司团队 + 散见多章出场的配角）都要随内容推进成长：岗位关切跨章一致（身份不变），概念认知随章递进（见过→拥有）；台词语句是"此刻认知水位"的表达，同一句岗位关切越说越准。仅一次出场的散见配角不涉成长；多次出场者必成长。**成长分量按 §九 行序分配**（2026-08-26 定：徐漾>玉杰>逸人>万辉>小白>水忠>文正>黄程>董勐>李旭）——排前者成长线更饱满、翻折更完整，排后者轻成长；但所有贯穿出场成员都须有成长，李旭殿后也须有。没有成员的成长，案例就退化成概念挂架。

### 案例优化规则（2026-08-25 定 · 全库铺开操作依据）

> 依据第1/2/10/15章四章样板提炼；写/改某章案例时，按本节五条执行，再进 §十 素材包取料。

**1. 五个目标判据（同时满足）**
- **专业**：错误是"该行业普遍存在、代价高"的错误，不是为演示概念造出来的错误；细节真实（数字 / 流程 / 成本 / 周期）。
- **深度**：把概念推到反直觉处或极限——误解的张力拉满，演示概念最硬的一面，不泛泛演示。
- **典型**：读者照镜子——"最常见的那类项目 / 那类错误"，可迁移当模板。
- **张力**：期望落差 × 代价。代价落到业务层（订单 / 对账 / 合规 / 返工 / 时间），不只停在认知层（说不出 / 答不上）。
- **与章一致**：误解 → 磨开 → 反转钉在本章反直觉核心命题上；每个案例进展钉住一个本章概念点或判据。

**2. 加戏规则（配角戏份，玉杰 / 逸人为主）**
- 加"岗位在场的必然性"，不加场面：运维（玉杰）站在约束 / 可验证 / 可复制 / 接缝 / 上线≠成功等概念正中央；制造（逸人）站在相关方关注点 / 约束即解放 / 批次追溯 / 治理边界 / 可实现性等概念正中央。
- 每次出场必须钉住一个概念点；台词是其岗位关切的一致表达——跨章一致性：玉杰永远追问"部署在哪、谁运维、上线怎么不炸"；逸人永远追问"产线 / 批次 / 物料怎么跟上"。
- **成长（2026-08-26 立）**：每次出场同时落在该成员"此刻的认知水位"——岗位关切不变、认知递进，同一句关切越说越准：玉杰从"上线不炸"长到"规则从没被写进系统"再到"桨还是那把桨"；逸人从"产线跟不跟得上"长到"系统边界与接缝"。不静态复读。
- 密度：每章主案例团队，配角至少两处实质戏份（台词 + 动作），不独占一场。
- 克制：不让配角抢主角戏；镜头权重可调（主演 → 在场证人）；关键台词保留、铺陈可删。

**3. 动机与代价**
- 结构性犯错优于卡通式犯错：给错误补"合理的组织动机"（KPI / 上线压力 / 成本 / 时间 / 激励错位）——读者觉得"这就是我们家"，不是"两个蠢团队"。
- 代价补足：误解 / 错误必须有业务层后果，且不破坏时间线 / 回声物件。

**4. 一致性硬约束（不可违反）**
- 判据、自查、练习、编号、跨章引用零改动（除非用户明确要求）。
- 时间线、回声物件、判词、角色画像零改动（以本文件登记为准）。
- 角色岗位关切跨章一致（自第1章起立）。
- 散文段 ≤150 汉字（对话 / 判据条目豁免）。
- 每次改动同步本文件 §十 素材包 + 版本号。

**5. 操作流程**
① 读本章正文 → 诊断案例现状（强 / 弱、未被案例覆盖的概念点）→ ② 找玉杰 / 逸人岗位关切在本章的天然落点 → ③ 补动机与代价、提张力 → ④ 修改（守第4条）→ ⑤ 版本记录 + 本文件同步 → ⑥ 机械校验（段落长度 / 编号 / 残留）。

## 二、案例身份

### 案例A · 冰链科技 —— 医疗冷链运输温控箱

**产品**：M3 医疗冷链温控箱。硬件 + 嵌入式 + 云端 + App 一体，用于疫苗/药品 -20℃~8℃ 宽范围冷链运输（冷藏疫苗常见 2~8℃、冻干制品 -20℃ 冷冻，M3 一箱通吃），要求全程温度可追溯、断链可告警。

**团队**：
| 角色 | 姓名 | 性别 | 职责 |
|---|---|---|---|
| 产品经理 | 文正 | 男 | 需求、评审、对客户 |
| 嵌入式硬件工程师 | 水忠 | 男 | 温控硬件、固件 |
| 云端软件团队 | 董勐等 3 人 | 男 | 数据采集、App、追溯平台 |
| 测试 | 李旭 | 男 | 验证与确认 |
| 制造/供应链 | 逸人 | 男 | 量产、物料、批次 |

> 冰链配角（散见各章具名）：销售小冯（第3章案例①）、疾控中心刘主任（第3章案例④·采购方代表）、硬件组新人小陈（第10章起具名）。

**走位**：主案例章节 3 / 5 / 7 / 10 / 11 / 13；镜照 2 / 4 / 6 / 8 / 12 / 14；第9章双线判词（水忠=模块工程师岗位拓宽中，①③⑤顶配缺②⑥）；第16章双线合流续（水忠在模块工程师岗位上做架构工作、缺②⑥，写老规矩长成——一只脚跨进架构师地盘）。

### 案例B · 恒信集团 —— 跨部门合同审批系统

**产品**：合同审批数字化系统。业务流程系统，覆盖法务 / 财务 / 业务三部门审批链，含合同版本管理、审批流、台账。

## 六、两条案例线的关系（概念跨域演示逻辑）

1. **一个造"有形设备"，一个造"无形系统"**——全书最好的"工程系统 vs 技术系统"演示对（第2章）。
2. **同一套概念在两个世界长一个样**——每个概念至少一条线深度演示，另一条线做"镜照"段落（200-400 字）：镜照只照"同一个概念换了世界"，不引入新概念。
3. **案例团队的行为模式**：先因"词汇病"做错（各章章首"误解现场"），经正确概念纠正（各章"认知反转"）——读者看着团队犯自己也在犯的错。
4. **第9章工程师**在链的中段先把"谁是工程师"的人判词立起来（万辉伪工程缺①④⑥、水忠手艺极致缺②⑥）；**第15章整合**：两条线各走一遍完整变更闭环，最后合起来收束"系统"；**第16章架构师**继续收束到"人"——给两条线里做架构工作的人（万辉有头衔缺底座、水忠无头衔有一半底座）落定"是不是架构师"的判词。
5. **概念不挑行业**——这是本书想证明的事：质量既可以是温控箱的温度精度，也可以是审批系统的查询响应时间；架构既可以是硬件模块划分，也可以是服务边界设计。**这套概念是同一副骨架，换的只是血肉。**
