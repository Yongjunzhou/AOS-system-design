## 第 1 步 · 剖章立骨：核心内容地图

**这一章回答的问题**：工程师到底是个什么样的物种？头衔、证书、年限都不定义工程师——六项能力才定义；能力不中性，④定义方向；工程师不是铁板一块——一个物种三种粒度，背的是同一副骨架，账却不是同一本。怎么判断一个人是不是工程师（六项能力 + 产品数据）、怎么长成（拓宽：模块→系统）、怎么失败（四式）、怎么被检验（按粒度背的产品数据）。

**三幕对齐（省一步推导）**：
- **第一幕 是什么（定界）**：9.2 六项能力清单（9.2.1 一句开场白：把四层背在身上 → 9.2.2~9.2.6 六项逐项，各配判据 + 误区 + 培养 → 9.2.7 三个领域同一副骨架 → 9.2.8 沟通与团队=执行手段）+ 案例进展①水忠—— 喂第一组·概念题（见树见林）；
- **第二幕 不是什么（磨边弧）**：9.3 角色边界与粒度谱系（9.3.1 不是技术员 → 9.3.2 不是科学家 → 9.3.3 不是手艺人 → 9.3.4 不是"会写代码的人" → 9.3.5 不是头衔证书年限 → **9.3.6 不是铁板一块：一个物种三种粒度**）+ 案例进展②万辉—— 喂真悖论·辨边界题；
- **第三幕 往哪去（运用）**：9.4 怎么长成（9.4.1 拓宽：模块→系统 → 9.4.2 叠加顺序+技能四层 → 9.4.3 成长的标志：第一次"说不" → 9.4.4 被任命≠成为 → 9.4.5 失败四式 → **9.4.6 产品数据：三粒度责任矩阵**）+ 案例进展③双线判词—— 喂第二组·落地 / 方法时刻题（规则 15）。

按 `00-方法论的底座` §六 特殊章适配：角色章无概念档案，走"能力清单 + 判词"，清单四问化——每项能力按"是什么 / 不是什么 / 判据"组织。当前正文骨架升级为**两件套**：① 六项能力清单（四问化 + 误区 + 培养，三种粒度共用的底座）；② 三粒度谱系（粒度 × 责任，本章新增的内部边界）。**三幕对齐**：第一幕钉"工程师"本身（六项各是什么，三种粒度共用底座）；第二幕把它和容易混的东西分开（外部边界 + 内部粒度）；第三幕回答"怎么长成、怎么死掉、怎么被检验"。

### 核心概念（角色章的"概念" = 清单 + 粒度谱系 + 检验尺 + 判词任务 + 反直觉命题）

> 标注规则（v2.1）：按正文根概念四标准（原子性/生成性/不可替代性/递归性）标出本章档案中的**承重柱**——先抓根、再展骨架。本章的承重柱 = **工程师**（见头注论证）；六项能力清单为定义单位、三粒度谱系为骨架层枢纽。

1. **工程师**【根概念 · 本章承重柱】：把四层结构背在身上的人——第2章四层结构（工程科学/方法论/工具实践/价值与伦理）每一层在一个人身上长成一项能力，共六项（①科学素养 ②方法论素养 ③实践能力 ④职业伦理 ⑤工程判断·横切 ⑥可复现意识·元）。判据：六项能力一项一项亮起来 + 换个人能交付 + 关键时刻守得住底线。**承重柱证据**：原子性（由六项能力清单定义，是角色判断的最小判定单位，不可由域内其他概念定义）/ 生成性（三粒度谱系=三种尺码、拓宽=成长、失败四式=退化、产品数据=检验、双线判词=度量——全部从它派生）/ 不可替代性（去掉它，清单/粒度/判词全部悬空）/ 递归性（ch16 架构师=工程师+增量，层层生效）。与"名义"的区别（能力 vs 头衔/证书/年限）见 §9.3.5。
2. **六项能力清单**（定义单位）【骨架 · 枢纽】：四层各一项能力 + ⑤横切四层 + ⑥元能力。前四项与第2章四层一一对应；⑤⑥恰恰是工程师区别于"会做工程的人"的地方。判据：六把体检尺逐项自问（见本章判据）。六项不是平行的——④殿后收束方向。
3. **①科学素养**：回答"做的东西凭什么能行、换个上下文还成立吗"——理解原理 / 判断边界 / 应用建模。判据：没遇过的情况——从原理推、翻旧经验、还是信玄学？培养循环=**预测对账**（改动前写预测、事后对账找偏差，偏差先问"哪条原理越了界"）+ 反向追问 / 数量级估算 / 费曼输出 / **失效分析**。
4. **②方法论素养**：把工作组织成方法——过程设计 / 显性化 / 过程治理。判据：我的方法能被别人学会吗？培养循环=**转化链**（隐性判断→显性化→标准化→组织能力）+ 写 SOP 交给同事照做 + 三问审计。有章法不等于算法化，方法必须留判断空间。
5. **③实践能力**：亲手把方案变成现实、东西坏了能修好——动手实现 / 工具驾驭 / 排错集成。判据：我最近一次亲手落地，是什么时候？只能从"做"里长——强度光谱（阅读→看演示→跟做→仿做→**独立做·判断进场**→**救火·排错定力**）。
6. **④职业伦理**（方向定义者）：能力不中性——能力放大"选择的规模"，方向由④定义。身份的定义性特征（the profession，不是差事；NSPE 对公众负责）；两功能=**定义方向 + 守底线**。判据：压力面前会为进度悄悄牺牲可靠性吗？相关方知情吗？有记录吗？①②③⑤是"增量型"能力、④不是（只能靠"在压力下不越线"证明）。
7. **⑤工程判断**（横切四层）：规则没有覆盖的地方做对的取舍——不是"会做决定"，是"在约束下做对的取舍"（ABET：applied with judgment；约束越多判断价值越大）。三步闭环=识别约束 → 权衡取舍 → 担责闭环。唯一"必须亲自做错"的能力——生长点是复盘。
8. **⑥可复现意识**（元能力）：第2章试金石在个人身上的落点——"换个人也能交付"，把个人能力变成组织能力。判据：我的判断换个人能接住吗？与②分工：**②是"写成什么样"的本事、⑥是"必须写成那样"的自觉**；三层次=判断显性化 → 方法可传授 → 组织化。
9. **三粒度谱系**（模块工程师 / 系统工程师 / 系统架构师）：一个物种三种粒度，背同一副骨架，账却不是同一本——模块负元素实现**专责**（responsibility，可委托可追责）、系统负系统成败**终责**（accountability，不可委托）、架构负结构演化**专责**；**粒度 × 责任 决定角色**。
10. **系统工程师**（四动词）：转化 / 统筹 / 把关 / 守护 + INCOSE 六件事；24765"实践系统工程学科的个人，与其正式头衔无关"；系统工程师的产出不是零件，是让零件协同的系统本身。
11. **分形 + 分形不对称**：模块工程师=系统工程师的分形（迷你系统工程师——模块级跑同构闭环）；分形不对称=模块级没有 **对外架构**（边界/接口/职责来自上层分配，架构师画好不能改；**内部**架构——结构/依赖/实现策略——归模块工程师自己定义，**模块也有架构——对应的角色就是模块架构师**（后记四角色的第四位，先定义模块"是什么"再把它做出来，通常即模块工程师自己/团队，§9.3.6）/ **确认**（真实使用环境，系统级）/ **部署**（系统级行为）/ **集成**（系统级把模块装起来）；模块在边界内自治、边界外（接口）听架构的。
12. **拓宽**（模块→系统）：成长的方向=拓宽=视角换轨 + 责任接管（单点最优→系统最优，可牺牲单点）；换轨标志="第一次为系统牺牲自己的模块还觉得值"；分叉不是阶梯（往系统走 vs 往管理走正交，没有高低）。依据 INCOSE《系统工程愿景 2035》（R-69）。
13. **三粒度责任矩阵**（§9.4.6）：模块级 7 项（模块需求/模块详细定义/模块实现方案/模块实现报告/模块测试/模块验证/模块运维，编制） / 系统级 13 项（相关方需求、运行概念、系统需求、系统详细定义、技术方案、实现方案、集成方案、集成测试、验证、确认、部署、运维、退役等，**编制 + 批准模块级·兼终责**） / 系统架构（结构/接口/演化原则，第16章展开）；系统工程师是唯一横跨两层的角色。**模块级 7 项按后记四角色口径再拆一层**：模块架构师管「模块概要定义、模块内部结构、模块内接口、模块级设计准则与演进准则」（先把模块"是什么"定义出来），模块工程师管「模块详细定义、实现物、单元测试记录、版本与基线记录」（再把它做出来）——**通常是同一个人，或同一个团队**：先定义，再实现。
14. **沟通与团队**（执行手段）：**不是第七、第八项能力**，是④⑤⑥的执行手段——④让相关方知情靠沟通、⑤把取舍讲清楚靠沟通、⑥让方法被接住靠沟通（ABET 把沟通/团队列为独立成果，不是遗漏，是执行手段）。
15. **四个相邻角色**（技术员 / 科学家 / 手艺人 / 会写代码的人）：和工程师像但不一样——技术员照单执行、科学家求真、手艺人依赖个人、会写代码只是载体。
16. **名义三件套**（头衔 / 证书 / 年限）：名义不定义能力——头衔可印上可收走 / 证书只证明考过一次试 / 年资可能是手艺的壳子。

### 关联概念（近界 · 辨析）

- **六项能力 ↔ 第2章四层结构**：前四项与四层一一对应，⑤横切四层、⑥元——一套结构，两个说法（学科四层 vs 人六项）。
- **⑥可复现意识 ↔ 第2章试金石**：试金石"换个人能交付质量相当的结果"的具象化=换个人拿着你负责的产品数据能接着种、继续演进。
- **三粒度 ↔ 粒度×责任（§9.3.6）**：一个物种三种粒度，背同一副骨架；粒度不同，背的账不同（专责 vs 终责）——**粒度尺（判据7）就是这张表的内化**。
- **模块工程师 ↔ 系统工程师（分形）**：模块工程师=系统工程师的分形（迷你系统工程师），模块级跑同构闭环；分形不对称（模块没有对外架构/确认/部署/集成，内部架构归自己）——与"系统元素可递归视为系统"（第2章）呼应，但分形不是递归复制全套，是"少四样结构件、不少判断"。
- **系统工程师 ↔ 第2章系统工程（元工程）**：9.3.6 把第2章"系统工程是元工程"落到一个具体角色上——系统工程师=实践系统工程学科的个人（24765）；四动词+INCOSE 六件事是把元工程的话翻译成人做的事。
- **拓宽 ↔ 9.4.1 成长**：模块→系统=拓宽=视角换轨+责任接管；粒度变了，背的账就从"专责"换成"终责"（§9.3.6 那张表的成长版）。
- **三粒度责任矩阵 ↔ 第6章（需求与方案结对）**：概详分离是每份方案的普遍结构（不是角色分工）；**分工在粒度**——你负责哪个粒度，你的产品数据就是那个粒度的产品数据（模块级7项/系统级13项/系统架构）。第6章那棵树的叶子=产品数据的详细定义。
- **系统架构师 ↔ 第16章**：第三种粒度专责"架构定义"，第16章从头到尾量一遍；万辉=架构师头衔缺底座，底座缺一块、增量全是空转（前向预告）。
- **④职业伦理三问 ↔ 第8章三个看门人**：相关方知情 / 评审 / 记录——正是第8章评审要相关方知情、结论记录在案、验证确认要客观证据的门禁在压力下的落点。
- **⑤工程判断 ↔ 第2章"约束越多判断价值越大"**：判断=在约束下做取舍；"先上再说"也是判断，坏在没让相关方知情、没走评审。
- **沟通与团队 ↔ ④⑤⑥执行手段**：一个判断做得对、说不清楚，等于没做；一个方法写得出、不主动沟通，没人会用（§9.2.8）。

- **技能四层 ↔ 六项能力**：思维与认知地基≈①⑤、工程方法≈②、技术工具≈③、软技能≈④；⑥可复现是横在四层之上的元能力。

- **失败四式 ↔ 六项能力缺项**：手艺型缺⑥ / PPT 工程师缺③ / 守不住底线缺④ / 能力失控方向错（④）。

- **④职业伦理 ↔ 案例进展③万辉判词**：④不是可选项——万辉有②③、缺①④⑥，①④=里子缺（判断与底线）、⑥=复现站不住（面子半）。

### 核心原理（14 条）

**第一幕 · 是什么的底层机制**
1. 工程师是把四层结构背在身上的人——学科四层缺一层工程不完整，人四层缺一项能力工程师不完整（第2章四层结构在个人身上的落点）。
2. 六项能力不是平行的——前四项与四层对应，⑤横切四层、⑥是元能力；⑤⑥恰恰是工程师区别于"会做工程的人"的地方；每项各配判据 + 培养循环（①预测对账 / ②转化链·写SOP / ③强度光谱从做里长 / ⑤三步闭环+复盘 / ⑥交接演练 / ④不可越线清单+决策留痕）。
3. 能力不中性，④定义方向——能力放大"选择的规模"，方向由④定义；①②③⑤⑥是"增量型"能力，④不是（不能靠多做练习增值，只能靠"在压力下不越线"证明）；①③⑤顶配、④为零的人破坏比"不会做"的人大得多（737 MAX 不缺会算的工程师，缺守住底线的工程师）。
4. 价值层失守三问（相关方知不知情 / 有没有评审 / 有没有记录）成立——客观原因不留记录；价值层失守恰恰发生在"没有记录"的地方（第8章三个看门人在压力下的落点）。
5. 沟通与团队不是第七项能力，是④⑤⑥的执行手段——④让相关方知情靠沟通、⑤把取舍讲清楚靠沟通、⑥让方法被接住靠沟通；一个判断做得对、说不清楚，等于没做（ABET 单列沟通/团队，不是遗漏，是执行手段）。
6. 三个领域六项能力同一副骨架——系统工程管"缝"、软件工程管"过程"、硬件工程管"物理"；缺一项任何领域都不完整，区别只在权重（系统工程①⑤最重、软件②③主战场、硬件①④红线）。

**第二幕 · 磨边弧的机制（不是什么）**
7. 四条边界各有分界判据——技术员 vs 工程师分界不是学历是"规则留白时谁来拍板"；科学家问"世界是什么"、工程师问"应该造出什么"（求真 vs 求有用）；手艺人 vs 工程师唯一分界=交付依赖不依赖具体的人；写代码是载体不是判据（载体人人都可以拥有，判据不是人人都有）。
8. 名义不定义能力——头衔是组织发的位置（可印上可收走）、证书是社会认证（只证明考过一次试）、年资是时间累积（二十年可能都在用手艺的壳子）。
9. 一个物种三种粒度，背同一副骨架——粒度 × 责任 决定角色：模块负元素实现专责（responsibility，可委托可追责）、系统负系统成败终责（accountability，不可委托）、架构负结构演化专责；**终责是甩不掉的账，专责是划得清的账**；系统工程师对"系统成败"的账不可委托。
10. 模块工程师=系统工程师的分形，但分形不对称——模块级跑同构闭环（模块需求→设计→实现→验证），却少四样（对外架构=边界由上层分配 / 确认=真实环境系统级 / 部署=系统级行为 / 集成=系统级把模块装起来）；**模块内部架构（结构/依赖/实现策略）归模块工程师自己定义——边界内自治、边界外听架构的**；分形对称化是把角色谱系当"小一号全套复制"的误解源头。
11. 系统工程师=把系统工程落到项目里的人（24765：与其正式头衔无关）——四动词（转化/统筹/把关/守护）+ INCOSE 六件事；系统工程师的产出不是零件，是让零件协同的系统本身；没有一件是"亲手写代码"。

**第三幕 · 往哪去的机制（运用）**
12. 成长=拓宽不是升职——拓宽=视角换轨 + 责任接管（从对"我的模块"负责切到对"整个系统"负责，优化目标从单点最优到系统最优——系统最优往往要求某个模块让利）；判断依据从"怎么做"升到"守什么"（照做→会选→会取舍→守底线）；换轨标志=第一次为系统牺牲自己的模块还觉得值；**分叉不是阶梯**（往系统走 vs 往管理走正交，没有高低）；升职是组织换位置、拓宽是自己换轨道。
13. 失败四式各缺一项——手艺型缺⑥（判断不可接住）、PPT 工程师缺③（方法论悬空）、守不住底线缺④（价值层失守）、能力失控④定义方向错（能力越强方向错破坏越大）；**最危险的是能力失控（看起来最优秀）、最隐蔽的是守不住（症状不是不会做是做的时候没守住）**；每一种都能在六项清单里找到缺的那一项。
14. 能力最终体现在产品数据上——六项能力抽象在人身上不可直接检验（面试会看走眼、领导凭印象打分）；最终体现是能否开发出本角色负责的产品数据（**规定不是记录**，写在实现之前）；**按粒度分账**（模块级7项 / 系统级13项编制兼终责 / 系统架构）；能力再强开发不出来也不成立；换个人拿着能接着种才算数。

**反天赋论（方法底座时刻，显式命名）**：能力可检验、可训练，不是天生的——把六项能力列成清单，就是为了让你一项一项亮起来；头衔不定义人；缺的项可以补（①预测对账 / ②转化链·写SOP / ③强度光谱从做里长 / ⑤三步闭环+复盘 / ⑥交接演练 / ④不可越线清单+决策留痕）。

### 对立误解（喂给第 3 步误解库 / 第 4 步陷阱清单）

1. "会写代码的人，就是工程师。"（载体判据 + ③实践误区）
2. "有职称 / 有证书的人，就是工程师。"（名义判据）
3. "干了二十年，一定是好工程师。"（年资判据）
4. "工程师就是照着流程做的人。"（技术员混淆）
5. "工程师和科学家是一回事，都是求真。"（物种混淆）
6. "科学素养 = 懂很多公式 / 懂科学不被忽悠。"（①误区）
7. "方法论素养 = 会背方法论名词。"（②误区）
8. "实践能力 = 会写代码 / 会画图。"（③误区）
9. "工程判断 = 直觉 / 敢拍板 / 魄力。"（⑤误区）
10. "可复现 = 爱写文档 / 复制粘贴模板。"（⑥误区）
11. "工程师只要技术好，伦理是管理者的事。"（④可选项）
12. "职业伦理 = 背规章 / 算风险概率 / 服从组织。"（④误区）
13. "能力越强的工程师越值得信赖。"（能力不中性）
14. "判断不需要换个人也接得住。"（判断私有）
15. "把经验写成文档，就算工程化了。"（显性化=全部）
16. "沟通 / 团队协作是锦上添花的软技能，技术强就够了。"（§9.2.8 误区）
17. "工程师是天赋，干得出来是天生的。"（反天赋论对立）
18. "工程师是铁板一块，没有粒度之分。"（铁板一块）
19. "模块工程师也要做架构、做确认、做部署、做集成。"（分形对称化）
20. "系统工程师是比模块工程师更高的职级。"（粒度当职级）
21. "从模块到系统是升职，升不上去才走架构线。"（拓宽当升职 / 分叉当阶梯）
22. "一个工程师好不好，聊一聊就能判断。"（不可直接检验）
23. "拿到工程师头衔，就是工程师了，一辈子都是。"（被任命=成为）

### 本章判据（8 条：六项体检 6 尺 + 粒度尺 7 + 拓宽尺 8）

1. **科学素养**：我做的东西，凭什么能行？换个上下文还成立吗？**违反即崩：容量评估被砍，万辉不追问"凭什么能行"——换个场景就抓瞎，只会套模板。**
2. **方法论素养**：我的方法能被别人学会吗？还是只有我会？**违反即崩：水忠的方法只在自己脑子里——他休假，产线就没人敢签那个字，人走方法走。**
3. **实践能力**：我最近一次亲手落地，是什么时候？**违反即崩：只会说、不会做——方法论讲得头头是道，换不了任何一个具体的决定。**
4. **职业伦理**：压力面前，我会不会为进度悄悄牺牲可靠性？有没有让相关方知情？**违反即崩：为进度砍容量评估，"先上再说"——没有评审、没有记录、没有人知道。**
5. **工程判断**：规则没有覆盖的地方，我能做对的取舍吗？**违反即崩：有流程也选不对，约束一变就懵——"先上再说"也是个判断，只是没人知情、没走评审的坏判断。**
6. **可复现意识**：我的判断换个人能接住吗？我把它写成规则、文档、标准了吗？**违反即崩：CI/CD 靠张三的隐藏命令——万辉一出差，发版就只能等他回来。**
7. **粒度尺**：我背的账，是专责（划得清的账）还是终责（甩不掉的账）？我清楚自己处在哪个粒度吗？**违反即崩：名片印着"架构师"、实际只做单点——粒度看的是你背的账，不是印的名片。**
8. **拓宽尺**：我是在单点最优，还是系统最优？我愿意为系统牺牲自己的模块吗？**违反即崩：永远把"我的模块"护在最前——那只是模块工程师做得久，不是系统工程师长得成。**

体检之外还有配套尺：**成长尺**（判断的依据在哪个尺度：照做 / 会选 / 会取舍 / 守底线——从"怎么做"升到"守什么"才是长成）；**终极尺**（能力再强，也要看能不能开发出高质量的产品数据——换个人，拿着它，能不能做出来、继续演进）；**执行手段判据**（§9.2.8 配套：一个判断做得对、我说得清楚吗？一个方法写得出、我主动沟通、让团队会用吗？）。

### 判据层（应会用，8 条 = 书判据 8：六项体检 6 尺 + 粒度尺 + 拓宽尺）

1. **六项能力体检**（六把尺子：科学素养 / 方法论素养 / 实践能力 / 职业伦理 / 工程判断 / 可复现意识）：逐项自问，三种场合（招人面试 / 团队体检 / 自己对照）各会用。
2. **角色判据 · 试金石**：换个人，用同样的需求和方法，能交付质量相当的结果=工程师；交付依赖你=手艺人——哪怕你也会写代码、画图纸。
3. **价值层三问**：相关方知不知情 / 有没有评审 / 有没有记录——当场打勾；"没有记录"的地方就是失守可能潜伏的地方。
4. **粒度尺（判据7）**：我背的账，是专责（划得清的账）还是终责（甩不掉的账）？我清楚自己处在哪个粒度吗？——用于定位自己/别人在谱系里的位置、揪出"名片一个粒度、实际另一个粒度"。
5. **拓宽尺（判据8）**：我是在单点最优，还是系统最优？我愿意为系统牺牲自己的模块吗？——用于判断是否在拓宽（换轨）、该不该认领跨模块任务。
6. **成长尺（动态配套）**：判断的依据在哪个尺度（照做 / 会选 / 会取舍 / 守底线）——定位自己下一步往哪升。
7. **终极尺（配套）**：能力再强，也要看能不能开发出高质量的产品数据——换个人拿着它做出来、继续演进，能力才成立。
8. **执行手段判据（§9.2.8 配套）**：一个判断做得对，我说得清楚吗？一个方法写得出，我主动沟通、让团队会用吗？——沟通与团队是④⑤⑥落地的通道，不是加分项。

## 第 5 步 · 正误有方：纠错策略

### 强化点优先级（一个知识点反制多个误解）

| 优先级 | 强化点 | 反制误解 | 练到何种程度 |
|---|---|---|---|

### 纠错红线十条

1. **先表态后翻案**：先让学员说"会写代码就是工程师，这还用讨论吗"，再翻，不让结论先入。
2. **反转精确不造新误解**："载体不是判据"别翻成"写代码不重要 / 工程师不用会写代码"；"头衔不定义工程师"别翻成"头衔没用 / 该取消职称"；"能力不中性"别翻成"能力本身是坏的"；"方法论不是背名词"别翻成"不用学方法论"；**"粒度×责任"别翻成"模块工程师低人一等 / 系统工程师全包"**；**"分形不对称"别翻成"模块工程师什么都不用管"**（是少四样结构件——对外架构/确认/部署/集成——不是少判断；内部架构还是他自己的）；**"拓宽不是升职"别翻成"升职没用"**（升职正当，只是和拓宽不是一回事）。
3. **判据配机制**：每条反转都有"为什么"（机制）和"怎么当场验证"（判据）。
4. **归责到可对照动作**："他不是工程师"落到"⑥没打勾——判断换个人接不住 / ④没打勾——压力面前为进度让路 / 粒度尺没打勾——背的是专责还是终责说不清"，不归咎"人不行"。
5. **教机制不教断言**：教"为什么能力不中性"（方向由④定义、737 MAX 不缺会算的工程师），不教"讲伦理就安全"；教"为什么分形不对称"（对外架构已分配/确认系统级/部署系统级/集成系统级），不教"模块不用做这些"；教"为什么拓宽不是升职"（视角换轨+责任接管），不教"升职是错的"。
6. **先立尺子再翻案**：先给六项体检 + 粒度尺 + 拓宽尺判据，再翻万辉"我已是高级工程师"、水忠"十五年经验就是工程师"。
7. **拉开强度层次**：★★★ 常识（会写代码=工程师 / 有证书=工程师 / 经验多=工程师 / 能力强=值得信赖 / 判断=直觉魄力 / 聊一聊就能判断 / 铁板一块 / 分形对称化 / 粒度当职级 / 拓宽当升职）重点翻。
8. **每个纠正落到可操作动作**：讨论完给"回去做一件事"（用六项体检给团队某人打勾、用粒度尺定位一个岗位、用拓宽尺自测一次、配一个培养动作）。
9. **单一权威不另立标准**：判据引用书（判据 8：六项体检 + 粒度尺 + 拓宽尺 + 配套成长尺/终极尺/执行手段），不发明新尺子。
10. **网搜当佐证**：N1~N7 只作"这不是书里一个人的说法"佐证，药与判据全在书内；N5 尤其标注"range restriction"批评方，不把 Google 一家当铁证。

## 第 6 步 · 化尺为用：落地工具

### 作业指南（主产出）：用八把判据做一次"工程师体检"——六项打勾 + 粒度定位 + 拓宽自测，落判词 + 配培养动作

> 目标：把六项能力清单 + 粒度尺 + 拓宽尺从"背诵对象"变成"体检的尺子"——给团队里一位公认最像工程师的人做一次完整体检（六项打勾 + 粒度定位 + 拓宽自测），落一条判词（谁缺哪项、在哪条路上），再反身给自己打勾，给最缺的一项配一个培养动作（反天赋论落地）。§9.2.8 的"沟通与团队"以执行手段的方式嵌进每项体检（④⑤⑥ 靠沟通落地）。
> 场景：回部门落地。时长：一次 60 分钟；两周后复查。

1. **挑对象（先立枢纽）**：选团队里"公认最像工程师的人"——最像的，往往也最容易在某一项打不上勾。
2. **项目一 · 六项体检打勾**（每题带"沟通/团队"执行手段的落点）：①科学素养——他做的东西"凭什么能行"能讲出原理吗（靠预测对账练，不是懂公式）？②方法论素养——他的方法能被别人学会吗（写 SOP 给同事照做，看卡在哪一步）？③实践能力——他最近一次亲手落地是什么时候（强度光谱到"独立做"了吗）？④职业伦理——压力面前会为进度牺牲可靠性吗（不可越线清单/决策留痕）？⑤工程判断——规则没覆盖的地方能做对取舍吗（三步闭环：识别约束→权衡取舍→担责闭环）？⑥可复现意识——他的判断换个人能接住吗（交接演练：写交接包，写不出的地方=没想清楚的地方）？
3. **项目二 · 粒度尺定位**（判据7）：他背的账是专责（划得清的账）还是终责（甩不掉的账）？他的名片粒度 vs 实际粒度一致吗？——水忠是"模块工程师的岗位、系统工程师的活"（拓宽中），万辉是"架构师的头衔、底座缺"；你们团队谁在"名片一个粒度、实际另一个粒度"？**话术**："他的账，是划得清的还是甩不掉的？"
4. **项目三 · 拓宽尺自测**（判据8）：他是在单点最优，还是系统最优？愿不愿意为系统牺牲自己的模块？——换轨标志=第一次为系统牺牲自己的模块还觉得值；判断依据在哪个尺度（照做/会选/会取舍/守底线）？
5. **项目四 · 落判词**：对照两条基准线——水忠①③⑤顶配缺②⑥（手艺极致，模块岗位拓宽中）、万辉有②③缺①④⑥（伪工程，架构师头衔缺底座）——你的对象像哪条线？缺的是哪一项？在哪个粒度？**话术**："他不是不会做，是做的能力不可复制"（像水忠）/ "他不是不会说，是说的和做的对不上"（像万辉）。
6. **项目五 · 反身自检 + 配一个培养动作（反天赋论落地）**：用同一张清单给自己打勾——你缺的那一项，正是你在"背清单"而不是"用清单"的地方；给最缺的一项配一个可执行动作——①缺就做预测对账（改动前写预测、事后对账）；②缺就走转化链（把最近一次做对的事写成 SOP 交给同事照做）；③缺就沿强度光谱补"独立做"（从零复现一个已知功能）；⑤缺就记决策日记（约束打架/选哪个/后果/重来选什么）+ 案例裁决；⑥缺就做交接演练（写交接包）；④缺就写不可越线清单 + 决策留痕（谁知情/评审/记录）。
7. **项目六 · 落到产品数据**（终极尺）：问最后一个问题——他/你负责的那个粒度的产品数据（模块级 7 项 / 系统级 13 项 / 系统架构），换个人拿着能接着种吗？这是六项能力唯一可检验的落点。
8. **出体检报告**：六项各打勾/缺项 + 粒度定位 + 拓宽自测，落判词，最该先补最缺的一项 + 配一个培养动作；两周后复查补了什么。

**卡住怎么判断**：打不上勾的那一项就是最该补的；⑥打不上勾=手艺型（判断换个人接不住），④打不上勾=最危险（能力越强方向越偏）；粒度尺答不上"专责还是终责"=不清楚自己在谱系里的位置（先定位再体检）；价值层三问（相关方知情/评审/记录）当场打勾——"没有记录"的地方就是④可能缺席、也是①和⑥最容易现形的地方。

### 工作检查单（配套素材）

| 检查项 | 是/否 | 否 → 可讨论发现 |
|---|---|---|
| 六项能力逐项能打勾？ | □ | 打不上勾的那一项=最该补的 |

## 第 7 步 · 淬问成题：题卡（10 题 2×5）

### 第一组 · 概念与原理（5 题）

**Q1（破题 · 见树见林① · 概念本身）**
"恒信 IT 部要招一名『高级工程师』，徐漾主持面试。候选人甲是算法高手，笔试几乎满分，口答流畅得像背书——『会写代码的，不就是工程师吗？』候选人乙带着软考高级证书，职称评审的材料叠了一沓——『有职称、有证书，还不算工程师？』候选人丙干了二十年，项目数不清，可当徐漾问到『你的判断，换个人接得住吗』，他答不上来——『干了这么多年，经验还不够吗？』徐漾问了三个人同一个问题：『换个人，用同样的需求，交付的东西能和你质量相当吗？』三个人都沉默了。三句话三个『工程师』，错在哪？『工程师』到底是个什么样的物种？"
追问：① 六项能力清单——四层各一项 + 横切⑤ + 元⑥，怎么构成一个整体？每项各配一句判据（①科学素养"凭什么能行"为什么靠预测对账长出来——科学素养是"懂很多公式"吗）？这份清单不是拍脑袋列的——它对照什么凝练出来的（第2章四层结构为骨架、ABET 七条交叉验证；沟通/团队为什么没显式单列）？② "会写代码 / 有证书 / 经验多"分别把什么当成了判据（载体 / 名义 / 年资）？③ 反身：你自己判断身边谁是工程师，用的是这三样里的哪样，还是看他开发出的产品数据（换个人能不能接着种）？

**Q2（见树见林② · 概念关系）**
"请给出 工程师 和 技术员、科学家、手艺人、会写代码的人 这四种身份的关系，并说明：为什么说『写代码是载体不是判据』？六项能力里，⑤工程判断为什么是横切、⑥可复现意识为什么是元？ABET 把『沟通』与『团队』列为独立的工程师成果，六项能力清单为什么没有单列它们——它们是第七、第八项能力吗？"
追问：① 技术员和工程师的分界为什么不是学历（规则留白时谁来拍板）？② 手艺人 vs 工程师唯一分界=交付依赖不依赖具体的人——水忠为什么不在这条线的工程师那边？③ 沟通与团队为什么是④⑤⑥的执行手段（④让相关方知情 / ⑤把取舍讲清楚 / ⑥让方法被接住）——一个判断做得对、说不清楚，等于做没做？④ 反身：你们团队里"被当成工程师、其实是技术员/手艺人/会写代码的人"的例子，缺的是清单里的哪一项？

**Q3（真悖论 · 一个物种三种粒度）**
"『工程师就是工程师，一个统一的物种——模块工程师是低配、系统工程师是高配』——还是『一个物种，三种粒度，背同一副骨架，账却不是同一本』？模块工程师和系统工程师，到底谁『更高』？『系统工程师是比模块工程师更高的职级』对吗？什么判据能分清这三种粒度？"
追问：① 三种粒度各负什么责——模块负元素实现（专责 responsibility，可委托可追责）、系统负系统成败（终责 accountability，不可委托）、架构负结构演化（专责）？为什么说『终责是甩不掉的账，专责是划得清的账』？② 模块工程师为什么是系统工程师的『分形』（迷你系统工程师——模块级也跑完整闭环：模块需求→模块设计→模块实现→模块验证）？分形为什么不对称——模块为什么没有 对外架构 / 确认 / 部署 / 集成（对外边界来自上层分配，内部架构归自己 / 真实使用环境是系统级 / 部署是系统级行为 / 集成是系统级把模块装起来）？③ 系统工程师这个人怎么识别——24765 说他是『实践系统工程学科的个人，与其正式头衔无关』；四动词（转化 / 统筹 / 把关 / 守护）和 INCOSE 六件事里，为什么没有一件是『亲手写代码』？④ 反身：水忠的岗位是模块工程师，却在干系统级的事（老规矩 / 拦直连）——他的『名片粒度』和『实际粒度』一致吗？你们团队里有这样的人吗？

**Q4（真悖论 · 能力强 vs 值得信赖）**
"冰链的水忠十五年温控产品，车间里没有一份完整测试方案，但他『心里有数』——哪个批次容易出问题、哪种工况要降额、哪家供应商不可靠，全在脑子里；他①科学素养顶配、③实践能力顶配、⑤工程判断顶配，每个取舍都准。他是工程师吗？『能力越强的工程师越值得信赖』对吗？还是『能力不中性，④定义方向』？"
追问：① 水忠缺②⑥——为什么手艺的极致不是工程师的画像（做的能力不可复制；他的判断换个人就是做不出来）？② 737 MAX 不缺"会算的工程师"，缺"守住底线的工程师"——为什么能力放大的是选择的规模，方向由④定义？能力越强、④越缺，为什么越危险？③ 反身：你们团队里技术最强的那个人，④职业伦理这条打过勾吗？

**Q5（真悖论 · 照单执行 vs 规则留白）**
"『工程师就是照着流程做的人』——有人说：流程全覆盖、照单执行，最不容易出错，这才是工程师。这一章却说：那是技术员；工程师在规则没有覆盖的地方做判断。哪个对？技术员和工程师的分界到底是什么？『判断力好 = 敢拍板、有魄力』对吗？"
追问：① 判断落在人身上是工程师、判断可完全交给规则是技术员——分界为什么不是学历？② ⑤工程判断的判据是"规则没有覆盖的地方能做对的取舍吗"——"先上再说"也是判断，为什么是坏的判断（没让相关方知情、没走评审）？③ 工程判断为什么不是直觉 / 规则决策树 / 魄力（直觉只是线索、判断要有依据；约束一变规则就失效；魄力是敢拍板，判断是拍得对、拍得能负责）？方法论为什么也必须留判断空间（写过头就退化成"技术员照单执行"）？④ 反身：你最近一次"规则留白"的决策，是你自己判断负责了，还是推给了流程？你判断的依据在哪个尺度（照做/会选/会取舍/守底线）？

### 第二组 · 落地与实践（5 题）

**Q6（判据运用 · 双线判词 + 粒度语境）**
"用六项能力清单，给水忠和万辉下判词：水忠是①③⑤顶配缺②⑥（手艺的极致），万辉是有②③缺①④⑥（伪工程）。先把这两条判词逐项打勾验证，再说说：两个人都是『缺』，缺的性质有什么不同？放进三粒度谱系看，他们的粒度定位各是什么？谁更接近工程师？"
追问：① 水忠的里子（判断顶配）vs 面子（不可复制）；万辉的面子（表达——方法能说清）vs 里子（守不住底线；复现⑥也站不住）——两个人都不是完整的工程师，那"在长成"是什么意思（都在用清单量自己、补缺项）？② 粒度语境：水忠是模块工程师的岗位、做着系统工程师的活（拓宽中，专责称职、终责未接）——他缺的②⑥正是"把模块的活干成系统的活"所缺的成文能力；万辉的名片是架构师（系统架构师粒度）、缺的却是架构师最不能缺的底座①④⑥——底座缺一块，第16章的增量全是空转。这说明了什么？③ 判词（案例进展①~③）和 9.4.6（产品数据）量的是同一把尺子——水忠缺的②⑥和万辉缺的①④⑥，各自露在产品数据的哪里？④ 反身：你更接近哪条线？你的名片粒度和实际粒度一致吗？

**Q7（判据运用 · 粒度尺 + 三粒度责任矩阵）**
"用粒度尺（判据7）给你们的团队做一次粒度定位：模块工程师背的是模块级 7 项（编制），系统工程师背的是系统级 13 项（编制 + 批准模块级·兼终责），系统架构师背的是系统架构（第16章展开）。你们团队的核心成员各在哪个粒度？谁『名片一个粒度、实际另一个粒度』？谁的账是专责、谁的账是终责？系统工程师为什么是唯一横跨两层的角色？"
追问：① 为什么系统工程师是唯一横跨两层的角色——系统级 13 项几乎全是他编制、模块级 7 项全部由他"批准"（模块工程师干活、他验收）？『谁负责的东西最多、又给别人的东西签字，谁就是那个兜底的』——终责（accountability）的落点在哪里？② 粒度隔离为什么是模块化的意义——系统工程师不需要知道模块内部细节，只需要接口和验证结果；模块在自己的边界内自治、把成果交上去？③ 水忠的产品数据漏在模块级和系统级交界的地方——模块级没有成文的测试方案（缺②⑥，手艺不出纸面）、系统级的事做了也没有成文系统数据——他的产品数据『薄』在哪？换个人拿着他的东西能接着种吗（终极尺）？④ 反身：你负责的那个粒度，产品数据换个人能接着种吗？

**Q8（判据运用 · 失败四式 + 拓宽 + 成长尺）**
"失败四式——只会做不会说（手艺型）、只会说不做（PPT 工程师）、守不住底线（价值层失守）、能力失控（有能力的坏工程师）。用六项能力清单，说出每一宗死法缺的是哪一项。哪一宗最危险？为什么？『从模块到系统是升职，升不上去才走架构线』对吗？"
追问：① 手艺型死于判断不可接住（⑥缺席）——水忠为什么不是被辞退，而是死于"团队发现他的判断不能复制"？② 守不住底线（④缺席）为什么最普遍也最隐蔽（症状不是不会做，是做的时候没守住；泰坦尼克/挑战者/737 MAX 的共同点）？④为什么不是规章清单 / 风险管理 / 服从组织（规则背不完压力时刻判断要在场 / 风险管理算概率、伦理定立场 / NSPE 对公众负责不是对老板负责——挑战者号里工程师反对发射、管理者施压）？③ 拓宽 vs 升职——成长是『拓宽』（视角换轨 + 责任接管，从对"我的模块"负责切到对"整个系统"负责，优化目标从单点最优到系统最优；判断依据从"怎么做"升到"守什么"）不是『升职』（组织换位置）；这条成长线是 INCOSE《系统工程愿景 2035》列的系统工程师能力发展主线；换轨标志=第一次为系统牺牲自己的模块还觉得值；分叉不是阶梯（往系统走 vs 往管理走正交，没有高低）——为什么『升不上去才走架构线』是错的？④ 反身：你判断的依据在哪个尺度（照做/会选/会取舍/守底线）？你最近一次"为系统牺牲自己的模块"是什么时候？有没有那次"还觉得值"？

**Q9（方法时刻 · 规则 15 · 反天赋论 + 判词变体 + 转述形态）**
"万辉有『高级工程师』头衔、水忠没头衔——可这一章的方法底座时刻是反天赋论：能力可检验、可训练，不是天生的；头衔不定义人。把六项能力清单从『背诵对象』变成『判人的尺子』：先用它判万辉（缺哪几项？证据是什么？）、再判水忠、最后反身判你自己的团队——谁缺哪一项？用什么判据检验（不是头衔、不是感觉）？"
追问（判词变体）：① 你给万辉判"缺①④⑥"，证据各是什么（容量评估被砍——①不追问"凭什么能行"；没让相关方知情、没记录——④；CI/CD 靠张三的隐藏命令——⑥）？给水忠判"缺②⑥"，证据是什么（方法说不成体系——②；车间没有一份完整测试方案——⑥）？② 判词加粒度语境：水忠=模块工程师岗位拓宽中（①③⑤顶配缺②⑥），万辉=架构师头衔缺底座（有②③缺①④⑥）——同一个清单，为什么量出的是一条"手艺的极致"、一条"伪工程"？同一个清单拿到恒信↔冰链两个世界，判据变没变（跨域：概念不挑行业）？③ 反身判团队：拿掉名片和年资，用六项逐项打勾——你们团队"最像工程师的人"缺哪一项？他正在长成的是哪一项？他的粒度定位是什么（模块/系统/架构）？④ 转述形态（规则 15 新增·压缩测试）：把你对"工程师"的判断——六项能力清单——用三五句话讲给一个完全外行的人听。讲到哪卡住，缺口就在哪：卡在"⑥可复现"讲不清，还是卡在"④为什么定义方向"讲不清？——四问与转述，测的是同一件事：你答不齐的那一问，和你转述卡住的那一处，是同一个缺口。⑤ 反天赋论还意味着什么——缺的项能不能补？怎么补（①科学素养靠预测对账、②方法论走转化链/写SOP、③实践沿强度光谱从做里长、⑤判断走三步闭环+复盘、⑥靠交接演练、④写不可越线清单+决策留痕）？——能答全六项能力的四问、能用清单量别人量自己、能三五句讲给外行，才算拥有，这把尺子现在装进你手里了吗？

**Q10（落地生根 · 回部门工程师体检）**
"结合你们部门现状，用八把判据（六项体检 + 粒度尺 + 拓宽尺 + 成长尺 + 终极尺）给一位『被当成工程师的人』（或你自己）做一次工程师体检——逐项打勾，指出缺项，定位他/你的粒度（模块级 7 项？系统级 13 项终责？系统架构？），落一条判词（像水忠缺②⑥还是像万辉缺①④⑥？），用拓宽尺定一个成长方向，给出最该先补的一项，落到一个动作。"
追问：① 六项体检 + 价值层三问（相关方知情/评审/记录）先查哪两项？② 粒度尺 vs 名片——你们团队的"架构师/系统工程师/模块工程师"，背的账是专责还是终责？谁在"名片一个粒度、实际另一个粒度"（像水忠模块岗位干系统活）？系统级 13 项有人背吗？③ 你们的招聘/晋升，用的是六项判据，还是"会写代码/有证书/经验多"三个错判据？沟通与团队在你们的评估里，是独立加分项，还是④⑤⑥的执行手段（不会沟通，④⑤⑥能不能落地）？④ 两周后回来报告：谁打了勾、缺了哪项、补了哪个动作、成长方向定了哪条？
