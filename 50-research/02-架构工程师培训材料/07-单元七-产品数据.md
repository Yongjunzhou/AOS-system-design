## 一、单元导读

### 主题

这一章回答一个绕不开的问题：**开发的产品到底是什么？**水忠在 M3 二代开发会上说"二代加了边缘断链预判，硬件改了两版，固件这周能跑"，文正问"功能基线呢？验收标准定了吗？"水忠答不上来。一直没开口的产品开发经理永兵补了一句认账："第3章那张参数表，是我签的'通过'。当时我们比的是谁做得高，没问一句——它是不是 M3 真正要的东西。"他的直觉是"产品是实物、数据是文档、开发完再补"——**这一章要推翻的正是这个直觉：产品有两个存在（物理存在与信息存在），开发阶段你亲手造的是那个信息存在——产品数据；实物只是它的复制品。**开发产品就是开发产品数据：数据质量决定产品质量的上限（多环相乘）、产品数据是协作的中枢与职责的落点、产品会死而数据体系活着、数字化是上户口而转型是生利息。永兵那句认账还点破了一层：**比参数做得高 ≠ 对需求负责——签'通过'要对需求数据的内容负责，不只是对参数负责**（呼应第3章等级≠质量、第5章样机≠产品）。本章的承重柱是**产品数据**（ch1 §1.6.6 三示例之一：企业运行的根正是产品数据）——两域三态是它的存在方式、价值沉淀池给它的价值定位。

### 开场破题（对应章首误解现场）

念出 M3 二代开发会那场问答：会议室墙上贴满图纸，水忠指着固件架构图说"边缘断链预判——传感器异常时，箱体自己本地判一次，不依赖云端，这是我最得意的地方"。文正翻着本子问："功能基线呢？验收标准定了吗？拆到哪些模块？谁负责验证？"水忠愣住："需求……不是写完了吗？在共享盘那个文件夹里。"文正追问："哪个文件夹？我搜'二代'搜出三个版本，还有一个叫'M3 二代最终版'——哪个是准的？你改了什么、为什么改，有没有记录？"一直没开口的产品开发经理永兵接了一句："第3章那张参数表，是我签的'通过'。当时我们比的是谁做得高，没问一句——它是不是 M3 真正要的东西。"水忠这才意识到：产品长什么样、为什么长这样、怎么证明做对了——他一件都说不全。

管这套追溯平台的董勐在旁边补了一句："追溯数据就是产品用起来之后往回吐的那一环——箱子把温度实况吐回云端，平台收进来、存成可查的记录。它要作数，先得采集可靠：现场断一秒，追溯就缺一块，缺了块，整条链都不完整。"水忠听到这里愣了一下：连使用期的实况，也是产品数据。（正文里这句落在 §7.3.2 数字孪生段，此处并入开场渲染"使用期实况也是产品数据"）

让各组表态：水忠那句"产品是实物、数据是文档、开发完再补"冤不冤？永兵那句认账——"比的是谁做得高，没问是不是真正要的东西"——他当年在第3章签'通过'错在哪？大多数人一开始都站在他们这边——这正是这一章要推翻的直觉。

### 本单元要反转的直觉

- **产品就是实物，数据是文档，开发完再补**（× 产品有两个存在；开发全程在信息存在上工作；数据是开发工作的全部对象）
- **数据不就是文档吗**（× 数据是内容，文档是容器——同一个需求换载体还是那份）
- **质量在车间里，开发环节没有质量**（× 开发环节的质量就是数据质量；数据质量决定上限、不决定达成）
- **开发产品就是把实物做出来**（× 设计态里开发产品 ≡ 开发产品数据；开发 = 定义生成）
- **质量是检验出来的，不是设计出来的**（× 检验只能发现数据里的缺陷，缺陷早在数据里了）
- **往产品数据上加东西就是增值**（× 增值还要顾客需要（防过度加工）+ 流动效率；加顾客不要的特性 = 过度加工）
- **职责锚在流程上，比锚在产品数据上更清楚**（× 数据职责可证伪/可映射/可度量；缺数据流程空转）
- **数字化就是把数据存进系统，就算转完型了**（× 数字化是上户口（存起来）、转型是生利息（用起来驱动决策））
- **软件没有产品数据这回事**（× 软件 = 菜谱就是菜，产品数据 = 产品本身）
- **产品数据会过时，攒着没用**（× 产品会死，数据体系活着；四类数据资产跨产品跨代际复用）
- **签'通过'时比的是谁做得高，参数达标就算对了**（× 永兵认账：没问是不是 M3 真正要的东西——参数领先 ≠ 需求对；开发产品=开发产品数据，签字要对需求数据的内容负责，不只对参数负责）

### 本轮题卡的内在逻辑（10 题 2×5 + 方法时刻）

**第一组 · 概念与原理（先立概念）**：Q1 产品有几个存在、产品数据是不是文档（破题·概念本身，含永兵认账回声 + 溯源 ISO 10303/三层链）→ Q2 四词四层 + 三态 + 资产数字化链（概念关系，含溯源 as-designed/as-built/as-maintained + 数字孪生）→ Q3 开发产品 vs 制造产品（真悖论·设计态同一性）→ Q4 数据质量 vs 产品质量（真悖论·多环相乘）→ Q5 流水线上流动的是什么 + 协作/价值/职责（原理）。由"是什么"走到"为什么"。

**第二组 · 落地与实践（用尺量）**：Q6 BOM vs 图纸——实现方案是最重的一份（判据运用·案例进展①）→ Q7 设计评审三层接不住（判据运用·案例进展②，含董勐追溯断）→ Q8 恒信"上线了，数据没人管"（判据运用·案例进展③镜照，含价值三层溯源）→ **Q9 方法时刻·织关系 + 转述**（规则 15：织关系 = 方法操作类独立成题，亲手织一张产品数据概念关系图 + 三五句话讲给外行，压缩测试 + 跨域变体）→ Q10 回部门产品数据完整性体检（落地生根）。判据运用 + 落地动作。

### 同类分组说明

产品组与 IT 组答同一组题，答案互为镜像。这一章的题尤其适合镜像对照：产品组的"产品数据"是 M3 温控箱——六类数据、BOM vs 图纸、边缘断链预判的需求-设计-验证断层；IT 组的"产品数据"是合同审批系统——规则/变更/设计逻辑散在各人脑子里、上线 ≠ 数据归位、代码即产品。产品组出问题靠"批次追溯查得清"、IT 组靠"数据没人管 = 系统没人管"——**同一个概念、两个世界、判据不变**（开发产品 = 开发数据；数据齐不齐、准不准、可不可追溯），这正是本章"概念不挑行业"的现场证明（方法时刻 Q9 跨域变体当场验）。两边还会撞见同一个签字问题：永兵签"通过"比参数、产品组和 IT 组的经理签验收时比什么？——比的是不是"真正要的东西"？

## 二、题卡（打印分发）

**答题要求**：组内讨论 25 分钟 / 答案 ≤5 行 / 上台讲解 4–5 分钟 / 观点不同必须给理由。

### 第一组 · 概念与原理

**Q1｜产品到底有几个"存在"？水忠亲手造的是哪一个？**
"水忠在 M3 二代开发会上说：'二代加了边缘断链预判——传感器异常时，箱体自己在本地判一次，不依赖云端。硬件改了两版，固件这周就能跑。'文正问：'功能基线呢？验收标准定了吗？拆到哪些模块？谁负责验证？'水忠愣住了。一直没开口的产品开发经理永兵接了一句：'第3章那张参数表，是我签的"通过"。当时我们比的是谁做得高，没问一句——它是不是 M3 真正要的东西。'水忠的直觉是'产品是实物，数据是文档，开发完再补'。请回答：产品有几个'存在'？水忠开发 M3 二代这几年，亲手造的是哪一个？'数据是文档'这句话错在哪？"

追问：① 物理存在 vs 信息存在——为什么说'实物是信息存在被复制出来的结果'（同一份图纸造一万台箱子）？② 产品数据 ≠ 文档：数据是内容、文档是容器——同一个需求从 Word 搬进数据库还是那份吗？③ 溯源：产品数据这个词从哪来——ISO 10303（STEP）为什么为数据交换而定义？对象→数据→信息（ISO 9000 §3.6.1/3.8.1/3.8.2）三层链怎么叠出"产品数据"？④ 第6章那棵设计树，为什么说'那棵树就是产品数据'（枝干概要+叶子详细全落在六类数据里）？⑤ 永兵那句认账——'第3章那张参数表，是我签的"通过"，比的是谁做得高，没问一句它是不是 M3 真正要的东西'——他当年签'通过'错在哪（把参数/等级达标当'对'，没问需求内容对不对，呼应第3章等级≠质量、第5章放大生产翻车）？'开发产品就是开发产品数据'怎么让这句认账成立（签字要对需求数据的内容负责，不只对参数负责）？⑥ 你们最近一次签'通过'，签的是参数达标，还是需求内容？你们最近一个产品，开发阶段亲手造的到底是实物还是数据？

**Q2｜产品、产品数据、配置项、文档什么关系？三态什么关系？往哪去？**
"请把 产品、产品数据、配置项、文档 四个词排成关系；再给出 设计态、制造态、使用态 三态各等于什么；最后给出 产品数据 → 企业资产 → 数字化/转型 这条往哪去的链——说明为什么'产品数据 ≠ 产品本身'却'验证要求两者一致'，为什么'产品会死，数据体系活着'，为什么'数字化是上户口，转型是生利息'？"

追问：① 四词四层（产品=物 / 产品数据=物的信息 / 配置项=被纳入配置管理范围的实体 / 文档=装信息的盒子）——为什么混成"产品+文档"两个词就出问题？② 两域三态：设计态为什么特殊（产品=纯数据）？溯源——三态的名字 as-designed / as-built / as-maintained 从哪来（PLM/STEP 数据管理实践：设计→制造→维护三个生命周期阶段各以什么形态存在）？数字孪生为什么是信息域对物理域的实时映射（数据跟上现实才管用，否则只是仓库）？③ 顺着树往下长：实现方案=设计数据+制造数据=八方案——为什么它是产品数据里最重的一份（制造完全照着它复制，错一处一万处错）？④ 往哪去：为什么产品数据是唯一四性兼备的资产（可积累/可复用/可转移/可评价）？需求/设计架构/验证/管理四类资产为什么跨产品跨代际复用？⑤ 你平时说的"产品"，到底指四词里的哪一个？

**Q3｜开发产品，到底是"做实物"还是"造数据"？**
"水忠不服：'我干了几十年硬件，产品当然是我做出来的——图纸、固件、样机、量产，哪个不是我造的东西？'文正说：'你造的其实只有数据，样机只是数据完备性的一个旁证。'两个说法都对？什么判据分清'开发产品'和'制造产品'，什么范围里'开发产品=开发产品数据'成立？"

追问：① 设计态同一性：为什么说'在设计态，开发产品 ≡ 开发产品数据，无歧义'（设计态里没有实物，产品=纯数据）？② 两个边界——这句话为什么只在设计态、对纯信息产品严格成立？为什么不等于'产品就是数据'（产品还有实物/体验/价值实现）？③ 菜谱与菜：软件为什么'菜谱就是菜'（没有独立制造环节、开发=生产）？对软件的配置管理意味着什么（更容易改着改着忘了改了什么）？④ 实操意义：既然开发=定义生成，水忠团队考核该看'样机出来没'还是'数据齐不齐、准不准、可不可追溯'？⑤ 你们上次被夸'样机出来了'，其实是哪层数据没齐？

**Q4｜数据质量能决定产品质量吗？决定到什么程度？**
"水忠说：'质量在车间里——箱子好不好，得看装出来、用起来。'文正说：'开发环节的质量，就是数据质量。'车间和开发，哪个说了算？数据质量到底能决定产品质量吗？决定到什么程度？"

追问：① 多环相乘：最终质量 = 需求正确性 × 数据质量 × 制造质量 × 使用质量——为什么是乘法不是加法（短板效应，任何一环为零全盘皆输）？② 为什么说'数据质量决定产品质量的上限，不决定达成值'——为什么'需求方向错了（验证全绿、确认全红）数据再好也没用'？③ ISO/IEC 25012 五尺（准确性/完整性/一致性/时效性/可信度）——案例进展① BOM vs 图纸对不上，是哪两尺（准确性与一致性）没量住？④ 缺陷传播链：为什么'越往下游修越贵（早期修 1、使用期修 30~70 倍）'是乘法模型的必然？⑤ 增值判据：往产品数据上加东西（额外特性）就是增值吗——为什么'贡献了数据≠有价值，还得顾客需要'？⑥ 你们上次质量事故，哪一环是零？最差的一尺是哪一尺？

**Q5｜开发流水线上流动的，是什么？**
"水忠在制造流水线上干了一辈子。文正说：你的开发流水线上，流动的从来不是实物，是产品数据——需求数据流进设计、设计数据流进验证、验证证据流进基线。顺着流水线往下看：产品数据是协作的中枢（谁围着它读写）、价值的锚（它装得下全部价值吗）、职责的落点（为什么锚在数据上而不是流程上）。制造流水线和开发流水线的三个本质区别是什么？为什么'开发缺陷沿流动传播并放大'是最要命的一条？"

追问：① 流水线三要素：工件=产品数据、工位=需求定义（转译）/设计（物化）/实现（实例化）/验证（取证）/移交（冻结）、增值=每个工位往数据上添加价值或缺陷？② 制造 vs 开发三区别：工件性质（实物复制 vs 信息原创）、加工方式（确定性复制 vs 创造性转换）、缺陷行为（单件 vs 沿流动传播放大）？这个'流水线视角'和常说的'瀑布流程'是一回事吗（瀑布=流程组织方式·阶段串行；流水线=数据流动视角·工件沿工位增值——不管跑瀑布还是敏捷，数据都沿工位流动）？③ 协作中枢：内部相关方围绕什么协作（同一份产品数据读写，不是目标不是计划）；用户/客户为什么是源与宿（需要/使用/反馈/验收四条路径——出题判卷都是他们）？④ 价值三层：物化层完全在数据里、决策层部分沉淀（ADR）、过程层只留评审记录——为什么说'数据是投影与锚，不是本体'（完美工件可能是错误决策的产物）？顺着这个定位，角色价值=工件质量×判断质量×下游影响（乘数）——为什么架构师的好决策让下游一百个工程师少走弯路，价值体现在别人的工件质量上？⑤ 职责锚定：为什么'缺了流程数据职责还在（降级可运行）、缺了数据流程空转（数据无人负责）'？⑥ 你们开发流水线上，哪一站断过？协作是围着开会转还是围着数据转？

### 第二组 · 落地与实践

**Q6｜BOM 和图纸对不上——实现方案到底算什么？**
"M3 二代的实现方案出来两周，制造逸人拿着 BOM 和装配图来找水忠：'BOM 里压缩机写的是 A 型号，装配图上画的是 B 型号——底座孔位都不一样。我按图纸备了料，车间一装就装不上。'水忠翻半天：'图纸是设计那边出的，BOM 是工艺那边配的，两边各干各的。'文正说：'实现方案不是一份，是八份拼起来的整体。'请用产品数据判据拆解：实现方案是什么？为什么它是最重的一份？BOM 和图纸对不上，是什么数据质量问题？"

追问：① 实现方案 = 设计数据 + 制造数据 = 八方案（技术/物料采购/制造/测试/交付/部署/操作/运维）——它和六类数据什么关系（八方案的产出归质量/服务数据，两把尺子按"方案 vs 数据"分开）？② 为什么'错一处，一万台箱子错一万处'（制造完全照着它复制）？'方案齐备 = 可实现 = 设计开发终点'（第3章）怎么接上？③ 用数据质量五尺裁决 BOM vs 图纸：哪两尺没量住（准确性=数据反映真实对象、一致性=数据内部不矛盾）？④ 为什么实现方案散在好几份各干各的文档里就会对不上（数据不是文档，是关联成整体的一套）？⑤ 你们产品的'实现方案'，是不是也散在好几份各管各的文档里？

**Q7｜需求、设计、验证三层接不住，产品为什么就断？**
"开完会一周，冰链第一次 M3 二代设计评审。文正铺开六类数据一件件过：'边缘断链预判的验收标准定了吗？'水忠翻出文档：'定了，传感器异常时箱体本地判定并报警，30 秒内完成。''拆到哪几个模块了？接口契约呢？'水忠愣住：'以前都是直接干，没写过这个。'李旭接话：'那验证就做不了——验收标准在需求数据里，接口契约在设计数据里，两层对不上，我不知道是固件负责还是传感器负责，也不知道哪个接口给我触发信号。'董勐也接：'我这边一样断——接口契约没定，我不知道存哪个字段、由谁触发，这条追溯记录就写不全。'为什么'需求数据、设计数据、验证数据'三层一层断、产品就断？李旭的测试用例为什么'没法定'？"

追问：① 六类数据各自的'从哪来、到哪去'——需求数据流进设计、设计数据流进验证、验证证据流回需求与设计——为什么这是接力不是单向？② 数据质量五尺哪一尺管'接口契约缺失'（完整性=覆盖无遗漏）？③ 水忠说'我明白了，不是补文档，是把每一层的定义造全、造准，让下一层接得住'——这句话怎么翻译成判据（数据完备到'可制造、可验证'=开发才算完成）？④ 设计态同一性：这次评审是在哪个态发生、验的什么（设计态，验的是数据齐不齐）？⑤ 你们最近一次验证做不了，卡在两层数据没接上？

**Q8｜恒信"上线了，但数据没人管"——丢的是哪几层？**
"恒信合同审批系统上线半年，徐漾问万辉三个问题：'25 号之后签的合同算哪个月——这条规则，现在在系统里，还是在谁的脑子里？上线后改过四次审批流，每一次谁改的、为什么改，有没有记录？下个月玉杰调走了，这套系统的设计逻辑，他从哪交接给新人？'万辉答不上来。徐漾说：'系统的产品数据——规则、变更、设计逻辑——散在各人脑子里，等于系统没人管，只是跑起来骗过了所有人。'请用价值三层（物化/决策/过程）回答：恒信丢的是哪几层？'数据没人管'为什么等于'系统没人管'？"

### Q1 产品到底有几个"存在"？水忠亲手造的是哪一个？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "水忠说得对，产品就是实物，数据不就是文档吗？开发完补一补就行。永兵签'通过'没错，参数达标就是合格。" | 正是要翻的——把"开发"当"造实物"、把"数据"当"事后文档"、把"参数达标"当"需求内容对" |
| 中 | 能说"产品有两个存在"，但"开发造的是信息存在"没落到六类数据/判据/溯源；永兵认账只当闲话没接住 | 词背了，判据（两存在判据 + 数据≠载体判据）与溯源（ISO 10303/三层链）没用起来；永兵"比参数不问需求"的认账没翻到"签字要对需求数据内容负责" |
| 好 | "产品有两个存在（物理/信息）；开发全程在信息存在上工作、实物是复制品；数据是内容、文档是容器——同一份需求换载体还是那份；溯源：ISO 10303（STEP）为数据交换而定义、对象→数据→信息三层链叠出产品数据；第6章那棵树（枝干概要+叶子详细）就是产品数据的结构；永兵认账点破'比参数做得高≠对需求负责'——签'通过'要对需求数据的内容负责，不只对参数负责（呼应第3章等级≠质量、第5章样机≠产品）；'把产品做出来'=把产品数据造全、造准、造到可制造可验证。" | 两存在 + 数据≠载体 + 溯源 + 树=产品数据结构 + 永兵认账 + 开发终点全咬合 |

**产品侧 vs IT侧**：产品组答"M3 的六类数据——需求/图纸/固件/测试/工艺，没有一样是实物，实物是制造照数据复制的"；IT 组答"合同系统的规则/变更/设计逻辑——代码即数据、跑起来≠数据归位"。两边都容易把"文档"当"数据"——**数据是内容，文档是容器**；都答不出产品数据"从哪来"（ISO 10303 为数据交换而定义）；都容易像永兵一样"比谁做得高不问是不是真正要的东西"——产品组比温度精度谁做得好、IT 组比查询响应谁更快，都不问需求内容对不对。

**反转话术**（对应章首 + 7.2.1/7.2.3/7.2.4 + 7.2.5）：水忠那句"产品是实物、数据是文档"错在两处——第一，产品有两个存在：物理存在（摸得到用得了、会老化报废）和信息存在（描述"是什么/为什么/怎么做/怎么证明对"的全部数据、可复制可传递可留存）。开发全程没有一件实物可摸：你写需求、画图纸、编源码、跑测试，全部是在**数据**上工作，实物只是数据被"复制"出来的结果。第二，数据不是文档——**文档是容器、数据是内容**：同一个需求从 Word 搬进数据库还是那份，文档只是产品数据最常用的载体。再答"从哪来"：产品数据这个词来自 ISO 10303（STEP）——工程界要跨系统交换产品数据，必须先定义"产品数据"是什么，标准为数据交换而生；对象（那台 M3 或它的图纸，ISO 9000 §3.6.1）→数据（关于对象的事实"制冷 -20℃"，§3.8.1）→信息（有意义的数据，§3.8.2）三层一叠，"产品数据"就精确了。第6章那棵树（枝干概要+叶子详细）就是产品数据的结构。最后接住永兵那句认账：他当年在第3章签'通过'，签的是那张**参数表**，比的是'谁做得高'（等级），没问一句'它是不是 M3 真正要的东西'（需求内容）——第5章'放大生产'也是他签的字。这不是他一个人的错，是'开发=造实物、数据=文档'这套直觉的必然：你盯着实物和参数，就看不见'需求内容对不对'也是要造的数据。**开发产品就是开发产品数据，每一道签字都要对需求数据的内容负责，不只是对参数负责**（呼应第3章等级≠质量、第5章样机≠产品）。所以水忠那句"把产品做出来"，正确翻译是"把产品数据造全、造准、造到可制造可验证"。

**参考答案要点**：两存在见 §7.2.1；产品数据定义与三层链见 §7.2.3 / 本章判据1·2·3；数据≠文档见 §7.2.4；树=产品数据结构见 §7.2.5；四词四层见 §7.2.4；永兵认账见章首 + §7.3.3（开发=定义生成）/ 本章判据5。

### Q2 产品、产品数据、配置项、文档什么关系？三态什么关系？往哪去？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "产品、产品数据、配置项、文档是一个东西的几种叫法。" | 正是要翻的——四层关系没立起来 |
| 中 | 能说"四词四层"，但三态 / 资产四性 / 数字化转型链没接上，三态溯源没答 | 概念族对了，往哪去的链缺（资产/数字化没接上）+ 溯源缺 |
| 好 | "产品=物、产品数据=物的信息（全部）、配置项=被纳入配置管理范围的实体（受控）、文档=装信息的盒子；三态=纯数据/数据+实物/实物+实况，是同一产品的三种存在方式不是三个产品；溯源：三态名字来自 PLM/STEP 数据管理实践——设计→制造→维护三个阶段各以什么形态存在、数字孪生=信息域对物理域的实时映射；产品数据唯一四性兼备、产品会死数据体系活着；数字化=上户口、转型=生利息。" | 四词四层 + 三态 + 溯源 + 资产数字化链全到位 |

**产品侧 vs IT侧**：产品组答"M3 是产品、六类数据是产品数据、被基线化的固件是配置项、BOM 表是文档"；IT 组答"合同系统是产品、规则/变更/设计逻辑是产品数据、被变更控制的审批流是配置项、需求文档是文档"。两边都要注意**四词四层，别混成'产品+文档'两个词**（第13章配置管理会用上这套区分）；都要补三态溯源（as-designed/as-built/as-maintained 是 PLM 通行术语，不是发明）。

**反转话术**（对应 7.2.4/7.2.3/7.3.2/7.4.5/7.4.6）：水忠以前把四个词混成"产品+文档"两个词——产品是"物"、产品数据是"物的信息"（全部）、配置项是"被纳入配置管理范围的实体"（受控的那部分，被基线化/变更控制的才算，草稿不是）、文档是"装信息的盒子"（一个容器可装多份数据）。三态是同一产品的三种存在方式不是三个产品：设计态=纯数据（还没有实物）、制造态=数据+实物、使用态=实物+实况。**三态的名字从哪来？** PLM/STEP 的数据管理实践——as-designed（设计）、as-built（制造）、as-maintained（维护）正是产品生命周期的三个阶段，各以不同形态存在；两域之间靠**数字孪生**连着——信息域的模型实时跟上物理域的实况（数据质量特性之一"时效性"），只有使用数据回流、设计数据实时更新才真正"孪生"，否则只是一个存数据的仓库。往哪去：产品数据唯一四性兼备（可积累/可复用/可转移/可评价），所以"产品会死，数据体系活着"——真正的资产是跨产品跨代际复用的四类数据资产（需求/设计架构/验证/管理）；数字化=给资产上户口（存起来）、转型=让资产生利息（用起来驱动决策）——"买平台"≠"做转型"。

**参考答案要点**：四词四层见 §7.2.4 / 本章判据3；两域三态 + 数字孪生见 §7.3.2 / 本章判据4；实现方案八方案见 §7.2.6 / 本章判据11；资产四性与数字化转型见 §7.4.5/§7.4.6 / 本章判据10·14。

### Q3 开发产品，到底是"做实物"还是"造数据"？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "水忠说得对，产品当然是他做出来的实物。" | 正是要翻的——把开发当造实物 |
| 中 | 能说"开发=定义生成"，但两个边界没划清 | 设计态同一性只答了一半，边界没给 |
| 好 | "设计态里开发产品≡开发产品数据（设计态没有实物，产品=纯数据）；两个边界——只对设计态/纯信息产品无歧义成立、'产品就是数据'不成立；开发=定义生成、制造=复制实物；软件=菜谱就是菜；考核看数据齐不齐不是样机出来没。" | 设计态同一性 + 两个边界 + 菜谱与菜 + 实操意义全到位 |

**产品侧 vs IT侧**：产品组答"水忠花两年定义 M3 二代、车间两周造第一批——定义和复制差两个数量级"；IT 组答"软件没有独立制造环节，写菜谱=做菜、开发=生产"。两边都要翻"产品是我做出来的"——**制造环节造实物，开发环节造数据，一个判据划清各自成立的范围**。

**反转话术**（对应 7.3.1/7.3.3/7.3.4）：水忠没错，但只对了一半——制造环节确实造实物，可开发环节没有实物可摸。设计态里产品没有物理实体，它的全部存在就是那组受控产品数据——所以"在设计态，开发产品 ≡ 开发产品数据，无歧义"。两个边界必须划清：**第一，只在设计态、对纯信息产品严格成立**（制造态有实物环节、物理域一切数据管不着）；**第二，"开发产品=开发产品数据"不等于"产品就是数据"**（产品还有实物、体验、价值实现——数据是产品的信息形态，不是产品本身）。严格说：**开发=定义生成，制造=复制实物**。这里还要防一个同名混用（§7.3.3 术语注）：本章的"同一性"是**设计态同一性**（开发这个动作和生成定义是同一件事），和第10章的**同一性目的论**（系统是谁由目的构成、演化中仍是它自己）是同一个词的两个概念——别混，前者讲开发、后者讲系统是谁。软件=菜谱就是菜——没有独立制造环节、写菜谱=做菜、开发=生产，所以软件迭代按天算、硬件按版本爬坡；但软件也更容易"改着改着忘了改了什么"，配置管理反而更重要。实操意义：既然开发=定义生成，水忠团队考核该看"数据齐不齐、准不准、可不可追溯"，不是"样机出来没"——样机只是数据完备性的一个旁证。

**参考答案要点**：开发三特征见 §7.3.1；设计态同一性见 §7.3.3（含同一性目的论同名辨析术语注）/ 本章判据5；菜谱与菜见 §7.3.4。

### Q4 数据质量能决定产品质量吗？决定到什么程度？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "水忠说得对，质量当然在车间里，数据只是记录。" | 正是要翻的——把"管不到达成"当"管不到上限" |
| 中 | 能说"数据质量决定上限"，但多环相乘、五尺、缺陷链没接上 | 结论对，机制缺 |
| 好 | "最终质量=需求正确性×数据质量×制造质量×使用质量（乘法=短板效应）；数据质量决定上限不决定达成；五尺里 BOM vs 图纸=准确性与一致性；缺陷传播链越下游越贵（早期1使用期30~70倍）；增值还要顾客需要，加顾客不要的特性=过度加工。" | 多环相乘 + 上限不决定达成 + 五尺 + 缺陷链 + 增值判据全到位 |

**产品侧 vs IT侧**：产品组答"需求说制冷-20℃、数据没写全，做出来就错；BOM vs 图纸=一致性问题"；IT 组答"查询响应时间指标、规则/逻辑散在脑子里——系统跑起来不等于质量好"。两边都要翻"质量在车间里"——**开发环节的质量就是数据质量；质量是设计出来的，不是检验出来的**。

**反转话术**（对应 7.3.5 + 案例进展① + 7.4.4）："质量在车间里"对一半——实物环节（制造偏差、材料批次、工艺水平）确实不在数据里；但对开发环节不成立——设计态里没有实物，你能拿什么评判"产品好不好"？只能拿产品数据：需求全不全、设计对不对、验证有没有证据。多环相乘：**最终质量=需求正确性×数据质量×制造质量×使用质量**——每环是乘法，任何一环为零全盘皆输；所以数据质量**决定上限、不决定达成值**——需求方向错了（验证全绿、确认全红），数据再好也没用。数据质量怎么量？ISO/IEC 25012 五尺（准确/完整/一致/时效/可信）全是拿数据当对象；案例进展① BOM 里 A 型号、装配图 B 型号——**准确性与一致性**没量住。缺陷传播链：需求错→设计错→制造错→使用错，越下游修越贵（早期修 1、使用期修 30~70 倍）——这是乘法模型的必然。补一句增值判据：往数据上加东西≠增值——还得顾客需要，加顾客不要的特性=过度加工（浪费）。

**参考答案要点**：多环相乘与上限见 §7.3.5 / 本章判据6；五尺见 §7.3.5 / 本章判据6·7；缺陷传播链见 §7.3.5 / 本章判据12；增值判据见 §7.4.4 / 本章判据13。

### Q5 开发流水线上流动的，是什么？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "开发流水线上流动的当然是实物零件。" | 正是要翻的——用制造流水线套开发流水线 |
| 中 | 能说流水线三要素，但协作/价值/职责没接上 | 三要素对了，往哪去的三样（中枢/锚/落点）没接上 |
| 好 | "工件=产品数据、工位=需求/设计/实现/验证/移交、增值=加价值或加缺陷；三区别=工件性质（实物复制vs信息原创）、加工方式（确定性复制vs创造性转换）、缺陷行为（单件vs沿流动放大）；协作中枢=同一份数据读写、用户/客户是源与宿（出题判卷都是他们）；价值三层=数据是投影与锚不是本体；职责锚定=缺流程数据职责还在、缺数据流程空转。" | 三要素 + 三区别 + 协作/价值/职责全到位 |

**产品侧 vs IT侧**：产品组答"需求数据流进设计、设计数据流进验证、验证证据流进基线"；IT 组答"规则/变更/设计逻辑沿开发链流动、上线只是把数据从开发部交出去"。两边都要点破——**流动的从来不是实物，是产品数据；缺陷沿流动传播并放大**。

**反转话术**（对应 7.3.6 + 7.4.1/7.4.2/7.4.3）：水忠一眼懂制造流水线（工件是钢铁零件、工位是机床、增值是越来越接近成品），但从没意识到开发流水线上流动的是产品数据——需求数据流进设计、设计数据流进验证、验证证据流进基线，一路变成受控配置。三个本质区别：**工件性质**（制造是实物=复制，开发是信息=原创，信息可复制一万次不磨损）；**加工方式**（制造是确定性复制照图纸做，开发是创造性转换把需求译成设计，每个工位有判断有取舍）；**缺陷行为**（制造缺陷在单件、可挑出来扔掉；开发缺陷沿流动传播并放大——需求里的一个错误流进设计/实现/验证，越下游修越贵）。还要划一条边：这个"流水线"不等于常说的"瀑布流程"——**瀑布是流程组织方式（阶段串行），流水线是数据流动视角（工件沿工位增值）**；不管跑瀑布还是敏捷，产品数据都沿工位流动——看的是"数据在不在流动、有没有增值"，不是"流程怎么排"。顺着流水线往下看：产品数据是**协作中枢**（内部相关方围绕同一份数据读写，会议是数据对齐的形式；用户/客户是源与宿——需要/使用/反馈/验收四条路径，出题判卷都是他们）、**价值锚**（物化层全在/决策层部分沉淀/过程层只留记录——数据是投影与锚不是本体，价值本体是判断与协作）、**职责落点**（缺流程数据职责还在=降级可运行、缺数据流程空转——锚点在工件不在活动；三角色分工件：架构师管"长得对"（形状）、系统工程师管"要得对"（语义）、模块工程师管"做得对"（细节），模块工程师在其模块内还兼模块架构师）。

**参考答案要点**：流水线见 §7.3.6 / 本章判据12；协作中枢与源宿见 §7.4.1 / 本章判据7；价值三层见 §7.4.2 / 本章判据8；职责锚定见 §7.4.3 / 本章判据9。

### Q6 BOM 和图纸对不上——实现方案到底算什么？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "实现方案就是一张图纸，图纸画对就行。" | 正是要翻的——把八方案缩成一层 |
| 中 | 能说"实现方案是八方案"，但"为什么最重/什么质量问题"没接上 | 名字对了，判据（五尺/最重）没摆 |
| 好 | "实现方案=设计数据+制造数据=八方案（技术/物料采购/制造/测试/交付/部署/操作/运维），图纸只是其中一层；制造完全照它复制，错一处一万处错；方案齐备=可实现=设计开发终点；用五尺裁决 BOM vs 图纸=准确性与一致性没量住；数据不是文档，是关联成整体的一套。" | 八方案 + 最重 + 五尺裁决 + 关联成整体全到位 |

**产品侧 vs IT侧**：产品组答"BOM/图纸/工艺/固件/测试都是实现方案，任何一层对不上制造就照着错"；IT 组答"部署包/配置/数据库脚本/接口文档都是实现方案，任何一层对不上上线就照着错"。两边都是同一把尺子——**实现方案是产品数据里最重的一份，方案齐备=可实现**。

**反转话术**（对应 7.2.6 + 案例进展① + 7.3.5）：水忠以为"图纸"就是实现方案——其实实现方案是一整套产品数据（技术/物料采购/制造/测试/交付/部署/操作/运维八方案），图纸只是其中一层。BOM 错、工艺错、固件错，跟图纸错一样致命，因为制造全照着它来——**错一处，一万台箱子错一万处**。为什么散在好几份文档里就会对不上？因为**数据不是文档，是关联成整体的一套**——同一个 M3 的实现方案，任何一层对不上，制造就照着错。用数据质量五尺裁决：BOM 里 A 型号、装配图 B 型号——**准确性**（数据反映真实对象）没量住、**一致性**（数据内部不矛盾）没量住。第3章说过"设计开发止于可实现"——这一章补一句：**方案齐备=可实现=设计开发终点**。逸人那句"两边各干各的"，正是实现方案散成八份没人织成一张网的结果。

**参考答案要点**：实现方案八方案见 §7.2.6 / 本章判据11；案例进展①见 §7.2.6 后；五尺见 §7.3.5 / 本章判据6。

### Q7 需求、设计、验证三层接不住，产品为什么就断？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "验收标准定了不就行了，接口契约是小事。" | 正是要翻的——把"验收标准定了"当"数据造全了" |
| 中 | 能说"三层要接住"，但判据（完整性/设计态同一性）没接上 | 结论对，判据没摆 |
| 好 | "需求数据接住客户需要、设计数据接住需求数据、验证数据接住设计数据——任何一层断产品就断；接口契约缺失=五尺的完整性没量住；李旭没法定=测试的触发源没定、董勐写不全=追溯字段没定，两层数据对不上；数据完备到'可制造、可验证'=开发才算完成（设计态同一性）；这次评审在设计态发生、验的是数据齐不齐不是样机。" | 六类接力 + 完整性 + 设计态同一性 + 评审验什么全到位 |

**产品侧 vs IT侧**：产品组答"验收标准在需求数据、接口契约在设计数据、测试用例要两个都拿到才能写"；IT 组答"审批规则在需求、数据结构在设计、验收用例要两层对齐"。两边都要翻"验收标准定了就行"——**三层数据是接力，任何一层断，下一层就没法接**。

**反转话术**（对应 7.2.3 + 案例进展② + 7.3.3/7.3.5）：水忠第一次看到"他做了一辈子的事原来是一层一层的数据接力"——需求数据接住客户需要、设计数据接住需求数据、验证数据接住设计数据。李旭"没法定"不是测试不行，是**验收标准（需求数据）和接口契约（设计数据）两层对不上**——五尺里的**完整性**（覆盖无遗漏）没量住：接口契约缺失，测试不知道哪个接口给触发信号。董勐的追溯平台也一样断——"告警回传云端落记录，接口契约没定，我不知道存哪个字段、由谁触发，这条追溯记录就写不全。"文正那句"这就像一条流水线——每一站都往数据上加价值，也可能加缺陷"，正是判据12：**开发流水线上流动的是产品数据，需求断在设计与验证之间，产品就在那一站断**。水忠说的"不是补文档，是把每一层的定义造全、造准，让下一层接得住"，翻译成判据就是设计态同一性：**数据完备到"可制造、可验证"，开发才算完成**。这次评审发生在设计态——验的是数据齐不齐，不是样机出没出来。

**参考答案要点**：六类数据接力见 §7.2.3；案例进展②见 §7.3.6 后；设计态同一性见 §7.3.3 / 本章判据5；完整性见 §7.3.5 / 本章判据6。

### Q8 恒信"上线了，但数据没人管"——丢的是哪几层？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "系统上线了、UAT 也过了，就是成功了。" | 正是要翻的——把"上线"当"数据归位" |
| 中 | 能说"规则/变更/设计逻辑散在各人脑子里"，但价值三层/职责没接上 | 现象看到了，层没拆开 |
| 好 | "价值三层：规则散在脑子里=物化层没归位、'谁改的为什么改'=决策层只部分沉淀（要 ADR）、设计逻辑交接=过程层只留结果；溯源：隐性知识写不进数据（Polanyi：我们知道的多于我们能说出的）；数据是投影与锚不是本体；缺数据流程空转——徐漾三问对应落地三步法（识别工件→指定 owner→挂机制）；软件=菜谱就是菜、产品数据=产品本身，所以更容易改了忘改了什么，配置管理更重要。" | 价值三层 + 溯源 + 投影与锚 + 职责锚定 + 软件产品数据全到位 |

**产品侧 vs IT侧**：产品组答"M3 的六类数据没人管=追溯/验证/交接全断"；IT 组答"合同系统的规则/变更/设计逻辑没人管=系统没人管，跑起来骗过所有人"。两边都要点破——**产品数据的完整性，才是产品站不站得住的根本**。

**反转话术**（对应 7.4.1/7.4.2/7.4.3 + 案例进展③）：万辉把"上线"当终点——可系统的数据（规则、变更、设计逻辑）散在各人脑子里，等于系统没人管，只是"跑起来"骗过了所有人。用价值三层拆开：**规则散在脑子里=物化层没归位**（需求/架构/实现工件没进数据）；**"谁改的、为什么改"=决策层只部分沉淀**（判断本身不在数据里，要 ADR 才留一半）；**设计逻辑交接=过程层只留结果**（谁说服了谁、谁推着方向走根本没落成数据）。为什么只沉淀一小半？因为**隐性知识写不进数据**——Polanyi："我们知道的多于我们能说出的"，决策层/过程层的价值能沉淀进数据的只有一小半。所以"数据是投影与锚，不是本体"——完美工件可能是错误决策的产物（验证全绿、确认全红）。职责锚定：**缺了流程，数据职责还在（降级可运行）；缺了数据，流程职责空转（数据无人负责）**——徐漾三问对应的正是落地三步法：识别工件（规则/变更/设计逻辑是配置项）→指定 owner（一件只一人）→挂机制（记录/审批/交接）。恒信"软件的产品数据就是产品本身"——结合菜谱与菜：软件没有独立制造环节，改菜谱=改产品，所以软件更容易"改着改着忘了改了什么"，**配置管理反而更依赖数据严谨**。

**参考答案要点**：协作中枢与源宿见 §7.4.1 / 本章判据7；价值三层 + Polanyi 见 §7.4.2 / 本章判据8；职责锚定见 §7.4.3 / 本章判据9；案例进展③见 §7.4.3 后；菜谱与菜见 §7.3.4。

| 弱 | 背书上的定义："产品数据是产品的信息存在。" | 只答了"是什么"，没做"织图+标对立承接+转述"这个动作——方法没上手 |
| 中 | 织出了图但没标对立/承接，转述讲到一半卡住但没追问缺口 | 织了，但"各就其位"（对立/承接/枢纽）和"压缩测试"没到位 |
| 好 | "亲手织出六词关系图：产品=物（两个存在）、产品数据=物的信息（枢纽——被反复调用、自己前置少）、两域三态=产品的存在方式（设计态=纯数据）、数据质量=产品数据↔产品质量之间的尺（决定上限）、企业资产=产品数据的往哪去（四性兼备、产品会死数据体系活着）；标出至少三处对立+两处承接；用三五句话把'开发产品就是开发产品数据'讲给外行，卡壳处正好是图上没织牢的那条边——织关系建结构、转述测结构，同一个缺口；跨域变体：恒信软件世界换到冰链硬件世界，判据没变——数据齐不齐准不准可不可追溯，不挑行业。" | 织图 + 对立承接 + 枢纽 + 转述压缩测试 + 跨域判据全到位 |

**产品侧 vs IT侧**：产品组织"M3 六类数据 ↔ 设计态=纯数据 ↔ 十年冷链数据体系"；IT 组织"规则/变更/设计逻辑 ↔ 设计态=源码/配置/文档 ↔ 合同系统知识资产"。两边织出的网结构相同、转述讲的话同判据——**这正是本章方法时刻的核心：织关系让概念各就其位；转述测出结构成没成型；概念不挑行业，判据不变**。

**反转话术**（对应方法底座时刻 = 织关系；规则 15）：这是本单元的**方法时刻**——前面八题在讲"产品数据是什么"，这一题让亲手做一遍方法底座时刻：**织关系**。水忠原来把需求、图纸、报告当一堆散件（堆），这一章把它们织成树、织成链（结构）——数据不是文档堆，是产品唯一的信息形态。织图要点：产品=物（两个存在）、**产品数据=物的信息（枢纽——被反复调用、自己前置少）**、两域三态=产品的存在方式（设计态=纯数据）、数据质量=产品数据↔产品质量之间的尺（决定上限不决定达成）、企业资产=产品数据的往哪去（四性兼备、产品会死数据体系活着）。对立至少三处：产品数据 ↔ 产品本身（描述与被描述者）、数据质量 ↔ 产品质量达成值（上限 vs 达成）、数字化 ↔ 转型（上户口 vs 生利息）；承接至少两处：产品数据 ← 用户/客户（源与宿）、产品数据 → 企业资产（往哪去）。**织完再做第二件事——转述（压缩测试，v2.1 规则 15 新增形态）**：用三五句话把"开发产品就是开发产品数据"讲给一个完全外行的人——讲到哪卡住，缺口就在哪；织的网建的是结构，转述测的就是结构成没成型，讲不清=织的网有洞、卡壳处=边界缺口。**你答不齐的那一问，和你转述卡住的那一处，是同一个缺口**。跨域变体：冰链六类数据（硬件世界）换到恒信（软件世界，规则/变更/设计逻辑），同一个概念"开发产品=开发产品数据、产品会死数据体系活着"——**判据变没变？没变——判据是"数据齐不齐、准不准、可不可追溯"，不挑行业**。反身：这几个词你们是"见过"还是"拥有"（能答全四问——是什么/不是什么/从哪来/往哪去）？——用这张网验，答不齐的那一问就是最薄处。

**参考答案要点**：方法底座时刻（织关系）见 00-案例设定 §三 第7章行 + §7.4.7/章末认知反转；转述=压缩测试见第1章 §1.4.3；概念关系见 §7.2.4（四词四层）/§7.3.2（两域三态）/§7.4.5（资产四性）/§7.4.6（数字化转型）；规则 15 注：织关系=方法操作类，方法时刻题独立成题、不与判据运用题合并；转述（压缩测试）=v2.1 新增形态。

### 金句（书"本章判据"提炼）

- **产品有两个存在：物理存在（实物）与信息存在（产品数据）——开发阶段你亲手造的是信息存在，实物是它的复制品。**
- **产品数据 = 关于产品的信息表示（ISO 10303-1）**——六类数据（需求/设计/制造/质量/服务/管理）覆盖产品全程，每一条开发输出都是产品数据。
- **产品数据 ≠ 文档**（数据是内容，文档是容器）；**≠ 配置项**（受控的才是）；**≠ 产品**（描述与被描述者，验证要求两者一致）。
- **两域三态**：设计态（纯数据）/制造态（数据+实物）/使用态（实物+实况）——开发工作全部发生在设计态。
- **设计态里开发产品 ≡ 开发产品数据**；严格说"开发 = 定义生成"；只在设计态、对纯信息产品无歧义成立，"产品就是数据"不成立。
- **数据质量决定产品质量的上限，不决定达成**：最终质量 = 需求正确性 × 数据质量 × 制造质量 × 使用质量（乘法 = 短板效应）。
- **用户/客户是产品数据的源与宿**：需要（源头）、使用（新数据）、反馈（修正）、验收（把关）四条路径——出题和判卷都是他们。
- **产品数据是价值的投影与锚，不是本体**：物化层完全在数据里，决策层/过程层只部分沉淀；价值本体是判断与协作。
- **职责锚定到产品数据**：工件所有权（一件只一人）+ 四机制挂到 owner——缺流程数据职责还在，缺数据流程空转。
- **产品数据是企业最重要的资产**：四性兼备（可积累/可复用/可转移/可评价）；**产品会死，数据体系活着**。
- **实现方案是产品数据里最重的一份**：实物产品 = 八方案，方案齐备 = 可实现 = 设计开发终点——错一处，一万台箱子错一万处。
- **开发流水线上流动的是产品数据**：开发缺陷沿流动传播并放大（越下游修复越贵）。
- **活动值不值看产品数据是否增值**：增值需顾客需要（防过度加工）+ 流动效率（双维）；不增值 ≠ 浪费。
- **数字化 ≠ 转型**：数字化 = 给资产上户口（存起来）；转型 = 让资产生利息（用起来，驱动决策）。

## 五、课后作业

1. **书练习（与题卡同源）**：列出你们产品的六类数据（需求/设计/制造/质量/服务/管理），每类举两个具体工件；标出哪一类最容易漏、为什么。（书练习 1）
2. **书练习**：用 ISO/IEC 25012 五特性（准确性/完整性/一致性/时效性/可信度）检查你们的一份产品数据，逐项给证据——最差的一尺是哪一尺？（书练习 5）
3. **回部门落地**：结合现状，用两域三态、六类数据、数据≠载体判据、数据质量五尺、增值判据，给你们产品做一次"产品数据完整性体检"——给出最该改进的三件事，每个落到一个可检查的动作。**两周后回来报告**：哪个判据测出不合格、补了哪个动作、效果如何。加一条：下一次签"通过"前，先问一句"这是不是真正要的东西"——把永兵式认账还掉。

### 作业指南（回部门落地的步骤 + 话术）

> 照着做，60 分钟完成一次产品数据完整性体检：
>
> 1. **挑对象（先立枢纽）**：选一个"正在设计态、你心里最有底"的产品/系统——产品的主程序 / 固件 / 服务 / 温控箱 / 审批系统。最自信的，往往是数据断层最深的。
> 2. **过两域三态（产品在哪存在）**：设计态 / 制造态 / 使用态各有什么数据？你们开发工作全部发生在设计态吗——设计态里产品=纯数据吗？**话术**："你们产品现在，在哪个域哪个态？那里有没有实物？"
> 3. **列六类数据（该做什么→做对了吗→用起来怎么样）**：需求 / 设计 / 制造 / 质量 / 服务 / 管理，每类举两个具体工件——哪一类最容易漏？**话术**："'该做什么''怎么做''怎么证明对'，你们三类数据齐吗？"
> 4. **过数据≠载体判据（数据是不是被当文档管）**：同一份数据换载体（Word→数据库→墙上）还是那份吗？你们管的是内容还是容器？**话术**："你们说'需求在共享盘'，那是需求本身，还是需求的载体？"
> 5. **用五尺量（数据质量）**：准确性 / 完整性 / 一致性 / 时效性 / 可信度，逐项拿证据——BOM vs 图纸对不上就是准确性与一致性没量住（案例进展①）。**话术**："最差的那一尺是哪一尺？证据是什么？"
> 6. **答设计态同一性（开发=定义生成）**：数据完备到"可制造、可验证"了吗？需求 / 设计 / 验证三层接得住吗（案例进展②）？**话术**："验收标准在需求数据里，接口契约在设计数据里——两层对得上吗？"
> 7. **过增值判据（活动值不值）**：上周做的事里，哪件让数据增值了（完善需求）？哪件是过度加工（加顾客不要的特性）？哪件必要非增值（合规）？哪件纯浪费（重复造轮子）？
> 8. **转述测试（压缩测试）**：用三五句话把"开发产品就是开发产品数据"讲给一个完全外行的人——讲到哪卡住，缺口就在哪；你织的那张概念关系图（方法时刻 Q9）牢不牢，一讲就知道。**话术**："用三句话讲给我这个外行听，讲到哪卡住，缺口就在哪。"
> 9. **出体检报告**：最该先补的 = 六类里最容易漏的那一类 + 五尺里最差的那一尺；最后一条建议照书抄——先给最大的产品数据补一套"可追溯、可验证"的档案/基线，把"数据散在每个人脑子里"收进组织的数据库（案例进展④师傅的本子）。
>
> 卡住时：六类列不全 = 完整性缺位，那一类就是断层点；换载体就"变了" = 把载体当数据（水忠"数据是文档"）；三层接不住 = 设计态同一性没到（案例进展②李旭"没法定"、董勐"追溯记录写不全"）；最差的一尺就是最该补的；"谁改的、为什么改"答不出 = 决策层没沉淀（恒信镜）；转述卡壳处 = 织的网有洞（织关系没到位、边界缺口）。不必九步全做完，找到第一个答不出的项目就能开工。
