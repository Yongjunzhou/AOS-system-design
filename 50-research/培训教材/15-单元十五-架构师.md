## 一、单元导读

### 主题

这一章回答全书书名那个问题：**架构师，到底是个怎样的物种？** 恒信把"年度架构师"颁给了李工，颁奖词是"全年产出架构图最多、架构文档最全"——会后 Ada 问了他一句让他愣住的话："当选架构师，意味着你现在是什么？"办公室里三个人接话，给出三个答案：开发说"更高级的工程师——升职了嘛"，测试说"画架构图的人，图画得最多那个"，运维说"什么都管的人，出了事都找他"。三句话，三个"架构师"。**头衔不定义架构师；架构师首先是一个工程师。** 底座六项 + 增量四项 = 十项能力清单，一项一项亮起来，才是架构师。这一章不再新增任何概念——它把前面十四章的尺子，收拢到一个人身上：从工程师，到架构师。

### 开场破题（对应章首误解现场）

念出恒信年度评优会那场戏：恒信把"年度架构师"颁给了李工，颁奖词是"**全年产出架构图最多、架构文档最全。**"会后，Ada 把李工叫住，问了一个让他愣住的问题："**当选架构师，意味着你现在是什么？**"李工张了张嘴，他发现自己答不上来。办公室里三个人接话：开发说"架构师就是更高级的工程师——升职了嘛"；测试说"架构师是画架构图的人，图画得最多那个"；运维说"架构师是什么都管的人，出了事都找他"。

让各组表态：三句话三个"架构师"，错在哪？大多数人一开始都会说"三个人各有道理，李工有头衔有图当然算架构师"——这正是这一章要推翻的直觉：**三句话，三个错判据——"更高级的工程师"把职级当成了能力，"画架构图的人"把画图当成了架构，"什么都管的人"把权力当成了责任。** 而更根本的问题，是全书从第一页就在问的：**架构师，到底是个怎样的物种？**

### 本单元要反转的直觉

- **架构师就是更高级的工程师——升职了嘛**（× 职级是位置，物种是能力；两种决策域，不是职级高低）
- **架构师是画架构图的人，图画得最多那个**（× 图是决定的表达不是替代；删掉图剩下的决定才是架构）
- **架构师是什么都管的人，出了事都找他**（× 管得最准，不是管得最多；什么都管是把约束管成枷锁）
- **把图画得最全的人，就是最好的架构师**（× 图越来越漂亮、图下没有决定；团队发现图不能用来做决定）
- **架构师可以不会写代码，反正有人实现**（× 远离代码，判断失去锚点；理论不落地像没有实物的建筑图）
- **被任命为架构师，就是架构师了**（× 被任命只是入场券；能力清单一项项亮起来才是成为）
- **架构师和项目经理是一回事，都管进度**（× 项目经理对日历负责，架构师对演化负责）
- **架构师的判断可以只凭经验，不需要理论**（× 没有理论的架构，像没有原理的工程）
- **架构师的底座和增量是两套能力**（× 增量全部长在底座上，底座缺一项，增量就空转）
- **架构师再往上就是升任 CTO——更高的职级**（× 再往上不是更深的架构，是关注维度从系统扩张到组织）

### 本轮题卡的内在逻辑（10 题 2×5 + 方法时刻）

**第一组 · 概念与原理（先立概念）**：Q1 架构师是什么 + 三句错判语逐条翻（破题·概念本身）→ Q2 五个相邻角色关系 + 增量长底座（概念关系）→ Q3 头衔/任命 vs 能力（真悖论·李工）→ Q4 画图 vs 架构（真悖论·画图匠判据）→ Q5 什么都管 vs 管得最准（真悖论·识别后果严重的决策）。由"是什么"走到"为什么"。

**第二组 · 落地与实践（用尺量）**：Q6 双线判词逐项打勾（判据运用·十项体检）→ Q7 失败四式各缺哪项（判据运用·四宗死法）→ Q8 成长 + 被任命≠成为 + 三种来路（判据运用·成长路径）→ **Q9 方法时刻·从见过到拥有**（规则 15：判李工/老周再反身判自己团队——判词变体必启用）→ Q10 回部门十项体检 + 落判词 + 工作检查单（落地生根）。判据运用 + 落地动作。

### 同类分组说明

产品组与 IT 组答同一组题，答案互为镜像。这一章的题尤其适合镜像对照：产品组的"有底座一半的架构师"是冰链老周——无头衔、做架构工作，判断顶配但缺②⑥（方法是手艺的极致、判断换个人做不出来）；IT 组的"被任命的架构师"是恒信李工——有头衔、有舞台，但缺①④⑥（理论悬空、伦理的账欠着、不写决策记录）。**同一个十项能力清单，两个世界的两条判词——这正是"概念不挑行业"的现场证明**：老周是无头衔缺②⑥，李工是有头衔缺①④⑥，量的是同一把尺子。产品组举"硬件大牛被叫架构师说不清"的例子，IT 组举"四张图当全部工作"的例子——两边都容易用"图多 / 文档全 / 头衔高"判人，都要翻到十项能力上。

## 二、题卡（打印分发）

**答题要求**：组内讨论 25 分钟 / 答案 ≤5 行 / 上台讲解 4–5 分钟 / 观点不同必须给理由。

### 第一组 · 概念与原理

**Q1｜"更高级的工程师 / 画架构图的人 / 什么都管的人"，三句话三个"架构师"——错在哪？架构师到底是什么？**
"年度评优会上，恒信把『年度架构师』颁给了李工，颁奖词是：『全年产出架构图最多、架构文档最全。』会后 Ada 问李工：『当选架构师，意味着你现在是什么？』他答不上来。办公室三个人接话：开发说『架构师就是更高级的工程师——升职了嘛』；测试说『架构师是画架构图的人，图画得最多那个』；运维说『架构师是什么都管的人，出了事都找他』。三句话三个『架构师』，错在哪？『架构师』到底是个什么样的物种？"

追问：① 十项能力清单——底座六项（第8章）+ 增量四项（第9、11章），怎么构成一个整体？『架构师首先是一个工程师』为什么是次序问题（没有那六项底座，『架构师』三个字只是一张名片）？② 三句话分别把什么当成了判据（职级 / 画图 / 权力——都是名义或载体，不是能力）？③ 你们公司颁『架构师』头衔 / 评优时，依据的是图多文档全，还是十项能力清单？

**Q2｜架构师和更高级的工程师、技术负责人、项目经理、领域专家、画图匠，什么关系？**
"请给出 架构师 和 更高级的工程师、技术负责人、项目经理、领域专家、画图匠 这五个相邻角色的关系，并说明：为什么说『职级也不定义架构师』？增量四项（⑦⑧⑨⑩）为什么长在底座六项上，而不是一套独立的『架构师能力』？"

追问：① 每一个角色边界各是"管什么 vs 管什么"（架构师管决定 / 管结构 / 管演化 vs 技术负责人管人 / 项目经理管进度 / 领域专家懂业务 / 画图匠画图）？② 为什么增量长在底座上（识别依赖工程判断、理论依赖科学素养、不可逆判断依赖工程判断——底座缺一块，增量全是空转）？③ 你们团队里"该由架构师决定却被别人抢走"的决定，抢走它的人缺的是清单里的哪一项？

**Q3｜有头衔、被任命，李工到底算不算架构师？**
"李工被任命为『年度架构师』、名片换了、评优都评上了——有头衔、有职位、有舞台。可 Ada 问他『当选架构师意味着你现在是什么』，他答不上来；按十项清单自我体检，他缺①④⑥。有头衔、被任命，到底算不算架构师？什么判据能分清『头衔』和『能力』？"

追问：① 头衔是组织给的位置、职级是组织给的位置——为什么都定义不了架构师（被任命只是拿到牌桌的入场券；『头衔一路在换，背在身上的东西没有变』）？② 李工缺①④⑥各是什么证据（①科学素养——长期不碰实现、理论开始悬空 / ④职业伦理——为进度悄悄牺牲可靠性的账没还清 / ⑥可复现意识——以前不写决策记录，现在开始写）？③ 你们部门有没有"头衔先于能力"的架构师？拿掉头衔，他还立得住吗？

**Q4｜把图画得最全，就是最好的架构师吗？图和架构差在哪？**
"李工的四张图挂满一面墙，图越来越漂亮、文档越来越全——评优就把『年度架构师』颁给了他。这一章却说：删掉你所有的图，你的决定还在，你是架构师；删掉图你什么也没剩下，你是画图匠。『把图画得最全』和『把架构做出来』到底差在哪？什么判据能分清『图』和『架构』？"

追问：① 图是决定的表达还是决定的替代——四张图为什么是画图匠的作品（图下面没有任何关于『决定』的字，直到 Ada 点醒他，把四张图换成一份决定清单）？② 老周的『老规矩』不是图，是一份清单（不可还原的涵义、设计准则、演进准则）——图是死的、视图是活的，为什么『让每个相关方的关注点都有一张图能落』（⑨）比图本身重要？③ 你最近一次交的『架构』，删掉图还剩什么？

**Q5｜什么都管，才叫对得起架构师这个头衔吗？**
"运维说：架构师是什么都管的人，出了事都找他——很多人也这么信，觉得架构师就该对每个接口、每行代码、每个表负责。这一章却说：管得最准，不是管得最多；对不重要的事情不决策，本身就是一种好的架构决策。哪个对？什么判据分清『该管的』和『不该管的』？"

追问：① 什么都管为什么危险（两条后果：团队失去自己判断的能力、他成了瓶颈；精力花在大量低价值决策上，真正重要的决策反而没有精力——缺⑦）？② 识别后果严重的决策的判据（影响半径大 / 持续时间长 / 修改成本高——按决策对待；对重要的事情不决策，是架构师的第一宗罪）？③ 你们团队最近一次"对重要的事情不决策、对不重要的事情疯狂决策"，是哪一个？

### 第二组 · 落地与实践

**Q6｜给李工和老周下判词：两个人都是"缺"，缺的性质有什么不同？**
"用十项能力清单，给李工和老周下判词：李工有头衔缺①④⑥，老周无头衔缺②⑥。先把两条判词逐项打勾验证，再说说：两个人都是『缺』，缺的性质有什么不同？两个人都不是完整的架构师，那『两个都在长成』是什么意思？"

追问：① 李工的里子（判断还悬着、伦理的账欠着）vs 老周的面子（判断顶配但不可复制）——各自缺项露在产品数据的哪里（李工四张图下没有决定，直到开始写 ADR / 老周老规矩写在纸上，但判断换个人做不出来）？② 判词（案例进展①②③）和 3.6（产品数据：上半棵树）量的是同一把尺子（换个人接得住吗）——为什么？③ 你更接近哪条线？缺的是哪一项？

**Q7｜失败四式，每一宗死法缺的是清单里的哪一项？哪一宗最危险？**
"失败四式——画图匠（只有视图没有判断）、什么都管（把约束管成枷锁）、不决策（把决定留给默认）、远离代码（判断失去锚点）。用十项能力清单，说出每一宗死法缺的是哪一项。哪一宗最危险？为什么？"

追问：① 画图匠为什么死于『团队发现图不能用来做决定』而不是被辞退（缺⑤工程判断——图说系统长这样，但遇到『数据放哪』没人能答，大家绕过图各做各的）？② 什么都管为什么看起来最负责、其实最危险（对不重要的事情疯狂决策、对重要的视而不见——缺⑦；他成了瓶颈）？③ 不决策为什么是把架构决策的资格交给运气和时间（不选就是选了默认，默认最保守最省事——缺⑩判断不可逆性）？④ 你最近一次架构决策更接近哪一宗？缺的是清单里的哪一项？

**Q8｜被任命"年度架构师"，为什么不等于成为架构师？怎么判断在不在长成？**
"李工被任命为『年度架构师』那天，头衔换了——但 Ada 那个问题他还是答不上来。为什么『被任命』不等于『成为』？怎么判断一个人是不是真的在长成架构师（判断的依据在哪个尺度）？三种来路（从开发长出来 / 空降 / 挂名）各是什么功课？"

追问：① 成长的本质=判断的依据换尺度（代码→模块→系统→架构决策：你关心的问题换了，你的物种就变了）——你现在判断的依据在哪个尺度？② 三种来路各缺什么（从开发长出来缺⑦⑧⑩、空降缺③⑥、挂名只有头衔）——判断一个人走哪条路，看他在补清单的哪一项？③ 成长的标志=第一次"说不"——阿凯自己把直连方案划掉改走受控导出、李工认下编号规则，拦下的为什么不是『错的』而是『没想清楚不可逆性的』（⑩判断不可逆性是最后一盏灯，需要前面所有能力到位才接得住）？

**Q9｜把十项能力清单变成判人的尺子：判李工、判老周、再反身判你们团队（方法时刻）**
"李工有『年度架构师』头衔、老周连名片上都印着『嵌入式硬件工程师』——可这一章的方法底座时刻是『从见过到拥有』：章首的李工对『架构师』只有『见过』——叫得出头衔、画得出图，却答不上『当选架构师意味着你现在是什么』；判词把他量成了『拥有』——能对着十项清单一项一项打勾、认得出自己缺什么。**判词把『架构师』从头衔钉成了能力清单。** 把这张清单从『背诵对象』变成『判人的尺子』：先用它判李工（有头衔缺①④⑥——证据是什么？）、再判老周（无头衔缺②⑥——证据是什么？）、最后反身判你自己的团队——谁缺哪一项？用什么判据检验（不是头衔、不是感觉）？"

追问（判词变体）：① 你给李工判"缺①④⑥"，证据各是什么（①长期不碰实现、理论开始悬空 / ④为进度悄悄牺牲可靠性的账没还清 / ⑥以前不写决策记录，现在开始写）？给老周判"缺②⑥"，证据是什么（方法是手艺的极致、不成体系 / 判断换个人做不出来、车间没有完整测试方案）？② 反身判团队：拿掉头衔和年资，用十项逐项打勾——你们团队"最像架构师的人"缺哪一项？他正在长成的是哪一项？③ 『从见过到拥有』还意味着什么——能答全十项能力的四问（各是什么、不是什么、判据是什么）、能用清单量别人量自己，才算拥有；这把尺子现在装进你手里了吗？

**Q10｜给你们部门做一次十项体检，落一条判词**
"结合你们部门现状，用十项能力清单给一位『被当成架构师的人』（或你自己）做一次体检——逐项打勾，指出缺项，落一条判词（像李工缺①④⑥还是像老周缺②⑥？），给出最该先补的一项，落到一个动作。"

追问：① 十项体检 + 工作检查单六条（影响半径大 / 持续时间长 / 修改成本高？理论对不对得起它？相关方视图跟上了吗？决策记录写了吗？在做决定还是在画图 / 什么都管 / 等默认？接口契约改了吗）先查哪两项？② 你们的架构评审 / 晋升，用的是十项判据，还是"图多 / 文档全 / 头衔高"三个错判据（和章首颁奖词一模一样）？③ 两周后回来报告：谁打了勾、缺了哪项、补了哪个动作。

## 三、点评要点·讲师版

> 点评纪律：先表态后翻案 / 反转精确不造新误解 / 判据配机制 / 归责到可对照动作 / 教机制不教断言 / 先立尺子再翻案 / 拉开强度层次 / 每个纠正落到可操作动作 / 单一权威不另立标准 / 网搜当佐证。

### Q1 "更高级的工程师 / 画架构图的人 / 什么都管的人"——错在哪？架构师到底是什么？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "三个人各有道理，李工有头衔有图当然算架构师。" | 正是要翻的——把职级/画图/权力当判据 |
| 中 | 能说"架构师=十项能力清单"，但说不清三句话各错在哪 | 清单背出来了，判据没用起来——没落到逐句翻 |
| 好 | "'更高级的工程师'把职级当能力、'画架构图的人'把画图当架构、'什么都管的人'把权力当责任；架构师=先是一个工程师（底座六项）+ 增量四项，头衔不定义架构师。" | 三句错判据逐条翻 + 十项清单 + 反直觉命题全咬合 |

**产品侧 vs IT侧**：产品组答"老周做架构工作却连名片上都不是架构师，不算架构师？"，IT 组答"李工当选年度架构师、图最多文档最全，不算架构师？"——两边都要翻"定义在名义上的都不稳，定义在能力上的才稳"。**这一章是角色收束章，十项能力清单就是尺子，不是标签。**

**反转话术**（对应开篇枢纽 + 1.1 + 章末认知反转）：三句话三个"架构师"，错在同一个地方——**用一个"名义 / 载体"去定义一个"能力"**。"更高级的工程师"把职级当成了能力；"画架构图的人"把画图当成了架构；"什么都管的人"把权力当成了责任。这一章不新增任何概念——前面十四章把尺子都发完了，它只做一件事：**把"架构师"这个人，放到那十四把尺子下面量一遍。** 量出来的第一层答案是：**架构师首先是一个工程师。** 第8章给工程师立过一把尺子——六项能力（科学素养、方法论素养、实践能力、职业伦理 + 横切工程判断 + 元可复现意识），缺一项，"工程师"就不是完整的人。**没有那六项能力，"架构师"三个字只是一张名片；有了它们，才谈得上往系统级长。** 再往上，是四项系统级增量：识别后果严重的决策、对系统的理论、把架构说清楚、判断不可逆性——底座六项 + 增量四项 = **十项能力清单**。三句评语错在哪？**它们都定义在名义上：职级是位置、画图是工具、权力是组织给的——都是可印上可收走的东西。定义在能力上的，才稳。** 章末 Ada 那句"当选架构师意味着你现在是什么"，李工答不上来——因为他只有"见过"（叫得出头衔、画得出图），还没到"拥有"（能对着十项清单一项一项打勾）。

**参考答案要点**：架构师定义见开篇枢纽 + §1.1；十项能力清单见 §1.2~1.3；两个反直觉命题见开篇枢纽；章末认知反转（见过→拥有）。

### Q2 架构师和五个相邻角色，什么关系？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "架构师就是最厉害的技术负责人 / 高级项目经理。" | 关系结构错误——五对角色被混成一团 |
| 中 | 能说出"不是画图匠 / 不是项目经理"，但技术负责人、领域专家没接上 | 边界磨了两对，另三对漏了 |
| 好 | "架构师管决定、技术负责人管人、项目经理管进度、领域专家懂业务、画图匠画图——架构师对演化负责、对结构负责；职级是位置、物种是能力；增量长在底座上：识别依赖工程判断、理论依赖科学素养、不可逆判断依赖工程判断，底座缺一块增量空转。" | 五对边界 + 职级≠物种 + 增量长底座全到位 |

**产品侧 vs IT侧**：产品组举"硬件老师傅被叫架构师说不清"；IT 组举"四张图当全部工作的李工"。两边都要翻同一句——**判断一个人是技术负责人还是架构师，看他在压力下护住的是什么：护住交付，是技术负责人；护住结构，是架构师。**

**反转话术**（对应 2.1~2.5 + 1.3）：架构师和五个人像但不一样。**不是更高级的工程师**——职级是组织给你的位置（你管多少人、拿多少钱），物种是能力决定的（你会做什么、能做什么）；两者不是职级高低，是**两种决策域**（架构设计管系统级、详细设计管模块内部）——同一个系统，工程师横着做深，架构师横着铺广。**不是技术负责人**——技术负责人管人（代码评审、任务分配、进度、绩效），架构师管决定（系统结构、接口边界、数据所有权、不可逆决策）；**管理权可以任命，领导力不能任命**。**不是项目经理**——项目经理对日历负责，架构师对演化负责。**不是领域专家**——领域专家懂业务，架构师懂系统（规则怎么被建模、数据怎么流动）。**不是画图匠**——画图匠画的是"系统长什么样"，架构师画的是"系统最重要的决定是什么"。**增量为什么长在底座上？** 识别后果严重的决策依赖工程判断、对系统的理论依赖科学素养、判断不可逆性依赖工程判断——**底座缺一块，增量全是空转**。拆开 ISO/IEC/IEEE 42010：架构是系统在环境中的基本概念或属性，体现在元素、关系、以及设计准则与演进准则里——**元素是工程师的，关系与演化是架构师的。**

**参考答案要点**：五对角色边界见 §2.1~2.5；增量长底座见 §1.1；ISO 42010 三组词分工见 §1.3。

### Q3 有头衔、被任命，李工到底算不算架构师？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "当选了年度架构师、评优都评上了，当然是架构师。" | 正是要翻的——把被任命当成为 |
| 中 | "不算，因为他答不上 Ada 那个问题。" 结论对，判据缺 | 十项逐项打勾没出来 |
| 好 | "头衔是组织给的位置、职级是组织给的位置，都定义不了能力；被任命只是入场券，能不能坐稳靠十项能力清单——李工缺①④⑥（理论悬空/伦理的账欠着/不写决策记录），他是'被任命的架构师'在补底座。" | 名义 vs 能力 + 李工逐项 + 被任命≠成为全到位 |

**产品侧 vs IT侧**：产品组举"公司发文任命某人当总架构师"；IT 组举"年度评优把架构师颁给图最多的人"。两边都是同一把尺子——**判断可检验的不在名片上，在十项能力清单上；被任命只是拿到一张牌桌的入场券，能不能在牌桌上坐稳，靠的是能力。**

**反转话术**（对应 3.2 + 案例进展① + 3.3）：被任命给了李工一个名头，但名头不给能力——**被任命只是拿到一张牌桌的入场券，能不能在牌桌上坐稳，靠的是十项能力清单。** 这听起来残酷，其实公平：**能力是可以长的，名头只是时间的快照。** 李工按清单逐项：缺①科学素养——长期不碰实现，理论开始悬空；缺④职业伦理——为进度悄悄牺牲可靠性的账没还清（第2章）；缺⑥可复现意识——以前不写决策记录，现在开始写（第11章六问）。**他是"被任命的架构师"，刚刚开始补底座。** 但那张自我体检单本身，就是他成为架构师的第一步——**他终于在用尺子量自己了。** 头衔一路在换，背在身上的东西没有变；"职级也不定义架构师"，在 CTO 那里依然成立（3.5）。

**参考答案要点**：被任命≠成为见 §3.2；李工判词见案例进展① + 案例设定 §五/§九；三种来路·挂名见 §3.3。

### Q4 把图画得最全，就是最好的架构师吗？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "四张图挂满墙、文档最全，当然是最好。" | 正是要翻的——把图当架构 |
| 中 | "图不是架构。" 结论对，判据缺 | 画图匠判据（删掉图剩下的决定）没点透 |
| 好 | "图是决定的表达还是决定的替代——四张图下没有任何关于'决定'的字，直到 Ada 点醒；老周的'老规矩'不是图是一份清单；删掉图剩下的决定才是架构；图死视图活，⑨把架构说清楚=让每个相关方的关注点都有一张图能落。" | 画图匠判据 + 老规矩 + 视图机制全到位 |

**产品侧 vs IT侧**：产品组举"M3 的四层方块图 vs 给疾控/司机/维修/监管的四张视图"；IT 组举"李工四张图 vs 老周的清单"。两边都是同一件事——**图是死的，视图是活的：每个相关方看到自己该看的那一面，而它们合起来，说的是同一个系统。**

**反转话术**（对应 2.5 + 1.6 + 案例进展①）：图是**决定的表达**，还是**决定的替代**——这是画图匠和架构师的唯一分界。**如果删掉你所有的图，你的决定还在，你是架构师；如果删掉你的图，你什么也没剩下，你是画图匠。** 李工的四张图挂满一面墙，但图的下面，没有任何关于"决定"的字——那四张图，是画图匠的作品，直到 Ada 点醒他，他把四张图换成一份决定清单（不可还原的涵义、设计准则、演进准则——老周的"老规矩"的恒信版）。**画图容易，写决定难。** 而"把架构说清楚"（⑨）不是"文档写得好"，是**让每个相关方的关注点都有一张图能落**——老周给客户发过四样东西，没有一样是他那张四层方块图：给疾控中心看追溯链路、给司机看状态视图、给维修看结构视图、给监管看合规视图。**图是死的，视图是活的。** 相关方的关注点天然冲突，架构师不消灭冲突，他给每个冲突一个可见的落点——这样冲突才能被讨论，而不是被闷在各自脑子里。

**参考答案要点**：不是画图匠见 §2.5；把架构说清楚见 §1.6；老规矩见案例进展① + 00-案例设定 §八。

### Q5 什么都管，才叫对得起架构师这个头衔吗？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "架构师就该什么都管，出了事都找他。" | 正是要翻的——把管太多当负责 |
| 中 | "管得最准不是最多。" 结论对，机制缺 | 两条后果（团队失去判断+他成瓶颈）没接上 |
| 好 | "什么都管看起来最负责其实最危险：团队失去自己判断的能力、他成瓶颈；精力花在低价值决策上、重要决策反而没精力——缺⑦；识别后果严重的决策判据=影响半径大/持续时间长/修改成本高，对不重要的事情不决策本身就是好的架构决策。" | 两条后果 + 缺⑦ + 三判据全到位 |

**产品侧 vs IT侧**：产品组举"每个接口都要老师傅过目"；IT 组举"李工想改编号规则却不知这是影响所有历史合同的决策"。两边都是同一件事——**对不重要的事情不决策，本身就是一种好的架构决策；对重要的事情不决策，是架构师的第一宗罪。**

**反转话术**（对应 2.6 + 1.4）：和第画图匠相反，什么都管把"管"发挥到极致——每个接口、每行代码、每个表都要过他。它为什么危险？**因为它看起来非常负责。** 两条后果：第一，团队失去了自己判断的能力，所有决定都等他，**他成了瓶颈**；第二，他把精力花在大量低价值决策上，真正重要的决策反而没有精力——**对不重要的事情疯狂决策，对重要的视而不见（缺⑦）。** 识别后果严重的决策，不是"想得多"，是"认得出哪类决策必须按决策对待"——判据就三条：**影响半径大、持续时间长、修改成本高**。这三条不是给你判断"哪个技术方案好"的，是给你判断"这件事值不值得开一次正式的会"的。李工的例子最典型：合同编号规则，在 Ada 点破前他一直当它是"今天就能改的字段"——他改起来很快，两天上线，却不知道这是影响所有历史合同的决策，直到三个月连环三爆。**对不重要的事情不决策，本身就是一种好的架构决策——这句话的另一面是：对重要的事情不决策，是架构师的第一宗罪。**

**参考答案要点**：什么都管死法见 §2.6；识别后果严重的决策见 §1.4；李工编号规则见 §1.4 + 第11章。

### Q6 给李工和老周下判词——缺的性质有什么不同？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "两个人都挺厉害，不好说谁不是架构师。" | 判词没落——清单没当尺子用 |
| 中 | "李工缺①④⑥、老周缺②⑥。" 判词对，性质没辨析 | 十项打勾了，"里子/面子"没接上 |
| 好 | "李工判断还悬着、伦理的账欠着=有职位缺里子；老周判断顶配但不可复制=有里子缺面子；两个都不是完整的架构师，都在用清单量自己、补缺项——判词和产品数据（上半棵树）量的是同一把尺子：换个人接得住吗。" | 双线判词 + 性质辨析 + 长成含义 + 同一把尺子全到位 |

**产品侧 vs IT侧**：产品组说"老周缺的是'把判断交给别人'的本事"；IT 组说"李工缺的是'关键时刻护住'的底气"。两边都是同一件事——**架构师不是一个头衔，是一张两项都站得住的清单。**

**反转话术**（对应 案例进展①②③ + 3.6）：两份判词逐项验证：**李工**=有头衔，缺①④⑥——他有职位、有舞台，但判断还悬着（①长期不碰实现、理论悬空）、伦理的账还欠着（④为进度悄悄牺牲可靠性）、不写决策记录（⑥现在开始写）——他是**"被任命的架构师"在补底座**；**老周**=无头衔，缺②⑥——他有判断、有实践、有理论，但方法是手艺的极致不成体系（②）、判断换个人做不出来（⑥）——他是**"有底座一半的架构师"在补元能力**。缺的性质不同：李工缺"里子"（关键时刻护不住），老周缺"面子"（判断不可复制）。谁更接近架构师？**两个人都不是完整的架构师；但两个人都值得被叫一句"在成为架构师的路上"**——因为他们都在用十项能力清单量自己，都在补自己缺的那一项。**判词（案例进展①②③）和 3.6（产品数据）量的是同一把尺子**——李工的四张图下没有决定，直到开始写 ADR；老周的老规矩写在纸上，但判断换个人做不出来。两个人都不是，两个都在长成——**这正是全书对"架构师是个怎样的物种"的最终回答：它是一个方向、一张清单，不是头衔。**

**参考答案要点**：双线判词见案例进展③ + 本章判词；产品数据·上半棵树见 §3.6；角色画像见案例设定 §五。

### Q7 失败四式——每一宗死法缺哪一项？哪一宗最危险？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "失败就是干得不好，多练就行。" | 没落到四式+缺项——把死法当"不努力" |
| 中 | "画图匠缺⑤、什么都管缺⑦、不决策缺⑩、远离代码缺③。" 判词对，最危险那宗没说透 | 四式各配一项了，什么都管的机制缺 |
| 好 | "画图匠死于没判断（⑤）、什么都管死于管太多（⑦）、不决策死于把决定留给默认（⑩）、远离代码死于看不见（③）——最危险的是什么都管，因为他看起来最负责；最隐蔽的是不决策，不选就是选了默认。" | 四式缺项 + 最危险/最隐蔽机制全到位 |

**产品侧 vs IT侧**：产品组举"老师傅不让任何人碰他的判断"；IT 组举"架构师凡事都要过目，成了瓶颈"。两边都是同一件事——**四宗死法每一种，都能在十项能力清单里找到缺的那一项。**

**反转话术**（对应 2.6）：四宗死法四宗姿态：**画图匠**——只有视图、没有判断，图越来越多越来越漂亮，但图下面没有任何关于"决定"的东西；他死掉的方式不是被辞退，是**团队发现图不能用来做决定**——图说系统长这样，但遇到"数据放哪"没人能答，大家绕过图各做各的（**缺⑤工程判断**）。**什么都管**——把约束管成枷锁，团队失去自己判断的能力、他成了瓶颈，精力花在低价值决策上、重要决策反而没精力（**缺⑦识别后果严重的决策**）。**不决策**——症状不是"什么都不管"，是**把决定留给默认**：不选就是选了默认，默认往往最保守、最省事、最像"大家都这么做"；不做决策，系统也会被默认选项塑造，只是你在事后才认识它，而那时它已经不可逆了（**缺⑩判断不可逆性**）。**远离代码**——升上去了不再写代码，判断没有锚点，理论还在但不落在任何可实现的东西上——**不落地的理论，像没有实物的建筑图（缺③实践能力）**。最危险的是"什么都管"——**因为它看起来非常负责**；最隐蔽的是"不决策"——因为它看起来什么都没做错。

**参考答案要点**：失败四式见 §2.6；四式各缺项见 §2.6 末段 + 本章概念总图。

### Q8 被任命"年度架构师"，为什么不等于成为架构师？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "任命了就是架构师了，头衔就是证明。" | 正是要翻的——把被任命当成为 |
| 中 | "头衔不等于能力。" 结论对，成长机制浅 | 成长尺（判断依据换尺度）没接上 |
| 好 | "头衔是入场券，坐稳靠十项能力清单；成长=判断依据换尺度：代码→模块→系统→架构决策；三种来路各缺不同（开发长出来缺⑦⑧⑩/空降缺③⑥/挂名只有头衔）；成长的标志=第一次'说不'——拦下的不是错的，是没想清楚不可逆性的。" | 被任命≠成为 + 成长尺 + 三种来路 + 说不全到位 |

**产品侧 vs IT侧**：产品组问"老周没头衔怎么往架构师长？"；IT 组问"李工有头衔怎么真的成为？"——两边是同一个答案：**判断的依据从'代码'升到'系统'，你关心的问题换了，你的物种就变了。**

**反转话术**（对应 3.1/3.2/3.3/3.4）：被任命只给了一个名头，名头不给能力——**被任命只是拿到一张牌桌的入场券，能不能在牌桌上坐稳，靠的是十项能力清单。** 怎么判断一个人是不是真的在长成？看**判断的依据在哪个尺度**：开发问"这段代码怎么写才清晰"、模块设计问"这个模块怎么切依赖才不绕"、系统设计问"整棵设计树枝干和叶子怎么长"、架构决策问"哪些决策改错的代价大到不能等"——**判断的依据从"代码"升级到"系统"，你关心的问题换了，你的物种就变了。** 三种来路三种功课：**从开发长出来**（最常见）——底座六项往往有一半已经在身（实践、科学素养），缺的是系统级的判断（⑦⑧⑩），功课是把小团队的代码判断练成对整棵树的判断；**空降**——往往有理论有判断，缺对这个系统的实践（③）和可复现（⑥），功课是先落地再谈蓝图；**挂名**——只有头衔没有能力，功课是要么真的开始补清单、要么承认这只是个名头。**判断一个人走在哪条路上，看他在补清单的哪一项。** 成长的标志，是第一次"说不"——阿凯想给客户开直连接口，被老周点醒后自己把方案划掉改走"受控导出"；李工想改编号规则，被 Ada 点醒后自己认下了。两次"说不"的共同点：**拦下的不是"错的"，是"没想清楚不可逆性的"。** 判断不可逆性（⑩），是成长路上最后一盏亮起来的灯——因为它需要前面所有能力都到位，才接得住。

**参考答案要点**：成长路径见 §3.1；被任命≠成为见 §3.2；三种来路见 §3.3；成长的标志·说不见 §3.4。

### Q9 把清单变成判人的尺子：判李工、判老周、再反身判团队（方法时刻 · 规则 15）

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | 背书上的判词："李工缺①④⑥、老周缺②⑥。" | 只答了"是什么"，没做"判人"这个动作——清单还是背诵对象 |
| 中 | 能判李工老周，但反身判团队时只能举例、说不出判据 | 判人有证据，判自己团队"是不是/凭什么"说不清 |
| 好 | "判李工缺①④⑥，证据是长期不碰实现理论悬空/为进度牺牲可靠性的账没还清/以前不写决策记录；判老周缺②⑥，证据是方法不成体系/车间没有完整测试方案；反身判团队：拿掉头衔年资逐项打勾——某人⑥没打勾=手艺型架构师，正在补的是写 ADR/做交接——缺项可补，能答全十项四问才算拥有。" | 立判据判人 + 反身判团队 + 见过→拥有全到位 |

**产品侧 vs IT侧**：产品组给老周判词时自然写"判断全在脑子里，车间没有测试方案"；IT 组给李工判词时自然写"四张图下没有决定，以前不写 ADR"。两边立出的判据结构相同——**这就是本章方法时刻的核心：不考"方法名能不能背"，考"方法会不会用"；清单是判人的尺子，不是背诵的对象。**

**反转话术**（对应 方法底座时刻 = 从见过到拥有 + 案例进展①②③ + 章末见过→拥有）：这是本单元的**方法时刻**——前面九题在讲"架构师是什么"，这一题让你们亲手做一遍方法底座时刻：**从见过到拥有**。李工有头衔、老周没头衔——可章首的李工对"架构师"只有**"见过"**：叫得出头衔、画得出图，却答不上"当选架构师意味着你现在是什么"；判词把他量成了**"拥有"**：能对着十项清单一项一项打勾、认得出自己缺什么。**判词把"架构师"从头衔钉成了能力清单。** 判词变体：**用清单判人，再把尺子转向自己**——判李工：缺①④⑥，判据是"长期不碰实现、理论开始悬空"（①）、"为进度悄悄牺牲可靠性的账没还清"（④）、"以前不写决策记录，现在开始写"（⑥），**不是头衔、不是感觉**；判老周：缺②⑥，判据是"方法是手艺的极致、不成体系"（②）、"判断换个人做不出来、车间没有完整测试方案"（⑥）。再反身判自己团队：谁缺哪一项？证据是什么？怎么检验？——**有标签是见过，能答全十项能力的四问（各是什么、不是什么、判据是什么）、能用清单量别人量自己，才算拥有。** 这把尺子现在装进你手里了。而这也正是全书对书名问题的最终回答：**架构师不是一个头衔、不是一个职级、不是一张图——它是一个方向，工程师往系统级判断走的方向；它是一张清单，十项能力一项一项亮起来的过程。**

**参考答案要点**：方法底座时刻（从见过到拥有）见 00-案例设定 §三 第15章行 + 开篇枢纽；判词见案例进展①③ + 案例设定 §五/§九；见过→拥有见章末认知反转。

### Q10 给你们部门做一次十项体检，落一条判词

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | 泛泛"要加强评审、要多写文档。" | 没落到十项体检任何一项，不可检查 |
| 中 | 用一把尺子查出问题（如"某同事的判断换个人接不住"） | 有判据，但只照了一面 |
| 好 | 按十项逐项打勾、落判词（"像老周缺②⑥——判断换个人接不住"）、挑最该先补一项 + 一个可检查动作（"把关键决策写成 ADR，指定一个接手人，两周后让他独立续演进一次"）、说清先查哪两项、两周后报告什么 | 体检完整，判词落地，动作可执行，有复查机制 |

**产品侧 vs IT侧**：两组各给自己部门体检——体检表是同一份（十把尺子 + 终极尺 + 工作检查单六条），这正是"概念不挑行业"的现场证明：**产品组的判词叫"有底座一半缺②⑥"，IT 组的判词叫"被任命缺①④⑥"，量的是同一把尺子。**

**反转话术**（对应 3.6 + 本章判据 + 作业指南）：十项能力抽象在一个人身上，**不可直接检验**——面试会看走眼，领导会凭印象打分。架构师能力的最终体现，是能否**设计开发出本角色负责的产品数据**——第6章立过一棵树：枝干是概要定义（管结构、承接关系），叶子是详细定义（管内容、可验证）。**架构师负责枝干和枝梢，工程师负责叶子**——架构师的产品数据是上半棵树：概要定义、接口契约（枝梢）、架构决策（ADR）、架构描述（AD）、系统级验证方案。枝梢是 **1:1 搬入点**——架构师定的接口契约，就是工程师叶子落下的那根枝梢；架构决策错，代价是结构性的：**上半棵错了，整棵下半棵跟着错。** 检验的标准只有一条：**换个人，拿着你负责的架构描述和决策，能不能接住、继续演进？** 能，你的架构才成立；不能，再大的图也只是装饰。你们部门体检，先查哪两项？十项体检 + 工作检查单六条——**"没有记录"的地方，就是④可能缺席、也是①和⑥最容易现形的地方。** 你们的架构评审/晋升，用的是十项判据，还是"图多 / 文档全 / 头衔高"三个错判据？——这正是章首那句颁奖词要翻的东西：**"全年产出架构图最多、架构文档最全"是错判据，删掉图剩下的决定才是架构。**

**参考答案要点**：产品数据·上半棵树见 §3.6；枝梢=1:1 搬入点见 §3.6.1；检验句见 §3.6.3 + 本章判据；作业指南见本章分析文档第 6 步。

### 金句（书"本章判据"提炼）

- **架构师是一个方向，不是头衔；是一张清单，不是职级。** 它是一个方向——工程师往系统级判断走的方向；它是一张清单——十项能力一项一项亮起来的过程。
- **架构师首先是一个工程师**——没有那六项底座，"架构师"三个字只是一张名片；有了它们，才谈得上往系统级长。增量全部长在底座上，底座缺一项，增量就空转。
- 十项能力体检：①科学素养——我对这个系统的理论是什么？②方法论素养——我的方法能被别人学会吗？③实践能力——我最近一次亲手落地是什么时候？④职业伦理——压力面前我会为进度悄悄牺牲可靠性吗？⑤工程判断——冲突里我依据什么做取舍？⑥可复现意识——我的判断换个人能接住吗？⑦识别后果严重的决策——我分得清哪类决策必须按决策对待吗？⑧对系统的理论——我的架构有原理吗？⑨把架构说清楚——每个相关方的关注点都有一张图能落吗？⑩判断不可逆性——我认得出不可逆决策吗？
- **管得最准，不是管得最多；对不重要的事情不决策，本身就是一种好的架构决策。对重要的事情不决策，是架构师的第一宗罪。**
- **代码用测试验证，架构用评审验证**——架构没有唯一正确解，只能对目标（相关方关切汇聚成的"为什么要建这个系统"）评审。
- **画图匠判据：如果删掉你所有的图，你的决定还在，你是架构师；如果删掉你的图，你什么也没剩下，你是画图匠。**
- 判词：**李工有头衔缺①④⑥，老周无头衔缺②⑥——两个都不是，两个都在长成。**
- **头衔一路在换，背在身上的东西没有变。** 从元素到系统、从系统到组织，是同一种升级的两次上演——工具不变，棋盘变大。
- **能力再强，也要看我能不能开发出高质量的上半棵树——换个人，拿着它，能不能接住、继续演进？**
- **从见过到拥有**：对"架构师"这个词，原来只是"见过"——叫得出头衔、画得出图；这一章把它推到"拥有"——能答全十项能力的四问、能用清单量别人量自己。判词把"架构师"从头衔钉成了能力清单。

## 五、课后作业

1. **书练习（与题卡同源）**：用十项能力清单，给"你们公司最像架构师的人"做一次体检——逐项打勾，指出缺项，判断他走在哪条路上（若对象换成老周或李工，体检结果会是"缺②⑥"还是"缺①④⑥"？）。（书练习 1）
2. **书练习**：角色边界演练——在你们最近一个项目里，找一个"该由架构师决定却被项目经理/技术负责人/领域专家抢走"的决定，说出它本该归谁。（书练习 2）
3. **回部门落地**：结合现状，用十项能力清单给一位"被当成架构师的人"（或你自己）做一次体检——逐项打勾、指出缺项、落一条判词（像李工缺①④⑥还是像老周缺②⑥？）、给出最该先补的一项，落到一个动作；并把本章判据的"工作检查单"打印出来贴在下一个架构决策现场。**两周后回来报告**：谁打了勾、缺了哪项、补了哪个动作、效果如何。

### 作业指南（回部门落地的步骤 + 话术）

> 照着做，60 分钟完成一次十项体检 + 落判词 + 过工作检查单：
>
> 1. **挑对象（先立枢纽）**：选团队里"公认最像架构师的人"——最像的，往往也最容易在某一项打不上勾。
> 2. **项目一 · 十项体检打勾**：底座六项——①科学素养（他对系统的理论是什么？靠什么成功、最大压力在哪、做错什么最致命？）②方法论素养（他的方法能被别人学会吗？还是只有他会？）③实践能力（他最近一次亲手落地是什么时候？）④职业伦理（压力面前会为进度牺牲可靠性吗？有没有让相关方知情？）⑤工程判断（冲突里他依据什么做取舍？）⑥可复现意识（他的判断换个人能接住吗？他写决策记录吗？）；增量四项——⑦识别后果严重的决策（他分得清哪类决策必须按决策对待吗？）⑧对系统的理论（他的架构有原理吗？换个上下文还成立吗？）⑨把架构说清楚（每个相关方的关注点都有一张图能落吗？）⑩判断不可逆性（他认得出不可逆决策吗？该早做的早做、该推迟的显式推迟吗？）
> 3. **项目二 · 落判词**：对照两条基准线——李工有头衔缺①④⑥（被任命的架构师在补底座）、老周无头衔缺②⑥（有底座一半的架构师在补元能力）——你的对象像哪条线？缺的是哪一项？**话术**："他不是不会做，是做的能力不可复制"（像老周）/ "他不是不会画，是图下面没有决定"（像李工）。
> 4. **项目三 · 反身判团队 + 反身自检**：拿掉头衔和年资，用同一张清单给团队逐项打勾——谁缺哪一项？他正在长成的是哪一项？再用清单给自己打勾——你缺的那一项，正是你在"背清单"而不是"用清单"的地方。
> 5. **项目四 · 落到产品数据（上半棵树）**：问最后一个问题——他/你负责的上半棵树（概要定义 / 接口契约 / 架构决策 ADR / 架构描述 AD / 系统级验证方案），换个人拿着能接住、继续演进吗？②⑥两项尤其看纸面（方法写不写得成视图、判断换个人接不接得住）。
> 6. **项目五 · 过工作检查单六条**：下次做架构决策前，先过那六条（影响半径大/持续时间长/修改成本高？理论对不对得起它？相关方视图跟上了吗？决策记录写了吗？在做决定还是在画图/什么都管/等默认？接口契约改了吗？）——把它打印出来贴在下一个架构决策现场。
> 7. **出体检报告**：十项各打勾/缺项，落判词，最该先补最缺的一项；两周后复查补了什么。
>
> 卡住时：打不上勾的那一项就是最该补的；⑥打不上勾=手艺型架构师（判断换个人接不住）；④打不上勾=最危险（判断越准破坏越大）；⑦⑩打不上勾=把不可逆决策当日常节奏（阿凯改走受控导出 / 李工认下编号规则是正例）；价值层三问（相关方知情/评审/记录）当场打勾——"没有记录"的地方就是④可能缺席、也是①和⑥最容易现形的地方。
