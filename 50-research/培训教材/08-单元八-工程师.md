## 一、单元导读

### 主题

这一章回答一个每个人都躲不开的问题：**工程师，到底是个什么样的物种？** 恒信 IT 部招"高级工程师"，Ada 面了三个人——会写代码的、有证书的、干了二十年的，三个人都答不上同一个问题："换个人，用同样的需求，交付的东西能和你质量相当吗？"旁听席上名片印着"高级工程师"的李工，忽然意识到这个问题自己这些年也没答上来过。**头衔不定义工程师；能力不中性，④定义方向。** 六项能力，一项一项亮起来，才是工程师。本章不发明新概念——把第2章那四层结构的尺子，量到"人"身上：四层各一项能力 + 横切⑤ + 元⑥，再加一项执行手段——沟通与团队（藏在④⑤⑥里，不是第七项能力）。

### 开场破题（对应章首误解现场）

念出恒信 IT 部那场面试：Ada 要招一名"高级工程师"。候选人甲是算法高手，笔试几乎满分，口答流畅得像背书——"会写代码的，不就是工程师吗？"候选人乙带着软考高级证书，职称评审的材料叠了一沓——"有职称、有证书，还不算工程师？"候选人丙干了二十年，项目数不清，可当 Ada 问到"你的判断，换个人接得住吗"，他答不上来——"干了这么多年，经验还不够吗？"Ada 问了三个人同一个问题："**换个人，用同样的需求，交付的东西能和你质量相当吗？**"三个人都沉默了。

让各组表态：三句话三个"工程师"，错在哪？大多数人一开始都会说"三个人各有道理，都算工程师"——这正是这一章要推翻的直觉：**三句话，三个错判据——"会写代码"把载体当成了判据，"有职称"把头衔当成了判据，"经验多"把年资当成了判据。** 定义在自己身上的都不稳，定义在能力上的才稳。

### 本单元要反转的直觉

- **会写代码的人，就是工程师**（× 写代码是载体不是判据；工程师判断在规则留白处）
- **有职称 / 有证书的人，就是工程师**（× 证书只证明考过一次试；头衔不定义工程师）
- **干了二十年，一定是好工程师**（× 二十年可能都在用手艺的壳子；判断依据换尺度才是长成）
- **工程师就是照着流程做的人**（× 那是技术员；工程师在规则没有覆盖的地方判断）
- **科学素养 = 懂很多公式 / 懂科学不被忽悠**（× 工程语境科学素养="做的东西凭什么能行、换上下文还成立吗"；公式可以查，判断依据成立与否不能外包）
- **方法论素养 = 会背方法论名词**（× 那是"方法论词典"；素养是把工作组织成方法，可教可学可治理）
- **工程判断 = 直觉 / 敢拍板 / 魄力**（× 判断要有依据（informed judgment），直觉只是线索；魄力是敢拍板，判断是拍得对、拍得能负责）
- **可复现 = 爱写文档 / 复制粘贴模板**（× 可复现的本质是"判断换个人能接住"；可复现的是方法不是结果）
- **工程师只要技术好，伦理是管理者的事**（× ④职业伦理是六项能力之一，缺了会出事）
- **职业伦理 = 背规章 / 算风险概率 / 服从组织**（× 规章背不完、压力时刻判断要在场；风险管理算概率、伦理定立场；NSPE 对公众负责，不是对老板负责）
- **能力越强的工程师越值得信赖**（× 能力不中性，④定义方向；能力越强、④越缺、越危险）
- **拿到工程师头衔，就是工程师了，一辈子都是**（× 被任命 ≠ 成为；能力一项项亮起来才是成为）
- **沟通 / 团队协作是锦上添花的软技能，技术强就够了**（× 沟通与团队不是第七项能力，是④⑤⑥的执行手段——不会沟通，④⑤⑥落不了地）
- **一个工程师好不好，聊一聊就能判断**（× 六项能力抽象不可直接检验；看产品数据——换个人能接着种）

### 本轮题卡的内在逻辑（10 题 2×5 + 方法时刻）

**第一组 · 概念与原理（先立概念）**：Q1 工程师是什么 + 三句错判据逐条翻（破题·概念本身）→ Q2 四种身份关系 + 沟通与团队执行手段（概念关系，含 ABET 交叉验证）→ Q3 头衔 vs 能力（真悖论·李工）→ Q4 能力强 vs 值得信赖（真悖论·老周）→ Q5 照单执行 vs 规则留白（真悖论·技术员分界 + 工程判断误区）。由"是什么"走到"为什么"。

**第二组 · 落地与实践（用尺量）**：Q6 双线判词逐项打勾（判据运用·六项体检，含⑥与②分工）→ Q7 失败四式各缺哪项（判据运用·四宗死法，含④误区三边界）→ Q8 成长尺 + 被任命 ≠ 成为（判据运用·成长路径）→ **Q9 方法时刻·反天赋论**（规则 15：判李工/老周再反身判自己团队——判词变体必启用，追问把"缺的项可补"落到六个培养循环）→ Q10 回部门六项体检 + 落判词（落地生根，含 1.8 执行手段）。判据运用 + 落地动作。

### 同类分组说明

产品组与 IT 组答同一组题，答案互为镜像。这一章的题尤其适合镜像对照：产品组的"手艺极致"是冰链老周——十五年温控产品，判断全在脑子里，缺②⑥；IT 组的"伪工程"是恒信李工——敏捷 CI/CD 方法论工具都在，缺①④⑥。**同一个六项能力清单，两个世界的两条判词——这正是"概念不挑行业"的现场证明**：老周是①③⑤顶配缺②⑥，李工是有②③缺①④⑥，量的是同一把尺子。产品组举"老师傅 / 硬件大牛"的例子，IT 组举"技术骨干 / 代码大牛"的例子——两边都容易用"会写代码 / 有证书 / 经验多"判人，都要翻到六项能力上；两边也都容易把"沟通 / 团队"当软技能加分项，都要翻到"④⑤⑥的执行手段"上。

## 二、题卡（打印分发）

**答题要求**：组内讨论 25 分钟 / 答案 ≤5 行 / 上台讲解 4–5 分钟 / 观点不同必须给理由。

### 第一组 · 概念与原理

**Q1｜"会写代码 / 有证书 / 经验多"，三句话三个"工程师"——错在哪？工程师到底是什么？**
"恒信 IT 部要招一名『高级工程师』，Ada 主持面试。候选人甲是算法高手，笔试几乎满分，口答流畅得像背书——『会写代码的，不就是工程师吗？』候选人乙带着软考高级证书，职称评审的材料叠了一沓——『有职称、有证书，还不算工程师？』候选人丙干了二十年，项目数不清，可当 Ada 问到『你的判断，换个人接得住吗』，他答不上来——『干了这么多年，经验还不够吗？』Ada 问了三个人同一个问题：『换个人，用同样的需求，交付的东西能和你质量相当吗？』三个人都沉默了。三句话三个『工程师』，错在哪？『工程师』到底是个什么样的物种？"

追问：① 六项能力清单——四层各一项 + 横切⑤ + 元⑥，怎么构成一个整体？每项各配一句判据（①科学素养"凭什么能行"为什么靠预测对账长出来——科学素养是"懂很多公式"吗）？② "会写代码 / 有证书 / 经验多"分别把什么当成了判据（载体 / 名义 / 年资）？③ 你们自己判断身边谁是工程师，用的是这三样里的哪样，还是看他开发出的产品数据（换个人能不能接着种）？

**Q2｜工程师和技术员、科学家、手艺人、会写代码的人，什么关系？沟通与团队是第七项能力吗？**
"请给出 工程师 和 技术员、科学家、手艺人、会写代码的人 这四种身份的关系，并说明：为什么说『写代码是载体不是判据』？六项能力里，⑤工程判断为什么是横切、⑥可复现意识为什么是元？ABET 把『沟通』与『团队』列为独立的工程师成果，六项能力清单为什么没有单列它们——它们是第七、第八项能力吗？"

追问：① 技术员和工程师的分界为什么不是学历（规则留白时谁来拍板）？② 手艺人 vs 工程师唯一分界=交付依赖不依赖具体的人——老周为什么不在这条线的工程师那边？③ 沟通与团队为什么是④⑤⑥的执行手段（④让相关方知情 / ⑤把取舍讲清楚 / ⑥让方法被接住）——一个判断做得对、说不清楚，等于做没做？④ 你们团队里"被当成工程师、其实是技术员/手艺人/会写代码的人"的例子，缺的是清单里的哪一项？

**Q3｜有头衔、有方法论、有工具，李工到底算不算工程师？**
"李工的名片上印着『高级工程师』，恒信还上了敏捷、CI/CD、测试——方法论和工具都在。可 Ada 面完三个人，旁听席上的李工也意识到：『换个人能交付吗』这个问题的答案，他这些年也没答上来过。有头衔、有方法论、有工具，到底算不算工程师？什么判据能分清『头衔』和『能力』？"

追问：① 头衔是组织发的位置（可印上可收走）、证书是社会认证（只证明考过一次试）、年资是时间累积——为什么三个都定义不了工程师？② 李工按六项能力清单：有②③、缺①④⑥——为什么方法论和工具都在，四层却站不稳（容量评估被砍 / 为进度悄悄牺牲可靠性没让相关方知情 / CI/CD 靠隐藏命令）？③ 你们部门里有没有"头衔先于能力"的人？拿掉头衔，他还立得住吗？

**Q4｜老周手艺极致、每个取舍都准——他是工程师吗？能力越强越值得信赖吗？**
"冰链的老周十五年温控产品，车间里没有一份完整测试方案，但他『心里有数』——哪个批次容易出问题、哪种工况要降额、哪家供应商不可靠，全在脑子里；他①科学素养顶配、③实践能力顶配、⑤工程判断顶配，每个取舍都准。他是工程师吗？『能力越强的工程师越值得信赖』对吗？还是『能力不中性，④定义方向』？"

追问：① 老周缺②⑥——为什么手艺的极致不是工程师的画像（做的能力不可复制；他的判断换个人就是做不出来）？② 737 MAX 不缺"会算的工程师"，缺"守住底线的工程师"——为什么能力放大的是选择的规模，方向由④定义？能力越强、④越缺，为什么越危险？③ 你们团队里技术最强的那个人，④职业伦理这条打过勾吗？

**Q5｜照着流程做，是工程师还是技术员？判断力好 = 敢拍板吗？**
"『工程师就是照着流程做的人』——有人说：流程全覆盖、照单执行，最不容易出错，这才是工程师。这一章却说：那是技术员；工程师在规则没有覆盖的地方做判断。哪个对？技术员和工程师的分界到底是什么？『判断力好 = 敢拍板、有魄力』对吗？"

追问：① 判断落在人身上是工程师、判断可完全交给规则是技术员——分界为什么不是学历？② ⑤工程判断的判据是"规则没有覆盖的地方能做对的取舍吗"——"先上再说"也是判断，为什么是坏的判断（没让相关方知情、没走评审）？③ 工程判断为什么不是直觉 / 规则决策树 / 魄力（直觉只是线索、判断要有依据；约束一变规则就失效；魄力是敢拍板，判断是拍得对、拍得能负责）？④ 你最近一次"规则留白"的决策，是你自己判断负责了，还是推给了流程？你判断的依据在哪个尺度（照做/会选/会取舍/守底线）？

### 第二组 · 落地与实践

**Q6｜给老周和李工下判词：两个人都是"缺"，缺的性质有什么不同？**
"用六项能力清单，给老周和李工下判词：老周是①③⑤顶配缺②⑥（手艺的极致），李工是有②③缺①④⑥（伪工程）。先把这两条判词逐项打勾验证，再说说：两个人都是『缺』，缺的性质有什么不同？谁更接近工程师？"

追问：① 老周的里子（判断顶配）vs 面子（不可复制）；李工的面子（方法能说清）vs 里子（守不住底线）——两个人都不是完整的工程师，那"在长成"是什么意思（都在用清单量自己、补缺项）？② 判词（案例进展①②③）和 3.5（产品数据）量的是同一把尺子——老周缺的②⑥和李工缺的①④⑥，各自露在产品数据的哪里？③ ⑥可复现意识为什么"不是爱写文档的习惯"——老周不写测试方案，是②不行还是⑥不行（②是"写成什么样"的本事、⑥是"必须写成那样"的自觉）？④ 你更接近哪条线？缺的是哪一项？

**Q7｜失败四式，每一宗死法缺的是清单里的哪一项？哪一宗最危险？"职业伦理就是背规章、算风险概率、服从组织"对吗？**
"失败四式——只会做不会说（手艺型）、只会说不做（PPT 工程师）、守不住底线（价值层失守）、能力失控（有能力的坏工程师）。用六项能力清单，说出每一宗死法缺的是哪一项。哪一宗最危险？为什么？『职业伦理就是背规章、算风险概率、服从组织』对吗？"

追问：① 手艺型死于判断不可接住（⑥缺席）——老周为什么不是被辞退，而是死于"团队发现他的判断不能复制"？② 守不住底线（④缺席）为什么最普遍也最隐蔽（症状不是不会做，是做的时候没守住；泰坦尼克/挑战者/737 MAX 的共同点）？③ ④为什么不是规章清单 / 风险管理 / 服从组织（规则背不完压力时刻判断要在场 / 风险管理算概率、伦理定立场，哪怕概率极低红线也不能越 / NSPE 对公众负责不是对老板负责——挑战者号里工程师反对发射、管理者施压）？④ 你最近一次技术决策更接近哪一宗？缺的是清单里的哪一项？

**Q8｜被任命"高级工程师"，为什么不等于成为工程师？怎么判断在不在长成？**
"李工被任命为『高级工程师』那天，名片换了、工资涨了——但 Ada 那个问题他还是答不上来。为什么『被任命』不等于『成为』？怎么判断一个人是不是真的在长成工程师（判断的依据在哪个尺度）？"

追问：① 成长的本质=判断的依据换尺度：怎么做→会选→会取舍→守底线——你判断的依据现在在哪个尺度？② 六项能力有叠加顺序：先③实践（读和听几乎不产生实践能力，只能从做里长——强度光谱到"独立做"判断才进场）、再①科学、然后⑤判断、接着⑥可复现、最后④伦理——④为什么放最后（它约束方向）？③ 你最近一次"为一件做了也没人反对的事说不"，是对自己还是对别人？

**Q9｜把六项能力清单变成判人的尺子：判李工、判老周、再反身判你们团队（方法时刻）**
"李工有『高级工程师』头衔、老周没头衔——可这一章的方法底座时刻是反天赋论：能力可检验、可训练，不是天生的；头衔不定义人。把六项能力清单从『背诵对象』变成『判人的尺子』：先用它判李工（缺哪几项？证据是什么？）、再判老周、最后反身判你自己的团队——谁缺哪一项？用什么判据检验（不是头衔、不是感觉）？"

追问（判词变体）：① 你给李工判"缺①④⑥"，证据各是什么（容量评估被砍 / 没让相关方知情没记录 / CI/CD 靠隐藏命令）？给老周判"缺②⑥"，证据是什么（方法不成体系 / 车间没有一份完整测试方案）？② 反身判团队：拿掉名片和年资，用六项逐项打勾——你们团队"最像工程师的人"缺哪一项？他正在长成的是哪一项？③ 反天赋论还意味着什么——缺的项能不能补？怎么补（①科学素养靠预测对账、②方法论走转化链/写SOP、③实践沿强度光谱从做里长、⑤判断走三步闭环+复盘、⑥靠交接演练、④写不可越线清单+决策留痕）？——能答全六项能力的四问、能用清单量别人量自己，才算拥有，这把尺子现在装进你手里了吗？

**Q10｜给你们部门做一次六项体检，落一条判词，配一个培养动作**
"结合你们部门现状，用六项能力体检表给一位『被当成工程师的人』（或你自己）做一次体检——逐项打勾，指出缺项，落一条判词（像老周缺②⑥还是像李工缺①④⑥？），给出最该先补的一项，落到一个动作。"

追问：① 六项体检 + 价值层三问（相关方知情/评审/记录）先查哪两项？② 你们的招聘/晋升，用的是六项判据，还是"会写代码/有证书/经验多"三个错判据？沟通与团队在你们的评估里，是独立加分项，还是④⑤⑥的执行手段（不会沟通，④⑤⑥能不能落地）？③ 两周后回来报告：谁打了勾、缺了哪项、补了哪个动作？

## 三、点评要点·讲师版

> 点评纪律：先表态后翻案 / 反转精确不造新误解 / 判据配机制 / 归责到可对照动作 / 教机制不教断言 / 先立尺子再翻案 / 拉开强度层次 / 每个纠正落到可操作动作 / 单一权威不另立标准 / 网搜当佐证。

### Q1 "会写代码 / 有证书 / 经验多"——错在哪？工程师到底是什么？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "三个人各有道理，都算工程师；Ada 问得太刁钻。" | 正是要翻的——把载体/名义/年资当判据 |
| 中 | 能说"工程师是把四层背在身上的人、有六项能力"，但说不清三句话各错在哪 | 清单背出来了，判据没用起来——没落到逐句翻 |
| 好 | "'会写代码'把载体当判据、'有职称'把头衔当判据、'经验多'把年资当判据——三个人都定义在自己身上；工程师=四层各一项+横切⑤+元⑥，判断换个人能接住才算；①科学素养不是懂公式，是靠预测对账练出来的。" | 三句错判据逐条翻 + 六项清单 + 试金石 + ①误区全咬合 |

**产品侧 vs IT侧**：产品组答"老周十五年经验不算工程师？"，IT 组答"李工有头衔有 CI/CD 不算工程师？"——两边都要翻"定义在自己身上的都不稳，定义在能力上的才稳"。**这一章是角色章，六项能力清单就是尺子，不是标签。**

**反转话术**（对应开篇枢纽 + 1.1 + 章末认知反转）：三句话三个"工程师"，错在同一个地方——**用一个"名义 / 载体"去定义一个"能力"**。"会写代码"把载体当成了判据；"有职称"把头衔当成了判据；"经验多"把年资当成了判据。Ada 问的那个问题——"换个人，用同样的需求，交付的东西能和你质量相当吗？"——问的是第2章试金石在"人"身上的落点：**可复现（⑥）**。三人都答不上来，因为他们都把"工程师"定义在了自己身上。**定义在自己身上的，都不稳；定义在能力上的，才稳。** 工程师首先是什么？**把四层结构背在身上的人**——第2章立过四层（工程科学 / 方法论 / 工具实践 / 价值与伦理），四层同时在场工程才成立；每一层长在一个人身上就是一项能力，四层四项 + 横切⑤工程判断 + 元⑥可复现意识，一共六项。**注意第一项就有个误区：科学素养不是"懂很多公式"**——公式可以查，"判断依据成立与否"不能外包；它靠**预测对账**长出来：改动前写下预测，事后对账找偏差，偏差先问"是哪条原理越了界"。这一章不再发明新概念，只做一件事：**把"工程师"这个人，放到第2章那把四层的尺子下面，量一遍。**

**参考答案要点**：工程师定义见 §1.1；六项能力清单见 §1.2~1.6 + 表 1.1；①科学素养误区与培养见 §1.2；章首误解现场；章末认知反转（见过→拥有）。

### Q2 四种身份什么关系？沟通与团队是第七项能力吗？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "工程师就是会写代码的、懂科学的技术员；沟通就是会说话。" | 关系结构错误——四种身份被混成一团，沟通当软技能 |
| 中 | 能说出"不是技术员 / 不是手艺人"，但科学家、会写代码的人没接上；沟通没接上④⑤⑥ | 边界磨了两对，另两对漏了；执行手段没点透 |
| 好 | "技术员照单执行、工程师在规则留白处判断；科学家研究现存世界、工程师创造未存在的世界；手艺人依赖个人、工程师可复现；会写代码只是载体不是判据；沟通与团队不是第七项能力，是④⑤⑥的执行手段——ABET 把它俩单列，是因为它俩藏在六项里、不是额外两项。" | 四对边界 + 载体/判据 + 沟通执行手段 + ABET 交叉验证全到位 |

**产品侧 vs IT侧**：产品组举"老师傅 = 手艺人"；IT 组举"能把需求翻译成代码的人 = 可能只是手艺人"。两边都要翻同一句——**判断落在人身上是工程师，判断可以完全交给规则，那是技术员。** 沟通这一问尤其适合镜像：产品组的工程师要跟供应商/产线/客户讲清约束，IT 组的工程师要跟法务/财务/业务把取舍讲清楚——**都是让④⑤⑥作用于组织的通道。**

**反转话术**（对应 2.1/2.2/2.3/2.4 + 1.8）：技术员照单执行——操作规程怎么写就怎么做，判据是什么就按什么判；工程师也执行，但在**规则没有覆盖的地方做判断**。分界不是学历，是"**规则留白时谁来拍板**"。科学家研究现存的世界，工程师创造从未存在的世界——**求真和求有用，是两种目标，也是两种物种**。手艺人靠个人经验与技巧，结果绑定在人身上；工程师靠可复现的方法，结果可以脱离具体的人——**唯一分界=交付依赖不依赖具体的人**。会写代码的人可能只是把需求翻译成程序的手艺人；**写代码是载体，不是判据**。再补一节最容易误读的：**沟通与团队不是第七、第八项能力**——ABET 把"沟通(3)/团队(5)"列为独立成果，六项清单没有单列它们，不是遗漏：**它们是④⑤⑥的执行手段**——④职业伦理要"让相关方知情"靠沟通、⑤工程判断要"把取舍讲清楚、让判断被记录"靠沟通、⑥可复现意识要"让方法被接住"靠沟通。**一个判断做得对，说不清楚，等于没做；一个方法写得出，不主动沟通，没人会用。** 沟通不是"会说话"，是让能力真正作用于组织的通道。

**参考答案要点**：不是技术员见 §2.1；不是科学家见 §2.2；不是手艺人见 §2.3；不是会写代码的人见 §2.4；沟通与团队=执行手段见 §1.8；ABET 7条交叉验证见 §1.1。

### Q3 有头衔、有方法论、有工具，李工到底算不算工程师？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "有头衔、有 CI/CD、有测试，当然是工程师。" | 正是要翻的——把名义+工具当能力 |
| 中 | "不算，因为换个人答不上来。" 结论对，判据缺 | 试金石对了，六项逐项打勾没出来 |
| 好 | "头衔可印上可收走、证书只证明考过一次、年资可能是手艺壳——三个都定义不了；李工按清单有②③缺①④⑥（容量评估被砍/为进度悄悄牺牲可靠性/CI/CD 靠隐藏命令），方法论工具都在四层却站不稳。" | 名义三件套 + 李工六项逐项 + 判据全到位 |

**产品侧 vs IT侧**：产品组举"车间老师傅没职称但活好"；IT 组举"有'高级工程师'头衔但系统一换人就跑不了"。两边都是同一把尺子——**判断可检验的不在名片上，在六项能力清单上。**

**反转话术**（对应 2.5 + 1.6 + 案例进展② + 3.3）：有头衔、有方法论、有工具——这些都在"名字"和"壳子"这一侧。三个名义各是什么：**头衔**是组织发给你的位置——你可以被印上"工程师"，也可以被收走；**证书**是社会给你的认证——它只证明你通过了一次考试，不证明你天天在做工程；**年资**是时间的累积——干了二十年，可能二十年都在用手艺的壳子。**判断一个人是不是工程师，可检验的不在名片上，在六项能力清单上。** 李工按清单逐项：有②方法论素养、③实践能力；缺①科学素养——容量评估被砍，他不追问"为什么能行"；缺④职业伦理——为进度悄悄牺牲可靠性，没让任何人知情；CI/CD 依赖张三的隐藏命令、李四的环境变量——⑥可复现同样站不住。**李工是有②③、缺①④⑥的人——方法论和工具都在，四层却站不稳。** 被任命只是拿到一张牌桌的入场券，能不能坐稳，靠六项能力清单。

**参考答案要点**：名义不定义能力见 §2.5；李工判词见案例进展② + 案例设定 §五/§九；被任命 ≠ 成为见 §3.3。

### Q4 老周手艺极致——他是工程师吗？能力越强越值得信赖吗？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "老周十五年经验、活漂亮，当然是好工程师；能力强就值得信赖。" | 正是要翻的——把经验/能力强当判据 |
| 中 | "老周不是工程师，因为不可复制。" 结论对，能力不中性没接上 | ⑥可复现对了，④定义方向缺 |
| 好 | "老周①③⑤顶配缺②⑥——手艺的极致不是工程师的画像；能力不中性，④定义方向：能力放大选择的规模，方向由④定义，737 MAX 不缺会算的工程师缺守住底线的工程师。" | 判词 + 能力不中性 + 事故机制全到位 |

**产品侧 vs IT侧**：产品组举"老周的降额判断全在脑子里"；IT 组举"某大牛的核心模块只有他会改"。两边都是同一件事——**个人厉害 ≠ 工程厉害：前者依赖人，后者可复制。**

**反转话术**（对应 1.6 + 3.4 + 案例进展①）：老周是手艺的极致——①科学素养顶配（懂原理）、③实践能力顶配（活做得漂亮）、⑤工程判断顶配（每个取舍都准）。但他缺②方法论素养——方法说不成体系；缺⑥可复现意识——判断换个人做不出来。**老周不是不会做，是做的能力不可复制——手艺的极致，不是工程师的画像。** "能力越强的工程师越值得信赖"错在哪？**能力不中性——能力放大的是"选择的规模"，而选择的方向由④职业伦理定义。** 一个①③⑤顶配、④却为零的人，破坏比"不会做"的人大得多：他会算、能做、判断准，只差守住底线。**737 MAX 里不缺"会算的工程师"，缺的是"守住底线的工程师"。** 四宗死法里最危险的是"能力失控"——因为他看起来最优秀。

**参考答案要点**：能力不中性见 §1.6；老周判词见案例进展①；能力失控死法见 §3.4。

### Q5 照着流程做，是工程师还是技术员？判断力好 = 敢拍板吗？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "流程全覆盖、照单执行最稳妥，这就是工程师；判断力好就是敢拍板。" | 正是要翻的——把技术员当工程师、把判断当魄力 |
| 中 | "工程师在流程外判断。" 结论对，分界机制浅 | "规则留白时谁来拍板"没点透；⑤误区没翻 |
| 好 | "技术员遇到表里没有的工况会停下来问，工程师要自己判断自己负责——分界不是学历是'规则留白时谁来拍板'；判断不是直觉/规则树/魄力——直觉只是线索、判断要有依据，约束一变规则就失效，魄力是敢拍板、判断是拍得对拍得能负责；方法必须留判断空间。" | 分界判据 + 判断留人 + ⑤误区 + 方法留白全到位 |

**产品侧 vs IT侧**：产品组举"按工艺卡执行的操作工 vs 处理异常工况的工程师"；IT 组举"按脚本执行的 DBA vs 规则没覆盖时拍板的架构师"。两边都是同一件事——**规则留白时，谁来拍板、谁来负责。**

**反转话术**（对应 2.1 + 1.5 + 3.1）："流程全覆盖、照单执行"最不容易出错——这句话对技术员成立，对工程师不成立。技术员遇到表里没有的工况，会停下来问；工程师遇到表里没有的工况，要自己判断、自己负责。**判断落在人身上，是工程师；判断可以完全交给规则，那是技术员。** 分界不是学历，是"规则留白时谁来拍板"。自查第4条"工程师就是照着流程做的人"——错，那是技术员。再翻一个流行的误区：**工程判断力好，不等于"敢拍板、有魄力"**——判断不是直觉拍脑袋（直觉只是线索，判断要有依据 informed judgment）、不是规则决策树（约束一变，写好的规则就失效）、更不是勇气魄力（魄力是敢拍板，判断是拍得对、拍得能负责）。好的工程判断是三步闭环：**识别约束 → 权衡取舍 → 担责闭环**（让人知情、走评审、留记录）。方法论也一样：**有章法不等于算法化，方法必须留判断空间**——写过头，就退化成"技术员照单执行"。

**参考答案要点**：不是技术员见 §2.1 + 自查第4条；工程判断（不是直觉/规则/魄力 + 三步闭环）见 §1.5；方法留判断空间见 §1.3。

### Q6 给老周和李工下判词——缺的性质有什么不同？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "两个人都挺厉害的，不好说谁不是工程师。" | 判词没落——清单没当尺子用 |
| 中 | "老周缺②⑥、李工缺①④⑥。" 判词对，性质没辨析 | 六项打勾了，"里子/面子"没接上 |
| 好 | "老周判断顶配不可复制=有里子缺面子；李工方法能说清守不住底线=有面子缺里子；两个都不是完整的工程师，都在用清单量自己、补缺项——判词和产品数据量的是同一把尺子；老周不写测试方案不是②不行是⑥缺（②是写成什么样的本事、⑥是必须写成那样的自觉）。" | 双线判词 + 性质辨析 + 长成含义 + 同一把尺子 + ⑥与②分工全到位 |

**产品侧 vs IT侧**：产品组说"老周缺的是'把判断交给别人'的本事"；IT 组说"李工缺的是'关键时刻护住'的胆量"。两边都是同一件事——**工程师不是一张头衔，是一份两项都站得住的清单。**

**反转话术**（对应 案例进展①②③ + 1.5⑥ + 3.5）：两份判词逐项验证：**老周**=①③⑤顶配、缺②⑥（手艺的极致）——有工程师的"里子"（判断顶配），缺"换个人能接住"的"面子"（不可复制）；**李工**=有②③、缺①④⑥（伪工程）——有工程师的"面子"（方法能说清），缺"关键时刻护住"的"里子"（守不住底线）。缺的性质不同：老周缺的是"可复制"（⑥）和"成体系"（②）——他缺的是"面子"；李工缺的是"为什么能行"（①）、"底线"（④）、"可复现"（⑥）——他缺的是"里子"。谁更接近工程师？**两个人都不是完整的工程师；但两个人都值得被叫一句"在成为工程师的路上"**——因为他们都在用六项能力清单量自己，都在补自己缺的那一项。**判词（案例进展①②③）和 3.5（产品数据），量的是同一把尺子**——老周缺的②⑥最终都露在产品数据上（没有成文的测试方案）；李工的文档都在但不可信（容量评估被砍、CI/CD 靠隐藏命令）。顺带磨一个⑥的误区：**可复现不是"爱写文档的习惯"**——老周也不是完全不会写（②会），他缺的是"必须写成那样"的自觉（⑥缺）；②是"写成什么样"的本事，⑥是"必须写成那样"的自觉——很多人②会、⑥缺，文档写得出来就是不写，那不是能力问题，是意识问题。

**参考答案要点**：双线判词见案例进展③ + 本章判词；⑥与②分工见 §1.5⑥；产品数据见 §3.5；角色画像见案例设定 §五。

### Q7 失败四式——每一宗死法缺哪一项？哪一宗最危险？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "失败就是干得不好，多练就行；伦理就是背规章。" | 没落到四式+缺项——把死法当"不努力" |
| 中 | "手艺型缺⑥、PPT 缺③、守不住缺④、失控缺方向。" 判词对，最危险那宗没说透 | 四式各配一项了，能力失控的机制缺 |
| 好 | "手艺型死于说不清（⑥不可接住）、PPT 死于做不了（③悬空）、守不住死于没底线（④）、能力失控死于方向偏（能力越强④越缺破坏越大）——最危险的是能力失控，因为他看起来最优秀；最隐蔽的是守不住，症状不是不会做是没守住；④不是规章清单/风险管理/服从组织——NSPE 对公众负责不是对老板负责。" | 四式缺项 + 最危险/最隐蔽机制 + ④误区三边界 + 事故对照全到位 |

**产品侧 vs IT侧**：产品组举"守不住：为赶上市砍可靠性测试"；IT 组举"守不住：为月底上线砍容量评估"。两边都是同一件事——**四宗死法每一种，都能在六项能力清单里找到缺的那一项。**

**反转话术**（对应 3.4 + 1.6）：四宗死法四宗姿态：**手艺型死于说不清**（⑥缺席——判断不可接住）、**PPT 工程师死于做不了**（③缺席——方法论悬空）、**守不住底线死于没底线**（④缺席——价值层失守）、**能力失控死于方向偏**（④定义方向——能力越强方向错破坏越大）。最危险的是"能力失控"——因为他看起来最优秀，判断越准、能力越强，方向错了破坏越大。最普遍也最隐蔽的是"守不住底线"——它的症状不是"不会做"，而是"做的时候没守住"：泰坦尼克按"不会沉"配救生艇、挑战者在工程师反对声中升空、737 MAX 在认证压力下轻描淡写——三起事故的共同点：**不是不会做，是守不住。** 再磨一个④的大误区：**职业伦理不是背规章、不是算风险概率、更不是服从组织**——规章背不完，压力时刻判断要在场；风险管理算概率，伦理定立场——哪怕概率极低，红线也不能越；NSPE 要求对公众负责，不是对老板负责——挑战者号里，工程师反对发射、管理者施压。每一种死法，都能在六项能力清单里找到缺的那一项。

**参考答案要点**：失败四式见 §3.4；④误区三边界见 §1.6；三大事故见第2章 §2.3；恒信"先上再说"见 §3.4 + 第2章 §2.4。

### Q8 被任命"高级工程师"，为什么不等于成为工程师？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "任命了就是工程师了，名片就是证明。" | 正是要翻的——把被任命当成为 |
| 中 | "头衔不等于能力。" 结论对，成长机制浅 | 成长尺（判断依据换尺度）没接上 |
| 好 | "头衔是入场券，能不能坐稳靠六项能力清单；成长=判断依据换尺度：怎么做→会选→会取舍→守底线；六项有叠加顺序、④放最后因为它约束方向——第一次在压力面前护住底线才是成为的那天。" | 被任命≠成为 + 成长尺 + 叠加顺序 + 成长标志全到位 |

**产品侧 vs IT侧**：产品组问"我们老师傅怎么往工程师长？"；IT 组问"应届生怎么往高级工程师长？"——两边是同一个答案：**判断的依据从'怎么做'升到'守什么'，物种就从执行者长成工程师。**

**反转话术**（对应 3.1/3.2/3.3）：被任命只给了一个名头，名头不给能力——**被任命只是拿到一张牌桌的入场券，能不能坐稳，靠六项能力清单。** 怎么判断一个人是不是真的在长成？看**判断的依据在哪个尺度**：新手问"这一步怎么做"（照单执行）、熟手问"这一步有几种做法"（会选）、资深问"这里该不该取舍"（会权衡）、工程师问"这个取舍守不守得住底线"（守底线）。**判断的依据从"怎么做"升到"守什么"，你的物种就从执行者长成了工程师。** 六项能力有自然叠加顺序：先③实践、再①科学素养、然后⑤工程判断、接着⑥可复现、最后④职业伦理——**④为什么放最后？因为它最贵**，它约束的不是"你会不会做"，而是"你做的方向"。③为什么最先？**实践能力只能从"做"里长，读和听几乎不产生它**——强度光谱从阅读爬到"独立做"判断才进场，到"救火"才练出排错定力。成长的标志，是第一次为一件"做了也没人反对"的事说不——而那个"不"的第一个对象，常常是自己的冲动。**第一次在压力面前护住底线，是你真正成为工程师的那一天。**

**参考答案要点**：成长路径见 §3.1；叠加顺序见 §3.2；③强度光谱见 §1.4；被任命 ≠ 成为见 §3.3；反天赋论见开篇枢纽。

### Q9 把清单变成判人的尺子：判李工、判老周、再反身判团队（方法时刻 · 规则 15）

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | 背书上的判词："老周缺②⑥、李工缺①④⑥。" | 只答了"是什么"，没做"判人"这个动作——清单还是背诵对象 |
| 中 | 能判李工老周，但反身判团队时只能举例、说不出判据 | 判人有证据，判自己团队"是不是/凭什么"说不清 |
| 好 | "判李工缺①④⑥，证据是容量评估被砍/没让相关方知情没记录/CI/CD 靠隐藏命令；判老周缺②⑥，证据是方法不成体系/没有一份完整测试方案；反身判团队：拿掉名片年资逐项打勾——某人⑥没打勾=手艺型，正在补的是写文档/做交接——缺项可补，①预测对账/②转化链/③强度光谱/⑤三步闭环+复盘/⑥交接演练/④不可越线清单。" | 立判据判人 + 反身判团队 + 反天赋论（六项培养循环落地）全到位 |

**产品侧 vs IT侧**：产品组给老周判词时自然写"判断全在脑子里，车间没有测试方案"；IT 组给李工判词时自然写"CI/CD 靠隐藏命令"。两边立出的判据结构相同——**这就是本章方法时刻的核心：不考"方法名能不能背"，考"方法会不会用"；清单是判人的尺子，不是背诵的对象。**

**反转话术**（对应 方法底座时刻 = 反天赋论 + 案例进展①②③ + 章末见过→拥有）：这是本单元的**方法时刻**——前面八题在讲"工程师是什么"，这一题让你们亲手做一遍方法底座时刻：**反天赋论**。李工有头衔、老周没头衔——可**头衔不定义人：能力可检验、可训练，不是天生的**；把六项能力列成清单，就是为了让你一项一项亮起来。判词变体：**用清单判人，再把尺子转向自己**——判李工：缺①④⑥，判据是"容量评估被砍"（①——不追问为什么能行）、"没让相关方知情、没记录"（④——为进度悄悄牺牲可靠性）、"CI/CD 靠隐藏命令"（⑥——换个人接不住），**不是头衔、不是感觉**；判老周：缺②⑥，判据是"方法说不成体系""车间没有一份完整测试方案"（②⑥）。再反身判自己团队：谁缺哪一项？证据是什么？怎么检验？——**有标签是见过，能答全六项能力的四问（各是什么、不是什么、判据是什么）、能用清单量别人量自己，才算拥有。** 反天赋论还意味着什么？**缺的项可以补，每项配一个培养循环**——①科学素养靠**预测对账**（改动前写预测、事后对账）、②方法论走**转化链**（隐性判断→显性化→标准化→组织能力；写 SOP 交给同事照做）、③实践沿**强度光谱**从做里长（到"独立做"判断进场）、⑤判断走**三步闭环 + 复盘**（识别约束→权衡取舍→担责闭环；做错的决定+认真复盘 > 做对的决定+不复盘）、⑥靠**交接演练**（写交接包，写不出的地方=没想清楚的地方）、④写**不可越线清单 + 决策留痕**（谁知情/评审/记录）。这把尺子现在装进你手里了。

**参考答案要点**：方法底座时刻（反天赋论）见 00-案例设定 §三 第8章行 + 开篇枢纽；判词见案例进展①③ + 案例设定 §五/§九；六项培养循环见 §1.2~1.6；见过→拥有见章末认知反转。

### Q10 给你们部门做一次六项体检，落一条判词，配一个培养动作

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | 泛泛"要加强培训、要多招人、要会沟通。" | 没落到六项体检任何一项，不可检查 |
| 中 | 用一把尺子查出问题（如"某同事的 CI/CD 只有他会跑"） | 有判据，但只照了一面 |
| 好 | 按六项逐项打勾、落判词（"像老周缺②⑥——判断换个人接不住"）、挑最该先补一项 + 一个可检查动作（"把某模块的决策写成 ADR，指定一个接手人，两周后让他独立改一次"）、说清先查哪两项、两周后报告什么；沟通/团队不是加分项，而是④⑤⑥落地的通道 | 体检完整，判词落地，动作可执行，有复查机制，执行手段嵌进每项 |

**产品侧 vs IT侧**：两组各给自己部门体检——体检表是同一份（六把尺子 + 价值层三问 + 执行手段判据），这正是"概念不挑行业"的现场证明：**产品组的判词叫"手艺极致缺②⑥"，IT 组的判词叫"伪工程缺①④⑥"，量的是同一把尺子。**

**反转话术**（对应 3.5 + 1.8 + 本章判据 + 作业指南）：六项能力抽象在一个人身上，**不可直接检验**——面试会看走眼，领导会凭印象打分。能力的最终体现，是**能否设计开发出本角色负责的产品数据（文档）**。第6章立过一棵树：枝干是概要定义（管结构），叶子是详细定义（管内容、可验证）——工程师的工作，就是把这棵树种出来：用分解、分配、分析三个动作，把需求长成可检验的叶子。**换个人，拿着你负责的那套产品数据，能不能把产品做出来、继续演进？** 能，你的能力成立；不能，你只是手艺人。你们部门体检，先查哪两项？六项体检 + 价值层三问（相关方知情/评审/记录）——**"没有记录"的地方，就是④可能缺席、也是①和⑥最容易现形的地方。** 你们的招聘/晋升，用的是六项判据，还是"会写代码/有证书/经验多"三个错判据？——这正是章首 Ada 那场面试要翻的东西。最后，**沟通与团队不是独立加分项，是④⑤⑥的执行手段**——不会沟通，④让相关方知情落不了地、⑤把取舍讲清楚落不了地、⑥让方法被接住落不了地；评估一个人，别把"沟通好"当第七项能力，要看它有没有把④⑤⑥真正作用到组织上。每个缺项配一个培养动作（①预测对账 / ②转化链·写SOP / ③强度光谱 / ⑤三步闭环+复盘 / ⑥交接演练 / ④不可越线清单）——**反天赋论：能力是练出来的。**

**参考答案要点**：产品数据见 §3.5；六项能力在"种树"里的落点见 §3.5 表；沟通与团队执行手段见 §1.8；作业指南见本章分析文档第 6 步；判据见"本章判据"。

### 金句（书"本章判据"提炼）

- **工程师不是一个头衔，不是一沓证书，不是多少年的经验。它是把四层结构背在身上、关键时刻守得住底线、判断换个人也能接住的人。**
- 六项能力体检：①科学素养——我做的东西凭什么能行？②方法论素养——我的方法能被别人学会吗？③实践能力——我最近一次亲手落地是什么时候？④职业伦理——压力面前我会为进度悄悄牺牲可靠性吗？⑤工程判断——规则没有覆盖的地方我能做对的取舍吗？⑥可复现意识——我的判断换个人能接住吗？
- **能力不中性，④定义方向**——能力放大的是选择的规模，方向由④定义；能力越强、④越缺、破坏越大（737 MAX 不缺会算的工程师，缺守住底线的工程师）。
- 角色判据：**如果你不在，交付还能不能维持？能，你是工程师；不能，你是手艺人——哪怕你也会写代码、画图纸。**
- 价值层失守三问：**相关方知不知情？有没有评审？有没有记录？**——客观原因不留记录；失守恰恰发生在"没有记录"的地方。
- 成长尺：判断的依据在哪个尺度——**照做 / 会选 / 会取舍 / 守底线**？从"怎么做"升到"守什么"，才是长成。
- 沟通与团队：**不是第七项能力，是④⑤⑥的执行手段**——一个判断做得对，说不清楚，等于没做；一个方法写得出，不主动沟通，没人会用。
- 终极尺：**能力再强，也要看我能不能开发出高质量的产品数据——换个人，拿着它，能不能做出来、继续演进？**
- 反天赋论：**能力可检验、可训练，不是天生的**——头衔不定义人；缺的项可补（①预测对账 / ②转化链 / ③强度光谱 / ⑤三步闭环+复盘 / ⑥交接演练 / ④不可越线清单），把清单一项一项亮起来，才是工程师。

## 五、课后作业

1. **书练习（与题卡同源）**：用六项能力，给"你们公司最像工程师的人"做一次体检——逐项打勾，指出缺项，判断他走在哪条路上（若对象换成老周或李工，体检结果会是"缺②⑥"还是"缺①④⑥"？）。（书练习 1）
2. **书练习**：角色边界演练——在你们团队里，找一个"被当成工程师、其实是技术员/手艺人/会写代码的人"的例子，说出他缺的是哪一项。（书练习 2）
3. **回部门落地**：结合现状，用六项能力体检表给一位"被当成工程师的人"（或你自己）做一次体检——逐项打勾、指出缺项、落一条判词（像老周缺②⑥还是像李工缺①④⑥？）、给出最该先补的一项，**配一个培养动作**。**两周后回来报告**：谁打了勾、缺了哪项、补了哪个动作、效果如何。

### 作业指南（回部门落地的步骤 + 话术）

> 照着做，60 分钟完成一次六项体检 + 落判词 + 配培养动作：
>
> 1. **挑对象（先立枢纽）**：选团队里"公认最像工程师的人"——最像的，往往也最容易在某一项打不上勾。
> 2. **项目一 · 六项体检打勾**（每题带"沟通/团队"执行手段的落点）：①科学素养——他做的东西"凭什么能行"能讲出原理吗（靠预测对账练，不是懂公式）？②方法论素养——他的方法能被别人学会吗（写 SOP 给同事照做，看卡在哪一步）？③实践能力——他最近一次亲手落地是什么时候（强度光谱到"独立做"了吗）？④职业伦理——压力面前会为进度牺牲可靠性吗（不可越线清单/决策留痕）？⑤工程判断——规则没覆盖的地方能做对取舍吗（三步闭环：识别约束→权衡取舍→担责闭环）？⑥可复现意识——他的判断换个人能接住吗（交接演练：写交接包，写不出的地方=没想清楚的地方）？
> 3. **项目二 · 落判词**：对照两条基准线——老周①③⑤顶配缺②⑥（手艺极致）、李工有②③缺①④⑥（伪工程）——你的对象像哪条线？缺的是哪一项？**话术**："他不是不会做，是做的能力不可复制"（像老周）/ "他不是不会说，是说的和做的对不上"（像李工）。
> 4. **项目三 · 反身自检**：用同一张清单给自己打勾——你缺的那一项，正是你在"背清单"而不是"用清单"的地方（反天赋论：缺的项可补，能力是练出来的）。
> 5. **项目四 · 配一个培养动作（反天赋论落地）**：给最缺的一项配一个可执行动作——①缺就做预测对账（改动前写预测、事后对账）；②缺就走转化链（把最近一次做对的事写成 SOP 交给同事照做）；③缺就沿强度光谱补"独立做"（从零复现一个已知功能）；⑤缺就记决策日记（约束打架/选哪个/后果/重来选什么）+ 案例裁决；⑥缺就做交接演练（写交接包）；④缺就写不可越线清单 + 决策留痕（谁知情/评审/记录）。
> 6. **项目五 · 落到产品数据**：问最后一个问题——他/你开发的产品数据（文档/代码/工艺），换个人拿着能接着种吗？这是六项能力唯一可检验的落点。
> 7. **出体检报告**：六项各打勾/缺项，落判词，最该先补最缺的一项 + 配一个培养动作；两周后复查补了什么。
>
> 卡住时：打不上勾的那一项就是最该补的；⑥打不上勾=手艺型（判断换个人接不住），④打不上勾=最危险（能力越强方向越偏）；价值层三问（相关方知情/评审/记录）当场打勾——"没有记录"的地方就是④可能缺席、也是①和⑥最容易现形的地方。
