## 一、单元导读

### 主题

这一章回答一个每个人都躲不开的问题：**工程师，到底是个什么样的物种？** 恒信 IT 部招"高级工程师"，徐漾面了三个人——会写代码的、有证书的、干了二十年的，三个人都答不上同一个问题："换个人，用同样的需求，交付的东西能和你质量相当吗？"旁听席上名片印着"高级工程师"的万辉，忽然意识到这个问题自己这些年也没答上来过。**头衔不定义工程师；能力不中性，④定义方向；工程师不是铁板一块——一个物种，三种粒度。** 六项能力，一项一项亮起来，才是工程师。本章不发明新概念——把第2章那四层结构的尺子，量到"人"身上：四层各一项能力 + 横切⑤ + 元⑥，再加一项执行手段（沟通与团队，藏在④⑤⑥里，不是第七项能力）；再把"工程师"这个物种按粒度划开——模块工程师、系统工程师、系统架构师，背的是同一副骨架，账却不是同一本。

### 开场破题（对应章首误解现场）

念出恒信 IT 部那场面试：徐漾要招一名"高级工程师"。候选人甲是算法高手，笔试几乎满分，口答流畅得像背书——"会写代码的，不就是工程师吗？"候选人乙带着软考高级证书，职称评审的材料叠了一沓——"有职称、有证书，还不算工程师？"候选人丙干了二十年，项目数不清，可当徐漾问到"你的判断，换个人接得住吗"，他答不上来——"干了这么多年，经验还不够吗？"徐漾问了三个人同一个问题："**换个人，用同样的需求，交付的东西能和你质量相当吗？**"三个人都沉默了。

让各组表态：三句话三个"工程师"，错在哪？大多数人一开始都会说"三个人各有道理，都算工程师"——这正是这一章要推翻的直觉：**三句话，三个错判据——"会写代码"把载体当成了判据，"有职称"把头衔当成了判据，"经验多"把年资当成了判据。** 定义在自己身上的都不稳，定义在能力上的才稳。

冰链车间，这句话天天被验证：李旭要验证，翻遍台账找不到成文测试方案，只能拉水忠口述；逸人排量产，第一句总问"水忠哪天在厂里"，他不在没人敢签字放行；文正主持评审，收尾总追问"水忠，你确认？"；董勐盯云端读数，一不对头第一个电话就打给水忠——四个人都绕不开"心里有数"，而那恰恰是换个人接不住的地方。

### 本单元要反转的直觉

- **会写代码的人，就是工程师**（× 写代码是载体不是判据；工程师判断在规则留白处）
- **有职称 / 有证书的人，就是工程师**（× 证书只证明考过一次试；头衔不定义工程师）
- **干了二十年，一定是好工程师**（× 二十年可能都在用手艺的壳子；判断依据换尺度才是长成）
- **工程师就是照着流程做的人**（× 那是技术员；工程师在规则没有覆盖的地方判断）
- **工程师和科学家是一回事，都是求真**（× 科学家研究现存世界，工程师创造未存在的世界）
- **科学素养 = 懂很多公式 / 懂科学不被忽悠**（× 工程语境科学素养="做的东西凭什么能行、换上下文还成立吗"；公式可以查，判断依据成立与否不能外包）
- **方法论素养 = 会背方法论名词**（× 那是"方法论词典"；素养是把工作组织成方法，可教可学可治理）
- **工程判断 = 直觉 / 敢拍板 / 魄力**（× 判断要有依据（informed judgment），直觉只是线索；魄力是敢拍板，判断是拍得对、拍得能负责）
- **可复现 = 爱写文档 / 复制粘贴模板**（× 可复现的本质是"判断换个人能接住"；可复现的是方法不是结果）
- **工程师只要技术好，伦理是管理者的事**（× ④职业伦理是六项能力之一，缺了会出事）
- **职业伦理 = 背规章 / 算风险概率 / 服从组织**（× 规章背不完、压力时刻判断要在场；风险管理算概率、伦理定立场；NSPE 对公众负责，不是对老板负责）
- **能力越强的工程师越值得信赖**（× 能力不中性，④定义方向；能力越强、④越缺、越危险）
- **拿到工程师头衔，就是工程师了，一辈子都是**（× 被任命 ≠ 成为；能力一项项亮起来才是成为）
- **工程师是铁板一块，没有粒度之分**（× 一个物种三种粒度——模块工程师/系统工程师/系统架构师，背同一副骨架，账不是同一本：专责 vs 终责）
- **模块工程师也要做架构、做确认、做部署、做集成**（× 分形不对称：模块级没有架构/确认/部署/集成——少的是四样结构件，不是少判断）
- **系统工程师是比模块工程师更高的职级；从模块到系统是升职**（× 粒度不是职级是责任性质；成长是拓宽不是升职；往系统走/往管理走是分叉，方向正交没有高低）
- **沟通 / 团队协作是锦上添花的软技能，技术强就够了**（× 沟通与团队不是第七项能力，是④⑤⑥的执行手段——不会沟通，④⑤⑥落不了地）
- **一个工程师好不好，聊一聊就能判断**（× 六项能力抽象不可直接检验；看产品数据——换个人能接着种）

### 本轮题卡的内在逻辑（10 题 2×5 + 方法时刻）

**第一组 · 概念与原理（先立概念）**：Q1 工程师是什么 + 三句错判据逐条翻（破题·概念本身）→ Q2 四种身份关系 + 沟通与团队执行手段（概念关系，含 ABET 交叉验证）→ Q3 一个物种三种粒度（真悖论·粒度谱系，含分形不对称 + 系统工程师四动词）→ Q4 能力强 vs 值得信赖（真悖论·水忠）→ Q5 照单执行 vs 规则留白（真悖论·技术员分界 + 工程判断误区）。由"是什么"走到"为什么"。

**第二组 · 落地与实践（用尺量）**：Q6 双线判词逐项打勾 + 粒度语境（判据运用·六项体检 + 三粒度）→ Q7 三粒度责任矩阵定位团队（判据运用·粒度尺 + 产品数据终极尺）→ Q8 失败四式 + 拓宽 vs 升职 + 成长尺（判据运用·四宗死法 + 成长方向）→ **Q9 方法时刻·反天赋论**（规则 15：判万辉/水忠再反身判自己团队——判词变体必启用，追问把"缺的项可补"落到六个培养循环，跨域变体酌情）→ Q10 回部门工程师体检 + 粒度定位 + 拓宽自测（落地生根，含 1.8 执行手段）。判据运用 + 落地动作。

### 同类分组说明

产品组与 IT 组答同一组题，答案互为镜像。这一章的题尤其适合镜像对照：产品组的"手艺极致"是冰链水忠——十五年温控产品，判断全在脑子里，缺②⑥，模块工程师岗位却在干系统级的活（拓宽中）；IT 组的"伪工程"是恒信万辉——敏捷 CI/CD 方法论工具都在，缺①④⑥，名片印着架构师却缺底座。**同一个六项能力清单 + 同一副粒度骨架，两个世界的两条判词——这正是"概念不挑行业"的现场证明。** 产品组举"老师傅 / 硬件大牛"的例子，IT 组举"技术骨干 / 代码大牛"的例子——两边都容易用"会写代码 / 有证书 / 经验多"判人，都要翻到六项能力上；两边也都有"模块/系统"粒度之分（产品组：负责一个零件的工程师 vs 负责整机的系统工程师；IT 组：负责一个服务的开发者 vs 负责整个系统成败的系统工程师），都要翻到"粒度 × 责任"上。跨域变体自然涌现：水忠的判词拿到恒信、万辉的判词拿到冰链，判据变没变——不变，说明这张尺子不挑行业。

## 二、题卡（打印分发）

**答题要求**：组内讨论 25 分钟 / 答案 ≤5 行 / 上台讲解 4–5 分钟 / 观点不同必须给理由。

### 第一组 · 概念与原理

**Q1｜"会写代码 / 有证书 / 经验多"，三句话三个"工程师"——错在哪？工程师到底是什么？**
"恒信 IT 部要招一名『高级工程师』，徐漾主持面试。候选人甲是算法高手，笔试几乎满分，口答流畅得像背书——『会写代码的，不就是工程师吗？』候选人乙带着软考高级证书，职称评审的材料叠了一沓——『有职称、有证书，还不算工程师？』候选人丙干了二十年，项目数不清，可当徐漾问到『你的判断，换个人接得住吗』，他答不上来——『干了这么多年，经验还不够吗？』徐漾问了三个人同一个问题：『换个人，用同样的需求，交付的东西能和你质量相当吗？』三个人都沉默了。三句话三个『工程师』，错在哪？『工程师』到底是个什么样的物种？"

追问：① 六项能力清单——四层各一项 + 横切⑤ + 元⑥，怎么构成一个整体？每项各配一句判据（①科学素养"凭什么能行"为什么靠预测对账长出来——科学素养是"懂很多公式"吗）？② "会写代码 / 有证书 / 经验多"分别把什么当成了判据（载体 / 名义 / 年资）？③ 你们自己判断身边谁是工程师，用的是这三样里的哪样，还是看他开发出的产品数据（换个人能不能接着种）？

**Q2｜工程师和技术员、科学家、手艺人、会写代码的人，什么关系？沟通与团队是第七项能力吗？**
"请给出 工程师 和 技术员、科学家、手艺人、会写代码的人 这四种身份的关系，并说明：为什么说『写代码是载体不是判据』？六项能力里，⑤工程判断为什么是横切、⑥可复现意识为什么是元？ABET 把『沟通』与『团队』列为独立的工程师成果，六项能力清单为什么没有单列它们——它们是第七、第八项能力吗？"

追问：① 技术员和工程师的分界为什么不是学历（规则留白时谁来拍板）？② 手艺人 vs 工程师唯一分界=交付依赖不依赖具体的人——水忠为什么不在这条线的工程师那边？③ 沟通与团队为什么是④⑤⑥的执行手段（④让相关方知情 / ⑤把取舍讲清楚 / ⑥让方法被接住）——一个判断做得对、说不清楚，等于做没做？④ 你们团队里"被当成工程师、其实是技术员/手艺人/会写代码的人"的例子，缺的是清单里的哪一项？

**Q3｜一个物种，三种粒度——模块工程师、系统工程师、系统架构师，谁"更高"？**
"『工程师就是工程师，一个统一的物种——模块工程师是低配、系统工程师是高配』——还是『一个物种，三种粒度，背同一副骨架，账却不是同一本』？模块工程师和系统工程师，到底谁『更高』？『系统工程师是比模块工程师更高的职级』对吗？什么判据能分清这三种粒度？"

追问：① 三种粒度各负什么责——模块负元素实现（专责 responsibility，可委托可追责）、系统负系统成败（终责 accountability，不可委托）、架构负结构演化（专责）？为什么说『终责是甩不掉的账，专责是划得清的账』？② 模块工程师为什么是系统工程师的『分形』（迷你系统工程师——模块级也跑完整闭环：模块需求→模块设计→模块实现→模块验证）？分形为什么不对称——模块为什么没有 架构 / 确认 / 部署 / 集成（上层已分配 / 真实使用环境是系统级 / 部署是系统级行为 / 集成是系统级把模块装起来）？③ 系统工程师这个人怎么识别——24765 说他是『实践系统工程学科的个人，与其正式头衔无关』；四动词（转化 / 统筹 / 把关 / 守护）和 INCOSE 六件事里，为什么没有一件是『亲手写代码』？④ 水忠的岗位是模块工程师，却在干系统级的事（老规矩 / 拦直连）——他的『名片粒度』和『实际粒度』一致吗？你们团队里有这样的人吗？

**Q4｜水忠手艺极致、每个取舍都准——他是工程师吗？能力越强越值得信赖吗？**
"冰链的水忠十五年温控产品，车间里没有一份完整测试方案，但他『心里有数』——哪个批次容易出问题、哪种工况要降额、哪家供应商不可靠，全在脑子里；他①科学素养顶配、③实践能力顶配、⑤工程判断顶配，每个取舍都准。他是工程师吗？『能力越强的工程师越值得信赖』对吗？还是『能力不中性，④定义方向』？"

追问：① 水忠缺②⑥——为什么手艺的极致不是工程师的画像（做的能力不可复制；他的判断换个人就是做不出来）？② 737 MAX 不缺"会算的工程师"，缺"守住底线的工程师"——为什么能力放大的是选择的规模，方向由④定义？能力越强、④越缺，为什么越危险？③ 你们团队里技术最强的那个人，④职业伦理这条打过勾吗？

**Q5｜照着流程做，是工程师还是技术员？判断力好 = 敢拍板吗？**
"『工程师就是照着流程做的人』——有人说：流程全覆盖、照单执行，最不容易出错，这才是工程师。这一章却说：那是技术员；工程师在规则没有覆盖的地方做判断。哪个对？技术员和工程师的分界到底是什么？『判断力好 = 敢拍板、有魄力』对吗？"

追问：① 判断落在人身上是工程师、判断可完全交给规则是技术员——分界为什么不是学历？② ⑤工程判断的判据是"规则没有覆盖的地方能做对的取舍吗"——"先上再说"也是判断，为什么是坏的判断（没让相关方知情、没走评审）？③ 工程判断为什么不是直觉 / 规则决策树 / 魄力（直觉只是线索、判断要有依据；约束一变规则就失效；魄力是敢拍板，判断是拍得对、拍得能负责）？方法论为什么也必须留判断空间（写过头就退化成"技术员照单执行"）？④ 你最近一次"规则留白"的决策，是你自己判断负责了，还是推给了流程？你判断的依据在哪个尺度（照做/会选/会取舍/守底线）？

### 第二组 · 落地与实践

**Q6｜给水忠和万辉下判词：两个人都是"缺"，缺的性质有什么不同？粒度定位各是什么？**
"用六项能力清单，给水忠和万辉下判词：水忠是①③⑤顶配缺②⑥（手艺的极致），万辉是有②③缺①④⑥（伪工程）。先把这两条判词逐项打勾验证，再说说：两个人都是『缺』，缺的性质有什么不同？放进三粒度谱系看，他们的粒度定位各是什么？谁更接近工程师？"

追问：① 水忠的里子（判断顶配）vs 面子（不可复制）；万辉的面子（方法能说清）vs 里子（守不住底线）——两个人都不是完整的工程师，那"在长成"是什么意思（都在用清单量自己、补缺项）？② 粒度语境：水忠是模块工程师的岗位、做着系统工程师的活（拓宽中，专责称职、终责未接）——他缺的②⑥正是"把模块的活干成系统的活"所缺的成文能力；万辉的名片是架构师（系统架构师粒度）、缺的却是架构师最不能缺的底座①④⑥——底座缺一块，第16章的增量全是空转。这说明了什么？③ 判词（案例进展①②③）和 3.5（产品数据）量的是同一把尺子——水忠缺的②⑥和万辉缺的①④⑥，各自露在产品数据的哪里？④ 你更接近哪条线？你的名片粒度和实际粒度一致吗？

**Q7｜用粒度尺给团队做粒度定位：谁背专责、谁背终责？产品数据按粒度分账了吗？**
"用粒度尺（判据7）给你们的团队做一次粒度定位：模块工程师背的是模块级 7 项主责，系统工程师背的是系统级 13 项（主责兼终责），系统架构师背的是系统架构（主责，第16章展开）。你们团队的核心成员各在哪个粒度？谁『名片一个粒度、实际另一个粒度』？谁的账是专责、谁的账是终责？系统工程师为什么是唯一横跨两层的角色？"

追问：① 为什么系统工程师是唯一横跨两层的角色——系统级 13 项几乎全是他主责、模块级 7 项全部由他"批准"（模块工程师干活、他验收）？『谁负责的东西最多、又给别人的东西签字，谁就是那个兜底的』——终责（accountability）的落点在哪里？② 粒度隔离为什么是模块化的意义——系统工程师不需要知道模块内部细节，只需要接口和验证结果；模块在自己的边界内自治、把成果交上去？③ 水忠的产品数据漏在模块级和系统级交界的地方——模块级没有成文的测试方案（缺②⑥，手艺不出纸面）、系统级的事做了也没有成文系统数据——他的产品数据『薄』在哪？换个人拿着他的东西能接着种吗（终极尺）？④ 你负责的那个粒度，产品数据换个人能接着种吗？

**Q8｜失败四式，每一宗死法缺的是清单里的哪一项？"从模块到系统是升职"对吗？**
"失败四式——只会做不会说（手艺型）、只会说不做（PPT 工程师）、守不住底线（价值层失守）、能力失控（有能力的坏工程师）。用六项能力清单，说出每一宗死法缺的是哪一项。哪一宗最危险？为什么？『从模块到系统是升职，升不上去才走架构线』对吗？"

追问：① 手艺型死于判断不可接住（⑥缺席）——水忠为什么不是被辞退，而是死于"团队发现他的判断不能复制"？② 守不住底线（④缺席）为什么最普遍也最隐蔽（症状不是不会做，是做的时候没守住；泰坦尼克/挑战者/737 MAX 的共同点）？④为什么不是规章清单 / 风险管理 / 服从组织（规则背不完压力时刻判断要在场 / 风险管理算概率、伦理定立场 / NSPE 对公众负责不是对老板负责——挑战者号里工程师反对发射、管理者施压）？③ 拓宽 vs 升职——成长是『拓宽』（视角换轨 + 责任接管，从对"我的模块"负责切到对"整个系统"负责，优化目标从单点最优到系统最优）不是『升职』（组织换位置）；换轨标志=第一次为系统牺牲自己的模块还觉得值；分叉不是阶梯（往系统走 vs 往管理走正交，没有高低）——为什么『升不上去才走架构线』是错的？④ 你判断的依据在哪个尺度（照做/会选/会取舍/守底线）？你最近一次"为系统牺牲自己的模块"是什么时候？有没有那次"还觉得值"？

**Q9｜把六项能力清单变成判人的尺子：判万辉、判水忠、再反身判你们团队（方法时刻）**
"万辉有『高级工程师』头衔、水忠没头衔——可这一章的方法底座时刻是反天赋论：能力可检验、可训练，不是天生的；头衔不定义人。把六项能力清单从『背诵对象』变成『判人的尺子』：先用它判万辉（缺哪几项？证据是什么？）、再判水忠、最后反身判你自己的团队——谁缺哪一项？用什么判据检验（不是头衔、不是感觉）？"

追问（判词变体）：① 你给万辉判"缺①④⑥"，证据各是什么（容量评估被砍 / 没让相关方知情没记录 / CI/CD 靠隐藏命令）？给水忠判"缺②⑥"，证据是什么（方法不成体系 / 车间没有一份完整测试方案）？② 判词加粒度语境：水忠=模块工程师岗位拓宽中（①③⑤顶配缺②⑥），万辉=架构师头衔缺底座（有②③缺①④⑥）——同一个清单，为什么量出的是一条"手艺的极致"、一条"伪工程"？同一个清单拿到恒信↔冰链两个世界，判据变没变（跨域：概念不挑行业）？③ 反身判团队：拿掉名片和年资，用六项逐项打勾——你们团队"最像工程师的人"缺哪一项？他正在长成的是哪一项？他的粒度定位是什么（模块/系统/架构）？④ 反天赋论还意味着什么——缺的项能不能补？怎么补（①科学素养靠预测对账、②方法论走转化链/写SOP、③实践沿强度光谱从做里长、⑤判断走三步闭环+复盘、⑥靠交接演练、④写不可越线清单+决策留痕）？——能答全六项能力的四问、能用清单量别人量自己，才算拥有，这把尺子现在装进你手里了吗？

**Q10｜给你们部门做一次工程师体检：六项打勾 + 粒度定位 + 拓宽自测，落一条判词**
"结合你们部门现状，用八把判据（六项体检 + 粒度尺 + 拓宽尺 + 成长尺 + 终极尺）给一位『被当成工程师的人』（或你自己）做一次工程师体检——逐项打勾，指出缺项，定位他/你的粒度（模块级 7 项主责？系统级 13 项终责？系统架构？），落一条判词（像水忠缺②⑥还是像万辉缺①④⑥？），用拓宽尺定一个成长方向，给出最该先补的一项，落到一个动作。"

追问：① 六项体检 + 价值层三问（相关方知情/评审/记录）先查哪两项？② 粒度尺 vs 名片——你们团队的"架构师/系统工程师/模块工程师"，背的账是专责还是终责？谁在"名片一个粒度、实际另一个粒度"（像水忠模块岗位干系统活）？系统级 13 项有人背吗？③ 你们的招聘/晋升，用的是六项判据，还是"会写代码/有证书/经验多"三个错判据？沟通与团队在你们的评估里，是独立加分项，还是④⑤⑥的执行手段（不会沟通，④⑤⑥能不能落地）？④ 两周后回来报告：谁打了勾、缺了哪项、补了哪个动作、成长方向定了哪条？

### Q1 "会写代码 / 有证书 / 经验多"——错在哪？工程师到底是什么？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "三个人各有道理，都算工程师；徐漾问得太刁钻。" | 正是要翻的——把载体/名义/年资当判据 |
| 中 | 能说"工程师是把四层背在身上的人、有六项能力"，但说不清三句话各错在哪 | 清单背出来了，判据没用起来——没落到逐句翻 |
| 好 | "'会写代码'把载体当判据、'有职称'把头衔当判据、'经验多'把年资当判据——三个人都定义在自己身上；工程师=四层各一项+横切⑤+元⑥，判断换个人能接住才算；①科学素养不是懂公式，是靠预测对账练出来的。" | 三句错判据逐条翻 + 六项清单 + 试金石 + ①误区全咬合 |

**产品侧 vs IT侧**：产品组答"水忠十五年经验不算工程师？"，IT 组答"万辉有头衔有 CI/CD 不算工程师？"——两边都要翻"定义在自己身上的都不稳，定义在能力上的才稳"。**这一章是角色章，六项能力清单就是尺子，不是标签。**

**反转话术**（对应开篇枢纽 + 1.1 + 章末认知反转）：三句话三个"工程师"，错在同一个地方——**用一个"名义 / 载体"去定义一个"能力"**。"会写代码"把载体当成了判据；"有职称"把头衔当成了判据；"经验多"把年资当成了判据。徐漾问的那个问题——"换个人，用同样的需求，交付的东西能和你质量相当吗？"——问的是第2章试金石在"人"身上的落点：**可复现（⑥）**。三人都答不上来，因为他们都把"工程师"定义在了自己身上。**定义在自己身上的，都不稳；定义在能力上的，才稳。** 工程师首先是什么？**把四层结构背在身上的人**——第2章立过四层（工程科学 / 方法论 / 工具实践 / 价值与伦理），四层同时在场工程才成立；每一层长在一个人身上就是一项能力，四层四项 + 横切⑤工程判断 + 元⑥可复现意识，一共六项。**注意第一项就有个误区：科学素养不是"懂很多公式"**——公式可以查，"判断依据成立与否"不能外包；它靠**预测对账**长出来：改动前写下预测，事后对账找偏差，偏差先问"是哪条原理越了界"。这一章不再发明新概念，只做一件事：**把"工程师"这个人，放到第2章那把四层的尺子下面，量一遍**；再把"工程师"这个物种，按粒度划开。

**参考答案要点**：工程师定义见 §8.2.1；六项能力清单见 §8.2.2~8.2.6 + 表 1.1；①科学素养误区与培养见 §8.2.2；章首误解现场；章末认知反转（见过→拥有）。

### Q2 四种身份什么关系？沟通与团队是第七项能力吗？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "工程师就是会写代码的、懂科学的技术员；沟通就是会说话。" | 关系结构错误——四种身份被混成一团，沟通当软技能 |
| 中 | 能说出"不是技术员 / 不是手艺人"，但科学家、会写代码的人没接上；沟通没接上④⑤⑥ | 边界磨了两对，另两对漏了；执行手段没点透 |
| 好 | "技术员照单执行、工程师在规则留白处判断；科学家研究现存世界、工程师创造未存在的世界；手艺人依赖个人、工程师可复现；会写代码只是载体不是判据；沟通与团队不是第七项能力，是④⑤⑥的执行手段——ABET 把它俩单列，是因为它俩藏在六项里、不是额外两项。" | 四对边界 + 载体/判据 + 沟通执行手段 + ABET 交叉验证全到位 |

**产品侧 vs IT侧**：产品组举"老师傅 = 手艺人"；IT 组举"能把需求翻译成代码的人 = 可能只是手艺人"。两边都要翻同一句——**判断落在人身上是工程师，判断可以完全交给规则，那是技术员。** 沟通这一问尤其适合镜像：产品组的工程师要跟供应商/产线/客户讲清约束，IT 组的工程师要跟法务/财务/业务把取舍讲清楚——**都是让④⑤⑥作用于组织的通道。**

**反转话术**（对应 2.1/2.2/2.3/2.4 + 1.8）：技术员照单执行——操作规程怎么写就怎么做，判据是什么就按什么判；工程师也执行，但在**规则没有覆盖的地方做判断**。分界不是学历，是"**规则留白时谁来拍板**"。科学家研究现存的世界，工程师创造从未存在的世界——**求真和求有用，是两种目标，也是两种物种**。手艺人靠个人经验与技巧，结果绑定在人身上；工程师靠可复现的方法，结果可以脱离具体的人——**唯一分界=交付依赖不依赖具体的人**。会写代码的人可能只是把需求翻译成程序的手艺人；**写代码是载体，不是判据**。再补一节最容易误读的：**沟通与团队不是第七、第八项能力**——ABET 把"沟通(3)/团队(5)"列为独立成果，六项清单没有单列它们，不是遗漏：**它们是④⑤⑥的执行手段**——④职业伦理要"让相关方知情"靠沟通、⑤工程判断要"把取舍讲清楚、让判断被记录"靠沟通、⑥可复现意识要"让方法被接住"靠沟通。**一个判断做得对，说不清楚，等于没做；一个方法写得出，不主动沟通，没人会用。** 沟通不是"会说话"，是让能力真正作用于组织的通道。

**参考答案要点**：不是技术员见 §8.3.1；不是科学家见 §8.3.2；不是手艺人见 §8.3.3；不是会写代码的人见 §8.3.4；沟通与团队=执行手段见 §8.2.8；ABET 7条交叉验证见 §8.2.1。

### Q3 一个物种，三种粒度——模块工程师、系统工程师、系统架构师，谁"更高"？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "系统工程师比模块工程师高一级，架构师最高；模块工程师是低配。" | 正是要翻的——把粒度当职级 |
| 中 | 能说出"三种粒度、账不同"，但终责/专责分不清、分形不对称没点透 | 粒度表背出来了，责任性质与分形没咬合 |
| 好 | "粒度不是职级是责任性质：模块负元素实现专责、系统负系统成败终责（accountability 不可委托）、架构负结构演化专责；模块工程师是系统工程师的分形（迷你系统工程师，模块级也跑完整闭环），但分形不对称——模块没有架构/确认/部署/集成；系统工程师四动词转化/统筹/把关/守护、INCOSE 六件事没有一件是亲手写代码，24765 说与其正式头衔无关。" | 粒度×责任 + 终责专责 + 分形不对称 + 四动词六件事全到位 |

**产品侧 vs IT侧**：产品组举"负责一个零件的工程师 vs 负责整机成败的系统工程师"；IT 组举"负责一个服务的开发者 vs 负责整个系统成败的系统工程师"。两边都是同一件事——**一个物种，三种粒度，背的是同一副骨架，账却不是同一本。**

**反转话术**（对应 2.6 + 3.5 + 案例进展①/②）："工程师是一个统一的物种"——这句话对了一半：**一个物种没错，但它有三种粒度**，三种粒度不是高低职级，是**粒度 × 责任**的划分。**模块工程师**负系统元素/模块实现的**专责**（responsibility——划得清的账，可委托可追责）；**系统工程师**负系统全生命周期技术事务的**终责**（accountability——甩不掉的账，系统成败的账**不可委托**给任何人）；**系统架构师**负系统结构与演化的**专责**（架构正确性的账，可委托可追责）。一句话：**终责是甩不掉的账，专责是划得清的账。** 模块工程师不是"小一号的系统工程师"——他是系统工程师的**分形**（迷你系统工程师）：模块级也跑同构闭环（模块需求→模块设计→模块实现→模块验证）。**但分形不对称**：模块级比系统级少四样东西，不是遗漏是结构——模块没有自己的"架构"（就是上层架构的分配，架构师画好的边界）、没有"确认"（确认必须在真实使用环境里，那是系统级的事）、没有"部署"（系统级行为）、没有"集成"（系统级把模块装起来）。**模块在自己的边界内自治，边界外（接口）听架构的。** 系统工程师这个人怎么识别？按 ISO/IEC/IEEE 24765，他是"实践系统工程学科的个人，与其正式头衔无关"——你叫架构师还是 CTO，只要在实践系统工程，你就是系统工程师。四动词：**转化 / 统筹 / 把关 / 守护**；INCOSE 六件事：建立系统愿景并让团队买账、促成技术·业务·运营沟通、让多元团队协作、管理不确定性与涌现、系统层面好的技术决策与权衡、支撑商业论证——**注意，没有一件是"亲手写代码"**。系统工程师的产出不是零件，是让零件协同的系统本身。**三个粒度，背的是同一副骨架**：六项能力一项不能少，区别只在粒度与责任——模块用在"我这个元素"、系统用在"整个系统"、架构用在"系统的结构与演化"。**同一副骨架，三种尺码。**

**参考答案要点**：三粒度谱系见 §8.3.6（表 + 责任性质 + 分形不对称 + 系统工程师四动词 + INCOSE 六件事）；产品数据三粒度责任矩阵见 §8.4.5；24765/15288 见参考文献节；粒度尺见本章判据。

### Q4 水忠手艺极致——他是工程师吗？能力越强越值得信赖吗？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "水忠十五年经验、活漂亮，当然是好工程师；能力强就值得信赖。" | 正是要翻的——把经验/能力强当判据 |
| 中 | "水忠不是工程师，因为不可复制。" 结论对，能力不中性没接上 | ⑥可复现对了，④定义方向缺 |
| 好 | "水忠①③⑤顶配缺②⑥——手艺的极致不是工程师的画像；能力不中性，④定义方向：能力放大选择的规模，方向由④定义，737 MAX 不缺会算的工程师缺守住底线的工程师。" | 判词 + 能力不中性 + 事故机制全到位 |

**产品侧 vs IT侧**：产品组举"水忠的降额判断全在脑子里"；IT 组举"某大牛的核心模块只有他会改"。两边都是同一件事——**个人厉害 ≠ 工程厉害：前者依赖人，后者可复制。**

**反转话术**（对应 1.6 + 3.4 + 案例进展①）：水忠是手艺的极致——①科学素养顶配（懂原理）、③实践能力顶配（活做得漂亮）、⑤工程判断顶配（每个取舍都准）。但他缺②方法论素养——方法说不成体系；缺⑥可复现意识——判断换个人做不出来。**水忠不是不会做，是做的能力不可复制——手艺的极致，不是工程师的画像。** "能力越强的工程师越值得信赖"错在哪？**能力不中性——能力放大的是"选择的规模"，而选择的方向由④职业伦理定义。** 一个①③⑤顶配、④却为零的人，破坏比"不会做"的人大得多：他会算、能做、判断准，只差守住底线。**737 MAX 里不缺"会算的工程师"，缺的是"守住底线的工程师"。** 四宗死法里最危险的是"能力失控"——因为他看起来最优秀。

**参考答案要点**：能力不中性见 §8.2.6；水忠判词见案例进展①；能力失控死法见 §8.4.4。

### Q5 照着流程做，是工程师还是技术员？判断力好 = 敢拍板吗？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "流程全覆盖、照单执行最稳妥，这就是工程师；判断力好就是敢拍板。" | 正是要翻的——把技术员当工程师、把判断当魄力 |
| 中 | "工程师在流程外判断。" 结论对，分界机制浅 | "规则留白时谁来拍板"没点透；⑤误区没翻 |
| 好 | "技术员遇到表里没有的工况会停下来问，工程师要自己判断自己负责——分界不是学历是'规则留白时谁来拍板'；判断不是直觉/规则树/魄力——直觉只是线索、判断要有依据，约束一变规则就失效，魄力是敢拍板、判断是拍得对拍得能负责；方法必须留判断空间。" | 分界判据 + 判断留人 + ⑤误区 + 方法留白全到位 |

**产品侧 vs IT侧**：产品组举"按工艺卡执行的操作工 vs 处理异常工况的工程师"；IT 组举"按脚本执行的 DBA vs 规则没覆盖时拍板的架构师"。两边都是同一件事——**规则留白时，谁来拍板、谁来负责。**

**反转话术**（对应 2.1 + 1.5 + 3.1）："流程全覆盖、照单执行"最不容易出错——这句话对技术员成立，对工程师不成立。技术员遇到表里没有的工况，会停下来问；工程师遇到表里没有的工况，要自己判断、自己负责。**判断落在人身上，是工程师；判断可以完全交给规则，那是技术员。** 分界不是学历，是"规则留白时谁来拍板"。自查第4条"工程师就是照着流程做的人"——错，那是技术员。再翻一个流行的误区：**工程判断力好，不等于"敢拍板、有魄力"**——判断不是直觉拍脑袋（直觉只是线索，判断要有依据 informed judgment）、不是规则决策树（约束一变，写好的规则就失效）、更不是勇气魄力（魄力是敢拍板，判断是拍得对、拍得能负责）。好的工程判断是三步闭环：**识别约束 → 权衡取舍 → 担责闭环**（让人知情、走评审、留记录）。方法论也一样：**有章法不等于算法化，方法必须留判断空间**——写过头，就退化成"技术员照单执行"。

**参考答案要点**：不是技术员见 §8.3.1 + 自查第4条；工程判断（不是直觉/规则/魄力 + 三步闭环）见 §8.2.5；方法留判断空间见 §8.2.3。

### Q6 给水忠和万辉下判词——缺的性质有什么不同？粒度定位各是什么？

**反转话术**（对应 案例进展①②③ + 1.5⑥ + 2.6 + 3.5）：两份判词逐项验证：**水忠**=①③⑤顶配、缺②⑥（手艺的极致）——有工程师的"里子"（判断顶配），缺"换个人能接住"的"面子"（不可复制）；**万辉**=有②③、缺①④⑥（伪工程）——有工程师的"面子"（方法能说清），缺"关键时刻护住"的"里子"（守不住底线）。缺的性质不同：水忠缺的是"可复制"（⑥）和"成体系"（②）；万辉缺的是"为什么能行"（①）、"底线"（④）、"可复现"（⑥）。放进三粒度谱系看（§8.3.6）：**水忠是模块工程师的岗位，做着系统工程师的活——拓宽中**（专责称职、终责未接；他缺的②⑥，正是"把模块的活干成系统的活"所缺的成文能力：老规矩写在脑子里、不写成系统方法）；**万辉的名片是架构师（系统架构师粒度），缺的却是架构师最不能缺的底座①④⑥**——底座缺一块，第16章的增量（系统级判断）全是空转。谁更接近工程师？**两个人都不是完整的工程师；但两个人都值得被叫一句"在成为工程师的路上"**。**判词（案例进展①②③）和 3.5（产品数据），量的是同一把尺子**——水忠缺的②⑥最终都露在产品数据上（没有成文的测试方案）；万辉的文档都在但不可信（容量评估被砍、CI/CD 靠隐藏命令）。顺带磨一个⑥的误区：**可复现不是"爱写文档的习惯"**——水忠也不是完全不会写（②会），他缺的是"必须写成那样"的自觉（⑥缺）；②是"写成什么样"的本事，⑥是"必须写成那样"的自觉。

**参考答案要点**：双线判词见案例进展③ + 本章判词；⑥与②分工见 §8.2.5⑥；粒度语境见 §8.3.6 + 案例设定 §二走位/§五角色画像；产品数据见 §8.4.5。

**反转话术**（对应 3.5 + 2.6）：三粒度责任矩阵（§8.4.5）——**系统架构师**主责系统架构（结构/接口/演化原则，第16章展开）；**系统工程师**主责系统级 13 项（相关方需求、运行概念、系统需求、系统详细定义、技术方案、实现方案、集成方案、集成测试、验证、确认、部署、运维等），**主责兼终责**；**模块工程师**主责模块级 7 项（模块需求、模块详细定义、模块实现方案、模块实现报告、模块测试、模块验证、模块运维），系统工程师批准。两个看点：**第一，系统工程师是唯一横跨两层的角色**——系统级 13 项几乎全是他主责、模块级 7 项全部由他"批准"：模块工程师干活，他验收。这就是终责（accountability）的落点：**谁负责的东西最多、又给别人的东西签字，谁就是那个兜底的。** **第二，粒度隔离就是模块化的意义**——系统工程师不需要知道模块内部细节，只需要模块的接口和验证结果；模块工程师在自己的边界内自治，把成果交上去。你们团队体检，先问：系统级 13 项有人背吗？模块级 7 项有人主责、有人批准吗？水忠的产品数据漏在交界处——模块级没有成文测试方案（缺②⑥，手艺不出纸面）、系统级的事做了没有成文系统数据——能力全在脑子里，产品数据薄，检验这一关过不去。**能力再强，开发不出高质量的产品数据，这个工程师也不成立。**

**参考答案要点**：三粒度责任矩阵见 §8.4.5（表）；终责落点见 §8.3.6 + §8.4.5；产品数据=规定不是记录见 §8.4.5；水忠产品数据见 §8.4.5 + 案例进展①。

### Q8 失败四式——每一宗死法缺哪一项？"从模块到系统是升职"对吗？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "失败就是干得不好，多练就行；升职很正常。" | 没落到四式+缺项——把死法当"不努力"、把成长当升职 |
| 中 | "手艺型缺⑥、PPT 缺③、守不住缺④、失控缺方向。" 判词对，最危险那宗和拓宽没说透 | 四式各配一项了，能力失控机制与"拓宽不是升职"缺 |
| 好 | "手艺型死于说不清（⑥不可接住）、PPT 死于做不了（③悬空）、守不住死于没底线（④）、能力失控死于方向偏——最危险的是能力失控（看起来最优秀）、最隐蔽的是守不住（症状不是不会做是没守住）；成长是拓宽不是升职：视角换轨+责任接管，换轨标志=第一次为系统牺牲自己的模块还觉得值，分叉不是阶梯。" | 四式缺项 + 最危险/最隐蔽机制 + 拓宽vs升职 + 分叉正交全到位 |

**产品侧 vs IT侧**：产品组举"守不住：为赶上市砍可靠性测试"；IT 组举"守不住：为月底上线砍容量评估"。两边都是同一件事——**四宗死法每一种，都能在六项能力清单里找到缺的那一项；往哪走，都是拓宽不是升职。**

**反转话术**（对应 3.4 + 1.6 + 3.1）：四宗死法四宗姿态：**手艺型死于说不清**（⑥缺席——判断不可接住）、**PPT 工程师死于做不了**（③缺席——方法论悬空）、**守不住底线死于没底线**（④缺席——价值层失守）、**能力失控死于方向偏**（④定义方向——能力越强方向错破坏越大）。最危险的是"能力失控"——因为他看起来最优秀。最普遍也最隐蔽的是"守不住底线"——它的症状不是"不会做"，而是"做的时候没守住"：泰坦尼克按"不会沉"配救生艇、挑战者在工程师反对声中升空、737 MAX 在认证压力下轻描淡写——三起事故的共同点：**不是不会做，是守不住。** 再磨一个④的大误区：**职业伦理不是背规章、不是算风险概率、更不是服从组织**——NSPE 要求对公众负责，不是对老板负责——挑战者号里，工程师反对发射、管理者施压。最后翻"成长"这层：**从模块到系统是升职吗？不是——是拓宽。** 升职是组织给你换位置，拓宽是你自己换轨道：视角换轨（从"我的模块"切到"整个系统"）+ 责任接管（优化目标从单点最优到系统最优——系统最优往往要求某个模块让利）。**换轨标志很朴素：第一次因为系统牺牲了自己的模块，还觉得值——那一刻，你就换轨了。** 而且拓宽的方向不是唯一的：从模块工程师出来，一条路往系统走（系统工程师），一条路往管理走（技术经理、项目总监）——**两条路没有高低，只有方向正交**。这就是"分叉不是阶梯"。

**参考答案要点**：失败四式见 §8.4.4；④误区三边界见 §8.2.6；拓宽成长见 §8.4.1（视角换轨 + 责任接管 + 换轨标志 + 分叉不是阶梯）；成长尺见本章判据；三大事故见§2.3.3。

| 中 | 能判万辉水忠，但反身判团队时只能举例、说不出判据 | 判人有证据，判自己团队"是不是/凭什么"说不清 |
| 好 | "判万辉缺①④⑥，证据是容量评估被砍/没让相关方知情没记录/CI/CD 靠隐藏命令；判水忠缺②⑥，证据是方法不成体系/没有一份完整测试方案；加粒度语境——水忠模块岗位拓宽中、万辉架构师头衔缺底座；反身判团队：拿掉名片年资逐项打勾——某人⑥没打勾=手艺型，正在补的是写文档/做交接；缺项可补，①预测对账/②转化链/③强度光谱/⑤三步闭环+复盘/⑥交接演练/④不可越线清单。" | 立判据判人 + 粒度语境 + 反身判团队 + 反天赋论（六项培养循环落地）全到位 |

**产品侧 vs IT侧**：产品组给水忠判词时自然写"判断全在脑子里，车间没有测试方案"；IT 组给万辉判词时自然写"CI/CD 靠隐藏命令"。两边立出的判据结构相同——**这就是本章方法时刻的核心：不考"方法名能不能背"，考"方法会不会用"；清单是判人的尺子，不是背诵的对象。**

**反转话术**（对应 方法底座时刻 = 反天赋论 + 案例进展①②③ + 2.6 粒度语境 + 章末见过→拥有）：这是本单元的**方法时刻**——前面八题在讲"工程师是什么"，这一题让你们亲手做一遍方法底座时刻：**反天赋论**。万辉有头衔、水忠没头衔——可**头衔不定义人：能力可检验、可训练，不是天生的**；把六项能力列成清单，就是为了让你一项一项亮起来。判词变体：**用清单判人，再把尺子转向自己**——判万辉：缺①④⑥，判据是"容量评估被砍"（①——不追问为什么能行）、"没让相关方知情、没记录"（④——为进度悄悄牺牲可靠性）、"CI/CD 靠隐藏命令"（⑥——换个人接不住），**不是头衔、不是感觉**；判水忠：缺②⑥，判据是"方法说不成体系""车间没有一份完整测试方案"（②⑥）。再加一层粒度语境：**水忠=模块工程师岗位拓宽中**（模块的活干成系统的活，缺的是成文能力②⑥）、**万辉=架构师头衔缺底座**（第16章的增量全长在六项能力上，底座缺一块、增量空转）——同一个清单，量出"手艺的极致"和"伪工程"两条判词。**同一个清单拿到恒信↔冰链两个世界，判据变没变？** 不变——说明这张尺子不挑行业（跨域）。再反身判自己团队：谁缺哪一项？证据是什么？怎么检验？——**有标签是见过，能答全六项能力的四问（各是什么、不是什么、判据是什么）、能用清单量别人量自己，才算拥有。** 反天赋论还意味着什么？**缺的项可以补，每项配一个培养循环**——①科学素养靠**预测对账**（改动前写预测、事后对账）、②方法论走**转化链**（隐性判断→显性化→标准化→组织能力；写 SOP 交给同事照做）、③实践沿**强度光谱**从做里长（到"独立做"判断进场）、⑤判断走**三步闭环 + 复盘**（识别约束→权衡取舍→担责闭环；做错的决定+认真复盘 > 做对的决定+不复盘）、⑥靠**交接演练**（写交接包，写不出的地方=没想清楚的地方）、④写**不可越线清单 + 决策留痕**（谁知情/评审/记录）。这把尺子现在装进你手里了。

**参考答案要点**：方法底座时刻（反天赋论）见 00-案例设定 §三 第9章行 + 开篇枢纽；判词见案例进展①③ + 案例设定 §二走位/§五角色画像（粒度语境）；三粒度谱系见 §8.3.6；六项培养循环见 §8.2.2~8.2.6；跨域变体见 00-案例设定 §四（工程/工程系统行——恒信↔冰链同一副骨架）；见过→拥有见章末认知反转。

### Q10 给你们部门做一次工程师体检：六项打勾 + 粒度定位 + 拓宽自测

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | 泛泛"要加强培训、要多招人、要会沟通。" | 没落到八把判据任何一把，不可检查 |
| 中 | 用一把尺子查出问题（如"某同事的 CI/CD 只有他会跑"） | 有判据，但只照了一面（没做粒度定位/拓宽自测） |
| 好 | 按六项逐项打勾、粒度定位（"他背的是模块级 7 项、名片是系统工程师但终责没人背"）、拓宽自测（"他还在单点最优，换轨标志没出现"）、落判词（"像水忠缺②⑥——判断换个人接不住，模块岗位干系统活"）、挑最该先补一项 + 一个可检查动作（"把某模块的决策写成 ADR，指定一个接手人，两周后让他独立改一次"）、说清先查哪两项、两周后报告什么；沟通/团队不是加分项，而是④⑤⑥落地的通道 | 体检完整，粒度定位+拓宽自测到位，判词落地，动作可执行，有复查机制，执行手段嵌进每项 |

**产品侧 vs IT侧**：两组各给自己部门体检——体检表是同一份（六把尺子 + 粒度尺 + 拓宽尺 + 价值层三问 + 执行手段判据），这正是"概念不挑行业"的现场证明：**产品组的判词叫"手艺极致缺②⑥"，IT 组的判词叫"伪工程缺①④⑥"，量的是同一把尺子；两边都在查"系统级 13 项有没有人背终责"。**

**反转话术**（对应 3.5 + 1.8 + 2.6 + 3.1 + 本章判据 + 作业指南）：六项能力抽象在一个人身上，**不可直接检验**——面试会看走眼，领导会凭印象打分。能力的最终体现，是**能否设计开发出本角色负责的产品数据（文档）**；产品数据是**规定**不是记录——写在实现之前，声明"产品应该是这样"，让别人照做、让验证有标尺。**按粒度分账**：模块工程师管模块级 7 项、系统工程师管系统级 13 项（主责兼终责）、系统架构归架构师主责（第16章展开）。**换个人，拿着你负责的那套产品数据，能不能把产品做出来、继续演进？** 能，你的能力成立；不能，你只是手艺人。你们部门体检，先查哪两项？六项体检 + 粒度尺 + 拓宽尺——**"没有记录"的地方，就是④可能缺席、也是①和⑥最容易现形的地方；答不上"专责还是终责"，就是粒度定位失准（先定位再体检）。** 你们的招聘/晋升，用的是六项判据，还是"会写代码/有证书/经验多"三个错判据？——这正是章首徐漾那场面试要翻的东西。系统级 13 项有人背吗？——很多团队模块级 7 项有人管、系统级 13 项没人背终责，这正是万辉那类"头衔在、账没人背"的来源。**最后，沟通与团队不是独立加分项，是④⑤⑥的执行手段**——不会沟通，④让相关方知情落不了地、⑤把取舍讲清楚落不了地、⑥让方法被接住落不了地；评估一个人，别把"沟通好"当第七项能力，要看它有没有把④⑤⑥真正作用到组织上。每个缺项配一个培养动作（①预测对账 / ②转化链·写SOP / ③强度光谱 / ⑤三步闭环+复盘 / ⑥交接演练 / ④不可越线清单）——**反天赋论：能力是练出来的。**

**参考答案要点**：产品数据见 §8.4.5（三粒度责任矩阵 + 规定不是记录 + 六项在"长叶子"里的落点）；三粒度谱系见 §8.3.6；拓宽成长见 §8.4.1；沟通与团队执行手段见 §8.2.8；作业指南见本章分析文档第 6 步；判据见"本章判据"（判据 8）。

### 金句（书"本章判据"提炼）

- **工程师不是一个头衔，不是一沓证书，不是多少年的经验。它是把四层结构背在身上、关键时刻守得住底线、判断换个人也能接住的人。**
- 六项能力体检：①科学素养——我做的东西凭什么能行？②方法论素养——我的方法能被别人学会吗？③实践能力——我最近一次亲手落地是什么时候？④职业伦理——压力面前我会为进度悄悄牺牲可靠性吗？⑤工程判断——规则没有覆盖的地方我能做对的取舍吗？⑥可复现意识——我的判断换个人能接住吗？
- **能力不中性，④定义方向**——能力放大的是选择的规模，方向由④定义；能力越强、④越缺、破坏越大（737 MAX 不缺会算的工程师，缺守住底线的工程师）。
- 角色判据：**如果你不在，交付还能不能维持？能，你是工程师；不能，你是手艺人——哪怕你也会写代码、画图纸。**
- **一个物种，三种粒度——背同一副骨架，账却不是同一本**：模块工程师负元素实现专责（划得清的账）、系统工程师负系统成败终责（甩不掉的账，accountability 不可委托）、系统架构师负结构演化专责；模块工程师是系统工程师的分形，分形不对称（模块没有架构/确认/部署/集成）。
- **成长是拓宽，不是升职**：视角换轨 + 责任接管，换轨标志=第一次为系统牺牲自己的模块还觉得值；分叉不是阶梯（往系统走 vs 往管理走正交）。
- 价值层失守三问：**相关方知不知情？有没有评审？有没有记录？**——客观原因不留记录；失守恰恰发生在"没有记录"的地方。
- 成长尺：判断的依据在哪个尺度——**照做 / 会选 / 会取舍 / 守底线**？从"怎么做"升到"守什么"，才是长成。
- 沟通与团队：**不是第七项能力，是④⑤⑥的执行手段**——一个判断做得对，说不清楚，等于没做；一个方法写得出，不主动沟通，没人会用。
- 终极尺：**能力再强，也要看我能不能开发出高质量的产品数据——换个人，拿着它，能不能做出来、继续演进？** 产品数据按粒度分账：模块级 7 项 / 系统级 13 项 / 系统架构。
- 反天赋论：**能力可检验、可训练，不是天生的**——头衔不定义人；缺的项可补（①预测对账 / ②转化链 / ③强度光谱 / ⑤三步闭环+复盘 / ⑥交接演练 / ④不可越线清单），把清单一项一项亮起来，才是工程师。

## 五、课后作业

1. **书练习（与题卡同源）**：用六项能力，给"你们公司最像工程师的人"做一次体检——逐项打勾，指出缺项，判断他走在哪条路上（若对象换成水忠或万辉，体检结果会是"缺②⑥"还是"缺①④⑥"？）。（书练习 1）
2. **书练习（新内容同源）**：粒度定位——把你们团队的核心成员放进三粒度谱系（模块工程师/系统工程师/系统架构师），说出每个人背的账是专责还是终责——有没有"名片一个粒度、实际另一个粒度"的人（像水忠模块岗位干系统活）？（书练习 2）
3. **回部门落地**：结合现状，用八把判据（六项体检 + 粒度尺 + 拓宽尺 + 成长尺 + 终极尺）给一位"被当成工程师的人"（或你自己）做一次工程师体检——逐项打勾、指出缺项、定位粒度、落一条判词（像水忠缺②⑥还是像万辉缺①④⑥？）、用拓宽尺定一个成长方向、给出最该先补的一项，**配一个培养动作**。**两周后回来报告**：谁打了勾、缺了哪项、补了哪个动作、成长方向定了哪条、效果如何。

### 作业指南（回部门落地的步骤 + 话术）

> 照着做，60 分钟完成一次"工程师体检"（六项打勾 + 粒度定位 + 拓宽自测 + 落判词 + 配培养动作）：
>
> 1. **挑对象（先立枢纽）**：选团队里"公认最像工程师的人"——最像的，往往也最容易在某一项打不上勾。
> 2. **项目一 · 六项体检打勾**（每题带"沟通/团队"执行手段的落点）：①科学素养——他做的东西"凭什么能行"能讲出原理吗（靠预测对账练，不是懂公式）？②方法论素养——他的方法能被别人学会吗（写 SOP 给同事照做，看卡在哪一步）？③实践能力——他最近一次亲手落地是什么时候（强度光谱到"独立做"了吗）？④职业伦理——压力面前会为进度牺牲可靠性吗（不可越线清单/决策留痕）？⑤工程判断——规则没覆盖的地方能做对取舍吗（三步闭环：识别约束→权衡取舍→担责闭环）？⑥可复现意识——他的判断换个人能接住吗（交接演练：写交接包，写不出的地方=没想清楚的地方）？
> 3. **项目二 · 粒度尺定位**（判据7）：他背的账是专责（划得清的账）还是终责（甩不掉的账）？他的名片粒度 vs 实际粒度一致吗？——水忠是"模块工程师的岗位、系统工程师的活"（拓宽中），万辉是"架构师的头衔、底座缺"；你们团队谁在"名片一个粒度、实际另一个粒度"？**话术**："他的账，是划得清的还是甩不掉的？"
> 4. **项目三 · 拓宽尺自测**（判据8）：他是在单点最优，还是系统最优？愿不愿意为系统牺牲自己的模块？——换轨标志=第一次为系统牺牲自己的模块还觉得值；判断依据在哪个尺度（照做/会选/会取舍/守底线）？
> 5. **项目四 · 落判词**：对照两条基准线——水忠①③⑤顶配缺②⑥（手艺极致，模块岗位拓宽中）、万辉有②③缺①④⑥（伪工程，架构师头衔缺底座）——你的对象像哪条线？缺的是哪一项？在哪个粒度？**话术**："他不是不会做，是做的能力不可复制"（像水忠）/ "他不是不会说，是说的和做的对不上"（像万辉）。
> 6. **项目五 · 反身自检 + 配一个培养动作（反天赋论落地）**：用同一张清单给自己打勾——你缺的那一项，正是你在"背清单"而不是"用清单"的地方；给最缺的一项配一个可执行动作——①缺就做预测对账（改动前写预测、事后对账）；②缺就走转化链（把最近一次做对的事写成 SOP 交给同事照做）；③缺就沿强度光谱补"独立做"（从零复现一个已知功能）；⑤缺就记决策日记（约束打架/选哪个/后果/重来选什么）+ 案例裁决；⑥缺就做交接演练（写交接包）；④缺就写不可越线清单 + 决策留痕（谁知情/评审/记录）。
> 7. **项目六 · 落到产品数据**（终极尺）：问最后一个问题——他/你负责的那个粒度的产品数据（模块级 7 项 / 系统级 13 项 / 系统架构），换个人拿着能接着种吗？这是六项能力唯一可检验的落点。
> 8. **出体检报告**：六项各打勾/缺项 + 粒度定位 + 拓宽自测，落判词，最该先补最缺的一项 + 配一个培养动作；两周后复查补了什么。
>
> 卡住时：打不上勾的那一项就是最该补的；⑥打不上勾=手艺型（判断换个人接不住），④打不上勾=最危险（能力越强方向越偏）；粒度尺答不上"专责还是终责"=不清楚自己在谱系里的位置（先定位再体检）；价值层三问（相关方知情/评审/记录）当场打勾——"没有记录"的地方就是④可能缺席、也是①和⑥最容易现形的地方。
