## 五、张舒然设定（主笔代拟稿，待核准）

> 依据：① 四角色里**冰链缺系统工程师**（文正＝产品经理、永兵＝产品开发经理、水忠＝嵌入式、董勐＝云端、李旭＝测试、逸人＝制造）；② 后记四份清单中"系统工程师"那一份（整条链受控、可追溯）在案例里还没有人背；③ "戏份在周逸人之前"取**甲·成长分量序**，并把首次出场放到第2章（同时满足乙）。

| 项 | 设定 | 理由 |
|---|---|---|
| 姓名 | **张舒然** | 用户给定 |
| 公司 | **冰链** | 系统工程在硬件＋嵌入式＋云端一体的产品上更有落点；恒信侧万辉已担架构、满海担产品，再添 SE 会挤 |
| 岗位 | **系统工程师**（系统工程／总体设计） | 补四角色缺口；后记"系统工程师"清单（需求与运行概念／计划／集成与验证确认／基线与变更／部署运维退役）正需要一个案例人物 |
| 性别 | 男 | 现队女性仅小白；不加设定变化，若要平衡可改为女（用户定） |
| 与逸人关系 | **职责链上游**：可造、可验、可交付在制造之前由他定；技术上与逸人对接量产 | 让"戏份在逸人之前"在甲、丙两种读法下都成立 |
| 成长分量 | 徐漾 ＞ 玉杰 ＞ **张舒然** ＞ 逸人 ＞ 万辉 ＞ …（第 3 位） | 只越过逸人一位，最小改动满足用户 |
| 首次出场 | **第2章**（冰链镜照，一句"换个人接得住吗"） | 早于逸人首现（第3章）；第1章双会仍保持"各五张脸"不动 |
| 关键戏（建议） | 3 设计开发（可实现）／5 需求完整性（三类与载体）／7 产品数据（整条链的数据在不在）／8 三把尺子／12 改字段谁批／15 哪一版算数／17 接缝清单／18 与万辉对照（终责 vs 专责） | 落在全书关键概念站 |
| 台词关切 | 永远问"**这一段是谁签的字、换个人接不接得住**" | 与第2章试金石、第9/18章判据同轴 |
| 判词 | **不夺**万辉（缺①④⑥）与水忠（缺②⑥）的判词；他是"链上还缺一个人"的那面镜子 | 保两个既有判词稳定 |

**连带五件（核准后同批）**：案例设定（§二 团队表／§五 登记与画像／§八 后记回声／§九 行序／§十 素材包）｜三条线索（12→13 人、在场矩阵）｜前言「十二个人」与致谢（14→15 名）｜后记「冰链六个／恒信六个」｜训侧人数口径。
