## 二、核心结论（供后续章取用）

1. **决策有定义、权衡没有**：`architecture decision`／`architecture rationale` 定义句在 **42010:2022 §5.2.12**（概念章），**第 3 章无词条**；`trade-off` 四份正本均无定义句，定义性表述落在 **tradespace**（42020 §8.4.6 NOTE 2／§9.4.8 NOTE 3）。
2. **决策＝一组选择**（选择对象见 §5.2.12 EXAMPLE 1）；**理据六项含 alternatives and trade-offs considered**——权衡由理据进决策档案。
3. **权衡三对＋一**：解内／解间／与现状／与未被提出的其他解（§8.4.6 e) 1)2)3)）；典型清单见 §8.4.6 NOTE 4；**tradespace 常无完全满足解**；**权重非必需**（§9.4.5 NOTE 2）。
4. **两侧互补**：概念化侧技术视角（§8.4.6 NOTE 1）↔ 评估侧价值视角（§9.4.8 NOTE 2）。
5. **拍板通常在架构过程之外**（§5.7、§8.4.7 NOTE 7）→ 决策管理过程（15288 §6.3.3）；**评估不含处置决定**（42030 §3.4 Note 1）。
6. **记录**：AD **shall** 记关键决策；13 条选择准则、11 项内容（42010 §6.10.1）；理据四处（§6.10.2）；**标准未给"关键"的判据**＝本书自定处。
7. **现行版与在途**：**42020 与 42030 均已立 AWI 项目**（阶段 20.00，生效日 2026-05-22，题名改 *Enterprise, systems and software — …*）；42010、15288 未查到在途项目。判据仍以 2019／2022／2023 现行为准。

## 四、2026-10-13 追加：架构决策的"目的／意义／价值"底层逻辑（面谈分析，供 ch12 取用）

**四条不对称，推出四问**（我的定性，各配正本锚点）：

1. **信息不对称**（承诺作出时信息最不全、兑现时信息最全）→ 故须**记录理据**：15288 §6.3.3.1 NOTE 1 逐字 *Key study data (e.g. assumptions and decision rationale) are typically managed to inform decision-makers, re-justify the decision in the future, and support future decision-making.*（中译：关键研究数据（如假设与决策理据）通常被管理起来，以告知决策者、在将来**重新证成**该决策，并支撑未来的决策。）
2. **责任不对称**（判断在个人、后果在组织）→ 故须记**决策权威或所有者**：42010 §6.10.1 第 3 项＋42020 §6.2 c)（有理由支撑的决策由**适当权威**作出并传达）。
3. **目标不对称**（多个目标不可兼得）→ 故**理据必含权衡**：42010 §5.2.12 六项内容项之 *alternatives and trade-offs considered*。
4. **承诺不对称**（收窄设计空间的收益即时、改起来的代价延后且高昂）→ 故**只记关键决策、且要留出设计空间**：42010 §6.10.1 十三准则里"*likely to be costly to change*"（中译：改起来很可能代价高昂）与"*highly sensitive to changes*"（中译：对变更高度敏感）；反向约束是 15288 §5.4／42020 §5.6 的 *as design-agnostic as possible*（中译：尽可能与设计无关）与 *maximum flexibility in the design tradespace*（中译：设计权衡空间的最大灵活性）。

**三问判据（本书自定，须与十三准则对表）**：一条选择若满足以下任一条，即属"关键"——（a）它一旦定了会**约束下游多个专业的选择**；（b）它**事后改起来的代价远高于当时定它的代价**；（c）**别人必须知道它才能正确工作**。三问皆有正本对应项，（a）≈影响关键相关方与进入下游计划、（b）≈代价与不可逆一组、（c）≈关系与追溯项（§6.10.1 第 5、6 项）。

**产品研发领域的特殊性**（我的定性，落 ch12 时用）：研发是"在信息最不全时作最贵承诺"的活动；并行度高（多专业须以边界冻结为前提）、外购比例高（决策即采购与技术路线锁定）、验证周期长（安全关键件与认证件**不可回滚**）；平台型产品（如 EOS）的架构决策直接兑成**变更边际成本**——哪些事一种产品做一次、哪些每个订单都要做。四者叠加，使决策记录成为研发领域**唯一可持续的责任与知识载体**（对应本书四案例的失效形态：误导／演进失控／漏检／架构未识别）。

## 五、2026-10-13 追加：架构决策 ↔ 架构定义 的关系（面谈分析，供 ch11／ch12 接缝取用）

**身份不对称**：「架构定义（architecture definition）」在正本里是**过程名**（15288:2023 §6.4.4 system architecture definition process；42020:2019 是它的过程细化：三核心过程 §8／§9／§10＋两并行过程 §6／§7；15288 §6.4.4.3 NOTE 1 明写 42020 三核心过程之对应）；「架构决策」是**概念名**（42010:2022 §5.2.12 定义句＋§5.2.9 是 AD 元素）。故二者不是两个概念的关系，而是**过程与过程中的取值**的关系。

**四条关系**：① **包含**——15288 §6.4.4.1 目的句三动词 *generate… select one or more… and express*（中译：生成……选出一个或多个……并表达），"select" 即决策站位；② **宾语**——§5.2.12 EXAMPLE 1 首项即 *Selection of architecture concepts*（中译：架构概念的选择），定义的产出正是决策的宾语之一；③ **分层**——定义产出＝基本概念或属性＋管控原则（§3.2），决策与理据＝**AD 元素**（§5.2.9），§6.10.1 NOTE 1 *An AD expresses decisions about an architecture.*（中译：架构描述表达关于某架构的决策）；**决策进记录不改变定义的产出种类**；④ **时序**——定义多轮迭代（42020 §8.3 b)），决策在概念化阶段即捕获（§8.4.8 g)），但**拍板通常在定义之外**（§5.7／§8.4.7 NOTE 7）。

**标准自己的分工**：15288:2023 **§5.9 NOTE 2** 逐字——*Practices, conventions, principles, and concepts for system architecture definition are specified by the ISO/IEC/IEEE 420x0 family…*（中译：系统架构定义的做法、惯例、原则与概念由 ISO/IEC/IEEE 420x0 族规定：42020 给过程（治理／管理／概念化／评估／细化）、42030 给评估框架、42010 给描述的原则与概念）。

**本书口径的接缝（定案脊柱四环，框架 ch11 行已立）**：①判断 → ②立成概念·属性·原则 → ③**选定并背书** → ④下游必须依据它。**ch11（定义）走到②**（产出三张清单）；**③＝架构决策（ch12）**；④＝架构描述与治理（ch13／ch16）。一句话：**定义给出"可选项"，决策把它定成一个；没有③，②只是三张清单，管不住下游；没有②，③无从选起。**

**三条不许混**：① 把决策当定义（"选了 A 方案"＝"架构就是 A"）→ 把架构降为方案、锁死设计空间，违 15288 §5.9 的 *design-agnostic as possible* 与 42020 §5.6 的 *maximum flexibility in the design tradespace*；② 把定义当决策（出清单不留痕）→ 违 42010 §6.10.2 shall，且失去 §6.10.1 NOTE 3"理据失效时可重作决策"的依据；③ 把决策塞进定义产出（三张清单加第四类）→ 内容侧与描述侧缝成一条，触本书禁词表与 37 号警戒。

**一处桥接**：§5.2.12 EXAMPLE 1 含 *choice of range of implementation technologies or other realizations to be considered*（中译：所要考虑的实现技术范围或其他实现方式的选择）——**决策划定后续设计能选什么**，即 42020 §E.2.1 的架构即约束（architecture as constraint），可作 ch12→ch14 的过渡锚点。

## 六、2026-10-13 追加：架构决策 ↔ 架构权衡 的关系（面谈分析，供 ch12 取用）

**方向**：**权衡是决策的输入，决策是权衡的落点**，且标准把"权衡必入理据"写成硬要求——42010 §5.2.12 理据六项含 *alternatives and trade-offs considered*（中译：考虑过的备选与权衡），§6.10.2 又规定关键决策的理据是 **shall**；故**理据里不写权衡＝未兑现该 shall**。反向上，决策冻结权衡状态，**改决策＝重开权衡**（42030 §4.3.1 权衡在评估综合时可被重新审视；42010 §6.10.1 NOTE 3 理据失效时决策须重作）。

**过程上的两段各占**：权衡在 42020 §8.4.6（技术侧）与 §9.4.8（价值侧）；而 **trade space 与备选的识别也在决策管理过程内**（15288 §6.3.3.3 b) 3) *Identify the trade space and alternatives.*（中译：识别权衡空间与备选。））——同一件事在两个过程里各有一段，不是两件事。

**五个不对称**：① 定义——决策有定义句（§5.2.12），权衡无定义句（可用的是 tradespace，42020 §8.4.6 NOTE 2）；② 回答——权衡答"此消彼长得到什么失去什么"，决策答"取哪一条、谁背书"；③ 对象——权衡在"解 ↔ 目标／关注点"之间，决策的对象是做法（概念／元素／框架／分层／技术／战术／模式／风格／实现范围／选项集）；④ 结论——权衡可以没有结论（§9.4.5 NOTE 2：把权衡摆给相关方即可，权重非必需），决策必须有结论（15288 §6.3.3.2 c) 选定优先路线）；⑤ 主体与代价——权衡由架构师／评估者做、便宜可反复可定性；决策由有权限者作（42020 §6.2 c)）、昂贵且收窄设计空间。

**互为条件**：权衡无决策 → 选择留给下游或分析瘫痪（42030 §3.4 Note 1：处置不在评估范围）；决策无权衡 → 理据缺项、备选无法区分，选择退化为偏好。**一句话机制：权衡是筛子的刃，决策是筛子的柄**——§9.4.7 b) 剔除相似且不具区分度者；§9.4.8 b) NOTE 1 权衡完全相同者不予考察、须考察跨越 tradespace 的一组；§9.4.8 e) 选出最佳。

**三处易混边界**：① **"暂不决定"不是决策**——标准的合法落点是**已知问题／未决议题**（42010 §6.7 d) NOTE 2 *Open issues can lead to decisions to be made.*（中译：未决议题可导致待作的决策。）），故本书"显式推迟"应记入未决议题，不记成一条决策；② **"现状照旧"是备选之一**（42020 §9.4.7 NOTE 2、§8.4.6 NOTE 4），"什么都不做"也要进权衡、也要被决策，不能以"没决策"逃掉；③ **对象不同但有交点**——交点在 §8.4.7 c) 候选架构间的权衡，与 §5.2.12 EXAMPLE 1 的 *choice of option sets to be considered*（中译：所要考虑的选项集的选择），即**"把谁摆上桌"本身就是一条决策**。

**压成一句**：权衡给决策的是**可比较性**，决策给权衡的是**终结性**，理据是把二者钉在一起的那颗钉子。ch12 骨架即此关系：`12.2` 权衡 → `12.3` 筛与选 → `12.4` 排序与时机 → `12.5` 记录（决策与理据）；旧稿"不可逆"只作排序与时机、不作准入（已裁）。
