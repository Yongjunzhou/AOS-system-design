# 工作方式指示 · 只管本子项目，主项目区不管

**用户原话（2026-09-25）**：「**你只管本项目，另外一个AOS项目不管 100 目录下的子项目**」。

## 口径

1. **范围＝`100-subprojects/01-系统工程研究/`**（教材子项目：`00-系统工程相关研究报告/`、`01-流程工程师培训课件/`、`02-架构工程师培训材料/`、`03-架构师是个怎样的物种/`、`claude-memory/`）。本会话的读写、提交、推送，都只针对这个目录。
2. **主项目区不归本会话管**：仓库根的 `.claude/memory/`、`20-pl4eos/`、`00-generalspec/`、`30-eos/` 等处的改动，以及**其他会话（AOS 主线）的提交、分支与远端状态**——
   - **不调查**（不去查它在做什么、改了什么）；
   - **不报告**（不写进本子项目记忆、不在收尾里汇报、不列"建议它怎么推"）；
   - **不处置**（不代它 commit／push／force-push，不替它调和 ref 差异）。
3. **提交纪律照旧**：一次提交只含 `100-subprojects/01-系统工程研究/` 范围内的文件；**推送前先 `git log -1` 确认 HEAD 是否为本会话的提交**——若不是（并行会话刚提交过），只推自己的提交，**并且不把它人的提交写进记忆**。
4. **越界发现即止**：万一在本目录之外看到改动，**记一句"目录外未触碰"即可**，不展开、不追因、不登记细节。

## 为什么

单仓库多会话并行时，一方去"关照"另一方的提交，既超出本子项目的操作边界（仓库约定：**主题上可互引、操作上互不干扰**），也会把与自己无关的瞬时状态写进本子项目记忆，抬高后续会话的读量、造成误导。

## 与既有规则的关系

- 上游：AOS 根 `CLAUDE.md` §九「子项目 · 隔离原则」与「提交边界（单仓库 + 约定分区）」；本子项目 `CLAUDE.md`「子项目边界」「提交边界」。
- 本条是它们的**会话级执行口径**：不只"改动分别提交"，还包括**不看不报他人提交**。
