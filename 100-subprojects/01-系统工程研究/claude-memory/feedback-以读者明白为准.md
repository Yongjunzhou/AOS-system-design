# 以读者明白为准（2026-10-14 用户定）

**原话**：「我的建议是，把这个事情说清楚，书的读者能够明白就OK了。」

**背景**：报告 38 号 v1.4/v1.5 把"决策与描述"的三问整理成学理形态（三句可带走的定名、档位声明、使用注、条款索引）；随即议"据此修订教材 ch12／ch13"。用户以此句给出**修订的判据**。

## 四条取法（据此执行）

1. **判据是复述，不是齐备**：一段补写算不算成，看**读者能不能用自己的话说出那件事**（对象是什么／记在哪／结果去哪），不看条款号是否列全、机制是否声明完整。
2. **报告的黑话不进正文**：`④档`／`档位声明`／`可带走的定名`／`使用注`／`本报告定性` 一类元语言，属研究报告体，**教材正文不用**；正文只写"是什么"。
3. **条款号只作括注**：出处放句末括注（如 §5.2.12），**不为迁就出处而加句、不堆条款**；但**落笔前仍回正本核一遍**——那是防错，不是仪式。批内新增引文的探针登记照旧做，属后台动作，不占正文。
4. **验收用冷读**：改完做一次冷读（只给正文、只问"这三件事你能用自己的话说一遍吗"），**替代**加码的程序件；发现读者卡住的地方就改那句话，不加注解。

## 与既有纪律的关系

- 不取消既有红线与复算（量尺、三条线索、引文回正本核）——它们管"写得对不对、像不像本书"，与本条管的"读者懂不懂"并行。
- 不取消七阶段门禁：**已收口章的连带改动仍走"解冻一改"**，只是不再为该类小改加开程序批次。
