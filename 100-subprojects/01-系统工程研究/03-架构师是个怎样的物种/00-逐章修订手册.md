## ★ 会话模式：一次一章

**用户定（2026-09-26）：「每次对话只修订一章」。** 故本项目的修订按**章**切分对话，不按批次：

| | 做法 |
|---|---|
| **一次对话** | 只修订**一章**——开门读记忆与当章底本，做完**该章的 §〇 底本核对 ＋ 布局与风格整理**，收工 |
| **收工三件** | ① 复算（§八 那些脚本）② 记忆写回（`claude-memory/` 当章进度＋索引）③ 提交＋推送（只含本目录） |
| **下一章** | **另开一次对话**，开工话术见下 |

**为什么这样切**：① 一章的底本核对（§〇）本身就要逐条回标准正本核，是重活；② 章的修订是**独立可交付**的，一次一章能保证每章都"做完、验过、推过"，不留半成品；③ 章与章之间没有交叉引用（`附录 D` 的引用只挂在第1章），不必攒批。

**开工话术（按章说，通用）**：

> 读 `claude-memory/MEMORY.md` 与 `claude-memory/pending-ch<N>-revision.md`，修订第 N 章。

**每章开一次新对话时，入口文件是 `claude-memory/pending-ch<N>-revision.md`**（第1章为 `pending-ch1-structure.md`，属样例）；该文件由上一章收工时按本章模板新建（或按需现建），内容只放三样：**① 本章底本＝哪几号报告＋要核的标准；② 本章已勘明的活（标题／块序／指称／字母／清点块）；③ 开工前需用户裁定的事项**。

## 〇、第〇步（最要紧，先做）：对着最新底本核内容

**改结构、改标题之前，先把"这一章说的话对不对、是不是最新"办掉。** 内容不对，结构改得再整齐也是白改——这是第2~18章（概念章）的**第一件事**，也是本手册里唯一"不能后补"的一步。

### 0.1 底本两类

- **各章底本＝对应号的研习报告**（`00-系统工程相关研究报告/`，00~34 号）。框架 §三 每章的"来源"列已写明该章依哪几号报告；
- **权威正本＝库内标准**（`00-系统工程相关研究报告/` 下）：ISO/IEC/IEEE 42010:2022／42020:2019／42030:2020／15288:2023／ISO 9000:2026（正本均有中英对照版与 PDF）。**引标准必须回正本逐字核，不得凭记忆、不得凭二手转述。**

### 0.2 逐条引文的核法（**本轮之前四批已立的做法，照搬**）

1. **取英文特征串**（而不是中文译文）到正本里检索；
2. **命中** → 该引文可称"一手"，标注**条款号**，并补版本年号；
3. **零命中** → **降为"二手派生表述"**，写"SEH 表述＋正本邻近句"或改引正本可核的句子，**不得写成"标准说……"**；
4. 中文译文按**现行版本**统一（本轮已统一：`相关方→利益相关方`、`生命周期→生存周期` 等——**注意"全生命周期"应作"生存周期"而非"全生存周期"**，批量替换后必须对"错误产物"反向检索）；
5. 引用落 D：**先登记附录 D 编号 → 再同步章末参考文献切片**（D 是单一权威）。

- **未做**：**ch2／ch5／ch9**（以及第1章——它是方法论章、不引标准，本轮整章重写时已顺带核过 R 号）。

### 0.4 与结构整理的关系

**顺序：第〇步（内容对齐）→ 第一步（量）→ 第二步（结构／标题／块序）。**

理由：内容一改，"哪一句该当判据、哪一块该留"这些结构判断的前提就变了；先改结构再改内容，等于把结构推倒重来两次。**第1章当初反过来做，是因为它整章重写、且无标准引用**——那是特例，不是通例。

## 一、第一条规则：布局与风格都参考第一章

**后续每一章的布局与风格，以第1章为样板。** 第1章这一轮把章首、章末、块名、块序、字母、标题句式，以及语体配比、加粗、比喻、白话都整过一遍，**那套形与那套调就是各章要照着落的**——不必每章重新发明，也不该各章各样。

### 1.1 样板（第1章的现行形）

```
# 第N章 章题

---

## N.1 引言
   引言段（这一段交代：本章先给什么、后给什么、怎么接上后面的正文）
### N.1.1 误解现场
### N.1.2 这一章要回答什么
### N.1.3 这一章的骨架

## N.2 …（正文第一块）
### N.2.1 …
## N.3 …（正文第二块）
## N.4 …（正文第三块）
   案例进展①｜…（无编号，按需穿插）

## 认知反转            ← 不带位置标签；第1章为 ### 1.7.5，各章可择一，但全书要齐
## 小结
## 附录                ← 分组标题
### A 本章概念总图
### B 本章的能力级      ← 清点块：独立成节（其余章另有「本章判据」待裁）
### C 自查 · 这些说法对吗？
### D 练习
### E 参考文献
```

### 1.2 照搬的五件

1. **章首三块与引言段**：`N.1 引言`（＋引言段）→ `误解现场` → `这一章要回答什么` → `这一章的骨架`；
2. **块名与块序**：`认知反转 → 小结 → 附录（分组标题）→ 附录组内各块`；
3. **附录组字母化**：组内各块降 `###` 并给**连续字母**（不跳号）；**字母按该章实际块定**——第1章为 A~E，其余章多一个「本章判据」，故其字母待该块去留裁定后定；
4. **去位置标签**：块名只写功能（不写"章首""章末""第N部分""第N幕"）；
5. **标题句式**：`核心说：补充说`（详见 §三）。

### 1.3 风格照搬的六件（判据全文在 [`00-风格参考.md`](00-风格参考.md)，此处只列"该照什么"）

| 照什么 | 判据出处 | 第1章的实测（可作对照） |
|---|---|---|
| **语体配比**：章首 ≤4%（提示线）／论证 ≥60%／可压件 ≤22%／案例合计 ≤12% 且单块 ≤700 汉字 | 风格参考 §6.1 | 章首 4.7（登记例外）／论证 79.2／可压件 16.1 |
| **加粗只标关键词**：禁整句加粗；≤6 块每千字、占比 ≤7%、每节 ≤3 处 | 风格参考 §6.5「啰嗦三条」 | 已瘦身过一轮 |
| **一个判断只正说一次**：章末各块之间不得复述；同一概念点全书完整表述 ≤3 次 | 同上 | 章末各块已去重 |
| **判据后不写"解释＋例子＋总结"四段式** | 同上 | — |
| **白话优先**：不拿抽象名词当动词、不拿行话当连接词；术语留、行话去；一句话一口气读懂 | 风格参考 §6.6 | 词表命中已清零 |
| **比喻准入**：只在确实有助于理解新概念／图式／心智模型／解释框架时才用；一章并用 ≤4 套；不以喻代定义（尤其节标题） | 风格参考 §6.4 | 在用 4 套 |

**复算**：`python "03-架构师是个怎样的物种/00-风格参考-量尺.py"`（配比与红线，**单一量尺**）＋`audit_verbosity.py`（加粗与重复）＋`audit_metaphor_density.py`（比喻）＋`audit_plainwords.py`（白话，提示线每章 ≤10）。

### 1.4 各章自带、不照搬的两件

- **正文主干的切法**：第1章是六问（`1.2`~`1.7`），其余章是**三幕（定界／磨边界弧／运用）**——这是各章内容决定的，**不改成六问**；
- **节号形式**：第1章的 `§1.3.5` 被其余 17 章章末刻度行引用，各章自己的节号照旧。**唯一要求**：各章章末刻度行回指第1章时写 `§1.3.5`，而各章自身的刻度行按自己的节号写。

### 1.5 三处必须全书一致的口径

1. **刻度行的量词用「级」**（"从第 ① 级（表征）推到第 ② 级（图式）"）——第1章 §1.3.6 已立术语注"论能力说第几级"，各章现写作"层"的须改齐；
2. **`本章的能力级` 清点块**：四行点名（表征／图式／心智模型／解释框架，缺级如实留白）＋`>` 收束句（"见过→拥有"那一句）；
3. **章末刻度行**保留（"用第1章 §1.3.5 的尺子量一下：这一章把 X 从第 ① 级推到第 ② 级……"）。

## 二、三条总原则

### 1. 先量后议，量法本身要正交

改标题、拆块、删内容之前，**先让脚本把现状量出来**，再据数讨论。第1章这一轮的每一个结论都有数撑着：26 个小节题逐条回查（标题词在正文中的出现次数）、骨架 328 字的构成、章末各块字数、口径三种算法的并排。

**更要紧的一条**：**量尺本身可能说谎，必须用另一把尺子验它**。本轮两次实测到量尺误报：

- 量尺把"本章的能力级"这一新独立节归进了"**论证**"（它的归类表里没有"能力级"这一条），于是 ch1 论证虚高到 80.5%、可压件虚低到 14.8%——**改一个字都不报错，只是数字悄悄错**；
- `ch1_layout.py` 的表头漏减 H1 章题 15 字，与量尺的 15020 长期不一致。

**做法**：改完结构必须**用两个以上脚本交叉复算**（`ch1_layout.py` 出逐块字数、`00-风格参考-量尺.py` 出配比、`check_ch1.py` 出目录↔正文与条数），任一处数字变了就追到根因再往下走。

### 2. 标题说事，正文解释；不造词，不贴标签

用户这一轮反复砍的都是同一类东西——**"关于书的标签"**：

| 砍掉的 | 理由 |
|---|---|
| `章首 · 误解现场`／`开篇·本章枢纽` | 两个近义词都指"开头"，读者分不清谁是谁 |
| `本章问题`／`本章骨架` | 是结构标签（说"这块在书里干什么"），不像书的标题；正文讲自己一律用"**这一章**"（实测 242 处） |
| `章末 · 认知反转` | 块序里唯一带位置标签的块，而它后面还有 7 块——"章末"之后还有小节，逻辑不通 |
| `第一部分` | 章节题自带编号已足够，"部分/幕"两个词指同一层级，还显得大 |
| `主问`／`追问` | 内部工作用词，不是书里的话 |
| `第一项归零`（我自造） | 官腔；读者得先知道"归零项"才读得懂——**同级的新词不要叠着造** |

**留下的**是**"书里的话"**：`骨架`（18 章正文 199 次，11 章首句同一模板）、`枢纽`／`根概念`／`乘法律`／`归零项`（附录 A 有户口或本轮已补）。**判据很简单：这个词在正文里用不用？用，就留；只在元文件里用，就换。**

### 3. 一行只改一件事，改完立即复算

标题改一条就复算一次（目录↔正文逐字、条数）。本轮"第一项归零"这类自造词，就是因为**改的时候没有当场读一遍改后的标题**才漏出去的。

## 三、标题整理的规则（26 条小节的实践）

**统一句式＝`核心说：补充说`**——冒号前是这一节的核心，冒号后是它的边界或落点；没有补充就单说。全书章节题本就是这个句式，**不引入新体例**。

四条硬规则：

1. **不用标签腔起首**（"四构件：…""归零项一：…""两个层级：…"）——起首要是实词；
2. **"vs"不许进标题**（全书仅两处，都在第1章，已清）；
3. **喻体不许撑标题**（"承重柱与方向盘"→"核心概念与根概念"；"五环"→"五步一圈"）；喻体是正文用来解释的，不是标题用来命名的——与风格参考 §6.4「比喻准入·三查」同旨；
4. **标题里的词必须有户口**：要么是日常话，要么是附录 A 有条（或本轮已补条）的词。

**两条附带动作**（本轮实测会漏）：

- **标题改完，必读该节首句**——标题把话说全后，首句常常成了同义第二遍（§1.4.4 的"一句冷静的话。"、§1.3.6 的"你要说到第几级"都是这么清掉的）；
- **标题改完，必扫全库引用**——框架 §一／§三、目录、记忆底板、`.work-style` 脚本里都可能写着旧标题（本轮扫出 7 个脚本按旧块名认块）。

## 四、章首与章末的结构（现状要点）

**章首**：`## N.1 引言` ＋ 三子节（`误解现场`／`这一章要回答什么`／`这一章的骨架`）＋ 引言段（交代三块用途与怎么接上后面六节）。

**章末**：

```
## 认知反转            ← 不带位置标签
## 小结
## 附录                ← 分组标题
  ### A 本章概念总图
  ### B 本章的能力级    ← 第1章；其余章还有「本章判据」待裁
  ### C 自查 · 这些说法对吗？
  ### D 练习
  ### E 参考文献
```

**三条口径**：① 块名按功能取，位置由顺序表达；② 附录组内各块**降为 `###` 并给连续字母**（不跳号）；③ **字母与书末附录字母同名不同物**（章末附录 C ＝本章练习；书末附录 C ＝误解清单），引用时**必须带位置**（"章末""书末"）或写全名。

## 五、术语与引用的登记规则

1. **高频词必须有户口**：本轮查出 `乘法律`（正文 10 处）与 `归零项`（13 处）在附录 A 一条都没有——**正文用了、附录没登记，就是黑户**。已补 T-171／T-172。**逐章修订时要专门查一遍：本章反复用的词，附录 A 有没有条？**
2. **来源分三类**（框架 §五 第 7 条）：`D.1 标准`／`D.2 经典文献`（公开可引，给 R 编号，**进各章章末参考文献切片**）／`D.3 内源`（研习笔记，**只列不给编号、不作引用依据、不进切片**）。**判定问一句**：这是"公开可引的产物"还是"我们自己的记录"？前者进 D.2，后者留 D.3。本轮《万维钢·现代思维工具100讲》即由 D.3 升入 D.2（R-106）。
3. **D 是单一权威**：新增引用**先登记 D 编号 → 再同步章末切片**；只改章末、不改 D，就制造了"切片与总表不一致"。

## 七、逐章修订的推荐流程

0. **对底本核内容**（**第〇步，最要紧、不能后补**）：依该章对应号的研习报告＋库内标准正本，逐条核引文与口径；命中升一手、零命中降二手；引用先登记附录 D 编号再同步章末切片（详见 §〇）；
1. **量**：该章的逐块字数（`ch1_layout.py` 同类）＋`00-风格参考-量尺.py`（配比）＋`audit_chapter_openings.py`（块名与旧叫法）＋`ch1_titles.py` 同类（标题名实回查）；
2. **列清单**：把该章要改的标题、块序、附属件逐条列成表，**标出属"机械替换"还是"要重写"**（前者可脚本化，后者要人写）；
3. **先落零风险件**：块名／标题／字母／指称改写——**这些落完不回炉**；
4. **再落要重写的件**：如清点块（四层逐级点名）——它依赖该章内容，必须人写；
5. **复算**：同一套脚本跑一遍，与改动前对照；
6. **写回记忆**：该章修订记入 `claude-memory/`（对象级 progress／pending），索引同步；
7. **提交**：只提交本子项目目录（见 §九）。

**顺序上的一条建议**：**先改"不回炉"的，再改"会回炉"的**。本轮 ch2 试点就是卡在这里——「本章判据」去留未裁，字母排法就要跟着变，所以先做与字母无关的三件（引言化、删幕、级层统一）。

## 九、纪律（本轮用血换来的四条）

1. **只提交本子项目目录**：`git status` 看全貌 → 显式路径 `git add`（不用 `-A`／`.`）→ `git diff --cached --name-only` 复核全部落在 `100-subprojects/01-系统工程研究/` → 确认无合并在途（`.git/MERGE_HEAD`）后提交；不 `--amend`、不 force-push。
2. **别人在合并时，不提交、不解决、不 abort**——先备份本会话改动并如实报告。
3. **大改动落盘后立即提交或先备份**：本轮曾因别会话处置合并，把未提交的一整轮标题整理打回原状（24 条标题、2 条词条、框架版本全丢），靠 `.work-style/_backup-<日期>/`（含 sha256 校验）逐行恢复。备份放 gitignore 内的 `.work-style/`，不进仓库。
4. **未提交的改动随时会消失**：一次只做一件可提交的事，做完就提交。

## 十、本轮的教训清单（供逐章修订时对照）

1. **"我论证过"不等于"我做了"**——"删第N部分"我早先已论证"代价为零"，隔几轮才被用户追问"不是不用第几部分了吗"；**判断落地才算数**。
2. **不要把结论放进讨论中的示例里**——我曾在一份"待裁"的标题示例里把已论证该删的标签写回去，用户当即追问"为什么还保留"。**示例也是承诺**。
3. **数字不能想当然**：章首占比 5.0%→4.7%，我误判为"落到 4% 线下了"——**4.7 仍大于 4**。登记值与实测值要一起改，比较方向不能拍脑袋。
4. **块层级一动，全库脚本跟着抖**：`## X` 变 `### X X` 之后，所有按块名精确认块的脚本**不报错、只是认不出来**（`check_tail_order.py` 一度把 ch1 整个放过了）。改层级前先用 `scan_block_matchers.py` 扫一遍。
5. **锚点别写死字母**：附录字母随章节增减而变，脚本锚点写得越"具体"越脆。
6. **同名是债**：章末「附录」与书末附录、章末字母与书末字母，都是**有意为之的重复**——每次引用都要带位置限定，否则读者与后续修订者都会踩。
7. **改完必须读一遍改后的东西**（不是读 diff）——自造词、"同义第二遍"都是这么发现的。
