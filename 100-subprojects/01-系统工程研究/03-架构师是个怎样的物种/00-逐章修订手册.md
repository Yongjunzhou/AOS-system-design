> **性质**：**操作流程与经验**，不是体例——体例的单一权威是 [`00-全书框架.md`](00-全书框架.md) §五／§十；本文件与框架冲突，以框架为准。
> **适用范围**：**第1~18章，所有章一视同仁——没有例外**（2026-09-27 用户定：「**修订手册是针对所有章的，没有例外**」）。第1章已完成，但**重做时同样照本手册走**；它另有一个身份：本手册 §六「体例照搬」的样板来源。
> **★ 三件不能违反的**：**① 一次对话只修订一章**（**修订下一章一定要新开一个对话**，2026-09-27 用户定——不在上一章的对话里接着改下一章）；**② 四个阶段逐段走，每段先展示、后确认**（未确认不进下一阶段）；**③ 正文未经确认不落库**（不提交、不推送）。

> **★ 标题的硬上限**（2026-09-27 用户定）：「**标题的长度不要超过 15 个汉字**」——**只数汉字**（编号／标点／拉丁字母／阿拉伯数字不计）；**块题与节题同受此限**。**作用＝逼出"题里只说事"**：要在一行里把清单点全，说明那份清单该留在正文。判据全文＝**§七 第 7 条**与 [`00-风格参考.md`](00-风格参考.md) §6.8（标题四律）。

## 一、总流程

### 1.1 一次一章（会话模式）

**用户定（2026-09-26）：「每次对话只修订一章」。** 修订按**章**切分对话，不按批次：

| | 做法 |
|---|---|
| **一次对话** | 只修订**一章**——开门读记忆与当章入口文件，按四阶段走到收工，不跨章。**不要在一次对话里连改多章。** |
| **收工四件** | ① 复算（§十一）② 记忆写回（`claude-memory/` 当章进度＋索引）③ 提交＋推送（只含本子项目目录）④ **为下一章备好入口文件与「开工单」**，并**在收工消息末尾贴出下一章那一行开工语**（`开工第N+1章`）（2026-09-27 用户定，见 §1.6） |
| **下一章** | **一定要新开一个对话**（用户原话：「**修订下一章一定要新开一个对话**」）——把上一章收工备好的**开工提示词**（§1.6.1）整段贴进去即可；**禁止在上一章的对话里接着改下一章** |

**为什么这样切**：① 一章的底本核对（§5.1）本身就要逐条回标准正本核，是重活；② 章的修订是**独立可交付**的，一次一章能保证每章都"做完、验过、推过"，不留半成品；③ 章与章之间没有交叉引用（`附录 D` 的引用只挂在第1章），不必攒批。

### 1.2 四个阶段（关口）

**2026-09-26 定三阶段；2026-09-27 用户定在最前面增设第一个阶段**——每一次重写某一章，**逐阶段走，上一阶段未经确认，不进入下一阶段**：

| 阶段 | 产出 | 过的关 | 详见 |
|---|---|---|---|
| **一、给出本章的目的、目标、主线、内容概要** | **先站到全书上看**——**深入理解本书的目的、目标、主线（三条线）**，**并读懂本章之前各章的目的、目标、主线、概要与框架以及它们对全书目的、目标、主线的支撑**（2026-09-27 用户定）→ 再立**这一章为什么写**（目的）／**写出来要达成什么**（目标）／**这一章的主线**（本章由哪一句话串起来——**★ 必须支撑本章题目**）／**打算写哪些内容**（内容概要）——**在取料之前先把"这一章要干什么"立住** | **★ 展示**（**贴全文、逐条列**）→ 对话确认 → 进阶段二 | §二 |
| **二、给出原料清单** | **这一章重写要用的全部原料**——哪几号研究报告（**带版本号**）、库内哪几份标准正本、哪几份对照与迁移报告、哪些相关报告只作边界澄清、哪些来源**库内无正本（库外·不可核）**；每条注明**位置**与**在本章的用法** | **★ 展示**（**贴全表、逐条列**）→ 对话确认 → 进阶段三 | §三 |
| **三、设计开发本章框架** | 七件＝**主张 ＋ 结构（块与节，含节数增减）＋ 内容重做清单（依最新底本）＋ 案例与对话 ＋ 比喻处置 ＋ 连带清单 ＋ 待裁事项** | **★ 展示**（**框架全文，或"框架条目 ↔ 落在哪节"逐条对照表**）→ 逐条讨论确认 → 进阶段四 | §四 |
| **四、设计开发本章内容** | **按确认的框架写出正文**（含章末件与全部连带） | **★ 展示**（成稿可读；改了什么、落在哪节、复算数字一并报）→ 讨论确认 → **提交＋双推** | §五 |

### 1.3 十二步总表（阶段四的施工顺序）

> **十二步是第四阶段内部的干活顺序**（关口之外的活都在这里），顺序纪律一句话：**内容先对齐 → 结构照第一章 → 逐项裁定 → 减重 → 对话专业化 → 比喻处置 → 一致性 → 收口 → 标题整理 → 全文表达优化**。**先改"不回炉"的，再改"会回炉"的；内容没定，标题别动。**

| 步 | 做什么 | 详见 |
|---|---|---|
| **准备** | **底本与核法**——底本两类、逐条引文核法五条（第一步的准备） | §5.1 |
| **第一步** | **重写本章内容**——基于新版报告与标准，把该章内容**重做一遍** | §5.2 |
| **第二步** | **量，并列清单**——先让脚本把现状量出来再议 | §5.3 |
| **第三步** | **落"不回炉"的结构件**——章首引言化／删「第N幕」／刻度行"层"→"级"／清点块 | §5.4 |
| **第四步** | **逐项请裁，裁完即落**——待裁的先摆出来请用户点头 | §5.5 |
| **第五步** | **落"会回炉"的件**——章末「附录」组、承接与连带 | §5.6 |
| **第六步** | **减重**——加粗瘦身／多余空格／白话清扫／去重复 | §5.7 |
| **第七步** | **案例对话专业化**——人物用概念体系说话，不用情节推进 | §5.8 |
| **第八步** | **处置比喻**——能不做类比就不做，除非它便于读者理解新的概念 | §5.9 |
| **第九步** | **一致性收尾**——文件名与跨文件引用 | §5.10 |
| **第十步** | **复算、写回、提交** | §5.11 |
| **第十一步** | **标题的第二道把关（名实关）**——正文定稿后核：名实相符／不与正文重复／与主线对表／扫全库引用（**第一道·形式关已在阶段三过**） | §5.12 |
| **第十二步（最后）** | **优化全文表达**——**先对段落范例（工序〇）**，再**逐段、逐句**优化；目标是**更通顺、更优雅、更专业** | §5.13 |

### 1.4 两套编号怎么对上

**四个阶段是关口**（产出 → 展示 → 确认 → 放行）；**§5.1 与十二步是关口内的施工顺序**：

| 阶段 | 关口 | 关口内干什么 |
|---|---|---|
| 一 | 立目的·目标·主线·内容概要 | **先懂全书（①）与前序各章（④）**，再读元文件·全库·本章现行内容（②③⑤）；读解基础五类（§2.1） |
| 二 | 取料、出原料清单 | 取料四步（§3.1） |
| 三 | 定框架 | 七件（§4.1） |
| 四 | 写正文 | **十二步施工**（§5.1~§5.13） |

**别把"阶段"与"第几步"混着数**：说"第一步"只指**重写**，说"阶段一"只指**目的·目标·主线·内容概要**。

### 1.5 五条纪律

1. **阶段一不过，不取料**——本章的**目的、目标、主线、内容概要**没经确认，原料清单无从谈起：**不知道要写什么，就不知道要什么料**。
2. **阶段二不过，不设计框架**——原料没定，"依最新底本"就无从谈起（**现行内容不参与定清单**）。用户原话：「**重写的所需要的原料是各最新版的研究报告、标准等，这个要牢记**」。
3. **阶段三不写正文**——内容未定时写正文＝返工；而对着一章既有内容"就地改"，最容易只改到表皮（第2章第一轮的教训：第一步退化成核几条引文、迁几个术语，**那是核对，不是重写**）。
4. **阶段四确认之后才提交＋双推**——正文写完**先请裁、不先落库**。**旧内容始终只作参考材料**：不是打补丁式修订，主张、结构、案例、方法件都按最新底本重做（用户原话见第1章先例「之前的第一章内容仅仅作为参考，无需在这个基础上修改，完全可以另起炉灶」）。
5. **★ 每一阶段的产出都要"展示"出来才算过关**（2026-09-26 用户两度定：先「**框架设计好后，一定要展示出来**」，再「**其实，原料清单也应该给展示出来，便于对话确认**」）——**展示＝把产出摆到用户面前过目、供对话确认**：**目的·目标·主线·内容概要贴全文**｜**原料清单贴全表**（报告带版本／库内正本／只作边界澄清者／库外·不可核者／每条的位置与用法，逐条列，**不得只给一句汇总**）｜**框架贴全文**，或给"框架条目 ↔ 落在哪节"的逐条对照表｜**正文**给可读的成稿并报明改了什么、落在哪节、复算多少。**只给摘要、只给文件路径、或把一句"同意"当成对没展示过的东西的确认——都不算过关**，不得进入下一阶段。**★ 这条是从第4章的实测教训来的**（见附录 A.4）：第4章阶段三只给了一次对话摘要、正式版直接写进 `pending-chN-revision.md`，随后把用户的"同意你的建议"当成整体确认就去写正文了——**框架没被逐条看过，等于这一关没走**（补救办法：正文已落也可回炉，按"主张／结构／内容／待裁"四档报改动代价）。

**工作风格照旧**：四个阶段一律**散文陈述**（背景＋问题＋建议＋理由），**不用选项卡片**。

### 1.6 开工话术、入口文件与开工单

**兜底话术（任何情况下够用的一句话）**：

> 开工下一章。

**这句话的效力**：agent 收到后**自己**读三样——`claude-memory/MEMORY.md`（记忆索引）→ 该章入口文件 `claude-memory/pending-ch<N>-revision.md`（含 `§〇 开工单`）→ 本手册；然后**只做阶段一**，把目的、目标、主线、内容概要贴出来待确认。

**★ 为什么这一句就够了**：章号由 agent 自己算；长文不必由人搬运。**★ 还有一条 DSH 专属理由**：**DSH 没有记忆机制**（仓库 [`AGENTS.md`](../../../AGENTS.md) §八 明写，各 Agent 工具自带的记忆与本仓库 `claude-memory/` **互不相通**），它不会自动加载记忆——所以开工这句话（或承接它的技能）**必须点明"读记忆与入口"**，不能省成"继续"。

**入口文件＝`claude-memory/pending-ch<N>-revision.md`**（第1章入口＝`pending-ch1-revision.md`，另有其第二轮重写件 `pending-ch1-rewrite.md`）；由上一章收工时新建（或按需现建），内容只放三样：**① 本章底本＝哪几号报告＋要核的标准；② 本章已勘明的活（标题／块序／指称／字母／清点块）；③ 开工前需用户裁定的事项**。

#### 1.6.1 开工单（放下一章入口文件；给 agent 读，不由人搬）

**用户令**：「**为修订下一章准备好提示词，并把提示词放在某个文档中**」；同日改口径：**交接内容是给 agent 读的，不是给人复制粘贴的**——人只发一句话（§1.6.2／§1.6.3）。

**放哪儿**：**下一章入口文件的 `§〇 开工单（agent 自读）`**。**理由**：入口文件本就是那一章的唯一入口，开工单与"本章底本／已勘明的活／待裁事项"同处一份——**不分家、不漂移**；另建一份"提示词集"只会多一处要同步的地方。**由谁写**：**上一章收工时**写（收工第四件，见 §1.1、§5.11）——手里正好握着刚勘明的接口与待裁，写出来最准。**谁读**：**agent**；人不开文件、不复制。

**开工单模板（六件，按章替换 `N` 与方括号内容）**：

> 读 `claude-memory/MEMORY.md` 与 `claude-memory/pending-ch<N>-revision.md` 的 `§〇 开工单`，按《逐章修订手册》**四阶段**重写**第 N 章**。
> **先只做阶段一**：给出本章的**目的、目标、主线、内容概要**（**主线＝本章主线，要支撑本章题目**），**贴全文**给我看（不要只给摘要），我确认后再进阶段二。
> **读解基础按手册 §2.1 五类办**：**先懂全书的目的·目标·主线（三条线）** → **再懂本章之前各章的目的·目标·主线·概要与框架及其对全书主线的支撑** → 书的顶层全部 00 号文档 → 报告库所有研究报告与标准（逐份过、每份给判定）→ 本章现行内容（**通读但只作参考**）。
> **本章已勘明的待裁**：［逐条列出，取自本入口文件的裁定清单］。
> **铁约束**：旧内容只作参考材料；每一阶段先展示、后确认；**正文未经我确认不落库、不提交**。
> **收工**：复算（§十一）＋记忆写回＋提交并推送双远端，**并为下一章备好入口文件与开工单**。

#### 1.6.2 本机开工（DSH）

**DSH 的四个入口（2026-09-27 实测）**：

| 入口 | 实情 |
|---|---|
| **Web GUI**（`dsh web` → http://127.0.0.1:3080） | 新建会话可定工作目录，多轮交互、需审批的操作都能走——**本机开工的正路** |
| `dsh headless "任务"` | 一条任务、打印即退（`--session-id` 可续同一会话）；**无审批应答者时写操作 fail closed**——只用于"先出一份阶段一草稿" |
| `dsh tui` | 本机**没有** tui profile（`~/.dsh/profiles` 下只有 `web`），不可用 |
| 技能 **仓库根** `.claude/skills/next-chapter/` | DSH 会读（`.claude/skills/` 下的技能进技能目录；另两个 conformance 技能同处）——触发语 **`开工下一章`**；算章号也可跑 `.tools/next-chapter.js` |

**三步开工**：① 打开 http://127.0.0.1:3080 → **新建会话**；② **工作目录选 `100-subprojects/01-系统工程研究`**；③ 发 **`开工下一章`**（想点名就发 `开工第5章`）。

**为什么必须选对目录**：子项目的 `CLAUDE.md` 与 `claude-memory/` 靠**工作目录**划边界；选到仓库根，就丢了教材子项目这一层。

**终端预览（可选）**：`cd 100-subprojects/01-系统工程研究 && dsh headless "开工第5章"`——打印阶段一草稿；要往下走（确认、写文件、提交）**回 GUI**，headless 写不了文件。

**旁支（某台机器若用 Claude Code）**：`cd <子项目> && claude "开工第N章"`——**别用 `-c`**（它续该目录下最近那个对话，正好犯"下一章必须新开一个对话"）。

#### 1.6.3 换机开工

1. `git pull origin master`（或 `git pull gitee master`，两边一致）；`git status` 确认干净；

6. **★★ 权重：只有"本章之前的各章"作权威**（2026-09-27 用户定）——**本章与后续各章的内容不作权威，参考权重 <10%**：它们大概率会在各自修订时被改（结构、主张、清点块都会动），拿它们当依据就是拿还没定的东西当尺子。落到做法上：④ 只读**前序**各章并当判据用；本章现行内容（⑤）只用于看缺口与承接；**后续各章只用于看"全书大致走到哪、别把后面该讲的话讲掉"，不作论据、不引作判据**。

**后续每一章的布局与风格，以第1章为样板。** 第1章这一轮把章首、章末、块名、块序、字母、标题句式，以及语体配比、加粗、比喻、白话都整过一遍，**那套形与那套调就是各章要照着落的**——不必每章重新发明，也不该各章各样。

**章首**：`## N.1 引言` ＋ 三子节（`误解现场`／`这一章要回答什么`／`这一章的骨架`）＋ 引言段。

**三条口径**：① **块名按功能取，位置由顺序表达**；② 附录组内各块**降为 `###` 并给连续字母**（不跳号）；③ **字母与书末附录字母同名不同物**（章末附录 C ＝本章练习；书末附录 C ＝误解清单），引用时**必须带位置**（"章末""书末"）或写全名。

1. **章首三块与引言段**：`N.1 引言`（＋引言段）→ `误解现场` → `这一章要回答什么` → `这一章的骨架`；

## 七、标题整理的规则

**统一句式＝`核心说：补充说`**——冒号前是这一节的核心，冒号后是它的边界或落点；没有补充就单说。全书章节题本就是这个句式，**不引入新体例**。**目标只有六个字：优雅、一致**（2026-09-26 用户令：「**标题应优雅、一致**」）——数字入题即不优雅，喻体入题即以喻代定义，同一层不同句式即不一致，**长题让人先读第二遍**；四条判据全文见 [`00-风格参考.md`](00-风格参考.md) §6.8。

**七条硬规则**：

> **★ 标题的两道把关**（2026-09-27 用户定：「**对于标题，我们做两道把关**」）：
>
> **第一道·形式关**（**阶段三**，定块题与节题时）——**标题四律 ＋ 七条硬规则**逐条过：**逐题标出汉字数**，并注明已过哪几项（数字／喻体／同一层同一句式／长度 ≤15 汉字／标签腔／符号表达式／户口／工序名与位置描述）；**未过不进阶段四**（§4.1 第 2 件、§4.3 过关条件①）。
>
> **第二道·名实关**（**阶段四第十一步**，正文定稿后）——四项检查：① **名实相符**：读完该节，标题是否说中了这一节真正讲的事；② **不与正文重复**：标题把话说全后，该节首句是否成了同义第二遍（是，就连首句一起改）；③ **与主线对表**：该块是否仍承担本章主线的那一段（内容一调，挂点可能漂移）；④ **扫全库引用**：目录／框架／训侧／脚本锚点里的旧题。**这一关不是重新设计标题**，而是防"内容定稿后标题失准"。
>
> **两道都过，标题才算定。**

1. **不用标签腔起首**（"四构件：…""归零项一：…""两个层级：…"）——起首要是实词；
2. **符号表达式不进标题**（`vs`／`≠`／`⊃`／`=`）——标题用话，不用式子：`核心概念 vs 根概念`→`核心概念与根概念`、`系统化 ≠ 算法化`→`系统化不等于算法化`、`工程系统 ⊃ 技术系统`→`工程系统包含技术系统`。**★ 存量**：全书标题带 `vs`／`≠`／`⊃` 的原共 18 处、散在 8 章；**ch2／ch3／ch4 已随各自重写清掉，现存 8 处、散在 6 章**（ch5 两处／ch6 一处／ch8 两处／ch9 一处／ch11 一处／ch18 一处，2026-09-27 实测），随各自修订轮次清；
3. **喻体不许撑标题**（"承重柱与方向盘"→"核心概念与根概念"；"五环"→"五步一圈"）；喻体是正文用来解释的，不是标题用来命名的——与风格参考 §6.4「比喻准入·三查」同旨；
4. **标题里的词必须有户口**：要么是日常话，要么是附录 A 有条（或本轮已补条）的词；
5. **工序名与位置描述不进标题**（2026-09-26 新增）——① **工序标签**：三幕的 `（定界）`／`（磨边界弧）`／`（运用）` 是内部工作用词（与"主问／追问"同性），读者要的是"这一节讲什么"、不是"它算工序第几步"：`2.2 工程是什么（定界）`→**`2.2 工程是什么`**；**工序名不丢**——它本来就写在每幕的**幕首导语**里，框架 §六 也留着三幕标准。② **位置描述**：`试金石的第一次使用`（"第一次"）与 `（判据前移）`（"前移"）都是**内部账**——前者改 `不是手艺：靠人，还是靠方法`，后者整条括注删。③ **括注带内容**一律去（与仓库写作规则"括号只放指针不放内容"同旨）。
6. **数字不进题**（2026-09-26 用户令新增：「**标题中（其实也是内容中）的数字太多，比如：一句话说清楚、四个要素、工程有四层、三条判据等，这也会让读者蒙圈**」）——题里一个数字都不出现（年份、级号这类"数字本身就是内容"的除外）：`一句话说清工程`→`先给工程一个定义`、`四个要素各司其职`→`定义里的每一样都不能少`、`不是方法论：工程有四层`→`不是方法论：工程比它大`、`工程体检：六个项目挨个过`→`回头给恒信量一遍`。**同一令也管正文**：清单可以留，**数字名要拆**（"四要素""四层""两把尺子""三条判据"一律点名），判据全文＝[`00-风格参考.md`](00-风格参考.md) §6.7；**连带**：附录 A 总图／附录 B 清点块／附录 C 处方行同批改。

7. **长度不超过 15 个汉字**（2026-09-27 用户令：「**标题的长度不要超过 15 个汉字**」）——**只数汉字**：编号（`1.2`）、标点（`：`／`、`／`，`）、拉丁字母与阿拉伯数字**都不计**。**作用＝逼出"题里只说事"**：要在一行里把五步、四样都点全，说明那份清单该留在正文，不该搬进标题。**正反例**（第1章阶段三实题）：`先说准哪个词：一个领域里真正要紧的词很少`（19 字）→**`先说准哪个词：真正要紧的词很少`**（14 字）；`这副能力是什么：挑出枢纽、连起关系、搬到新场景、划清边界`（25 字）→**`概念体系能力：哪几样本事`**（11 字）；`怎么练：立枢纽、连关系、讲出去、校准、用起来`（17 字）→**`怎么练：从立枢纽到用起来`**（11 字）。**连带**：块题与节题同受此限；改完照"两条附带动作"读首句、扫全库引用。

**两条附带动作**（实测会漏）：

- **标题改完，必读该节首句**——标题把话说全后，首句常常成了同义第二遍（§1.4.4 的"一句冷静的话。"、§1.4.5 的"你要说到第几级"都是这么清掉的）；
- **标题改完，必扫全库引用**——框架 §一／§三、目录、记忆底板、脚本锚点里都可能写着旧标题（第1章那轮扫出 7 个脚本按旧块名认块；第2章这轮扫出训侧两处引用旧题，已登记挂账）。

## 八、四条总原则

### 1. 先量后议，量法本身要正交

改标题、拆块、删内容之前，**先让脚本把现状量出来**，再据数讨论。第1章这一轮的每一个结论都有数撑着：26 个小节题逐条回查、骨架 328 字的构成、章末各块字数、口径三种算法的并排。

**更要紧的一条**：**量尺本身可能说谎，必须用另一把尺子验它**（两次实测误报见附录 A.1）。**做法**：改完结构必须**用两个以上脚本交叉复算**（逐块字数、配比红线、目录↔正文与条数），任一处数字变了就追到根因再往下走。

### 2. 标题说事，正文解释；不造词，不贴标签

用户反复砍的都是同一类东西——**"关于书的标签"**（清单见附录 A.2）。**留下的**是**"书里的话"**：`骨架`／`枢纽`／`根概念`／`乘法律`／`归零项`（附录 A 有户口或已补）。**判据很简单：这个词在正文里用不用？用，就留；只在元文件里用，就换。**

### 3. 一行只改一件事，改完立即复算

标题改一条就复算一次（目录↔正文逐字、条数）。自造词就是因为**改的时候没有当场读一遍改后的标题**才漏出去的。

### 4. 以达成目的·目标·主线为重，不以工作量与下游影响为由改选方案

**用户定（2026-09-27）**：「**在修订时，要以达成目的、目标、主线为重，不要考虑改动的工作量和对其他章节的影响**」。**三条做法**：① **阶段三待裁事项的建议与理由，只准写"哪一案更达成目的·目标·主线"**——"这样改动小""避免影响其他 17 章"**一律不得作理由**（阶段一、阶段二的取舍同理）；② **结构、块序、节号、章题、附录字母，凡主线需要即可动**，动完按 §十 连带清单**一次做净**（含其余章引用、附录、目录、训侧、脚本锚点）；③ **仍不可动的只剩体例与红线**（框架 §五 体例、量尺红线、条数口径）——那是产品标准问题，不是工作量问题。**与 §1.5 纪律 5 同源**：展示给用户的是"哪一案更对"，不是"哪一案更省"。

## 九、术语与引用的登记规则

1. **高频词必须有户口**：**正文用了、附录没登记，就是黑户**（第1章查出 `乘法律` 10 处、`归零项` 13 处无条，已补 T-171／T-172）。**逐章修订时要专门查一遍：本章反复用的词，附录 A 有没有条？**

3. **D 是单一权威**：新增引用**先登记 D 编号 → 再同步章末切片**；只改章末、不改 D，就制造了"切片与总表不一致"。

## 十二、提交与协作红线（四条）

1. **只提交本子项目目录**：`git status` 看全貌 → 显式路径 `git add`（不用 `-A`／`.`）→ `git diff --cached --name-only` 复核全部落在 `100-subprojects/01-系统工程研究/` → 确认无合并在途（`.git/MERGE_HEAD`）后提交；不 `--amend`、不 force-push。
2. **别人在合并时，不提交、不解决、不 abort**——先备份本会话改动并如实报告。
3. **大改动落盘后立即提交或先备份**（第1章曾因别会话处置合并，把未提交的一整轮标题整理打回原状，靠备份逐行恢复）。备份放 gitignore 内的 `.work-style/`，不进仓库。
4. **未提交的改动随时会消失**：一次只做一件可提交的事，做完就提交。

## 十三、教训清单（供逐章修订时对照）

1. **"我论证过"不等于"我做了"**——判断落地才算数。
2. **不要把结论放进讨论中的示例里**——**示例也是承诺**。
3. **数字不能想当然**：章首占比 5.0%→4.7%，我误判为"落到 4% 线下了"——**4.7 仍大于 4**。登记值与实测值要一起改，比较方向不能拍脑袋。
4. **块层级一动，全库脚本跟着抖**：`## X` 变 `### X X` 之后，按块名精确认块的脚本**不报错、只是认不出来**。改层级前先扫一遍块匹配。
5. **锚点别写死字母**：附录字母随章节增减而变，锚点写得越"具体"越脆。
6. **同名是债**：章末「附录」与书末附录、章末字母与书末字母是**有意为之的重复**——每次引用都要带位置限定。
7. **改完必须读一遍改后的东西**（不是读 diff）——自造词、"同义第二遍"都是这么发现的。
