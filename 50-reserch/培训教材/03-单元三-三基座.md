# 单元三 三基座：需求·设计开发·质量

> 八步萃取分析见 [03-第3章-需求设计开发与质量-从教材到问题分析.md](../教材书/03-第3章-需求设计开发与质量-从教材到问题分析.md)

## 一、单元导读

### 主题

一个产品开发流程从哪到哪——需求、设计开发、质量三兄弟怎么互相定义、拆不掉？"质量好"和"等级高"被多少人当成同一个词？

### 开场破题（对应章首误解现场）

念出小林在产品评审会上的宣言："兄弟们，我们 M3 温控箱的温度精度做到 ±0.3℃，竞品只有 ±0.5℃；保温时长 72 小时，竞品 48 小时；重量还轻了 2 公斤。**质量绝对没问题。** 现在唯一的悬念是宣传口径——是打'行业精度第一'还是'保温时长远超竞品'。"

让各组表态：这句话你们信吗？角落里测试小赵弱弱地问"那……测试判据是什么？"，小林摆摆手"技术方案都定了，测试判据后面自然会有"——这句"后面自然会有"，你们觉得对吗？

### 本单元要反转的直觉

- **质量 = 做得比人强、指标压过竞品**（× 等级 ≠ 质量；超出需求范围 = 过度设计）
- **设计开发 = 做出技术方案，后面自然会有**（× 止于"可实现"，八方案齐备才算）
- **需求 = 用户说出来的 / 客户没说要就不用做**（× 三形态并列，隐含需求漏了是缺陷）
- **技术方案完成 = 设计开发完成**（× 止于"可实现"；"可验证"是循环倒置）
- **特性越多、越高，质量越好**（× 过度设计只加成本不加质量）
- **质量能打分，85 分很精确**（× 程度是形容词，关键特性不能摊平）
- **等级高 = 质量好**（× 高档车可以是差质量，低档车可以是好质量）
- **质量 vs 进度只能二选一**（× 进度本身是需求——同一份需求集合内部打架）
- **先交付，验证后补**（× 验证可缩不可砍，风险后移成返工）
- **和客户一起砍需求 = 降质量**（× 一起剪裁是变更，单方面砍才叫偷换）

### 本轮题卡的内在逻辑（10 题 2×5）

**第一组 · 概念与原理（先立概念）**：Q1 质量定义（概念本身）→ Q2 基座三角（概念关系）→ Q3 起点判据（需求）→ Q4 终点判据（设计开发）→ Q5 质量 vs 进度（机制）。由"是什么"走到"为什么"。

**第二组 · 落地与实践（用尺量）**：Q6 没做调研的小林（起点判据运用）→ Q7 只有技术方案的 M3（终点判据运用）→ Q8 "85 分"的温控箱（质量程度运用）→ Q9 进度不够客户说真话（进度判据运用）→ Q10 回部门基座体检（落地生根）。判据运用 + 落地动作。

### 同类分组说明

产品组与 IT 组答同一组题，答案互为镜像。冰链 M3 温控箱（硬件 × 软件）与恒信合同审批系统（流程软件）是同一个概念的两面——需求三形态、八方案、等级≠质量、进度剪裁在两边都能验，这正是"基座三角"领域中立的证据。

## 二、题卡（打印分发）

**答题要求**：组内讨论 25 分钟 / 答案 ≤5 行 / 上台讲解 4–5 分钟 / 观点不同必须给理由。

### 第一组 · 概念与原理

**Q1｜质量是什么？**
"小林把参数对比表拍在桌上：温度精度 ±0.3℃（竞品 ±0.5℃）、保温 72 小时（竞品 48 小时）、还轻 2 公斤——他说『质量绝对没问题』。质量到底是什么？用定义里的三个关键词说清：他比出来的这一堆，是质量的哪部分、哪部分不是？"

追问：① 他其实说错了哪个字——想说『质量高』还是『等级高』？"高档车可以是差质量"为什么成立？② 需求只要 ±0.5℃，他把精度做到 ±0.3℃——超出需求范围的那一段，是质量加分还是过度设计？③ 你们最近一次说『质量好』，是拿参数和竞品比，还是拿特性和需求比？比的时候有接收准则吗？

**Q2｜三个词什么关系？**
"请给出 需求、设计开发、质量 三者的关系（一句口诀：定标尺 → 造标尺 → 读标尺），并解释：为什么三个定义互相引用、拆不掉？"

追问：① 客体、特性两个"承重构件"为什么是三角内部的横梁——抽掉任何一个，哪个定义悬空？② 三者的层级完全平级吗？"基座"的最底层是哪两个元概念，设计开发站在什么位置？③ 你们项目里"要什么 / 做成什么样 / 做得好不好"三个问题分别由谁回答？三个答案互相引用吗？

**Q3｜设计开发从哪一刻开始？**
"设计开发从哪一刻开始？『需求 = 用户说出来的』——对吗？"

追问：① 明示、通常隐含、必须履行三种形态是并列的——隐含需求漏了为什么是缺陷、不是『没写文档所以不算』？② 需要、期望、需求三个量级怎么分？『我们要成为冷链行业的精度第一』是需求吗——需求和目标差在哪？③ "可转化"四道闸门，哪个最容易被忽略？起点没收好，为什么是『终点越完美，偏离越远』？

**Q4｜设计开发什么时候算结束？**
"设计开发什么时候算结束？为什么不能拿『可验证』当终点？"

追问：① "可验证"为什么是循环倒置——验证的参照（规定需求）是谁的输出？② 技术方案做完了为什么不算结束？"还有哪个环节会在执行时反问『这到底怎么做』"——八个方案还缺几个？③ 三层"可实现"（原理/方案/事实）各是谁给的？设计开发交付的是事实还是声明？

**Q5｜质量和进度，只能二选一吗？**
"『多给我三个月，质量就自动变好』——对吗？『质量 vs 进度』的冲突，本质是什么？"

追问：① 质量为什么不是时间的函数？『进度本身是一种需求』——那冲突是谁和谁在打？② 四步解法：第一步判真伪、第二步用需求谈判不用质量谈判、第三步分清可妥协与不可妥协、第四步度量可缩不可砍——每一步在防什么？③ 砍掉超出需求范围的『过度设计』，为什么是唯一既省时间又不伤质量的操作？

### 第二组 · 落地与实践

**Q6｜小林为什么白干了七周？**
"小林立项时跳过研究，从『把精度做上去就能赢』的点子直接开工——七周后方案被推倒，销售老陈问『你立项前做过市场调研吗』。起点判据在哪一道闸门上放他过去的？"

追问：① 点子、研究、需求、设计开发的链条，哪一环断了？"合同里没写这条"为什么不是理由？② 客户自己都说不出口的需求——老陈拜访的三个疾控中心开口就问『能不能塞进疫苗运输车』，这个隐含需求怎么才会被主动挖到？③ 你们最近一次大返工，是起点问题（需求没收好）还是终点问题（方案没做透）？当时的调研受控存档了吗？

**Q7｜八个方案缺七个，怎么判？**
"M3 技术方案很漂亮：双压缩机冗余、±0.3℃ 恒温控制、全数字监控。但采购问『按什么型号采、合格准则是什么』、车间问『装配工艺文件呢』、测试问『判据是什么』、交付问『怎么装怎么培训』——七个『没有』。你用什么一句话当场判出『设计开发没结束』？"

追问：① 判据那句口诀怎么用："还有哪个环节会在执行时反问『这到底怎么做』"？② 八个方案对软件长什么样——恒信合同审批系统的"八方案"换成哪几个名字（数据/接口/部署/安全……）？③ 你们宣布"设计完成"的那一刻，测试方案、交付方案里写好了接收准则吗？

**Q8｜"85 分"精确吗？**
"小赵给 M3 打了 85 分：温度控制 92、保温 88、外壳做工 90、重量 70，加权平均。老周问她：『你把断电告警放进去了吗？』——质量能打分吗？这个 85 分错在哪？"

追问：① "程度"是认定出来的不是计算出来的——接收准则（提前写好的标尺）缺了，程度为什么只能"感觉"不能"认定"？② 单项是二元（符合/不符合）、整体是程度（差/好/优秀）——关键特性为什么不能被平均分摊平？断电告警是平均分里的一项吗？③ 老周说"这 85 分是精确的错误"——什么前提下分数才不是假的（需求完整/特性规定完整/证据可靠）？

**Q9｜进度不够，砍需求还是砍验证？**
"进度不够，小林去找老陈：砍掉『箱门单手打开』，老陈说『不行，护士经常一手抱孩子一手开箱』；降『App 实时推送』为两小时同步，老陈同意但『断电告警必须保留』；砍『重量轻 2 公斤』，老陈说『这条本来就是你们销售自己吹出来的』。三十分钟需求重排——这和单方面砍需求差在哪？"

追问：① 为什么和顾客一起剪裁才叫变更、单方面砍叫偷换？需求的所有权在谁手里？② 口头『差不多就行』为什么是最危险的变更形式——需求被悄悄偷换，验证和确认在跟一个什么靶子打？③ "进度冲突是隐含需求的显影剂"——平时问『你还有什么要求』他答『没有了』，今天为什么十分钟全说了？剪下来的需求是"挂账"不是"消失"，挂账用来干嘛？

**Q10｜给你们的部门做一次基座体检**
"结合你们部门现状，用六把尺子（起点判据/终点判据/质量吻合度/进度判据/等级判据/基座三角）给最近一次交付做一次基座体检——给出最该改进的三个事项，每个落到一个动作。"

追问：先做哪把尺子？为什么？两周后回来报告什么？

## 三、点评要点·讲师版

> 点评纪律：先表态后翻案 / 反转精确不造新误解 / 判据配机制 / 归责到可对照动作 / 教机制不教断言 / 先立尺子再翻案 / 拉开强度层次 / 每个纠正落到可操作动作 / 单一权威不另立标准 / 网搜当佐证。

### Q1 质量是什么？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "质量就是比竞品强，参数高就是质量好。" | 结果/载体误判——用"参数高低"替"需求满足"，把等级当质量 |
| 中 | "质量 = 固有特性满足需求的程度。" 定义能复述，但说不清等级 ≠ 质量 | 定义是背的，三个关键词没拆开 |
| 好 | 三个关键词（固有/满足/程度）+ "小林说错了一个字——等级；超出 ±0.5℃ 需求区的那段是过度设计，不加质量只加成本" | 定义与判据咬合，能当场区分等级/质量/过度设计 |

**产品侧 vs IT侧**：产品组答"温控箱精度/保温时长/重量"；IT 组答"响应快/功能多/界面好看"。两边都用"参数"替"需求满足"，都是小林。

**反转话术**（对应章末第一反转·等级 ≠ 质量）：小林想说的是"等级高"，不是"质量高"。M3 按更高标准设计制造、精度行业第一——它是高档产品，等级高。但等级高 ≠ 质量好：高档车可以是差质量，低档车可以是好质量。M3 的精度 ±0.3℃ 远超需求 ±0.5℃，那部分对"质量"没有贡献，只贡献了成本和复杂度——**不是质量，是过度设计**。

**参考答案要点**：质量定义三关键词见 §4.1；等级 ≠ 质量见 §4.3；过度设计见 §4.3 + "本章判据"3。

### Q2 三个词什么关系？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "三个概念排成一条线：需求 → 设计开发 → 质量（先后顺序）。" | 把"互相引用"错当成"单向先后"——顺序是结果不是关系 |
| 中 | "定标尺 → 造标尺 → 读标尺。" 口诀对，但说不出为什么"拆不掉"、说不出承重构件 | 关系结构对，机制缺 |
| 好 | 口诀 + 三定义互相引用（设计开发引需求、质量引需求+特性、需求以特性规定）+ 客体/特性是横梁 + 需求+质量是元概念、设计开发是桥 | 关系结构完整，能证明"拆不掉" |

**产品侧 vs IT侧**：两组都能套同一句口诀——冰链的标尺是"温度精度 ±0.5℃ 符合性"，恒信的标尺是"合同三部门审批流转"。标尺换内容，三角纹丝不动，这正是"领域中立"的现场证据。

**反转话术**：需求、设计开发、质量不是三个并列概念，是同一件事的三面——**三个定义互相引用、拆不掉**。基座的最底层不是设计开发，是需求+质量两个元概念（横跨一切领域），设计开发是架在它们之间的桥——桥是承重的，地基是那两个元概念。为什么 V 模型是 V？因为需求从哪一级分解下去，验证就必须从哪一级收回来——左右是镜像。**"基座"和"几个相关概念"的区别，就是能推出现有的全部方法。**

**参考答案要点**：基座三角见 §5.1；三层证据见 §5.2；承重构件/元概念见 §5.3；推出方法见 §5.4。

### Q3 设计开发从哪一刻开始？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "需求就是用户说出来的，没说的不用做。" | 把三形态砍成一种，隐含需求直接出局 |
| 中 | "三形态并列（明示/隐含/必须履行）。" 形态对，但说不清需求 ≠ 目标、说不清四闸门 | 概念对，判据缺 |
| 好 | 三形态并列 + 需要/期望/需求三个量级 + "精度第一"是目标不是需求 + 可转化四闸门 + 起点没收好终点越完美偏离越远 | 定义 + 判据 + 机制全到位 |

**产品侧 vs IT侧**：产品组举"塞不塞得进疫苗运输车"；IT 组举"审批人手机快速通过/离职审批人自动移交待办"——都是客户没写进合同的隐含需求，漏了客户用一天就认定"这产品不行"。

**反转话术**（对应"起点没收好"反转）："需求 = 用户说出来的"是半句话。ISO 9000 里明示、通常隐含、必须履行三种形态**并列、没有主次**。隐含需求不会自己开口，需要组织主动识别——漏了是缺陷，不是"没写文档所以不算"。再拆一个混用：**需求 ≠ 目标**。"成为冷链行业精度第一"是目标（为什么做），"温度波动 ≤±0.5℃"才是需求（做成什么样）——目标可以激励人，需求必须可判定。设计开发不始于点子，始于"被研究确认过的需求"。

**参考答案要点**：三形态见 §2.1；需要/期望/需求与需求≠目标见 §2.2；可转化四闸门见 §2.3；起点之前是研究见 §2.4；案例进展①。

### Q4 设计开发什么时候算结束？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "技术方案做完就结束了。" | 正是要翻的——用"最先完成的那个"判"全部完成" |
| 中 | "止于可实现。" 结论对，但说不出为什么"可验证"不对、说不出八方案 | 判据用了，机制浅 |
| 好 | "可验证"是循环倒置（验证的参照 = 规定需求 = 设计开发的输出）+ 更详细是唯一判定标准 + 八方案齐备 + 三层次可实现（交付的是声明不是事实） | 机制 + 判据齐，能证明"终点在验证之前" |

**产品侧 vs IT侧**：产品组举"只有技术方案的 M3"；IT 组举"只做架构就宣布设计完成的软件项目"——凡是只做技术方案就宣布完成的，下游都连环空转，只是空转的名字不同（物料/工艺 ↔ 数据/接口/部署）。

**反转话术**（对应"设计开发止于可实现"反转）：两个流行的"终点"都不对。**"可验证"是循环倒置**——验证的参照（规定需求）正是设计开发的输出，拿它当终点等于让设计开发结束在验证的起跑线上。真正的终点是**"可实现"**：需求被细化到足以支撑客体实现、生产和服务提供可直接执行。技术方案只是八个方案里最先完成、最显眼的一个面——**终点由最后一个配齐的方案决定**。设计开发交付的不是事实，是一份"可信的可实现声明"，最终裁决权在终点之后的验证与确认。

**参考答案要点**：终点推导与可验证循环倒置见 §3.4；八方案见 §3.5；三层次可实现见 §3.6；案例进展②。

### Q5 质量和进度，只能二选一吗？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "只能二选一，砍质量保进度。" | 正是要翻的——把需求内讧当成两个系统拔河 |
| 中 | "进度本身是需求，冲突是需求内部打架。" 概念对，四步解法不全 | 机制有了，解法缺 |
| 好 | 质量不是时间函数 + 进度是需求 → 需求集合内讧 + 四步解法（判真伪/用需求谈判/分可妥协/验证可缩不可砍）+ 砍过度设计是唯一不伤质量又省时间的操作 | 机制 + 解法全，能当场用起来 |

**产品侧 vs IT侧**：产品组答"多给三个月温度控制就自动变好？"；IT 组答"多给三个月代码质量就自动变好？"——都错，质量 = 特性满足需求的程度，和时间没有必然关系。

**反转话术**（对应"一场被误判为打架的协调"）："质量 vs 进度"被误判成两个系统的拔河。拆掉两个伪前提：**① 质量不是时间的函数**——多给三个月质量不会自动变好；**② 进度本身就是一种需求**（ISO 9001 §8.2.2：交付时间和交付条件也是顾客要求）。所以本质是**同一份需求集合自己起内讧**——性能/功能需求 vs 交付时间需求。解法不是二选一，是重新平衡：判真伪（一半以上是估算失真的假冲突）→ 用需求谈判不用质量谈判 → 分清可妥协与不可妥协 → 验证可缩不可砍。**砍过度设计是唯一"既省时间又不伤质量"的操作**——超出需求区的特性本来就不是质量的一部分。

**参考答案要点**：质量不是时间函数 + 进度是需求见 §4.5；四步解法见 §4.5；三条禁忌见 §4.5；案例进展③。

### Q6 小林为什么白干了七周？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "小林运气不好 / 没调研是他的错，重做就行。" | 归责到人，没到机制——哪道闸门、什么判据 |
| 中 | "跳过了研究，起点是点子不是需求。" | 判据用了一层，没到"隐含需求"最贵那条 |
| 好 | 起点判据四闸门中"隐含需求已识别"最贵——"塞不塞得进疫苗运输车"是隐含需求；"合同里没写"不是理由（隐含需求就是没写的）；七周返工 = 起点没收好的全部代价 | 机制 + 判据齐，能当场定位断点 |

**产品侧 vs IT侧**：产品组举"尺寸塞不进现有疫苗运输车"；IT 组举"没调研用户真实工作流，系统上线没人用"。同一个病：把点子当需求，跳过研究。

**反转话术**：小林不是"运气不好"，是**起点没收好**。他的起点是点子（"把精度做上去就能赢"），跳过了研究直接进设计开发。设计开发转化的是需求，起点给错了需求，**转化得越彻底，浪费得越彻底**。"合同里没写这条"不是理由——隐含需求不会自己开口，需要组织主动识别，这正是起点判据里最贵的一条。老陈那三个疾控中心开口就问"能不能塞进疫苗运输车"——这是需求，只是没写进合同。

**参考答案要点**：起点之前是研究见 §2.4；可转化四闸门见 §2.3；案例进展①。

### Q7 八个方案缺七个，怎么判？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "M3 还没量产，赶紧补测试方案。" | 只见单个缺口，没提炼判据——七个缺口其实是同一件事 |
| 中 | "设计开发没结束，只做了技术方案。" | 结论对，一句话判据没出来 |
| 好 | "还有哪个环节会在执行时反问'这到底怎么做'？有，设计开发就没结束。" 采购/制造/测试/交付四问即四方案缺；八方案对软件 = 数据/接口/部署/安全方案 | 一句话判据 + 软件迁移全到位 |

**产品侧 vs IT侧**：产品组答"采购问型号、车间问工艺、测试问判据"；IT 组答"部署方案/接口契约/验收标准/运维手册"。两边空转的名字不同，判据同一句。

**反转话术**：老周那句"我们以为设计开发结束了，其实它连一半都没走完"——技术方案只是八方案里的**第一个面**。判据一句话：**还有哪个环节会在执行时反问"这到底怎么做"？有，设计开发就没结束。** 采购没有物料规格、生产没有工艺依据、测试没有判据（小赵那个被淹没的问题）、交付没有部署操作运维指令——四连空转。八方案对软件同样成立，只是名字从"物料/制造"换成"数据/接口/部署/安全"。凡是只做了技术方案就宣布"设计完成"的软件项目，和只有技术方案的 M3 一样，都会在下游连环空转。

**参考答案要点**：八方案见 §3.5；终点由最后一个配齐的方案决定见 §3.5；软件八方案见 §3.5；案例进展②。

### Q8 "85 分"精确吗？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "85 分很客观，数字比形容词精确。" | 被"数字"的精确假象带走，没看到摊平 |
| 中 | "关键特性不能摊平，断电告警该一票否决。" | 结论对，机制浅（程度是认定不是计算） |
| 好 | 程度是认定不是计算；单项二元/整体程度不对称；关键特性（8.3.5 d）不能摊平，否则"精确的错误"；分数成立三前提（需求完整/特性规定完整/证据可靠） | 机制 + 判据齐，能当场解释"什么前提下分数才不假" |

**产品侧 vs IT侧**：产品组答"断电告警失 2 分被温度控制 92 分补回来"；IT 组答"安全模块失分被性能高分补回来——总分 85 掩盖致命缺陷"。同一个"精确的错误"。

**反转话术**（对应"精确的错误"）：打分看起来比"程度"精确，但**精确的前提是把权重量对**。小赵的 85 分把"断电告警"——保命的、8.3.5 d 说的"对预期目的至关重要的特性"——当平均分里的一项：安全项失 2 分，被温度控制 92 分补回来。这个 85 分不是精确，是**精确的错误**：用假象掩盖致命问题。标准层面，质量（程度）、符合性（二元）、等级（分级）都不是分值；组织层面可以造分，但三个前提缺一个分就是假的（需求完整/特性规定完整/证据可靠），且关键特性必须一票否决或用加权、不能平均。

**参考答案要点**：程度三步见 §4.2；质量能有具体分值吗见 §4.4；关键特性优先见 §4.2/§4.4（8.3.5 d）；案例进展④。

### Q9 进度不够，砍需求还是砍验证？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "砍需求很正常，我们经常砍。" | 砍了"谁的所有权、走没走正式变更"——正是要翻的 |
| 中 | "要和客户一起砍，不能自己砍。" | 动作对，机制缺（所有权/挂账/显影剂） |
| 好 | 需求所有权在相关方手里 + 单方面砍=偷换、一起剪裁=变更 + 排序/留痕/挂账 + 口头改需求最危险（验证打移动靶）+ "进度冲突是隐含需求的显影剂" | 机制 + 判据 + 案例深意全到位 |

**产品侧 vs IT侧**：产品组答"老陈排出命根子/可降/可砍三档"；IT 组答"和业务方一起剪裁需求清单，而不是开发自己砍"。同一个"需求的所有权"。

**反转话术**（对应"与相关方一起剪裁需求"）：为什么"一起"是硬要求？**需求的所有权在相关方手里**——需求是"需要或期望"的表述，是顾客的资产，组织只是受托转化。单方面剪裁 = 拿别人的东西替别人做主。剪裁的正确动作是"排序"不是"删减"；剪裁要留痕、走正式变更（8.2.4/8.3.6）；剪下来的不是消失，是**挂账**——下一轮迭代的现成输入。口头"差不多就行"是最危险的变更形式：需求被悄悄偷换，验证和确认全在跟一个没被承认的靶子打。案例③的深意：**进度冲突是隐含需求的显影剂**——平时问"你还有什么要求"他答"没有了"，你说必须砍一样，他立刻知道真正在意的是什么。

**参考答案要点**：四步解法与三条禁忌见 §4.5；与相关方一起剪裁见 §4.5；案例进展③。

### Q10 给你们的部门做一次基座体检

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | 泛泛"要加强需求管理、要重视质量"。 | 没落到六把尺子任何一把，不可检查 |
| 中 | 用一把尺子查出缺口（如"测试方案没有接收准则"） | 有判据，但只照了一面 |
| 好 | 六把尺子逐项打勾，挑出三个缺口各配一个可检查动作，说出先做哪把、两周后报告什么 | 体检完整，动作可执行，有复查机制 |

**产品侧 vs IT侧**：两组各给自己部门体检——体检表本身是同一份（六把尺子），这正是"概念领域中立"的现场证明。

**反转话术**：这一章的判据不是彼此孤立的——起点判据管"要什么"，终点判据管"做成什么样"，质量判据管"做得好不好"，进度判据管"冲突怎么解"，等级判据管"别把档次当质量"，三角判据管"三兄弟咬合"。**六把尺子合起来，才是一份完整的基座体检。** 不用等全打完——找到第一个"否"，就能开工。

**参考答案要点**：六把尺子见"本章判据"；作业指南见课后作业。

## 四、知识卡片

### 一页图（书"本章概念总图"）

```
需求（3.6.4）标尺·要什么 ──可转化判据·起点──▶ 设计开发（3.4.8）造标尺·转化
设计开发 ──可实现判据·终点·八方案齐备──▶ 质量（3.6.2）读标尺·判据
质量 ──程度三步·验证确认──▶ 需求

三形态：明示 / 通常隐含 / 必须履行（并列，无主次）
需要 → 期望 → 需求（三个量级）；需求 ≠ 目标（为什么做 vs 做成什么样）
设计开发止于"可实现"：还有哪个环节执行时会反问"这到底怎么做"？——有，就没结束
质量 = 固有特性满足需求的程度；满足是判定，不是除法
等级 ≠ 质量 ≠ 符合性：按哪套需求分类 / 满足到什么程度 / 满足了吗
过度设计 = 特性超出需求范围——只加成本，不加质量
质量 vs 进度 = 同一份需求集合内部打架：判真伪 → 正式变更 → 验证可缩不可砍
剪裁：与相关方一起（排序/留痕/挂账）才是变更；单方面砍叫偷换
承重构件：客体（被设计的东西）+ 特性（可区分的特征）；基座最底层 = 需求 + 质量（元概念），设计开发是桥
```

### 金句（书"本章判据"提炼）

- 一个产品开发流程，无非是**定标尺、造标尺、读标尺**——需求、设计开发、质量互相引用、拆不掉。
- **起点没收好，转化的是错误需求——终点越完美，偏离越远。**
- 设计开发止于"可实现"：**还有哪个环节会在执行时反问"这到底怎么做"？有，设计开发就没结束。** 终点由最后一个配齐的方案决定。
- 质量是"吻合度"不是"除法"——**特性超出需求范围 = 过度设计，只加成本，不加质量。**
- "质量 vs 进度"不是两个系统拔河，**是同一份需求集合自己起内讧**——进度本身是一种需求。
- **单方面砍需求叫偷换，和顾客一起剪裁才叫变更——中间差着整个需求的所有权。**
- 剪下来的需求不是消失了，是**挂账**：本轮进度解了，下一轮就是现成输入。
- 等级高 ≠ 质量好——高档车可以是差质量，低档车可以是好质量。
- 关键特性不能被平均分摊平——**"85 分"给的不是精确，是精确的错误。**
- **没有接收准则，质量永远只能"感觉"，不能"认定"。**

## 五、课后作业

1. **书练习（与题卡同源）**：设计开发什么时候算结束？"技术方案做完了"够吗？列出至少三个还缺的方案，并说明为什么终点由"最后一个配齐的方案"决定。（书练习 2）
2. **书练习**："质量 vs 进度"的冲突本质是什么？砍掉验证/确认赶进度为什么最贵？口头改需求为什么最危险？（书练习 4）
3. **回部门落地**：结合现状，用六把尺子（起点判据/终点判据/质量吻合度/进度判据/等级判据/基座三角）给部门最近一次交付做一次基座体检——给出最该改进的三个事项，每个落到一个可检查的动作。**两周后回来报告**：哪一项做成了、哪一项卡住了、卡在哪个判据上。

### 作业指南（回部门落地的步骤 + 话术）

> 照着做，2 小时内完成一次体检：
>
> 1. **查起点（尺1）**：最近交付的需求规格，四闸门（完整/无歧义/不冲突/隐含已识别）逐条打勾——最弱一条写一句；隐含需求当初靠什么挖到（调研/访谈/竞品分析）？
> 2. **查终点（尺2）**：把下游环节列一遍（采购/生产/测试/交付/部署/操作/运维）——"还有哪个环节会在执行时反问'这到底怎么做'？"答不上的，就是没配齐的方案。
> 3. **查接收准则（尺3）**：测试方案里有提前写好的接收准则吗（判什么/用什么测/测多久/结论记在哪）？没有 → "质量好"只能感觉、不能认定。
> 4. **查过度设计（尺3 延伸）**：有没有特性超出需求范围、只加成本不加质量？砍掉它，省时间且不伤质量。
> 5. **查进度冲突（尺4）**：最近一次"质量 vs 进度"怎么解决的？先判真伪了吗？走正式变更了吗？和谁一起剪裁的？剪下来的挂账了吗？
> 6. **查三概念（尺5）**：你们说"质量好 / 等级高 / 符合要求"时，是三个概念还是一个？有没有把"降需求"说成"降质量"？
>
> 卡住时：找到第一个"否"就能开工，不必打完全部。产出三件最该改进事项（每条 = 一个可检查动作）。
