## 一、单元导读

### 主题

"改个字段"怎么就成了架构决策？——**架构决策**是"选错了要花大代价才能改对"的选择，三标志辨认（影响半径大 / 持续时间长 / 修改成本高），它藏在每一个"改个字段"里；**它不可避免**——不是做不做，是"成本低时主动做"还是"成本高时被动做"；**不可逆性是经济属性不是技术属性**，用三层框架判断（影响半径 / 信息成本 / 修改风险），数据所有权在其中几乎最不可逆。识别它、分诊它、记录它，是在成本低的时候提前投资。

### 开场破题（对应章首误解现场）

念出恒信合同审批系统里的对话：法务张总："李工，合同编号得改。电子签章平台那边的规则是'合同类型-年份-流水号'，跟咱们库里对不上。帮我们把编号规则改了？"李工瞄了一眼："改个编号格式的事，小事。今天就能上。"当天下午改字段、加状态枚举、测试、上线。三个月后连环三爆——财务对账查不出、台账乱成三条、历史审批链断在中间。

会议室里李工还觉得冤："我就是改了个字段。字段嘛，不是想改就改？"Ada 说："李工，你改的不是一个字段。你改的是这套系统的数据模型——它是这套系统里最不可逆的决策之一。你却把它当成了'改个变量名'。"

让各组表态：如果你坐在这间会议室里，你会站在李工那边吗？"改个字段"——听起来就是"改个字段"，怎么就成了"架构决策"？架构决策真的"想不做就不做"吗？

### 本单元要反转的直觉

- **改个字段就是改个字段，跟架构没关系**（× 数据模型/编号规则/状态枚举往往是系统里最不可逆的架构决策；架构决策藏在每一个"改个字段"里）
- **架构是评审会上画图的事，改字段是码农的事**（× 没被识别出来的架构决策，不会得到应有的审查，却依然承担全部代价）
- **我们直接写代码，不做架构决策**（× 写第一行代码时架构决策就已在发生；"不做"只是选择在成本高时被动做——伪选项）
- **技术上能改回去，所以可逆**（× 不可逆性是经济属性不是技术属性；"能改"和"值得改"是两回事）
- **架构决策越早定越好**（× 按不可逆性分级：高不可逆早做、低不可逆晚做保留期权价值；一刀切早做浪费分析资源）
- **推迟决策就是拖延，是坏事**（× 显式推迟=做"现在不做"的决策+记录"等什么信息、何时再评估"，是架构操作；回答不了三问才是真拖延）
- **写决策记录是浪费时间**（× 记录的价值在一年后——降低"重新发现为什么"的信息恢复成本，把决策从个人知识变成组织资产）
- **需求只是"要什么"，需求没有架构**（× 需求本身没架构，但"需求的方案"——需求怎么组织——有架构，而且是整条链的起点）

### 本轮题卡的内在逻辑（10 题 2×5）

**第一组 · 概念与原理（先立概念）**：Q1 架构决策是什么（概念本身·破题）→ Q2 架构决策/实现决策/架构风格/不可逆性的关系 + 画架构图辨析（概念关系·真悖论）→ Q3 不可逆是经济属性（真悖论）→ Q4 架构决策不可避免（真悖论）→ Q5 三层框架 + 数据所有权最不可逆（真悖论）。由"是什么"走到"为什么"。

**第二组 · 落地与实践（用尺量）**：Q6 恒信"改字段前三问"（识别判据·三标志）→ Q7 冰链直连接口（数据所有权·受控导出·真悖论）→ Q8 恒信六问记录（决策记录·真悖论）→ Q9 30 秒预判·显式推迟·审查分级（期权价值·真悖论）→ Q10 回部门"架构决策体检"（落地生根）。判据运用 + 落地动作。

### 同类分组说明

产品组与 IT 组答同一组题，答案互为镜像。恒信合同审批系统（流程软件）与冰链 M3 温控箱（硬件 × 软件）是同一个概念的两面——"改个字段"在两边都是改架构：恒信把"合同编号规则"当数据模型架构决策（动它，财务/台账/审计/电子签章全跟着动）；冰链把"数据所有权归追溯域"当最不可逆的决策（客户要直连，老周用判断矩阵拦下"受控导出"）。这正是"架构决策/不可逆性"领域中立的证据。

## 二、题卡（打印分发）

**答题要求**：组内讨论 25 分钟 / 答案 ≤5 行 / 上台讲解 4–5 分钟 / 观点不同必须给理由。

### 第一组 · 概念与原理

**Q1｜什么算"架构决策"？"加一个字段"怎么就成了架构决策？**
"李工改完合同编号，三个月后连环三爆。会议室里他还不服：'我就是改了个字段。字段嘛，不是想改就改？'Ada 看着他说：'你改的不是一个字段，你改的是这套系统的数据模型。'——什么算'架构决策'？'加一个字段'怎么就成了架构决策？"

追问：① 三标志：影响半径大（联动改多少）？持续时间长（多少决定建立在它上）？修改成本高（改回来代价多大）？编号规则三把尺子全中——尽管李工只敲了几行代码？② 藏得有多深：李工不是"改错了"，他甚至没意识到自己在做一个决策——"没被识别出来的架构决策，不会得到它应有的审查，却依然承担全部代价"，为什么"没意识到"才是最危险的？③ 你们最近一次"改个字段"，跑过三标志吗？它是架构决策还是实现决策，谁判的？

**Q2｜架构决策和"画架构图"是一回事吗？**
"请给出 架构决策 / 实现决策 / 架构风格 / 不可逆性 的关系（一句话）。再把'画架构图'放进去——架构决策和'画架构图'是不是一回事？为什么说架构决策不是技术难题，是选择难题？"

追问：① 辨析：架构决策 ≠ 架构风格——微服务/事件驱动是"套路"（模板），具体系统选了哪些决策才是架构决策本身？② 反例：改个变量名（可逆、局部、改得起）——三标志全否，不是架构决策？③ "架构=架构图/架构风格（我们画了微服务架构图，架构决策做了）" vs "架构=决策（藏在每个'改个字段'里，画图只是决策的落盘）"——两个都像，靠什么判据分清？④ 选择难题：书架怎么分类、厨房怎么布局、订单服务边界——都不是"技术难题"而是"选择难题"，难在"选哪个、为什么选、选了之后要承受什么"，为什么随手选=不做决策地做决策？

**Q3｜不可逆性是技术属性还是经济属性？**
"李工说：'编号规则技术上能改回去——数据库能迁移、能重构，没有改不了的。所以它是可逆的。'Ada：'能改，和值得改，是两回事。'——不可逆性到底是技术属性还是经济属性？"

追问：① 经济属性：不可逆取决于修改需要多少人、多少时间、冒多大风险——而不是"技术上能不能改"；几乎任何软件决策技术上都能改？② 能改→没人愿意改：改回去的代价=三个月账重对+历史数据重排+台账重新解析+审计重新自查——当这个代价摆上桌，理性的选择往往是"算了，将就着用吧"——"能改"怎么变成"没人愿意改"，这才叫不可逆？③ "技术上能改回去=可逆（数据库能迁移、接口能重设计）" vs "不可逆是经济属性（修改成本高到理性的人选择忍受，能改≠值得改）"——两个都对，靠什么判据分清？④ 复利：普通决策改得起选错问题不大；架构决策改不起，选错的那一刻代价开始复利——为什么"改不起"让选错变成了复利？

**Q4｜架构决策真的可以"不做"吗？**
"老周说：'咱们这次不做架构决策，直接开写，敏捷。'——架构决策真的可以'不做'吗？"

追问：① 不可避免：写第一行代码时架构决策就已在发生——数据存在哪个库、功能拆几个模块、接口怎么定义、状态枚举分几类，一个也跑不掉；不画架构图，不等于没有架构决策？② 伪选项："我们没做架构决策"是伪选项——你只是选择在成本低的时候主动做，或成本高的时候被动做；李工把决策推迟到"三个月后、历史数据都进去了"——用什么价格重新做了一遍决策？③ "不做架构决策，快速开写（跳过分析、敏捷交付）" vs "架构决策不可避免（写第一行代码时就在发生，被动做=在成本爆炸后做）"——两个都对，靠什么判据分清？④ 被动做为什么流行：乐观偏差（未来被想象得太便宜）/ 责任分散（没有所有者）/ 反馈滞后（代价几年后才显现、代价没有主人）/ 隐形决策（散落在改字段里无处显形）——这四个机制里，你们团队中招过哪一个？

**Q5｜数据所有权为什么几乎最不可逆？**
"老周说：'不可逆性是能把用的尺子——量影响半径、信息成本、修改风险。'为什么数据所有权/数据模型在这把尺子上几乎最不可逆？"

追问：① 三层框架：影响半径（结构/时间/组织耦合）→ 信息成本（知识深度/隐含上下文）→ 修改风险（爆炸半径/数据完整性）——三层各量什么？② 修改真正成本公式：修改一个决策的真正成本 = 重新发现当初为什么做这个决策的成本 + 实际修改的成本——为什么大多数时候真正贵的是前者？"不知道为什么要这么定"为什么是敢"今天就能上"的原因？③ 数据所有权三层全占满：影响半径大（数据被多个系统依赖）/ 信息成本高（当初为什么这么分域只有少数人知道）/ 修改风险极高（历史数据迁移一步错全盘错）——为什么它几乎最不可逆？④ "数据所有权改动是接口问题（加个直连接口就完事，需求要满足）" vs "数据所有权是系统里最不可逆的架构决策（三层全占满，动了它历史审计全断）"——两个都对，靠什么判据分清？

### 第二组 · 落地与实践

**Q6｜"改字段前的三问"为什么能拦住下一次爆炸？**
"编号爆炸复盘后，李工在笔记本上写下三个问题：改了它要联动改多少东西？它定了之后多少别的决定要建立在它上面？改错了改回来的代价有多大？——他管这叫'改字段前的三问'，'每次问完都会发现，真正值得动手改的字段，比想象中少得多。'——这三问各在量什么？为什么说'问完发现值得改的变少'本身就是在做架构决策？"

追问：① 三问 = 三标志 = 影响半径/持续时间/修改成本——它们怎么把"字段级"和"数据模型级"分开（李工只排查了 12 处代码引用=字段层面，台账/财务/审计=数据模型层面的下游）？② 案例进展①：如果李工改之前先问这三问，那场连环爆炸在哪一问上会被拦下来？③ 挑你们最近一次改动，跑这三问——有几问答"大"？它当时被当架构决策对待了吗？

**Q7｜客户需求要满足，数据所有权不能动，两个都对怎么办？**
"冰链来了个连锁药店客户，要自己导出原始温度数据接入质管系统。阿凯：'简单，开个直连接口，绕过追溯平台推过去。'老周拦住他：'你这一简单，把第8章我们当众写的'M3 最不可逆的决定'——数据所有权归追溯域——给改了。'——客户需求要满足，数据所有权不能动，两个都对，怎么办？"

追问：① 阿凯的"简单"改的是什么：不是加个接口，是数据所有权归追溯域这条线——追溯平台对这批数据失去控制，三年后追溯出问题谁负责？② "客户要导出数据，需求必须满足（客户是上帝）" vs "数据所有权是系统里最不可逆的决策，不能悄悄改（追溯平台看不见、管不着、审计对不上）"——两个都对，靠什么判据和解？③ 受控导出：导出还是能导出，但走追溯域的受控通道、每条导出记录留痕——数据所有权这条线谁都没动——为什么说"不可逆的决策不是不能做，是要在看清代价后用对的方式做"？④ 你们有没有"客户一句话，把系统里最不可逆的决定顺手改了"的经历？

**Q8｜六问决策记录的价值到底在哪？**
"编号风波过去一个月，恒信要加'签章方式'字段。李工这次没直接动手，先填了一份六问决策记录：决策名称/背景/选项/选择/影响/不可逆性。评审会上财务老王当场指出'混合模式下归档口径得分开，审计才好查'——补进了'影响'栏。Ada 路过看到：'你现在把改字段当成做决策了。'——六问记录的价值到底在哪？"

追问：① 记录的价值不在当下：当下李工当然知道为什么选 B——它的价值在一年后：换个人接手，看到"不可逆性：中-高"和"重排即破坏审计链"，就不会再犯"全局重排"的错——为什么？② "写决策记录是浪费时间（当下我知道为什么这么选，文档没人看）" vs "记录把决策从个人知识变成组织资产（换人接手靠记录不重犯，降低信息恢复成本）"——两个都对，靠什么判据分清？③ 六问里哪一问最容易被跳过？"背景"写不出来或"选项"没想过——说明什么（这个决策从没被认真记录过）？④ 你们最近一次重要决策，六问里填得出"背景"和"选项"吗？

**Q9｜"推迟不是拖延，推迟是决策"——为什么？**
"团队收到一个新变更。李工做 30 秒不可逆性预判：低不可逆→快速实施；高不可逆但信息不足→显式推迟：标记'需完整设计推演'，升级到更重的分析路径。老周：'推迟不是拖延，推迟是决策。'——为什么？"

追问：① 显式推迟 vs 被动拖延：显式推迟=做"现在不做"的决策+记录"等什么信息、什么时候再评估"；被动拖延=不做也不记录、等事故来逼——差别在哪？② 期权价值：一个决策如果现在信息不够，推迟本身就是价值——等到信息充分时再做，比现在瞎猜然后返工便宜得多；"提前投资"不是所有决策都早做，而是把有限的深度分析资源集中投到真正不可逆的决策上（服务边界早定/缓存策略晚定/数据所有权必须早定）？③ "推迟决策就是拖延，是坏事（踢皮球、不做决定）" vs "显式推迟是架构操作（决定现在不做+记录三问，信息不足时等一等比瞎猜返工便宜）"——两个都对，靠什么判据分清？④ 审查分级：审查深度按不可逆性分级——极高完整+多人 / 高完整+独立 / 中语义+同行 / 低快速自检；给低不可逆开三场评审会是浪费、给高不可逆走"自查"是灾难——你们团队在哪一档失配？

**Q10｜给你们的部门做一次"架构决策体检"**
"结合你们部门现状，用十把尺子（三标志 / 不可避免 / 经济属性 / 三层框架 / 数据所有权 / 按级定节奏 / 显式推迟 / 六问记录 / 审查分级 / 两端最高）给最近一次改动 / 决策做一次'架构决策体检'——给出最该改进的三个事项，每个落到一个动作。"

追问：先做哪把尺子？为什么？两周后回来报告什么？

## 三、点评要点·讲师版

> 点评纪律：先表态后翻案 / 反转精确不造新误解 / 判据配机制 / 归责到可对照动作 / 教机制不教断言 / 先立尺子再翻案 / 拉开强度层次 / 每个纠正落到可操作动作 / 单一权威不另立标准 / 网搜当佐证。

### Q1 什么算"架构决策"？"加一个字段"怎么就成了？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "改个字段就是改字段，跟架构没关系，架构是画图的事。" | 正是要翻的——没看见架构决策藏在每个"改个字段"里 |
| 中 | "架构决策是选错了要花大代价才能改对的选择。" 结论对，三标志/藏得多深说不清 | 结论对，机制缺 |
| 好 | 三标志（影响半径大/持续时间长/修改成本高，编号规则三把尺子全中）+ 藏在改字段里 + 没被识别的决策依然承担全部代价 | 判据 + 机制 + 必然性全到位 |

**产品侧 vs IT侧**：产品组答"M3 改固件版本号=改数据模型——批次追溯查不清（第10章固件误当基线的前兆）"；IT 组答"恒信改合同编号=改数据模型——财务/台账/审计/电子签章全跟着动"。同一个"改字段可能是改架构"。

**反转话术**（对应 §1.1~1.3 + 章首）：李工的病，不是"改错了字段"，而是把"数据模型"当成"字段"——把一件架构决策，当成一件普通实现。这是第1章说的**近邻混用**：两个东西长得像（都要改代码、都能改）、其实不同层。**架构决策 = 你在设计系统时做出的某个选择，选错了要花大代价才能改对。** 三标志：**影响半径大**（改了不止改一处，牵一发动全身）、**持续时间长**（一旦选定，无数决策建立在它上）、**修改成本高**（选错了改对，代价大到你会选择"算了就忍着吧"）。编号规则三把尺子全中：影响半径大（财务/台账/审计/电子签章全要跟着改）、持续时间长（三年后归档的合同还按它编码）、修改成本高（要重排历史数据、重对审计账）。但更隐蔽的陷阱是——**李工不是"改错了"，他甚至没意识到自己在做一个决策**。没被识别出来的架构决策，不会得到它应有的审查，却依然承担架构决策的全部代价。

**参考答案要点**：架构决策定义见 §1.2；三标志表见 §1.2；未识别陷阱见 §1.1；概念卡片·架构决策。

### Q2 架构决策和"画架构图"是一回事吗？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "架构决策就是画架构图，画完图架构决策就做完了。" | 正是要翻的——画图是落盘，决策藏在改字段里 |
| 中 | "架构决策≠架构风格。" 结论对，三标志划界/选择难题说不清 | 结论对，机制缺 |
| 好 | 架构决策×实现决策（三标志划界，无自动分界线）+ 架构决策×架构风格（套路 vs 具体选择）+ 架构决策×画架构图（藏在改字段里）+ 选择难题（难在选哪个/为什么选/承受什么，不是技术难题） | 辨析 + 判据 + 机制全到位 |

**产品侧 vs IT侧**：产品组答"M3 的'架构'不是那张框图——是传感器/云端/追溯平台的数据归属决定（第8章老规矩）"；IT 组答"恒信的'架构'不是系统架构图——是编号规则/状态枚举/审批链的决定"。同一个"架构是决策不是图"。

**反转话术**（对应 §1.2~1.3 + 辨析）：架构决策和**实现决策**之间，没有一条自动分界线——分界线靠三标志划：两问以上答"是"就该按架构决策对待，三问全否是实现决策（改个变量名不是）。架构决策也**不等于架构风格**——微服务、事件驱动是"套路"（模板），具体系统选了哪些决策才是架构决策本身。它更**不等于"画架构图的时候做的决定"**——它藏在每一个"改个字段"里。注意三个经典例子的共同点：**它们都不是"技术难题"，而是"选择难题"**——书架分类不需要高深知识，厨房布局不是物理难题，订单边界没有标准答案。架构决策的难不在"怎么做出来"，而在"选哪个、为什么选、选了之后要承受什么"。这也是为什么它常被当成"反正怎么选都行，那就随手选一个"——**随手选，就是不做决策地做决策，代价迟早来收账**（书架选了按颜色，找 Python 书翻遍所有颜色层）。

**参考答案要点**：三标志光谱表见 §1.3；架构决策×架构风格辨析见概念卡片；选择难题见 §1.3 末。

### Q3 不可逆性是技术属性还是经济属性？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "技术上能改回去，就是可逆的。" | 正是要翻的——把"能不能改"当"可逆性" |
| 中 | "不可逆是经济属性。" 结论对，能改→没人愿意改/复利说不清 | 结论对，机制缺 |
| 好 | 经济属性（取决于人/时间/风险）+ 能改≠值得改（能改变成没人愿意改才叫不可逆）+ 复利（改不起选错就开始复利）+ 修改成本曲线（错过窗口期几乎没法改） | 经济属性 + 机制 + 必然性全到位 |

**产品侧 vs IT侧**：产品组答"M3 温度数据迁移——技术上能导，但三年追溯记录一迁全断，宁可将就"；IT 组答"恒信编号规则能改回去，但三个月账重对+审计重查，理性的选择是'算了'"。同一个"能改≠值得改"。

**反转话术**（对应 §1.4 + §2.3）：这一章第一个"把话说死"的地方——**不可逆性不是技术属性，是经济属性**。一个决策是否不可逆，取决于修改它需要多少人、多少时间、冒多大风险——而不是"技术上能不能改"。几乎任何软件决策技术上都能改：数据库能迁移、接口能重新设计、数据结构能重构——没有改不了的。但"能改"和"值得改"是两回事。李工的编号规则技术上当然能改回去，但改回去的代价是：三个月的账重新对、历史数据重新排、台账重新解析、审计重新自查。当这个代价摆上桌，理性的选择往往是"算了，将就着用吧"——**"能改"变成了"没人愿意改"，这才叫不可逆**。这解释了为什么不可逆是架构决策的核心属性：**普通决策改得起，选错问题不大；架构决策改不起，选错的那一刻，代价就开始复利了**。再看修改成本曲线：前期的一小时决策买后期的一个月返工；曲线再陡至少还能改，有些决策错过窗口期之后不是贵、是**几乎没法改**——数据已迁移完、接口已发布、历史合同已归档。

**参考答案要点**：经济属性见 §1.4；复利见 §1.4；修改成本曲线见 §2.3；概念卡片·不可逆性。

### Q4 架构决策真的可以"不做"吗？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "跳过架构直接写代码，就没有架构决策。" | 正是要翻的——写第一行代码时决策就在发生 |
| 中 | "架构决策不可避免。" 结论对，伪选项/被动做四原因说不清 | 结论对，机制缺 |
| 好 | 不可避免（写第一行代码时就在发生）+ 伪选项（只在成本低主动/成本高被动之间选）+ 被动做四原因（乐观偏差/责任分散/反馈滞后/隐形决策）+ 盖楼思想实验（做法 A 只是把决策推迟到施工中） | 判据 + 机制 + 四原因全到位 |

**产品侧 vs IT侧**：产品组答"冰链不画架构图就开模——传感器/云端/追溯域的归属决定一个没少做，只是做的时候没人知道它不可逆"；IT 组答"恒信直接写代码——数据存哪个库、审批流拆几段、状态枚举分几类，决策一个也跑不掉"。同一个"没做架构决策是伪选项"。

**反转话术**（对应 §2.1~2.4 + 案例进展①）：盖楼思想实验：做法 A 直接开工、做法 B 先出结构图。直觉上 A 是"没有架构"、B 是"有架构"——**反直觉结论是：做法 A 不是"没有架构"，它只是把架构决策推迟到了施工过程中**。地基要多深、承重墙在哪、管线怎么走——这些决策在做法 A 里一个也没少做，只是发生在"挖到软土层之后""砌到五层之后""封顶之后"，晚到修改成本已经爆炸。**写第一行代码时，架构决策就已经在发生了**：数据存在哪个库、功能拆成几个模块、接口怎么定义、状态枚举分几类——这些决策一个也跑不掉。不画架构图，不等于没有架构决策，只是做这些决策的人没意识到它们的不可逆性。**"我们不做架构决策"是一个伪选项：你只是选择在成本低的时候主动做，或成本高的时候被动做。** 那为什么被动做这么流行？不是"他们傻"，是四个非常人性化的原因：**乐观偏差**（未来被想象得太便宜）、**责任分散**（没有所有者的决策得不到应有重视）、**反馈滞后**（代价几年后才显现、代价没有主人）、**隐形决策**（散落在"改个字段"里无处显形）。合起来指向同一个结论：**被动做不是没有架构，是"没有显式的架构"**——而让架构决策显式化的第一步，就是认出它。

**参考答案要点**：盖楼思想实验见 §2.1；伪选项见 §2.2；四原因见 §2.4；案例进展①。

### Q5 数据所有权为什么几乎最不可逆？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "数据所有权是 DBA 的事，加个接口就完事。" | 正是要翻的——数据所有权是最不可逆的架构决策 |
| 中 | "三层框架：影响半径、信息成本、修改风险。" 结论对，每层来源/公式说不清 | 结论对，机制缺 |
| 好 | 三层框架每层两来源（结构/时间/组织耦合 → 知识深度/隐含上下文 → 爆炸半径/数据完整性）+ 修改真正成本公式（重新发现为什么+实际修改）+ 数据所有权三层全占满 → 几乎最不可逆 | 三层 + 公式 + 案例全到位 |

**产品侧 vs IT侧**：产品组答"M3 温度数据归追溯域——传感器只管采、云端只管传、追溯平台管存管管看，动它历史追溯全断"；IT 组答"恒信合同数据归合同域——财务/台账/审计/电子签章全依赖，动它审计口径重建"。同一个"数据所有权最不可逆"。

**反转话术**（对应 §3.1~3.6 + 概念卡片·不可逆性）：不可逆性 = 修改成本高到理性的决策者宁愿忍受现状、也不掏钱去改的程度。怎么判断一个具体决策的不可逆程度？三层框架——**影响半径**（修改需要联动多少东西：结构耦合——数据归属/公开接口；时间耦合——渐进迁移 vs 一次性同步；组织耦合——一个团队 vs 跨团队开会）、**信息成本**（重新搞清楚应该改成什么样：知识深度——重走推演链；隐含上下文——背景信息只存在当事人脑子里）、**修改风险**（改错后果严重到无法接受：爆炸半径——是否在关键路径交汇点；数据完整性——涉及历史数据迁移自动升级风险）。**修改一个决策的真正成本 = 重新发现当初为什么做这个决策的成本 + 实际修改的成本**，大多数时候真正贵的是前者——"不知道为什么要这么定"，才是敢"今天就能上"的原因。为什么数据所有权/数据模型几乎最不可逆？因为它三层全占满：影响半径大（被多个系统依赖）、信息成本高（当初为什么这么分域只有少数人知道）、修改风险极高（历史数据迁移一步错全盘错）。这就是第8章把"数据所有权"列为 M3 最不可还原的决定的原因——这一章给那个判断补上了完整论证。判断矩阵是一把**分诊尺**：先粗判落在哪一档再决定待遇——分诊不需要完美，只要能把"高不可逆"从"低可逆"里挑出来，就已经赢了九成。

**参考答案要点**：三层框架三节见 §3.2~3.4；综合矩阵见 §3.5；完整演练见 §3.6；概念卡片·不可逆性。

### Q6 "改字段前的三问"为什么能拦住下一次爆炸？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "改字段之前多检查几处引用、多测几次。" | 正是要翻的——检查引用是字段层面，三问是数据模型层面 |
| 中 | "三问是三标志，能判断是不是架构决策。" 结论对，字段级/数据模型级分开说不清 | 结论对，机制缺 |
| 好 | 三问=三标志（联动改多少/多少决定建立在它上/改回来代价）+ 字段层面依赖 vs 数据模型层面依赖（12 处代码引用 vs 台账/财务/审计）+ 问完发现值得改的变少=识别本身在做架构决策 | 判据 + 层面划分 + 机制全到位 |

**产品侧 vs IT侧**：产品组答"M3 改采样算法前先三问——联动改多少（采集/传输/追溯全链）、多少决定建立在它上（断链判定逻辑）、改回来代价多大（已出厂箱子）"；IT 组答"恒信改编号规则前三问——联动改多少（财务/台账/审计/电子签章）、多少决定建立在它上（合同状态流转/审批链）、改回来代价多大（历史数据重排）"。同一个"改字段前三问"。

**反转话术**（对应案例进展①）：李工说"我查过所有引用这个字段的地方，十二处，全改了。测试也过了，为什么还会炸？"Ada 反问："合同编号这个字段，除了代码里十二处引用，还有谁在依赖它？"——**你说的十二处引用，是'字段'层面的依赖；台账、财务、审计，是'数据模型'层面的依赖**。你只排查了字段层面，就把一个数据模型级的决策，当成字段级的操作给做了。三问：**改了它，要联动改多少东西？它定了之后，多少别的决定要建立在它上面？改错了，改回来的代价有多大？** 三个问题里有两个答"大"，你就该停下来，把这次改动当成一个架构决策来处理——先论证、先评审、先记录，而不是"今天就能上"。李工后来每次问完都会发现：**真正值得动手改的"字段"，比想象中少得多**——因为"发现值得改的变少"这个动作本身，就是在做架构决策。

**参考答案要点**：案例进展①；三标志见 §1.2；影响半径三来源见 §3.2。

### Q7 客户需求要满足，数据所有权不能动，两个都对怎么办？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "客户要导出就给，开个直连接口最快。" | 正是要翻的——把"加接口"当小事，悄悄改了最不可逆的决策 |
| 中 | "数据所有权不能动，需求可以换个方式满足。" 结论对，受控导出/留痕说不清 | 结论对，机制缺 |
| 好 | 阿凯的"简单"改的是数据所有权线 + 判断矩阵圈出"数据所有权归属"极高不可逆 + 受控导出（走追溯域受控通道、每条导出留痕）+ 不可逆决策不是不能做、是看清代价后用对的方式做 | 数据所有权判据 + 案例 + 收束全到位 |

**产品侧 vs IT侧**：产品组答"冰链客户要原始温度数据——直连绕过追溯域=改最不可逆决策，走受控导出+留痕"；IT 组答"恒信客户要合同数据直连接口——绕过合同域=改数据所有权，走受控导出+审计留痕"。同一个"客户需求满足但不碰所有权线"。

**反转话术**（对应案例进展② + §3.5）：阿凯的第一反应是"简单，开个直连接口，把原始温度数据直接推过去"。老周问："数据从哪来？""追溯平台啊。""那'直连'的这条通道，绕过谁？"阿凯顿了一下："绕过追溯域。"——**你这一"简单"，把第8章当众写的'M3 最不可逆的决定'——数据所有权归追溯域——给改了**。阿凯拿出那张判断矩阵，把"数据所有权归属"那一行圈了出来：影响半径大、信息成本高、修改风险极高、综合判定极高不可逆。他刚才准备动手的"加个接口"，是这套系统里不可逆性最高的一档决策。**所以这不是"接口问题"，是"架构决策"。** 正确的做法是受控导出：客户要导出数据可以，但走追溯域的受控通道，每条导出记录留痕——导出还是能导出，但数据所有权这条线，谁都没动。**不可逆的决策，不是不能做——是要在看清代价之后，用对的方式做。** 客户需求可以满足，但满足的方式，不能是悄悄改掉系统里最不可逆的决定。

### Q8 六问决策记录的价值到底在哪？

| 中 | "记录把决策变成资产。" 结论对，信息恢复成本/不可逆性标注说不清 | 结论对，机制缺 |
| 好 | 六问（名称/背景/选项/选择/影响/不可逆性）+ 价值在一年后（换人接手靠记录不重犯）+ 从个人知识变组织资产 + 背景/选项写不出=从没认真记录过 + 关键节点标不可逆性（等级+理由+修改代价） | 记录 + 机制 + 标注全到位 |

**产品侧 vs IT侧**：产品组答"M3 采样算法改版记录——一年后新工程师看到'不可逆性：高，已出厂箱子数据'不重犯"；IT 组答"恒信签章方式决策记录——财务老王当场补'归档口径分开，审计才好查'进影响栏"。同一个"决策记录降低信息恢复成本"。

**反转话术**（对应 §4.3 + 案例进展③）：用恒信"合同编号规则"演示六问——决策名称 / 背景 / 选项（A 全局重排 vs B 新旧双轨） / 选择（B，因为历史合同已与纸质归档绑定，全局重排的审计与追溯风险远大于双轨过渡成本） / 影响（台账/报表需兼容两套编号） / 不可逆性（中-高，重排即破坏审计链）。**注意这段记录的价值——它不在当下**。当下李工当然知道为什么选 B；它的价值在一年后：换个人接手，看到"不可逆性：中-高"和"重排即破坏审计链"，就不会再犯"全局重排"的错。**决策记录是把一次决策，从"当事人脑子里的知识"变成"组织的资产"。** 六问之外还有配套动作——**在架构的关键节点上标注不可逆性**：合同数据模型（合同主表/审批记录/附件）：不可逆性极高、理由、修改代价。标注的价值不在当前设计者，在一年后换人接手——他看到"不可逆性：极高"就知道不要轻易动，看到"理由"就知道动了会波及什么。第8章案例进展④里老周把"老规矩"写下来当 M3 的架构；不可逆性标注，就是让这份"老规矩"在落到具体节点时，**自带警示牌**。

**参考答案要点**：决策记录六问见 §4.3；不可逆性标注见 §4.3 末；案例进展③。

### Q9 "推迟不是拖延，推迟是决策"——为什么？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "推迟就是踢皮球、不做决定，是坏事。" | 正是要翻的——把"显式推迟"当"被动拖延" |
| 中 | "显式推迟要记录三问。" 结论对，期权价值/审查分级说不清 | 结论对，机制缺 |
| 好 | 显式推迟 vs 被动拖延（做"现在不做"的决策+记录 vs 不做也不记录）+ 期权价值（信息不够时等一等比瞎猜返工便宜）+ 按不可逆性定节奏（高早/中预留/低晚）+ 审查分级（极高完整+多人/高完整+独立/中语义+同行/低快速自检）+ 30 秒预判 | 判据 + 期权 + 分级全到位 |

**产品侧 vs IT侧**：产品组答"冰链缓存策略可以晚定（信息不够改了不贵）、数据所有权必须早定（错了数据迁移）"；IT 组答"恒信服务边界早定（改它贵）、具体排序算法晚定（改了不贵）"。同一个"按不可逆性定节奏"。

**反转话术**（对应 §4.1~4.4）：架构决策的时间策略，不是一刀切"早做"，而是**按不可逆性分级**——高不可逆早做、充分分析、多人审查；中不可逆初步分析、预留调整空间；低不可逆晚做、快速决定、错了再改。注意最后一行"晚做"——它不是偷懒，是一条有名字的策略：**期权的价值（option value）**——一个决策如果现在信息不够，推迟它本身就是一种价值，等到信息充分时再做，比现在瞎猜然后返工要便宜得多。"提前投资"不是说所有架构决策都要尽早做死——恰恰相反，**好的架构投资，是把有限的深度分析资源，集中投到真正不可逆的决策上**（服务边界早定/缓存策略可以晚定/数据所有权必须早定）。而"推迟"从一种无奈变成一种操作，靠的是**显式地、有意识地、记录在案地"决定现在不做决定"**——记录"等什么信息、什么时候再评估"，然后主动去收集那个信息。显式推迟之所以是决策而不是逃避，因为它回答了三个问题：**现在为什么不做？等什么信息？什么时候再评估？** 回答不了这三个问题，才是真拖延。最后，审查深度也按不可逆性分级：极高完整+多人交叉 / 高完整+至少一人独立 / 中语义符合性 / 低快速自检——**把有限的审查资源，集中在真正不可逆的决策上，而不是均匀撒在所有决策上**；给低不可逆开三场评审会是浪费、给高不可逆走"自查"是灾难。回想第7章三个看门人：按级审查，是把关动作在"架构决策"上的具体配置——先分诊，再派尺子。

**参考答案要点**：期权价值见 §4.1；显式推迟见 §4.2；审查分级见 §4.4；对照第7章三个看门人。

### Q10 给你们的部门做一次"架构决策体检"

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | 泛泛"决策要认真、要多评审、要写文档"。 | 没落到十把尺子任何一把，不可检查 |
| 中 | 用一把尺子查出缺口（如"我们的数据所有权没人定过""最近一次改动没跑三标志"） | 有判据，但只照了一面 |
| 好 | 十把尺子逐项打勾，挑出三个缺口各配一个可检查动作，说出先做哪把、两周后报告什么 | 体检完整，动作可执行，有复查机制 |

**产品侧 vs IT侧**：两组各给自己部门体检——体检表本身是同一份（十把尺子），这正是"架构决策/不可逆性"概念领域中立的现场证明。

**反转话术**：这一章的判据不是彼此孤立的——三标志判据管"这是不是架构决策"（两问以上"大"就按架构决策对待）、不可避免判据管"有没有把'没做架构决策'当选项"（伪选项）、经济属性判据管"能不能改≠值不值得改"（愿意将就就是不可逆）、三层框架判据管"不可逆到什么程度"（影响半径→信息成本→风险）、数据所有权判据管"最不可逆的决策动了吗"（按最高不可逆对待）、按级定节奏判据管"早做晚做对不对"（期权价值）、显式推迟判据管"信息不足的决策是不是被硬做/硬拖"（三问答不上才是真拖延）、六问记录判据管"决策从个人知识变组织资产了吗"（价值在一年后）、审查分级判据管"审查资源花对地方了吗"（先分诊再派尺子）、两端最高判据管"这个变更落在哪一层"（在便宜的层解决）。**十把尺子合起来，才是一次完整的"架构决策体检"。** 不用等全打完——找到第一个"否"，就能开工。

**参考答案要点**：十把尺子见"本章判据"；作业指南见课后作业。

## 四、知识卡片

### 一页图（架构决策 · 不可逆性 · 提前投资）

```
架构决策 = 选错了要花大代价才能改对的选择
  三标志：影响半径大 · 持续时间长 · 修改成本高
  反例：改个变量名（可逆、局部、改得起）——不是架构决策
  藏在每个"改个字段"里：没被识别的决策依然承担全部代价

架构决策不可避免：不是做不做，是早晚
  被动做 = 在成本爆炸之后做（盖楼先开工）
  主动做 = 在成本低时做（先出结构图）
  伪选项："我们没做架构决策"——只是选了在哪个时刻做

不可逆性 = 经济属性，不是技术属性（能改 ≠ 值得改）
  三层判断框架：
    影响半径（结构/时间/组织耦合）→ 信息成本（知识深度/隐含上下文）→ 修改风险（爆炸半径/数据完整性）
  最不可逆：数据所有权 / 数据模型 / 服务边界 / 对外接口契约

提前投资：按不可逆性决定节奏
  高不可逆 → 早做 · 充分分析 · 多人审查
  中不可逆 → 初步分析 · 预留调整空间
  低不可逆 → 晚做 · 快速决定 · 错了再改（期权的价值）
  显式推迟 = 记录"现在不做，等什么信息，何时再评估"

决策记录六问：名称 · 背景 · 选项 · 选择 · 影响 · 不可逆性
  不可逆性标注：关键节点标"高/极高 + 理由 + 修改代价"
  审查深度按不可逆性分级，资源集中在刀刃上

设计链各层决策不同：需求组织（极高）→ 业务流程（中-高）→
  系统功能（中）→ 产品构件（极高）——两端最高，中间缓冲
  需求本身没有架构，需求的方案有架构
```

### 金句（书"本章判据"提炼）

- **架构决策 = 选错了要花大代价才能改对的选择——它藏在每一个"改个字段"里，不是评审会上"画架构"才发生。**
- **改个字段可能是改架构：数据模型、编号规则、状态枚举往往是系统里最不可逆的架构决策。**
- **"我们没做架构决策"是伪选项——不是做不做，是你选择在成本低的时候主动做，还是成本高的时候被动做。**
- **不可逆性是经济属性不是技术属性："能改"和"值得改"是两回事——修改成本高到理性的人选择忍受，就是不可逆。**
- **随手选，就是不做决策地做决策——代价迟早来收账。**
- **被动做不是没有架构，是"没有显式的架构"；让架构决策显式化的第一步，就是认出它。**
- **数据所有权/数据模型几乎最不可逆——影响半径大、信息成本高、修改风险极高，三层全占满。**
- **推迟不是拖延：显式推迟=做"现在不做"的决策，记录"等什么信息、何时再评估"——回答不了三问才是真拖延。**
- **决策记录的价值在一年后——把一次决策从"当事人脑子里的知识"变成"组织的资产"。**
- **在便宜的层做对的决策，贵的层才不用付返工的学费。**

## 五、课后作业

1. **书练习（与题卡同源）**：挑一个你最近做过的改动，用"三标志"检验：它影响半径大吗？持续时间长吗？修改成本高吗？它是个架构决策，还是个实现决策？（书练习 1）
2. **书练习**：用一个"当初不知道为什么要这么定、现在也不敢改"的决定——它大概率是信息成本极高的不可逆决策。把它写下来，补上"背景"。（书练习 4）
3. **回部门落地**：结合现状，用十把尺子（三标志 / 不可避免 / 经济属性 / 三层框架 / 数据所有权 / 按级定节奏 / 显式推迟 / 六问记录 / 审查分级 / 两端最高）给部门最近一次改动/决策做一次"架构决策体检"——给出最该改进的三个事项，每个落到一个可检查动作。**两周后回来报告**：哪一项做成了、哪一项卡住了、卡在哪把尺子上。

### 作业指南（回部门落地的步骤 + 话术）

> 照着做，1~2 小时内完成一次体检：
>
> 1. **识别（尺1）**：挑一个最近做完/正在做的改动，跑三标志——影响半径大吗？持续时间长吗？修改成本高吗？两问以上"大"→它是架构决策。
> 2. **查有没有被识别**：它当初被当成架构决策对待了吗——有论证、有评审、有记录？还是"顺手改动、今天就能上"？
> 3. **查被动做信号（尺2）**：有没有"我们没做架构决策"的说法？这个决策是在成本低时主动做的，还是在成本高时被事故逼着做的？
> 4. **量不可逆性（尺4）**：影响半径（结构/时间/组织耦合）？信息成本（知识深度/隐含上下文）？修改风险（爆炸半径/数据完整性）？三档各打高/中/低，得出综合判定。
> 5. **查数据所有权（尺5）**：这次改动碰数据模型/所有权了吗？数据归属谁定过、写过吗？
> 6. **查节奏（尺6）**：高不可逆的早做了吗？中不可逆的预留调整空间了吗？低不可逆的是不是被过度审查（开了三场评审会）？
> 7. **查推迟（尺7）**：有没有"信息不足+高风险"的决策被硬做了？该显式推迟的，三问（现在为什么不做/等什么信息/何时再评估）记下来了吗？
> 8. **查记录（尺8）**：重要决策有六问记录吗？关键节点标了不可逆性（等级+理由+修改代价）吗？
> 9. **查审查（尺9）**：审查深度匹配不可逆性吗——极高完整+多人 / 高完整+独立 / 中语义+同行 / 低快速自检？
> 10. **查层级（尺10）**：这个变更落在哪一层（需求组织/业务流程/系统功能/产品构件）？有没有跳过中间层、直接在产品构件这个最贵的层面动刀？
>
> 卡住时：找到第一个"否"就能开工，不必打完全部。产出三件最该改进事项（每条 = 一个可检查动作）。
