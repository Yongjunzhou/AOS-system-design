# 单元二　工程——你们做的是工程，还是手艺？

> 对应教材书：[第2章 工程](../教材书/02-第2章-工程.md)
> 配套检索：附录 A 术语表（T-13~25）· 附录 B 概念档案集（工程 / 工程系统）· 附录 C 误解清单（第2章行）

## 1. 单元导读

**主题**：工程是什么、不是什么；工程与手艺/科学/艺术的区别；系统化 ≠ 机械化；系统工程与工程系统；工程师需要什么能力。这一单元回答全书最基础的问题：**我们到底在做什么。**

**开场破题（请对此发表意见）**：念恒信季度会那场：架构师李工站在投影前，"各位，我们敏捷转型成功了。双周迭代、CI/CD 全绿、自动化测试覆盖 80%。**我们已经是工程化团队了。**"会议室鼓掌。只有需求分析师 Ada 低声问了一句："那……上个月上线那次事故，是为什么？"李工说："那是人手不够，临时赶工。跟工程化没关系。"**先让两组表态：李工的团队，是工程，还是不是？给出你们的判据。**

**本单元要反转的三个直觉**：

1. 「用了敏捷 + CI/CD + 测试 = 在做软件工程」——**错**。敏捷和 CI/CD 只覆盖工程四层里的两层。
2. 「系统化 = 有算法、机械化执行」——**错**。系统化是"有章法的判断"，不是"确定性的执行"。
3. 「系统上线了 = 工程成功 / 工程师头衔 = 在做工程」——**错**。技术系统 ≠ 工程系统；头衔不定义工程师，能力才定义。

**本轮 5 题的内在逻辑**：Q1 破题（工程体检——判"李工的团队是工程吗"）→ Q2 工程 vs 手艺（试金石）→ Q3 敏捷 ≠ 软件工程（四层结构）→ Q4 系统化 ≠ 机械化 → Q5 工程系统 vs 技术系统 + 工程师能力（给自己的工作做体检）。

**同类分组说明**：恒信（IT 主案例）和冰链（产品镜照）——IT 组容易把"系统上线"当"工程成功"，产品组容易把"样机验证通过"当"产品成功"；同一个概念（工程系统 vs 技术系统）在两个世界各长一个样子，正是"工程不挑行业"的证据。

## 2. 题卡（打印分发）

> **答题要求**：组内讨论 25 分钟，把答案写在便签/白板上。每题答案不超过 5 行。每组选派一人上台讲解（4–5 分钟）。允许观点不同，但必须给出理由。

**Q1（破题·先表态 + 追问链）** 恒信 IT 部上了敏捷、CI/CD 全绿、自动化测试覆盖 80%。季度会上李工宣布："我们敏捷转型成功了，已经是工程化团队了。"——**这个团队如果换成你们团队，你会点头吗？先表态。**然后回答：上个月合同审批系统月末高峰宕机 40 分钟，容量评估在冲刺计划里排了，却因为"这个功能月底要上"被砍了，没有评审、没有风险登记、没有签字。李工说"那是人手不够，跟工程化没关系"。①这个团队是工程还是不是？按四层结构，缺哪两层？②"容量评估被砍"砍掉的是哪一层？"先上再说"砍掉的又是哪一层？两刀砍在不同的层，后果各是什么？③如果让李工补上缺的两层，第一步做什么动作？（价值层不是口号——落到评审、风险登记、签字，具体是什么？）

**Q2（先表态 + 追问链）** 一个老师傅做了十五年温控产品，车间里没有一份完整的测试方案，但他"心里有数"——哪个批次容易出问题、哪种工况要降额、哪家供应商的电容不可靠，全在脑子里。他请两周假，产线出问题没人能定位；他回来十分钟找到。有人说："这就是工程——经验丰富的老师傅，就是最好的工程师。"**请先表态：这句话对还是错？**然后：①老师傅的问题不在"不厉害"，在"厉害不可复制"——试金石测的到底是什么？②如果给老周做"工程化改造"，第一步是把哪个"心法"写成可检验的规则？请写出那条规则的开头一句话。③你们团队最值钱的"手艺"是什么？它为什么还停留在人身上？

**Q3（先表态 + 追问链）** 李工说："我们用了敏捷、有 CI/CD、有自动化测试，所以我们在做软件工程。"——**这句话，大多数 IT 团队都会点头。请先表态：对还是错？**如果你说对，请回答：①泰坦尼克号的造船团队流程齐全吗？挑战者号发射前有检查吗？737 MAX 有测试吗？——它们都是怎么出事的？共性是什么："不会做"还是"做的时候没守住"？②这三次事故和李工团队"先上再说"，有什么同构？③用四层结构给你们最近上线/交付的一个东西做个体检：四层各缺什么？哪一层缺了最致命？

**Q4（先表态 + 追问链）** 有人建议把发布流程做成自动化、固化成算法，"这样就不用靠人了"。有人说："系统化，就是要把流程固化成算法，让机器自动跑。"**请先表态：这句话对还是错？**然后：①算法和工程方法的差别是什么？——为什么排序算法不需要判断，工程方法每一步都留判断？②自动化流水线上，哪些环节必须留给人判断？请举三个。③把"要不要自动""阈值设多少"也交给机器，会怎样？——这个追问说明什么？

**Q5（先表态 + 追问链 + 选边）** 恒信系统上线了、服务器跑起来了、模块全部上线，李工说"我们成功了"。**请先表态：按什么标准，才算成功？**然后：①按"技术系统"看，它上线了；按"工程系统"看，法务还在线下签、财务还是手工台账、业务还走邮件——到底算成功还是不算？缺的是"设备"还是"人/流程/组织"？②给恒信补上"工程系统"的验收，第一步改哪个动作？把验收参照从"上线"换成"被用起来"，具体怎么落地？③**最后一道选边题**：老周（手艺顶配、判断全在脑子里）和李工（流程齐全、却为进度砍了容量评估）——直觉上谁更配得上"工程师"？重新判断一次，这个直觉靠得住吗？老周缺哪两项能力、李工缺哪两项？

## 3. 点评要点·讲师版

### Q1　给恒信做工程体检（破题）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：是工程，流程工具都齐了 | 被"贴标签"骗了——正踩章首李工的病 |
| 中：不算，因为出事故了 | 方向对，但判据是"事故"不是"缺层" |
| 好：四层结构缺两层——工程科学（容量评估被砍）缺位、价值伦理（为进度砍可靠性）失守 | 四层体检到位 |

**产品侧 vs IT侧**：产品组可能说"那不就是样机过了就宣布成功吗"（提前用了第5章的话），IT 组说"系统上线了当然算工程"。两边其实都缺"工程系统"的验收参照——Q5 会收。

**反转话术**：
> 先让各组对"如果换成你们团队，你会点头吗"表态——**大多数组会犹豫，因为李工的团队就是多数 IT 团队的镜子。** 再追问："上个月那场事故，是'工程之外'的意外，还是'不是工程'的证据？"
> 落点：**敏捷 / CI/CD / 测试只覆盖四层里的两层（方法论、工具实践）。工程还有两层证没交：工程科学（你的'为什么'有依据吗？）和价值伦理（赶进度时，安全需求会让位吗？）。** 为进度悄悄牺牲可靠性、且没让任何相关方知情，是价值层失守的标准动作。**一个系统工程化与否，不取决于流程多完整，取决于它在压力面前会不会为质量让路。**

**参考答案要点**（书 §3.3~3.4、案例进展②）：四层结构缺层后果表；"只讲方法论不讲伦理，那不叫工程，叫有组织的赌博"；泰坦尼克/挑战者/737 MAX 都不是方法论出错，是价值层失守。

**追问链答案**：①缺工程科学（容量评估被砍 = 第一层）+ 价值伦理（为进度砍可靠性 = 第四层）；②"容量评估被砍"砍第一层（不知道"为什么能行"，换场景就抓瞎），"先上再说"砍第四层（价值层一票否决，直接出事故）；③补价值层第一步：让"砍需求"必须走评审 + 风险登记 + 负责人签字——**把"悄悄牺牲"变成"显性决策"**。

### Q2　工程 vs 手艺（试金石）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"老师傅就是最好的工程师" | 正中直觉——把"个人厉害"当"工程能力" |
| 中：说"老师傅是手艺不是工程" | 判对了，但没给出可检验的判据 |
| 好：手艺依赖具体的人，工程依赖可复现的方法——试金石：换个人还能同等交付吗 | 试金石到位 |

**产品侧 vs IT侧**：产品侧容易答"工程=有方法论的流程"，IT 侧容易答"工程=可测试可复现"。两者合起来正是完整判据——可复现 + 可检验。

**反转话术**：
> "'经验丰富的老师傅就是最好的工程师'——这句话错在把**团队的能力**和**工程的能力**混为一谈。老周请两周假，产线就没人能定位——**他在，质量在；他走，质量走。** 这是手艺。工程化不是废掉老周的手艺，而是把个人判断显性化成可教的规则、可查的文档、可检验的标准——**把个人能力变成组织能力。**"
> 落点：**试金石 = 换个团队、换个人，用同样的需求和约束，能不能交付质量相当的结果。能，是工程；不能，那是手艺。** 哪怕它碰巧也用了代码、图纸或电路。

**参考答案要点**（书 §2.2、案例进展①）：工程没有单一对立面——认识论上是科学（创造 vs 发现）、方法论上是手艺（可复现 vs 依赖个人）、目标上是艺术（满足需求 vs 自我表达）；试金石测的不是能力高低，是**可复制性**；老周的车间没有测试方案但"心里有数"，结果依赖具体的人。

**追问链答案**：①试金石测的是可复制性——"你不在的时候，团队还牛不牛"；②给老周做工程化改造第一步：把"哪个批次容易出问题"写成可检验的判据（如"供应商 X 的电容在 60°C 以上降额 20%"），写进物料/测试规则；③"最值钱的手艺"由学员自答——停留在人身上的原因通常是：没被要求写成文档/标准，或写了但不可检验。

### Q3　敏捷 ≠ 软件工程（四层结构）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：对，敏捷就是工程化 | 全盘接受——正是本单元靶心 |
| 中：不全对，敏捷只是流程 | 看到了"只是流程"，没说出缺什么 |
| 好：敏捷/CI/CD 只覆盖「方法论」和「工具实践」；工程还有「工程科学」和「价值与伦理」 | 四层结构完整 |

**产品侧 vs IT侧**：产品侧容易补"还缺需求管理、评审"，IT 侧容易补"还缺架构、容量评估"。两边补的其实都是"工程科学"这一层——产品侧补的需求、评审属于方法论/工具层，讲师要点出"工程科学"才是一般人漏的那层。

**反转话术**：
> "如果你说李工说得对，那请回答 Q3 的三连问：泰坦尼克号的造船团队流程齐全吗？挑战者号发射前有检查吗？737 MAX 有测试吗？——**有。它们都是怎么出事的？不是不会做，是做的时候没守住。** 敏捷 / CI/CD / 测试只是方法层和工具层；工程还有工程科学和价值伦理两层证没交。"
> 落点：**工程 = 知识 + 方法论 + 工具实践 + 价值伦理，四层同时在场。** 只讲方法论不讲伦理，那不叫工程，叫"有组织的赌博"。

**参考答案要点**（书 §3.1~3.2）：方法 < 方法论 < 工程；四层缺哪层的后果（工程科学→换场景抓瞎；方法论→靠人传人；工具实践→落不了地；价值伦理→会出事）；缺前三层是"不专业"，缺最后一层是"会出事"。

**追问链答案**：①三次事故的共性不是"不会做"，是"做的时候没守住"——价值层先松了手；②同构：李工团队也是方法论工具在、价值层失守（为进度砍容量评估，与 737 MAX 为市场砍安全认证同构）；③用四层给真实案例体检——对照四层逐条打钩，找出最致命的一层。

### Q4　系统化 ≠ 机械化

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：是一回事，系统化就是把流程固化成算法 | 正中误区 |
| 中：不完全一样，系统化强调步骤清晰 | 没抓住「判断」这个关键 |
| 好：算法是确定性执行（同输入必同输出、无需判断）；工程方法是有章法但每步留判断空间 | 核心命中 |

**产品侧 vs IT侧**：产品侧通常用"流程/模板"举例，IT 侧用"自动化/流水线"举例。可点出：连自动化流水线本身，"要不要自动、阈值设多少"仍是人的判断。

**反转话术**：
> "排序算法不会因为'今天心情不好'就排乱——算法是确定性的，不需要任何人判断。工程方法不是：它有步骤、有标准、有检查点，但每一步都留有人做判断的空间——材料公差、需求变化、成本权衡、风险取舍，没有唯一正确答案。ABET 的工程定义用词正是 **'applied with judgment'**（运用判断力加以应用）。"
> 落点：**系统化是"有章法的判断"，不是"确定性的执行"；工程靠方法，不靠算法。**

**参考答案要点**（书 §4.1、§4.3、判据#3）：三词辨析——**systematic**（系统化=做事有章法）、**systemic**（系统性=看问题有全局）、**algorithmic**（算法化=确定性执行）；工程化六方面里"有方法（含判断）"对应 ABET 的 "applied with judgment"；三问验证系统化（每步有输入输出吗 / 有可检验的检查点吗 / 换执行者结果稳定吗）。

**追问链答案**：①算法同输入必同输出、无需判断；工程方法有章法但每步留判断——材料公差/需求变化/成本权衡/风险取舍没有唯一正确答案；②留给人判断的环节：要不要自动、阈值设多少、异常怎么处置、成本/进度/质量怎么权衡；③把"要不要自动"也交给机器 → 失去对目标的判断，自动化变成盲目执行——正说明系统化是"有方法的判断"，不是"确定性的执行"。

### Q5　技术系统 vs 工程系统 + 工程师能力

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"上线了 = 成功了"（先表态选了技术系统标准） | 正中直觉——本单元收官靶心 |
| 中：说"按技术看成功、按工程看有问题"，但说不清缺什么 | 卡在"说不清"，讲师引导对号入座 |
| 好：先表态就犹豫了——按技术系统验收"上线了"，按工程系统看"没人用/流程没改/数据没清洗" | 经典案例——把技术系统误当工程系统验收 |

**产品侧 vs IT侧**：这题对 IT 侧冲击最大（ERP 经典翻车：软件部署好了、服务器跑起来了、模块上线了 = "系统成功"；采购流程没改、财务不会用、数据没清洗 = "系统失败"）。产品侧则容易想到"智能硬件交付后没人持续用"——硬件"上线"和软件"上线"是一个陷阱的两面。

**反转话术（技术系统 vs 工程系统）**：
> **软件系统本身是技术系统（代码、数据、服务器）；"软件 + 用户 + 业务流程 + 运维组织"才是工程系统。** 说"我们构建了一个技术系统"，说的是设备的集合；说"我们构建了一个工程系统"，承诺的是整个社会技术系统能运转起来——技术达标、人会用、流程顺、组织撑得住。你上次交付，承诺的是哪一个？

**反转话术（工程师能力）**：
> 选边题的直觉是选老周——手艺好、经验足，他不是工程师谁是？把直觉逼出来再翻：**老周缺的是方法论的组织和可复现（他的判断换个人做不出来）**；而李工流程齐全，却缺工程科学和价值层——**他也不是完整意义上的工程师**。两个人都不完整，合起来才是：**把四层背在身上。**
> 落点：**工程师 = 四层各一项能力（科学素养 / 方法论素养 / 实践能力 / 职业伦理）+ 工程判断（横切）+ 可复现意识（元能力）。** 头衔不定义工程师，六项能力才定义。真正的工程师，是换个人也能交付、关键时刻守得住底线的那个人。

**参考答案要点**（书 §5.1~5.3、§3.5）：系统工程 = 元工程（整合部件、管接口、做系统级验证），涌现属性——部件全对 ≠ 系统对；技术系统 ⊂ 工程系统（工程系统含人/流程/组织/信息，INCOSE 2019）；机场例子——工程系统的边界画在"整个运行环境"上，不是"设备的壳"上；20 世纪 70-80 年代最贵的教训：把工程系统当技术系统管；工程师六项能力（科学素养/方法论素养/实践能力/职业伦理/工程判断横切/可复现元能力），老周缺②⑥、李工缺①④⑥。

**追问链答案**：①缺的是"人/流程/组织"——法务线下签、财务手工台账、业务走邮件，都是工程系统的一部分；②第一步改验收动作：把"上线"里程碑换成"被用起来"（设定"法务电子签比例 ≥X%、财务台账迁移完成、业务走线上审批"作为验收条款）；③选边翻转：直觉选老周，但老周缺方法论组织（②）和可复现（⑥），李工缺工程科学（①）和职业伦理（④）——两人都不完整，头衔不定义工程师，六项能力才定义。

## 4. 知识卡片

### 一页图

```
工程 = 科学原理 × 判断创造 ——在约束下—— 用系统方法 → 有用且安全的人造物

工程的三维对立面
  认识论 → 科学（创造 vs 发现）
  方法论 → 手艺（可复现 vs 依赖个人）  ← 试金石：换团队能否同等交付
  目标   → 艺术（满足需求 vs 自我表达）

工程的四层结构（只讲方法论 ≠ 在做工程）
  价值与伦理 ← 重大事故的根源层
  工具与实践
  方法论     ← 敏捷在这里
  工程科学

三词辨析
  systematic 系统化  = 做事有章法（有步骤/检查点/判断）
  systemic   系统性  = 看问题有全局（部分关系/涌现/环境）
  algorithmic 算法化 = 确定性执行（同输入同输出）

系统工程 = 元工程（整合部件，不造部件）→ 涌现属性：部件全对 ≠ 整体对
技术系统 ⊂ 工程系统（人/流程/组织/信息也是工程系统的一部分）

工程师：四层各一项能力 + 工程判断（横切）+ 可复现意识（元能力）——头衔不定义工程师
```

### 金句

- **试金石**：换个团队、换个人，用同样的需求文档和约束，能交付质量相当的成果——能，是工程；不能，那是手艺。
- **约束即定义**：约束不是工程的对立面，约束是工程的全部舞台——约束越多，判断的价值越大。
- **系统化 ≠ 机械化**：系统化是"有章法的判断"，不是"确定性的执行"；工程靠方法，不靠算法。
- **涌现属性**：每个部件都正常，系统未必正常——系统工程存在，就是因为整体不是部分的相加。
- **头衔不定义工程师，能力才定义**——真正的工程师，是换个人也能交付、关键时刻守得住底线的那个人。
