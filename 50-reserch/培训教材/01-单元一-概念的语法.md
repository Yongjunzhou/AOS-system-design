## 1. 单元导读

**主题**：术语≠概念；同一个词各指各的（词汇病三形态）；用九格尺子钉死概念。这一单元是全书"发尺子"的一章——后面每一章讨论概念，都靠这把尺子。

**开场破题（请对此发表意见）**：念周三季度会那场：老板说"我们公司的**架构**不行，管理层级太多，决策太慢"；产品总监接话"我说的是产品**架构**——M3 的模块边界该重新划了"；技术总监皱眉"你们说的都不是**架构**。系统架构是服务边界、数据所有权这些事"。三个人吵了四十分钟，散会时都觉得"对方不可理喻"。**先让两组表态：这场吵架，是"人不对付"，还是"词没对齐"？**

**本单元要反转的五个直觉**：

1. 「术语和概念是一回事」——**错**。术语是能指（名牌），概念是所指（名牌背后的人）。
2. 「晨星和暮星是两颗不同的星」——**错**。指称相同（都是金星），只是涵义不同。
3. 「'评审就是开会'，这是评审的定义」——**错**。这是例子不是定义；定义要带可检验判据。
4. 「平时没出过词不齐的问题，说明我们没这病」——**错**。平时讨论增量不显形；关键时刻定义才成为判定依据——没爆过，只是还没到判定时刻。
5. 「验证和确认差不多，都是证明产品没问题」——**错**。翻译伪朋友：验证对照规定需求，确认对照预期用途。

**本轮 10 题的内在逻辑（两组 2×5，组内循序而进：识别→机制→判据/落地）**：

- **第一组 · 概念与原理（5 题）**：从"术语≠概念"的定义出发（Q1 概念本身，见树见林）→ 七个词的关系图（Q2 概念关系，见树见林——答错即暴露误解）→ 三条机制原理：语言是约定 + 漂移始于言语（Q3 真悖论收束）、病二"平时不爆关键时刻爆"（Q4 真悖论收束）、九格从误解反推 + 薄格可省（Q5）。这一组回答**"同一个词为什么会各指各的、怎么识破"**。
- **第二组 · 落地与实践（5 题）**：三种病在三段真实场景上依次用一遍——病一"例子≠定义"（Q6）、病二"验收=验证+确认"（Q7 真悖论收束）、病三"翻译伪朋友"（Q8）→ 九格三场景 + 语境决定所指（Q9 真悖论收束）→ 落地生根：回你们部门做一次词汇体检（Q10）。这一组回答**"怎么用这把尺子钉住我们自己"**。

## 2. 题卡（打印分发）

> **答题要求**：组内讨论 25 分钟，把答案写在便签/白板上。每题答案不超过 5 行。每组选派一人上台讲解（4–5 分钟）。允许观点不同，但必须给出理由。
> **分组**：第一组（Q1~Q5）偏概念与原理；第二组（Q6~Q10）偏落地与实践。

### 第一组 · 概念与原理（5 题）

**Q1（破题 · 概念本身）** 周三上午季度会：老板说"我们公司的**架构**不行，管理层级太多，决策太慢"；产品总监接话"我说的是产品**架构**——M3 的模块边界该重新划了"；技术总监皱眉"你们说的都不是**架构**，系统架构是服务边界、数据所有权这些事"。三个人吵了四十分钟，散会时都觉得"对方不可理喻"。**这场架，到底是"人不对付"，还是"词没对齐"？"术语"和"概念"各是什么？用这两个词解释：三个人为什么都在说"架构"，却从头到尾不在讨论同一件事。** 追问：①三个人的"架构"两个字，是同一个能指还是三个能指？他们吵的是同一个所指，还是三个所指？②"术语是能指，概念是所指"——同一个概念能不能换词？（微服务 = 微服务架构）同一个词能不能指向不同概念？（章首的"架构"）这说明"换不换词"和"换不换所指"，哪个才真正改变讨论？③索绪尔说"能指是任意的，所指才是实质"——为什么名牌可以换、人没变，而同一个名牌挂在不同人身上就要先分清楚？④反身：你刚才给"术语"和"概念"下的定义，是定义还是例子？带判据吗？（懂 ≠ 能定义，当场现形）

**Q2（概念关系）** 天刚亮你指着东方最亮的星说"晨星"，晚上指着西方最亮的星说"暮星"——它们是同一颗星（金星）。有人说："晨星和暮星当然是两颗不同的星，出现的时刻、方位都不一样。"也有人说："同物异名就是个别名而已，小事。"**请给出符号、能指、所指、术语、概念、涵义、指称这七个词的关系——谁包含谁、谁和谁对应。然后用这套关系回答：晨星和暮星是"同一个东西的两个名字"，还是"两个概念"？** 追问：①弗雷格的贡献是"涵义 ≠ 指称"——用晨星暮星说清楚，这个"≠"到底意味着什么？②"同物异名"和"同名异物"两种游戏——为什么一个"是漏的根源"（你以为在谈两件事、其实在谈同一件 → 重复建设），一个"是吵的根源"（你以为在谈同一件事、其实在谈三件 → 四十分钟吵架）？③"同一个概念可以有好几个词"——你身边有吗？（订单 = order、SRS = 需求规格说明书）"同一个词可以指向不同概念"呢？（质量、评审、需求、基线）④反身：你们部门最近一次"对不上"，是漏还是吵？它当时被归因为什么？

**Q3（原理 · 语言是约定）** 有人说："语言就该像编程语言一样精确——每个词对应一个定义，定义永不变，世界就清晰了。"也有人说："术语漂移是词典编辑者的事，跟我怎么用词没关系。"还有人反驳："把词钉死定义，就是阻碍语言的自然演化，太刻板了。"**语言到底是精确编码系统，还是约定？"术语漂移"始于谁？"钉死定义"反对的，是语言演化，还是别的东西？** 追问：①"语言的模糊是 feature 不是 bug"——这句话在替什么辩护？模糊的另一面是什么（歧义）？如果语言必须足够灵活才能让几亿人共用，那"歧义"是不是它必须付的代价？（**真悖论收束**：语言灵活 vs 概念要对齐——两个都对，靠什么判据分界？→ 同一场会议里三个版本演化，则该当场对齐）②索绪尔说"能指是任意的"——"任意"等于"随便"吗？（语言任意性 ≠ 随意性：我随便发明一个词没人懂，因为能指是社会约定）③"每一次漂移都始于某个人的某一次言语"——"我这次用词不精确"和"语言在演化"是什么关系？我随口一个误用，语言会立刻变吗？什么时候才变？（别人跟着用，用得多了）④反身：你现在的术语里，哪个词正在漂移？你说它的时候，是在为漂移添砖，还是在主动对齐？

**Q4（原理 · 病二判定时刻）** 你们的团队平时各干各的，从没为"质量""评审""验收"是什么意思吵过架。有人据此说："我们团队没有词不齐的问题，不用浪费时间对齐。"**"平时没爆"能证明"没有这病"吗？为什么词不齐的问题平时不显形、关键时刻才爆？** 追问：①平时讨论的是"加个功能"这种增量——双方各自的定义为什么不会被放到台面比较？关键时刻讨论的是"这件事对不对、算不算、该不该"——定义第一次成为判定依据，会发生什么？（**真悖论收束**：平时每句话都对齐 = 效率灾难 vs 判定时刻要对齐 = 该较真——两个都对，判据 = 是否进入判定时刻）②"两份合同平时各自执行各自的条款都没问题，一旦合并，条款冲突才暴露"——这个类比在说什么？③"矛盾出现时的对齐，已经是在收拾残局了"——为什么词对齐不能等矛盾出现再做？④反身：你们最近一次"爆了"的分歧，爆之前有没有人先问过"你说的 X 指什么"？如果问了，会怎样？

**Q5（原理 · 九格反推）** 有人说："字典不是给你定义了吗？'架构是系统的组织结构'——为什么还要九格？"也有人说："九格每一格都必须填满，这才是完整理解。"还有人说："九格太繁琐了，每次开会都填九格，谁受得了？"**九格为什么是九格，而不是一格？"每一格必须填满"对吗？九格是"每次都要量全"的尺子，还是"该查的时候查全"的尺子？** 追问：①九格是从哪反推出来的？（病一"说不出定义"→①定义+⑥对立面+⑦辨析；病二"同词异义"→②背景+③历史；病三"翻译伪朋友"→⑨英文来源；乱用→④问题+⑤场景；残余→⑧误区）——"反推"和"拍脑袋"的区别是什么？②"薄格可省，但不可被跳过"——"省"和"跳"有什么区别？"等级"这张档案大部分格子是空的——这是偷懒还是诚实？（该空时空着，是对概念诚实）填不出"背景"（②）可能意味着什么？③"该查时查全"和"每次都要量全"——什么时候该查全？（进入判定时刻：评审结论/验收标准/需求变更）平时为什么不用每次量全？④反身：用你行业里一个词（质量/评审/需求/架构），逐格过一遍，哪一格你最填不出？填不出 = 什么？

### 第二组 · 落地与实践（5 题）

**Q6（判据运用 · 病一）** 有人问："评审是什么？"答："就是开会过一遍。"再问："一次不走流程的聊天算不算评审？"答："……不算吧。"又问："那怎么判断？"答："不好说，反正评审就是开会。"**"评审就是开会"是定义还是例子？用它能不能判断"一次不走流程的聊天算不算评审"？为什么不能？一个定义要能分得清边界，必须带什么？** 追问：①"定义回答'它是什么'，例子只回答'它长这样'"——"验证就是测试""架构就是画图""质量就是档次高"，每句都少什么？②"说得出口的例子，往往让人误以为自己懂了"——"验证就是测试"这种理解，在什么时候会出事？（评审结论、验收标准、需求变更这些关键时刻）③给"评审"补一个带判据的定义——判据是什么？（得出结论了吗？留下记录了吗？——没有结论、没有记录，按定义它最多算聊天）④反身：你天天用的某个词（需求/质量/上线/通过），你能给它一句带判据的定义吗？还是只能举例？（懂 ≠ 能定义，当场现形）

**Q7（判据运用 · 病二验收）** 医疗器械公司跟医院签验收条款："系统通过验收后，尾款付清。"谁也没定义"通过验收"是什么。半年后系统上线，医院说"验收没过——临床科室用得顺才算"；公司说"功能测试通过就算"。两边都觉得有理，扯了四个月。最后查合同，"验收"一次都没定义过。**公司以为的"验收"和医院以为的"验收"，各是 ISO 9000 里的哪个词？把"验收"拆成两条之后，纠纷为什么消失了？** 追问：①验证（verification）和确认（validation）的参照各是什么？（对照规定需求 / 对照预期用途）——公司要的是哪个？医院要的是哪个？（**真悖论收束**：医院要确认 vs 公司要验证——两个都对，判据 = 拆成两条各配标准：功能验收对照技术规格 + 临床确认对照实际使用）②合同里一个"验收"，把两种概念的缝用什么糊上了？——中文里还有哪些词在干同样的事？（评审/验证/确认三个译名？）③"概念不对齐的代价，什么时候一次性结算"？（平时看不见，到合同纠纷/验收分歧/需求变更时才结算）④反身：你们最近一份合同/需求/验收标准，定义"通过"了吗？判据是什么？谁写的？

**Q8（判据运用 · 病三伪朋友）** 有人说："评审、验证、确认差不多，都是证明产品没问题。"也有人说："中文术语就是权威，我们按中文理解就行，不用管英文。"**"评审/验证/确认"是三个相近的词，还是三个不同的概念？怎么用三个动作当场现形？（回英文原词 / 查词根 / 看归组）** 追问：①英文一摆出来：review、verification、validation——三个完全不同的词，中文翻译为什么让人以为它们是近亲？（翻译逐词对应 + 1990 年代术语集中涌入 + 中文意合语言，三个历史原因）②"看归组"——ISO 9000 里评审（3.11.2）和验证/确认（3.8.12 / 3.8.13）各在哪个术语组？"在同一个术语组"意味着什么？（评审和"确定/监视/测量/检验"（3.11 组）是一家；验证/确认和"规范"（3.8 组）是一家——近亲就是该放一起辨析的对象）③为什么中文尤其容易踩翻译伪朋友的坑？（意合语言：不能靠词根一眼看出词族）——概念档案第⑨格"术语英文来源"存在的意义是什么？④反身：你工作中哪个中文词，回到英文才发现是伪朋友？（验证/确认？架构/architecture？治理/governance？）

**Q9（判据运用 · 九格三场景）** 有人说："'架构'在管理语境、产品语境、系统语境是三个概念——中文这么模糊，术语根本说不清，干脆别较真。"也有人说："正因为它有三个概念，我们才要每次说清楚用哪个——较真是应该的。"**中文术语的模糊，是"不说清"的理由，还是"更要说清"的理由？九格在个人、团队、组织三层分别怎么用？** 追问：①"语境决定所指"——"架构"在三种语境各指什么？（组织架构 = 管理层级 / 产品形态 = 模块边界 / 系统架构 = 服务边界）——"九格不是规定只能用哪个，是要求说清楚用的哪个"，这跟"别较真"的区别在哪？（**真悖论收束**：中文模糊 vs 术语要说清——两个都对，判据 = 回到英文原词 + 说清楚所指）②开会前（三分钟术语对齐清单）、审文档（九格当检查单）、写规格（先填档案再写正文）——三个场景各用哪几格？九格为什么"是动作不是知识"？③"该查时查全"和"每次都要量全"——什么时候该查全？（进入判定时刻：评审结论/验收标准/需求变更）平时为什么不用每次量全？④反身：你们部门的下一次关键会议，开场三分钟对齐哪三个词？谁来带头？

**Q10（落地生根 · 回部门词汇体检）** 章末那句话："你没有错，但你说的话没法验证对错，因为你没有用定义说话。"假设那场带尺子的会议真的重开了：摆词（每人一句"我指的是什么"）→ 对齐（三个所指里只有一个是我们讨论的"架构"）→ 分头处理（组织架构归 HR、产品形态另开评审、系统架构留下专项）——四十分钟的争吵变成十五分钟的对齐加三十五分钟的各干各的。**用同一套流程，给你们部门做一次词汇体检：列出最近一次会议或文档里最核心的三个词，各写一句"我指的是什么"（不许用例子），然后用病一/病二/病三三问检查每个词。然后给出你们部门最应该改进的三个事项——每个事项落到一个可操作动作（一句判据/一个检查项/一条话术）。**（提示：大多数团队会说"我们没这病"——先诚实面对"平时没爆 ≠ 没病"，再谈改进。缺的判据：术语是能指、概念是所指 / 例子不是定义 / 验证确认是伪朋友）

## 3. 点评要点·讲师版

### Q1　术语 ≠ 概念（定义 · 见树见林① · 破题）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"人不对付"；或答不出术语/概念定义、只能举例 | 定义缺席——正踩章首那场会（也是"懂≠能定义"） |
| 中：说"是词没对齐"但说不出能指/所指 | 方向对，判据没落到定义上 |
| 好：术语=能指（名牌）、概念=所指（人）；三个人三个所指；同一个概念可换词、同一个词可多概念 | 定义层反直觉全中 |

**产品侧 vs IT侧**：产品组容易说"产品总监和技术总监各有道理，是老板不懂"、IT 组容易说"他们根本不在一个频道"——两边都急着判人对错。讲师点破：三个人都没错，错的是会议本身没有先对齐。

**反转话术**：
> "'他们不可理喻'——先别急着判人对错。**三个人都没错：老板谈组织，产品谈形态，技术谈系统，手里都有真东西。错的是这场会议本身——一场没有对齐概念的会议。** 先立定义：**术语是能指——那个标签、那个名字；概念是所指——标签背后的本质。术语是名牌，概念是名牌背后的人。** 三个人都用了'架构'这个名牌，可名牌背后挂着三个不同的人：组织架构、产品形态、系统架构。**名词可以换，人没变；同一个名词也可以挂在不同人身上。** 这就是'术语是能指，概念是所指'——听起来像绕口令，却是这一章发出去的尺子。反身一刀：你刚才给'术语''概念'下的定义，是定义还是例子？带判据吗？"

**参考答案要点**（书 §1.1~1.3、判据1）：术语=能指（名牌）；概念=所指（人）；"架构"是同一个能指、三个所指（组织架构/产品形态/系统架构）；能指任意、所指实质。

**追问链答案**：①"架构"两个字是能指；吵的是三个所指；②可以换词（微服务=微服务架构）、可以一词多概念（章首架构）——换不换词不改变概念（名牌可以换、人没变），换不换所指才决定讨论的是什么；③能指任意、所指实质——名牌可换、人没变，同一个名牌挂在不同人身上就要先分清所指；④反身——定义应带判据（能说出所指+边界），只能举例=病一。

### Q2　七个词的关系（概念关系 · 见树见林②）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"晨星暮星=两颗星" | 正中直觉——把涵义当指称 |
| 中：说"是同一颗星"但说不清涵义/指称 | 结论对，关系图没搭起来 |
| 好：七词关系图（符号=能指+所指；术语=能指；概念=所指/涵义；指称=事物本身）+ 晨星暮星=同指称异涵义 + 两种游戏 | 关系结构全中 |

**产品侧 vs IT侧**：两边都会拿"同一个东西两个叫法"举例——产品组"SKU 号 vs 条码"、IT 组"order vs 订单"。可追问：你们部门最近一次"两个团队对不上"，是"漏"还是"吵"？

**反转话术**：
> "'晨星和暮星当然是两颗不同的星'——这个直觉就是弗雷格要治的病。**晨星和暮星是两个符号、两种涵义（一个清晨、一个傍晚），但指称相同——都是金星。涵义不等于指称，这是弗雷格模型的核心贡献：同一个指称可以有很多种涵义。** 由此分两种游戏：**同物异名**——同一个指称、多个涵义（你以为在谈两件事、其实在谈同一件）——这是漏的根源，合并时才发现重复建设；**同名异物**——同一个符号、多个所指（你以为在谈同一件事、其实在谈三件）——这是吵的根源，四十分钟的吵架就是这么来的。把这张图带回工作：你最近一次'分歧'，是漏还是吵？"

**参考答案要点**（书 §1.3、判据2）：符号=能指+所指；术语=能指（名词）；概念=所指（涵义/本质）；指称=实际对象；晨星暮星=同指称异涵义；同物异名=漏的根源、同名异物=吵的根源。

**追问链答案**：①同指称可多涵义——晨星暮星都是金星，"≠"意味着同一对象可多种呈现方式；②同物异名=漏（重复建设）、同名异物=吵（四十分钟）；③同一概念多词（订单=order、SRS=需求规格说明书）、一词多概念（质量/评审/需求/基线）；④归因"他们不配合/部门墙"——其实是没先摆词。

### Q3　语言是约定，漂移始于言语（原理 · 真悖论收束）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"语言应该精确"或"钉死=阻碍演化" | 各踩一个真悖论的一端 |
| 中：说"语言是约定"但说不出漂移始于言语 | 表态对，机制没到 |
| 好：模糊是 feature；漂移始于某个人的言语；钉死反对同会三版本；任意≠随意 | 机制全中 |

**产品侧 vs IT侧**：产品组拿"用户说'好用'各指各的"举例、IT 组拿"验收/上线各指各的"举例。可点出：两个组都可能说"我们团队没这病"——这正是 Q4 的病。

**反转话术**：
> "'语言就该像编程语言一样精确'——可语言真精确了，几亿人就没法用同一套符号表达千差万别的意思了。**模糊是 feature，不是 bug：它足够灵活，才能让语言通用；但灵活的另一面就是歧义。** 于是出现一个真悖论：**语言要灵活（否则表达不了千差万别）vs 概念要对齐（否则同一场会各说各话）——两个都对，靠什么分界？判据：同一场会议里出现三个版本演化，那就必须当场对齐。** 再拆两个误解：**能指任意 ≠ 随意**——'任意'是相对所指说的，'苹果'叫 banana 也可以，但那是社会约定，不是我随便发明一个词就有人懂；**漂移始于言语**——语言规则是全社会慢慢变的，而每一次漂移都始于某个人的某一次使用：有人把'架构'用在软件上，别人跟着用，用得多了，语言就多了一个所指。**所以'我怎么用词无所谓'是错的——每一次不精确使用，都在为漂移添砖。**"

**参考答案要点**（书 §1.1、§1.2、§1.4）：语言是约定不是精确编码；模糊是 feature；漂移始于言语（langue 变先变在 parole）；钉死≠反对演化，是反对同会三版本；任意性≠随意性。

**追问链答案**：①模糊是 feature——灵活才能被几亿人共用，歧义是灵活的代价；真悖论判据=同会三版本则对齐；②任意≠随意——约定是社会性的，随便发明没人懂；③"我用词不精确"=为漂移添砖；语言多一个所指，就从某个人的某次使用开始，别人跟着用才落地；④反身——哪个词正在漂移，我在添砖还是在对齐。

### Q4　病二：平时不爆，关键时刻爆（原理 · 真悖论收束）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"没爆=没病" | 正中陷阱——把没爆当没病 |
| 中：说"可能有问题"但说不出机制 | 方向对，机制没到 |
| 好：平时增量不显形、关键时刻定义才成判定依据；真悖论判据=是否进入判定时刻；对齐不能等矛盾出现 | 机制全中 |

**产品侧 vs IT侧**：两边都说"我们团队没吵过这个词"——讲师点破：没吵过=还没到判定时刻，不等于没病。用"合同条款平时各自执行、合并才冲突"类比。

**反转话术**：
> "'平时没爆=没这病'——这个推理最顺口，也最危险。**平时讨论的是'加个功能'这种增量，双方各自脑内的定义没被放到台面比较——所以不爆；关键时刻讨论的是'这件事对不对、算不算、该不该'，定义第一次成为判定依据，裂缝才显形。** 就像两份合同：平时各自执行各自的条款都没问题，一旦合并，条款冲突才暴露。于是又是一个真悖论：**平时每句话都对齐 = 效率灾难 vs 判定时刻要对齐 = 该较真——两个都对，判据：是否进入判定时刻。** 结论很硬：**矛盾出现时的对齐，已经是在收拾残局了。** 词对齐不能等矛盾出现再做——因为那一刻，代价已经一次性结算了。"

**参考答案要点**（书 §2.2、P8/P10）：病二=同名异物；平时讨论增量不显形、关键时刻定义成判定依据；"矛盾出现时的对齐已是收拾残局"；不对齐代价一次性结算。

**追问链答案**：①增量讨论不比较定义、判定时刻定义才成依据；真悖论判据=是否进入判定时刻；②两份合同各自执行没事、合并才冲突——定义裂缝平时不暴露；③对齐等矛盾出现=收拾残局，代价已结算；④反身——爆之前没人问过"你说的 X 指什么"；问了，可能当场就发现两个所指。

### Q5　九格从误解反推，薄格可省（原理 · 九格）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"字典就够"或"每格填满" | 各踩一个靶子 |
| 中：说"九格有用"但说不出反推逻辑 | 方向对，机制没到 |
| 好：九格从三类误解反推；薄格可省不可跳过；该查时查全不是每次量全 | 机制全中 |

**产品侧 vs IT侧**：产品组容易说"质量就是九格里的①"、IT 组容易说"我们写规格不用填档案"。可点出：字典定义治不了三病，九格多出来的八格全是误解藏身处。

**反转话术**：
> "'字典不是给你定义了吗？'——字典给定义，但定义治不了病一、病二、病三。**九格为什么是九格？因为它是从三类误解反推出来的：病一'说不出定义'→要定义（①）；病一还有个变种'说不出边界'→要对立面（⑥）和辨析（⑦）；病二'同词异义'→要知道它从哪来（②背景、③历史）；病三'翻译伪朋友'→要英文来源（⑨）；乱用→要知道为什么存在（④）、什么时候用（⑤）；残余→误区（⑧）。** 每种病需要什么信息，就给它一格——所以不是拍脑袋。再回答'每格填满'：**薄格可省，但不可被跳过**——'等级'这张档案大部分格子是空的，因为它的误解集中在一处（等级≠质量），该空时空着是对概念诚实；但跳过的那格，往往是误解潜伏的地方。最后：**九格是该查时查全的尺子，不是每次量全的尺子**——日常只动两三格（开会前用①、审文档用⑧⑦、写规格用①⑤），判定时刻才查全。"

**参考答案要点**（书 §3.1、§3.2、§3.6）：九格反推自三类误解；四层定界/溯源/致用/纠误；薄格可省不可跳过；"该查时查全"不是"每次量全"。

**追问链答案**：①病一→①⑥⑦、病二→②③、病三→⑨、乱用→④⑤、残余→⑧——反推不是拍脑袋；②省=薄格留空（诚实）、跳=格子空着也没想过（误解潜伏处）；填不出背景=可能不知道为什么用它；等级薄格=误解集中一处，诚实；③判定时刻（评审结论/验收标准/需求变更）才查全，平时只动两三格；④反身——哪格填不出=误解可能藏在那。

### Q6　病一：例子不是定义（判据运用 · 定义带判据）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"评审就是开会"是定义 | 正中陷阱——定义缺席 |
| 中：说"这是例子"但给不出带判据的定义 | 方向对，判据没落到定义上 |
| 好：定义带可检验判据（有结论？有记录？）——没有判据的判断不了边界 | 判据运用全中 |

**产品侧 vs IT侧**：产品组"评审=过一遍需求"、IT 组"评审=开会"——同一个病一，换了个载体。可追问：你们最近一次评审，有结论吗？有记录吗？

**反转话术**：
> "'评审就是开会'——这是例子，不是定义。**例子回答'它长这样'，定义回答'它是什么'。你说'评审就是开会'，只描述了你见过的一种评审；你没法用它判断'一次不走流程的聊天算不算评审'——因为你的回答里没有判据。** 病一的危险就在这：说得出口的例子让人误以为懂了——'验证就是测试''架构就是画图''质量就是档次高'，闲聊无伤大雅，在评审结论、验收标准、需求变更这些关键时刻，一个没有判据的理解就是事故的种子。**治病的药：定义要带可检验的判据。** 用评审示范：如果定义是'对客体实现所规定目标的适宜性、充分性或有效性的确定'，判据就是——有没有得出结论？有没有留下记录？一场'评审'开完没有结论、没有记录，按定义它不是评审，最多算聊天。"

**参考答案要点**（书 §2.1、判据4、P6/P7）：例子是插图不是定义；定义回答是什么、例子回答长什么样；定义要带可检验判据；判据让定义从一句话变成一把尺。

**追问链答案**：①都少判据；②"验证就是测试"当定义不够用——功能测试全过、临床用得不好时判不了；③评审判据=有没有结论、有没有记录——没有就是聊天；④反身——能否给天天用的词一句带判据的定义。

### Q7　验收 = 验证 + 确认（判据运用 · 病二 · 真悖论收束）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：站公司"功能测试通过就算"或站医院"临床用得顺才算"任一边 | 各抓一个概念，没看到是一个词糊了两个概念 |
| 中：说"两边都有理"但没到拆两条 | 结论对，没给判据 |
| 好：公司=验证（verification）、医院=确认（validation）；拆成两条各配标准；一个词糊住两种概念的缝 | 反直觉核心全中 |

**产品侧 vs IT侧**：产品组站"产品用起来才算成功"（确认）、IT 组站"功能测试过了就算"（验证）——两个组天然站两边，正是真悖论的现场。可点出：这不是谁对谁错，是同一个词糊了两个概念。

**反转话术**：
> "'功能测试通过就算'和'临床用得顺才算'——两边都觉得有理，其实都对。**公司要的是验证（verification）：对照规定需求、提供客观证据的认定；医院要的是确认（validation）：对照预期用途、放进真实场景的裁决。这是 ISO 9000 里两个词、两种参照，不是一回事。** 于是又一个真悖论：**医院要确认 vs 公司要验证——两个都对，怎么和解？判据：拆成两条各配标准——功能验收（对照技术规格）+ 临床确认（对照实际使用）。** 拆开了，各自都有明确标准，纠纷消失。**合同里一个'验收'，把两种概念的缝隙用胶水糊上了**——四个月的扯皮，最后两天拆词解决。这就是概念不对齐的代价：平时看不见，到合同纠纷、验收分歧、需求变更时才一次性结算。"

**参考答案要点**（书 §2.4、验证/确认、P10）：验证对照规定需求、确认对照预期用途；"验收"一词糊住两概念的缝；拆两条各配标准纠纷消失；不对齐代价一次性结算。

**追问链答案**：①验证=对照规定需求（公司）、确认=对照预期用途（医院）；真悖论判据=拆两条各配标准；②一个"验收"糊住验证+确认的缝；评审/验证/确认三个译名也干同样的事；③平时看不见、到合同纠纷/验收分歧/需求变更时结算；④反身——定义"通过"了吗？判据是什么？谁写的——没人写，就是病二在合同里的样子。

### Q8　翻译伪朋友：三个动作现形（判据运用 · 病三）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"验证确认差不多" | 正中陷阱——把译名近亲当同义 |
| 中：说"三个不同词"但说不出三动作 | 方向对，没到可操作动作 |
| 好：回英文原词/查词根/看归组三动作；ISO 9000 归组（3.11 vs 3.8）；中文意合语言 | 反直觉核心全中 |

**产品侧 vs IT侧**：产品组"确认=客户拍板"、IT 组"验证=测试通过"——两边各抓半张脸。可点出：英文一摆出来就现形。

**反转话术**：
> "'评审、验证、确认差不多'——把英文一摆出来就现形了：review、verification、validation，三个完全不同的词，中文翻译凑巧都带'评/验/认'。**它们是翻译伪朋友。** 治病三动作：**①回英文原词**——中文模糊处英文现形；**②查词根**——configuration = con + figurare（共同塑造），词根直接解释定义；**③看归组**——ISO 9000 里评审（3.11.2）和验证/确认（3.8.12/3.8.13）根本不在同一个术语组：评审和'确定/监视/测量/检验'（3.11 组）是一家，验证/确认和'规范'（3.8 组）是一家。**在同一个术语组=它该跟谁放一起辨析。** 为什么中文尤其容易踩坑？三个历史原因：中文术语大量来自翻译、翻译逐词对应；1990 年代术语集中涌入翻译风格不一；中文是意合语言，不像英文能靠词根一眼看出词族。**所以概念档案第⑨格'术语英文来源'，就是干这个的：中文看不清的地方，回英文就看清了。**"

**参考答案要点**（书 §2.3、P9）：翻译伪朋友；review/verification/validation；三动作（回英文原词/查词根/看归组）；ISO 9000 3.11 组 vs 3.8 组；三个历史原因（逐词翻译/集中涌入/意合语言）。

**追问链答案**：①逐词翻译+术语集中涌入+意合语言；②评审在 3.11 组（确定/监视/测量/检验）、验证/确认在 3.8 组（规范）——近亲就是该放一起辨析的对象；③意合语言不能靠词根看词族；⑨格=回英文现形；④反身——哪个词是伪朋友。

### Q9　九格三场景，语境决定所指（判据运用 · 真悖论收束）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"中文模糊说不清，别较真" | 正中陷阱——把模糊当不说清的理由 |
| 中：说"该较真"但说不出三场景怎么用 | 方向对，没到动作 |
| 好：语境决定所指；三场景各用哪几格；该查时查全不是每次量全 | 反直觉核心全中 |

**产品侧 vs IT侧**：产品组"产品架构"、IT 组"系统架构"、老板"组织架构"——三个语境三个所指。可点出：不是词的问题，是没分清语境。

**反转话术**：
> "'中文这么模糊，干脆别较真'——这句话把'模糊'当成了'不说清'的理由，其实它恰恰是'更要说清'的理由。**语境决定所指：'架构'在管理语境=组织架构（管理层级），产品语境=产品形态（模块边界），系统语境=系统架构（服务边界）。** 九格不是规定你只能用哪个，是要求你说清楚用哪个——这跟'别较真'的区别，就是真悖论的收束：**中文模糊 vs 术语要说清——两个都对，靠什么判据？回到英文原词 + 说清楚所指。** 那九格怎么用？三个场景：**开会前**——花三分钟列最容易歧义的词、各自一句话定义（用①）；**审文档**——对每个核心概念过一遍九格（定义给没给/判据有没/误区避没避，用⑧⑦）；**写规格**——先填档案再写正文（用①⑤）。**九格是动作不是知识**：每一次使用，都是把'我以为'变成'它定义上是什么'。再答'每次都要量全'：九格是**该查时查全**的尺子——判定时刻（评审结论/验收标准/需求变更）才查全，平时只动两三格。"

**参考答案要点**（书 §3.4、§3.5、§3.6、P13/P14）：语境决定所指；三场景（开会前对齐/审文档检查单/写规格先填档案）× 三层（个人/团队/组织）；九格是动作不是知识；该查时查全不是每次量全。

**追问链答案**：①组织架构=管理层级、产品形态=模块边界、系统架构=服务边界；"说清楚用哪个"vs"别较真"；真悖论判据=回英文+说清所指；②开会前用①、审文档用⑧⑦、写规格用①⑤；九格是动作因为每次都是把"我以为"变"定义上是什么"；③判定时刻才查全（评审结论/验收标准/需求变更）；④反身——下一场关键会对齐哪三个词、谁来带头。

### Q10　落地生根：回部门词汇体检（判据综合运用）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：说"我们没这病" / 只列词不落动作 | 体检自欺——没爆≠没病，本身就是本章的病 |
| 中：列了词但没用病一/二/三三问查 | 方向对，停在"该做"没到"怎么做" |
| 好：摆词→三问查病→三个事项各落一个可操作动作 | 落地全中 |

**产品侧 vs IT侧**：产品组的词是"样机/量产/质量"、IT 组的词是"上线/验收/需求"——同一套尺子两个世界。老师把两组的三件事摆在一起对照，点出"词汇病不挑行业"。

**反转话术**：
> "章末那句话没有骂任何人：'你没有错，但你说的话没法验证对错，因为你没有用定义说话。'**大多数人会跳过体检，直接说'我们没这病'——这正是本章最后一道陷阱：没爆过≠没病，只是还没到判定时刻。** 所以落地生根的作业要求：①先体检、诚实面对（列三个最核心的词，各写一句'我指的是什么'，不许用例子）；②用三问查病——写不出判据=病一，两个所指对不上=病二，中文译名像近亲=病三；③再选三个事项，**每个落到一个可操作动作**——不是'加强沟通'，是'下次评审开场三分钟过一遍术语口径'、'给验收条款补一句判据'、'把 verification/validation 写进术语表'。两周后回来报告：做到了几个？做不到的那个，为什么？"

**参考答案要点**（书 §3.4、判据1-5、作业指南）：词汇体检六步（收集/摆词/对齐/查病/验伪朋友/产出术语口径一页纸）；病一/二/三三问；三个事项各落一个可操作动作。

**追问链答案**：无固定答案；评讲标准=①是否诚实完成摆词体检（而非"我们没这病"跳过）；②三个词是否各经病一/二/三三问检查；③三个事项是否各落一个可操作动作（判据/检查项/话术）；④是否与课后作业"回部门落地"衔接（两周后回来报告）。

## 4. 知识卡片

### 一页图

```
误解的三个形态（词汇病）
  说不出定义（病一）──┐
  同词异义  （病二）──┼──→ 九格尺子：定界→溯源→致用→纠误 ──→ 每一章都用它钉死概念
  翻译伪朋友（病三）──┘

术语是能指，概念是所指（名牌 ≠ 名牌背后的人）
  符号 = 能指（形式）+ 所指（内容）——能指任意、所指实质
  符号 → 涵义 → 指称——涵义 ≠ 指称（晨星暮星 = 同一指称、两种涵义）
  同物异名 = 漏的根源 ｜ 同名异物 = 吵的根源
  语言（langue）≠ 言语（parole）——漂移始于某个人的某一次言语
  钉死 ≠ 反对语言演化，是反对在同一场会议里用三个版本演化
  任意性 ≠ 随意性——约定是社会性的

九格四层：定界（①定义 ⑥对立 ⑦辨析 ⑨英文）· 溯源（②背景 ③历史）
          · 致用（④问题 ⑤场景）· 纠误（⑧误区）
  薄格可省、不可跳过——跳过的那格往往是误解潜伏处
  九格是动作不是知识：开会前对齐 / 审文档当检查单 / 写规格先填档案
  九格是该查时查全的尺子，不是每次量全的尺子
  语境决定所指——九格不是规定只能用哪个，是要求说清楚用的哪个
```

### 金句

- **术语是能指，概念是所指。**（名词可以换，人没变；同一个名词也可以挂在不同人身上。）
- **名词不能替你定义。**（例子是插图，不是定义；定义要带可检验的判据。）
- **能指是任意的，所指才是实质。**（任意性 ≠ 随意性：约定是社会性的。）
- **涵义 ≠ 指称。**（晨星和暮星是同一颗星——同一个指称可以有很多种涵义。）
- **同物异名是漏的根源，同名异物是吵的根源。**
- **漂移无害，不对齐才可怕。**（钉死不是反对语言演化，是反对在同一场会议里用三个版本演化。）
- **没爆过，只是还没到判定时刻。**（矛盾出现时的对齐，已经是在收拾残局了。）
- **九格是该查时查全的尺子，不是每次量全的尺子。**（九格是动作不是知识。）
- **你没有错，但你说的话没法验证对错，因为你没有用定义说话。**
