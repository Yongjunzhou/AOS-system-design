## 1. 单元导读

**主题**：术语是能指、概念是所指；误解的三个形态（词汇病）；九格尺子。这一单元发的不是内容，是**工具**——后面十一个单元量概念的尺子。

**开场破题（请对此发表意见）**：念书里章首那场会——一家公司季度会，三个人三句话三个"架构"：老板说"我们公司的**架构**不行，管理层级太多，决策太慢"；产品总监说"我说的是产品**架构**，M3 的模块边界该重新划了"；技术总监说"你们说的都不是**架构**，系统架构是服务边界、数据所有权这些事"。吵了四十分钟，谁也没说服谁，散会时觉得"对方不可理喻"。**先让两组表态：这场会谁错了？** 不要急着给答案，让争论先发生——你会在点评 Q1 时把它收掉。

**本单元要反转的六个直觉**：

1. 「术语和概念是一回事，三个'架构'各有各的意思很正常」——**错**。术语是能指（名牌），概念是所指（名牌背后的人）；同一个能指可以挂三个所指。
2. 「晨星和暮星是两颗不同的星」——**错**。指称相同（都是金星），只是涵义不同。
3. 「语言是精确编码，一个词就该对一个意思；我随便用词没关系」——**错**。语言是约定，模糊是 feature、歧义是影子；漂移始于言语，任意性 ≠ 随意性。
4. 「平时没出过'同一个词各指各的'的问题，说明我们没这个病」——**错**。平时不爆 = 还没到判定时刻；增量不显形，关键时刻定义才成为判定依据。
5. 「'评审就是开会'这就是定义 / '评审验证确认'差不多」——**错**。例子不是定义；review / verification / validation 是翻译伪朋友。
6. 「看懂就够了，填九格是形式主义 / 九格每格都要填满」——**错**。"看懂"不可检验；九格从三种病反推；薄格可省，不可跳过。

**本轮 10 题的内在逻辑（两组 2×5，组内循序而进：识别→机制→判据/落地）**：

- **第一组 · 概念与原理（5 题）**：从"术语≠概念"的定义出发（Q1 概念本身，见树见林）→ 索绪尔×弗雷格七词 + 语言/言语关系图（Q2 概念关系，见树见林——答错即暴露误解）→ 三条机制原理：语言是约定、术语会漂移（Q3 真悖论：模糊是 feature vs 需要钉死）、病二"平时不爆关键时刻爆"（Q4 真悖论：平时效率 vs 判定正确）、九格从误解反推、薄格可省不可跳过（Q5）。这一组回答**"词和概念是什么关系、误解怎么来的、尺子怎么造"**。
- **第二组 · 落地与实践（5 题）**：三种病在真实场景里依次用判据——病一例子≠定义（Q6 当场下定义）、病二同词异义（Q7 验收翻车·真悖论：医院要确认 vs 公司要验证都对）、病三翻译伪朋友（Q8 回英文现形·真悖论：中文模糊 vs 术语要说清）→ 九格当动作（Q9 三场景·真悖论：每次量全 vs 该查时查全）→ 落地生根：回你们部门做词汇体检（Q10）。这一组回答**"怎么用尺子治病"**。

## 2. 题卡（打印分发）

> **答题要求**：组内讨论 25 分钟，把答案写在便签/白板上。每题答案不超过 5 行。每组选派一人上台讲解（4–5 分钟）。允许观点不同，但必须给出理由。
> **分组**：第一组（Q1~Q5）偏概念与原理；第二组（Q6~Q10）偏落地与实践。

### 第一组 · 概念与原理（5 题）

**Q1（破题 · 概念本身 · 术语≠概念）** 一家公司季度会，三个人三句话三个"架构"：老板说"我们公司的**架构**不行，管理层级太多"；产品总监说"我说的是产品**架构**，M3 的模块边界该重新划了"；技术总监说"你们说的都不是**架构**，系统架构是服务边界、数据所有权这些事"。吵了四十分钟，谁也没说服谁。有人劝架："三个'架构'各有各的意思很正常——语言本来就是灵活的约定，模糊是它的本性。术语和概念就是一回事，各干各的就行，何必较真。"**请先表态："术语和概念是一回事，各干各的就行"站得住吗？然后用一句话定义"术语"和"概念"（用能指/所指），并用你的定义判断：三个"架构"是一个概念还是三个概念？** 追问：①索绪尔：符号=能指+所指——三个"架构"是同一个能指、三个所指，对吗？②弗雷格：符号→涵义→指称——"晨星/暮星"是两个能指、两种涵义、同一个指称。这是"术语≠概念"的证据吗？③"语言灵活"和"概念对齐"都对——那到底什么时候该较真？给一条判据。（同一场会议里三个版本演化 = 该对齐；语言整体演化 = 不必钉死）④如果这场会不散、老板拍板"架构要改"，产品和技术各按自己的理解去改——两个月后会发生什么？（"各干各的"省下四十分钟，付出去的是什么？）⑤反身：你刚才给"术语 / 概念"下的定义，本身可检验吗？——还是你只能"举例说明"？（这一章的核心：懂 ≠ 能定义）

**Q2（概念关系 · 索绪尔×弗雷格七词 + langue·parole）** 有人说："索绪尔说符号=能指+所指，弗雷格说符号→涵义→指称——两套理论，我该记哪个？反正都是说'词和意思'。"也有人说："符号学是研究词的，跟我们做系统有什么关系？"**请给出符号、能指、所指、涵义、指称、术语、概念这七个词的关系——谁包含谁、谁对应谁；再把"语言（langue）"和"言语（parole）"放进这张图。然后回答：索绪尔和弗雷格是两套理论，还是同一件事的两层？** 追问：①索绪尔停在"符号有形式和内容"（能指+所指）；弗雷格多出的一元是什么？它回答什么问题？（涵义 = 呈现方式——同一个东西为什么能有两种说法）②"术语是名牌，概念是名牌背后的人"——比喻里"名牌"对应哪个词、"人"对应哪个？"涵义""指称"在比喻里又对应什么？③用这张关系图解释：晨星/暮星（同物异名）和章首"架构"（同名异物）——各是哪个关系出错了？（多涵义一指称 / 一符号多所指）④langue 和 parole 在哪一层？——"语言的规则是全社会慢慢变的，而每一次漂移都始于某个人的某一次言语"。这对"我自己用词随便点没事吗"给出了什么答案？⑤这张图对"判断一个词该不该对齐"有什么用？（先分清是漏还是吵——漏的根源 vs 吵的根源）

**Q3（原理 · 约定与漂移 · 真悖论）** 有人说："语言是精确的编码系统——一个词就该对一个意思。'架构'一个词挂了五个意思，这是语言出了 bug，得修。"也有人说："术语漂移是坏事，应该把每个词的词义都钉死，禁止演化。"还有人说："能指和所指本来就是随便配的——反正任意，我用什么词义都行。"**语言是 bug 还是 feature？术语漂移是坏事吗？'钉死定义'在反对什么？'语言任意'等于'随便用'吗？** 追问：①"苹果"为什么叫苹果？语言为什么是约定不是精确编码？（约定的灵活 = 几亿人共用一套符号；灵活的另一面 = 歧义）②"架构"从建筑→软件→组织→数据，每一次借用叠一个所指——漂移本身有害吗？有害的是什么？（没人察觉漂移 / 不对齐）③"钉死定义"反对的是什么？（反对在同一场会议里用三个版本演化，不是反对演化）④"语言任意性"说的是什么？——能指和所指之间没有必然理据（当初叫"banana"也行）；但约定一旦建立，"我随便用"还成立吗？（任意性 ≠ 随意性：langue 是规则系统，个体必须遵守才能被听懂）⑤你们团队有没有一个词正在漂移、没人察觉？（哪个词在不同部门各自长了一个意思？）

**Q4（原理 · 病二机制 · 真悖论）** 有人说："我们团队从没出过'同一个词各指各的'的问题，说明我们没这个病。"也有人说："词对齐等出问题再对齐也不迟——平时各干各的挺顺的，何必为可能不发生的矛盾提前花时间。"**平时没爆过，是没病，还是还没到判定时刻？词对齐能等矛盾出现再做吗？** 追问：①平时讨论"加个功能"（增量），为什么各自的定义不显形？关键时刻讨论"算不算/该不该"（判定），为什么定义才第一次成为依据？（两份合同平时各自执行没事、合并才冲突）②矛盾出现时的对齐，是在干什么？（收拾残局）——"验收"翻车案例：四个月扯皮才拆词，拆只要两天，为什么没人早拆？③真悖论收束："平时不较真"（效率）和"关键时刻对得上"（正确）都对——靠什么判据分清什么时候该花对齐的三分钟？④一场会议"没对齐就散会"和"对齐三分钟再开"，差别在哪？（四十分钟 vs 两个月）⑤你们团队最近一次"关键时刻"（评审/验收/变更），有没有一个词让大家突然发现"我们说的不是一回事"？（自我指涉）

**Q5（原理 · 九格反推 · 薄格）** 有人说："理解一个概念，看懂就够了，何必填九个格子——九格是形式主义。"也有人说："九格既然是九个格子，每一格都必须填满，少一格就是偷懒。"**九格是形式主义，还是从误解反推出来的尺子？每一格都必须填满吗？** 追问：①"看懂"这个标准本身可检验吗？——当场用一句话给"质量"下定义（不许举例）。下不出来的，是你不懂，还是"看懂"站不住？②九格怎么反推？——病一"说不出定义"要哪几格（定义①/对立⑥/辨析⑦）？病二"同词异义"要哪几格（背景②/历史③）？病三"翻译伪朋友"要哪几格（英文来源⑨）？③"薄格可省，不可跳过"——哪一格最容易空着？为什么空着的那格往往是误解潜伏的地方？（填不出误区⑧ = 正站在误区里；填不出背景② = 不知道为什么用它）④一个词有多个概念（"架构" = 组织/产品/系统），我到底该用哪个？——九格规定"只能用哪个"吗？（不——语境决定所指；九格要求"说清用的哪个"）⑤"每次开会都填九格谁受得了"——九格是"每次量全"还是"该查时查全"？（作者/审稿人的完整性清单；日常只动①或⑧⑦或①⑤两三星）

### 第二组 · 落地与实践（5 题）

**Q6（判据运用 · 病一）** 有人说："'评审就是开会过一遍''验证就是测试''质量就是档次高'——这些就是定义，大家都这么理解，够用了。"**请先表态：这些是定义吗？然后用一句话给"需求"下定义（不许举例）——定义要带什么才算数？"评审"的可检验判据是什么？** 追问：①例子是插图还是定义？——"不走流程的聊天算不算评审"，用"开会过一遍"判得出来吗？（例子只答"它长这样"，定义才答"它是什么"）②"说得出口的例子"为什么最危险？（让人误以为自己懂了；到评审结论/验收标准/需求变更这些关键时刻，一个没有判据的理解就是事故的种子）③你们最近一次"评审"，开完有没有结论、有没有记录？没有的话——按定义它最多算什么？它为什么会发生？（自我指涉）

**Q7（判据运用 · 病二验收 · 真悖论）** 一家医疗器械公司跟医院签验收条款："系统通过验收后，尾款付清。"谁也没定义"通过验收"是什么。半年后系统上线，医院说"验收没过——临床科室用得顺才算"；公司说"验收过了——功能测试通过"。扯了四个月，最后查合同，"验收"一次都没定义。有人说："总有一方在无理取闹——要么医院耍赖，要么公司推卸责任。"**请先表态：哪方在无理取闹？然后回答：如果两方都没错，错在哪个词上？'验收'糊住了几个概念、各是什么？** 追问：①真悖论收束：医院要"临床用得顺"（合理）和公司要"功能测试过"（也合理）——两个都对的要求，怎么化解？（拆成两条：功能验收 = 对照技术规格 / 临床确认 = 对照实际使用——验证 vs 确认，ISO 9000 本来就是两个词）②四个月没人拆，为什么拆只要两天？（概念早就存在，没人让合同对准概念——**拆词不是发明，是对准**）③该由谁负责定义"验收"？（承制方/专业方）——把"通过验收"留白，等于把定义权交给了哪一天？（扯皮那天）④你们合同/规格里有没有"大家都懂、但没写清"的词？哪个最贵？（自我指涉）

**Q8（判据运用 · 病三伪朋友 · 真悖论）** 有人说："'评审''验证''确认'——意思差不多，都是检查产品有没有问题。"也有人说："中文是意合语言，翻译又逐词对应，这三个词长得像不是我们的错，没法改。"**请先表态：第一句话对吗？第二句话呢？然后回答：三个词的英文原词各是什么？中文为什么看不出区别、英文一眼就能看出？"中文长得像"注定无解吗？** 追问：①review / verification / validation 词根各是什么？（re-view 再看 / veri-fication 求真 / valid-ation 有效化）——中文为什么看不出？（意合语言 + 翻译逐词对应）②看归组：评审和"确定/监视/测量/检验"是一组（ISO 3.11），验证/确认和"规范"是一组（3.8）——归组说明什么？（该和谁放在一起辨析）③按参照物给三个词各归各：评审对____、验证对____、确认对____。（目标/需求/用途）——为什么这个区分能治病？（一次"评审"开完没结论没记录，按定义最多算聊天）④真悖论收束："中文模糊是历史造成的"和"术语必须说清"——两个都对，靠什么解开？（第⑨格：中文看不清的地方，回到英文就看清了）⑤你们行业有没有"中文长得像、英文根本不是一回事"的词？（治理/统治、需求/要求……）

**Q9（判据运用 · 九格动作 · 三场景 · 真悖论）** 有人说："九格是好尺子，但我们平时用不上——写文档、开会、审文档都是靠经验，谁有空填九个格子。"**九格是知识还是动作？在开会前、审文档时、写规格前三个场景里，各怎么用？** 追问：①开会前：三分钟对齐清单（核心词各说一句"我指的是什么"）——省下的是什么？为什么很多成熟团队的开会邀请函里附一页"术语口径"？②审文档时：九格当检查单，先查什么？（定义给了吗/判据有吗/哪个概念只有例子没定义/哪格空了）——为什么说九格是审文档的显微镜？③写规格前：先填档案再写正文——为什么反而写得更快？（不用边写边纠结"这个词到底什么意思"）④真悖论收束："每次开会都填九格，谁受得了"（对——九格不是仪式）vs "该查的时候查全"（也对——跳过的那格是雷区）——怎么调和？（九格是作者/审稿人的完整性清单，日常只动其中两三星）⑤落地：设计一次"带尺子的会议"——列三个最易歧义的词，各写一句"我指的是什么"，让会议开场三分钟完成对齐。

**Q10（落地生根 · 回部门词汇体检）** 章首那场架构吵架：对齐三分钟就分流了（组织架构交 HR、产品形态另开产品评审、系统架构留下做专项），不对齐则花两个月收拾残局。有人说："那是别人的公司，我们团队没有这种'同一个词各指各的'的问题。"**先诚实回答：你们团队最近一次关键会议（评审/验收/变更），有没有一个词让大家突然发现"我们说的不是一回事"？然后：①列出你们团队最容易出歧义的三个词，各写一句"我指的是什么"；②设计一次开场三分钟完成对齐的会议（谁带头、问哪句、对齐后干什么）；③给出你们部门最应该改进的三个事项——每个事项落到一个可操作动作。**（提示："我们没这病"正是病二"平时不爆"的自我例证——先诚实面对，再谈改进。）

## 3. 点评要点·讲师版

### Q1　术语 ≠ 概念（破题 · 见树见林①）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"术语=概念，各干各的" / 定义不出术语和概念 | 定义缺席——正踩章首三个人的病，也是本单元第一道靶心 |
| 中：说"三个架构是三个概念"但没说清能指所指 | 方向对了，判据没落到符号学上 |
| 好：能指=词（同一）、所指=概念（三个）；晨星暮星=涵义≠指称；"各干各的"把分歧埋进执行，代价是两个月；"该不该较真"能给出判据（同一场会议三版本演化） | 索绪尔+弗雷格+账都算清了 |

**产品侧 vs IT侧**：产品组容易站产品总监（"模块边界当然重要"），IT 组容易站技术总监（"服务边界才是架构"）——两边都用"架构"，指的可能真是两个不同的概念。这正是问题：**不是谁对，是先没对齐。**

**反转话术**：
> "很多人心里想的正是'各干各的就行'——吵四十分钟，各干各的，看起来最省事。**但'术语和概念是一回事'这句话本身就错了：术语是能指（那个词），概念是所指（词背后的东西）。三个'架构'是同一个能指，挂了三个所指——组织、产品、系统。** 晨星暮星反过来证明：两个能指、两种涵义，指称却是同一颗星。**名词不能替你定义。** 但注意——'语言灵活'和'概念对齐'都是对的，较不较真的判据是：**是不是在同一个会议里、用同一个词演三个版本。是，就该对齐；不是，语言整体怎么演化不必你操心。** 而'各干各的'恰恰是灾难的开始——分歧没有消失，只是藏进了执行：老板拍板'架构要改'，产品改产品形态、技术改技术结构，两个月后系统集成不上，两边互指'你改的不对'。**没对齐的会议，四十分钟只是浪费；把错误的决定付诸执行才要命。** 最后反身一问：你刚才给'术语/概念'下的定义，是一句话加一条判据，还是只能举例？只能举例——你刚踩完病一。"
**参考答案要点**（书 §1.1~1.3、§3.4）：索绪尔"符号=能指+所指"、弗雷格"符号→涵义→指称"；"术语是名牌，概念是名牌背后的人"；案例进展①"重新开那场会"三步骤（摆词→对齐→分头处理）。
**追问链答案**：①是——三个"架构"同一能指、三个所指（组织架构/产品形态/系统架构）；②是——晨星暮星证明涵义≠指称，术语≠概念的正面证据；③判据=同一场会议里三个版本演化则该对齐（要真），语言整体演化不必钉死；④两个月后系统集成不上、互指"你改的不对"——"各干各的"省下四十分钟、付出两个月；⑤能说清"一句话定义+一条可检验判据"才算定义；只能举例=病一。

### Q2　七词关系（见树见林②）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"两套理论记一个就好" / "符号学跟做系统无关" | 把两模型当冲突，没看到是两层；把尺子当学问 |
| 中：能背出两模型但说不出怎么拼 | 记住了，没拼起来 |
| 好：七词关系图（索绪尔停在形式+内容；弗雷格多"涵义"=呈现方式；术语=能指/概念=所指；langue=规则系统/parole=个体使用）；两套是同一件事的两层；晨星暮星=同物异名、架构=同名异物 | 关系结构全中 |

**产品侧 vs IT侧**：产品侧用"样机/产品/原型"、IT 侧用"SRS/需求规格说明书"——都是同物异名；"验收"一个词产品侧指验证、IT 侧可能指确认，就是同名异物。

**反转话术**：
> "'两套理论记一个就好'——它们不是两套打架的理论，是**同一件事的两层**：索绪尔回答'符号由什么组成'（能指+所指），弗雷格回答'符号怎么指向世界'（符号→涵义→指称）。弗雷格多出的那一元叫**涵义**——符号呈现对象的方式。为什么要有这一层？因为'同一个东西为什么能有两种说法'——晨星和暮星指称相同、涵义不同。**把两张图拼起来：术语是能指（名牌），概念是所指（名牌背后的人），涵义是名牌上的说明文字（怎么介绍这个人），指称是本人。** 再把 langue（社会共有的规则系统）和 parole（某人某次的说话）放进来——**漂移就发生在 parole 那一层：每一次漂移都始于某个人的某一次使用。** 而'同物异名'和'同名异物'，就是这张图里两种不同的关系出错——**先分清是哪种错，才知道该防'漏'还是防'吵'。**"
**参考答案要点**（书 §1.2~1.3）：索绪尔两元、弗雷格三元；拼图表（符号↔术语/涵义↔概念/指称↔事物本身）；"术语是名牌，概念是名牌背后的人"；语言（langue）与言语（parole）。
**追问链答案**：①弗雷格多出"涵义"=呈现方式，回答"同一指称为何多种说法"；②名牌=能指/术语，人=所指/概念，涵义=说明文字（呈现方式），指称=本人；③晨星暮星=同物异名（多涵义一指称，漏的根源）；架构=同名异物（一符号多所指，吵的根源）；④langue=全社会规则系统、parole=个体使用——漂移始于 parole，所以"随便用"在为漂移添砖（回应 Q3④）；⑤先判断是漏（合并时才爆）还是吵（当场爆），再决定对齐动作。

### Q3　语言是约定，术语会漂移（原理 · 真悖论）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"语言是 bug / 漂移要禁止 / 随便用没关系" | 把约定当规则、把演化当错误、把任意当随意 |
| 中：说"语言是约定的"但说不出漂移、钉死、任意性的关系 | 前半对，机制没到 |
| 好：语言是约定（模糊是 feature，歧义是影子）；漂移无害、不对齐有害；钉死=反对一场会议三版本演化；任意性≠随意性（langue 是规则系统，个体须遵守） | 机制全中 |

**产品侧 vs IT侧**：产品侧容易说"产品名词要统一，不然客户听不懂"，IT 侧容易说"API 命名要规范"——都是"对齐"的本能，但容易滑向"钉死一切"。

**反转话术**：
> "'一个词就该对一个意思'——这是把语言当成了精确编码系统，但语言是**约定**：'苹果'为什么叫苹果？大家都这么叫，就这么叫。约定的好处是灵活——几亿人共用一套符号表达千差万别；**灵活的另一面就是歧义。所以模糊不是 bug，是 feature；歧义是它的影子，不是故障。** 那'架构'一个词挂了五个意思怎么办？——**漂移本身无害，有害的是没人察觉漂移。** '钉死定义'不是反对演化：语言本来就一直在演化，你钉不住也挡不住。**钉死反对的是'在同一场会议里用三个版本演化'。** 至于'反正任意、我用什么词义都行'——**任意 ≠ 随意：任意性说的是当初'苹果'叫'banana'也行（能指和所指之间没有必然理据）；可约定一旦建立，langue 就是规则系统，个体必须遵守才有人听得懂你。** 漂移不可怕，不对齐才可怕。"
**参考答案要点**（书 §1.1、§1.2、§1.4）：语言是约定不是精确编码；架构漂移史（建筑→软件→组织→数据）；语言（langue）/言语（parole）——漂移始于言语；"漂移不可怕，不对齐才可怕"；"钉死不是反对语言演化，是反对在同一个会议里用三个版本演化"；"能指是任意的"。
**追问链答案**：①约定——大家都这么叫；灵活让几亿人共用一套符号，歧义是灵活的另一面；②漂移无害、有害的是没人察觉漂移/不对齐（同一词各演各的）；③反对同一场会议用三个版本演化，不是反对演化本身；④任意性=能指所指无必然理据（"苹果"叫"banana"也行）；但约定建立后个体必须遵守（langue 是规则系统），不然没人听懂你——所以"随便用"不成立；⑤学员举例（需求/配置/架构在不同部门各长一个意思，正漂移没人察觉）。

### Q4　病二机制：平时不爆关键时刻爆（原理 · 真悖论）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"没爆过=没病" | 正踩最顽固的靶心——结果误判 |
| 中：说"该对齐"但说不出机制 | 结论对，机制没到 |
| 好：增量不显形、判定时刻定义才成依据；两份合同合并才冲突；矛盾时对齐=收拾残局；"该不该花对齐三分钟"能给出判据（是否进入判定时刻）；三分钟 vs 两个月 | 机制+账全中 |

**产品侧 vs IT侧**：产品侧"没吵过架=团队默契好"、IT 侧"接口文档大家都懂"——都是增量期没爆，判定期才爆的错觉。

**反转话术**：
> "'我们没出过这问题'——**没爆过，不是没病，是还没到判定时刻。** 平时讨论'加个功能'，这是增量：双方各自脑内的定义没被放到台面比较，各干各的当然顺。关键时刻讨论'这件事算不算、该不该、对没对'——**定义第一次成为判定依据，裂缝才显形。** 就像两份合同，平时各自执行各自的条款都没事，一旦合并，条款冲突才暴露。所以'词对齐'不能等矛盾出现再做——**矛盾出现时的对齐，已经是在收拾残局了。** 验收翻车就是样板：四个月扯皮才发现合同没定义'验收'，拆成'功能验收+临床确认'只要两天——**概念是现成的，只是没人早拆。** 而'平时不较真'和'关键时刻对得上'都是对的，判据是：**有没有进入'算不算/该不该/对没对'的判定时刻。** 进了，就花那三分钟；没进，各干各的。对齐的代价是三分钟，不对齐的代价是两个月。"
**参考答案要点**（书 §2.2、§2.4、章末）：病二机制（增量不显形、判定时刻定义才成依据）；"词对齐不能等矛盾出现再做"；验收翻车案例；对齐三分钟 vs 不对齐两个月。
**追问链答案**：①增量不显形（各干各的）；判定时刻定义才成判定依据（两份合同合并才冲突）；②矛盾时对齐=收拾残局；四个月没人拆因为没人让合同对准概念，概念早就存在；③判据=是否进入判定时刻（算不算/该不该/对没对）；④没对齐就散会=四十分钟浪费+错误决定付诸执行（两个月）；对齐三分钟=分流后各干各的；⑤学员举例（最近一次评审/验收/变更里突然对不上的词）。

### Q5　九格反推，薄格可省（原理）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"九格=形式主义"或"每格必填" | 一个低估尺子、一个误用尺子 |
| 中：说"九格有用但不全填" | 有判断，没说出"看懂"的漏洞和反推机制 |
| 好："看懂"不可检验（当场下定义失败）；九格从三病反推；薄格可省不可跳过、空着的格=雷区；语境决定所指；该查时查全不是每次量全 | 反推机制+"看懂"漏洞+语境全中 |

**产品侧 vs IT侧**：产品组爱量"质量"，IT 组爱量"架构/需求"——都行。当场实验是关键：让每个"说看懂"的人试着下定义，十有八九卡在病一（只能举例）。

**反转话术**：
> "'看懂就够了'——那请当场给'质量'下个定义。**下不出来的，不是你不懂，是'看懂'这个标准本身站不住：看得懂的例子（插图），不等于说得出的定义。** 九格也不是拍脑袋定的九个格——它是**从三种病反推**的：说不出定义→要定义①/对立⑥/辨析⑦；同词异义→要背景②/历史③；翻译伪朋友→要英文来源⑨。所以九格不是每次开会都量全，而是**该查的时候查全**。至于'每格都要填满'——反了。**薄格可省，但不可跳过：你填不出'误区'（⑧），很可能你正站在误区里；填不出'背景'（②），很可能你根本不知道为什么用它。跳过的那格，往往是误解潜伏的地方。** 还有一个高频问题：'架构'有组织/产品/系统三个概念，我到底用哪个？——**九格不规定只能用哪个，是要求你说清用的哪个：语境决定所指。**"
**参考答案要点**（书 §3.1、§3.2、§3.6）：九格从三类误解反推；四层九格；"薄格可省，不可跳过"；等级薄格示范；"语境决定所指"；"该查的时候查全"不是"每次量全"。
**追问链答案**：①下不出来→"看懂"不可检验（看得懂的例子≠说得出的定义）；②病一→①⑥⑦；病二→②③；病三→⑨；③最常空⑧误区（正站在误区里填不出）和②背景（不知道为什么用它）；空着的格=误解潜伏处；④九格不规定用哪个，要求说清用哪个（语境决定所指）；⑤该查时查全——作者/审稿人完整性清单，日常只动①或⑧⑦或①⑤两三星。

### Q6　病一：例子 ≠ 定义（判据运用）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"'评审就是开会'就是定义" | 正踩病一——"说得出口的例子"骗了你 |
| 中：说"不完整，还要有标准" | 方向对，没点出"判据可检验" |
| 好：例子是插图不是定义；定义要带可检验判据（评审=结论+记录）；"说得出口的例子"最危险 | 病一机制全中 |

**产品侧 vs IT侧**：产品侧容易说"样机就是验证""验收就是上线"；IT 侧容易说"评审就是评审会"——同一个病一：用例子代替定义。

**反转话术**：
> "'评审就是开会过一遍'——这是插图，不是定义。定义回答'它是什么'，例子只回答'它长这样'。**插图让你认得出它长什么样，但定义才让你分得清它和别的东西的边界。** 判据让定义从'一句话'变成'一把尺'：评审的定义是'对目标的三问判定'，判据就是——有没有得出结论？有没有留下记录？开完没有结论没有记录的，按定义不是评审，最多算聊天。**'说得出口的例子'恰恰最危险：它让你误以为自己懂了。到评审结论、验收标准、需求变更这些关键时刻，一个没有判据的理解，就是一场事故的种子。**"
**参考答案要点**（书 §2.1）：病一典型症状；"例子是插图，不是定义"；判据可检验（"评审有没有得出结论、留下记录"）。
**追问链答案**：①没有判据，判不了边界（"不走流程的聊天算不算评审"判不出来）；②例子骗你的是"你以为懂了"；到判定时刻没判据=事故种子；③没结论没记录的评审按定义最多算聊天；它会发生是因为没人把"评审"的判据当回事。

### Q7　病二：验收翻车（判据运用 · 真悖论）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：判"医院耍赖"或"公司推卸"，站了某一方 | 正中"必须有一方错"的直觉 |
| 中：说"两边都没错，是词的问题" | 方向对了，但没说清"谁该负责定义" |
| 好："验收"糊住了验证/确认两个所指；医院要确认、公司要验证都对，化解=拆成两条各配标准；拆词=对准已有概念不是发明；定义权由承制方（专业方）承担；留白=把定义权交给扯皮那天 | 机制+归责全中 |

**产品侧 vs IT侧**：产品侧容易举"样机/原型/产品"、IT 侧容易举"验收/发布/上线"。这个案例对两边都成立：任何"大家都懂、没写清"的条款都是同款地雷。

**反转话术**：
> 先让两组各站一边吵一会儿，再问："谁在无理取闹？"——等答案大概率落在"医院"或"公司"上。**没有恶人，也没有蠢人，只有一个没对齐的词。** 但注意这题的陷阱是"必须有一方错"——**医院要'临床用得顺'（确认）合理，公司要'功能测试过'（验证）也合理，两个都对，不是谁让谁。** 化解靠拆：功能验收 = 对照技术规格（验证），临床确认 = 对照实际使用（确认）——**ISO 9000 里本来就是两个词、两种参照，是中文的"验收"把两种概念的缝隙用胶水糊上了。** 而为什么四个月没人拆？——**概念是现成的（ISO 9000 里一直躺着两个词），只是没人让合同对准概念。拆词不是发明，是对准。** 更要命的是归责：把"通过验收"留白，等于把定义权交给了扯皮那天；而"谁定义验收"本来就该是承制方（专业方）的分内事。**概念不对齐的代价，平时看不见，到合同纠纷、验收分歧、需求变更时才一次性结算。**
**参考答案要点**（书 §2.4、§2.2）：验收翻车案例；验证/确认为 ISO 9000 3.8 组两个不同的词；"平时不爆、关键时刻爆"的机制；拆词=对准不是发明。
**追问链答案**：①拆成"功能验收+临床确认"两条、各配标准与记录（验证 vs 确认——两个都合理，拆开各得其所）；②拆只要两天因为概念早存在、没人对准；③承制方（公司作为专业方）；留白=把定义权交给扯皮那天；④学员找"没写清"的词（通过验收/满足要求/正常运行……）。

### Q8　病三：翻译伪朋友（判据运用 · 真悖论）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"差不多，都是检查产品有没有问题" / "中文长得像没法改" | 正中直觉——中文字面把三个词拉到一起，且误以为模糊无解 |
| 中：知道英文原词不同 | 对，但没说出"为什么中文看不出"的机制和解法 |
| 好：review / verification / validation 词根不同；中文是意合语言+翻译逐词对应；看归组（ISO 3.11 vs 3.8）；评审对目标/验证对需求/确认对用途；第⑨格=回英文现形 | 三因+归组+解法全中 |

**产品侧 vs IT侧**：重点引导到评审/验证/确认（第7章主角）；产品侧也可举"治理/统治""需求/要求"等带"治/求"的伪朋友。

**反转话术**：
> "'评审''验证''确认'——意思差不多？**英文一摆出来，伪朋友当场现形：review、verification、validation，三个完全不同的词，只是中文翻译凑巧都带'评/验/认'。** 词根更是明摆着：re-view（再看一次）、veri-fication（求真）、valid-ation（有效化）。中文看不出区别，不是词本身的问题，是翻译和历史共同造成的——中文是意合语言，不像英文能靠词根一眼看出词族关系。更硬的一招是**看归组**：ISO 9000 里评审（3.11.2）和"确定/监视/测量/检验"是一组，验证/确认（3.8.12/13）和"规范"是一组——**归组告诉你该把谁和谁放在一起辨析。** 那"中文长得像、没法改"怎么办？——**'中文模糊是历史造成的'（对）和'术语必须说清'（也对）不矛盾，解法就是概念档案第⑨格：中文看不清的地方，回到英文就看清了。** 这也是这本书坚持每张档案带"术语英文来源"一格的原因。"
**参考答案要点**（书 §2.3）：翻译伪朋友三因（翻译逐词对应 / 90 年代术语集中涌入译法不一 / 中文意合语言）；ISO 9000 评审（3.11.2）与验证/确认（3.8.12/13）不同术语组；治病三动作（回英文原词/查词根/看归组）。
**追问链答案**：①review=re-view（再看）、verification=veri-fication（求真）、validation=valid-ation（有效化）；中文意合+翻译逐词对应看不出；②归组=评审与"确定/监视/测量/检验"一家、验证/确认与"规范"一家——该和同组词辨析；③评审对目标、验证对需求、确认对用途；一次"评审"没结论没记录=最多算聊天；④解法=回英文现形（第⑨格），中文模糊是翻译+历史造成不是无解；⑤学员举例（治理/统治、需求/要求……）。

### Q9　九格是动作（判据运用 · 三场景 · 真悖论）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"九格平时用不上" | 把尺子当摆设——正踩判据5 靶心 |
| 中：说"三场景有用"但说不出具体动作 | 方向对，没落到动作 |
| 好：开会前三分钟对齐清单/审文档当检查单（显微镜）/写规格先填档案；"该查时查全"调和"每次量全谁受得了"；九格是动作不是知识 | 三场景动作全中 |

**产品侧 vs IT侧**：产品组"立项会前对口径"、IT 组"需求评审前对术语"——同一动作：核心词各说一句"我指的是什么"。

**反转话术**：
> "'平时用不上'——那是因为把它当成了知识，而九格是**动作**。三个场景里它直接干活：**开会前**，三分钟对齐清单——核心词各说一句'我指的是什么'，省下的是散会后三十分钟扯皮，这就是成熟团队开会邀请函附一页'术语口径'的原因；**审文档时**，九格当检查单——先查定义给了吗、判据有吗、哪个概念只有例子没定义、哪格空了，**它是审文档的显微镜**；**写规格前**，先填档案再写正文——档案填完了，正文里的每个词都经得起追问，写作速度反而更快，因为不用边写边纠结'这个词到底什么意思'。**那'每次开会都填九格谁受得了'怎么办？——对，九格不是仪式；但'该查的时候查全'也对，跳过的那格是雷区。调和就是：九格是作者/审稿人的完整性清单，日常只动其中两三星。** 九格不是知识，是动作——每一次使用，都是把'我以为'变成'它定义上是什么'。"
**参考答案要点**（书 §3.5、§3.6）：三场景（开会前对齐清单/审文档当检查单/写规格先填档案）；"九格不是知识，是动作"；"该查的时候查全"不是"每次量全"。
**追问链答案**：①省下的是散会后扯皮+把错误决定付诸执行的风险；②先查定义/判据/只有例子没定义的概念/哪格空了——九格是显微镜；③先填档案让正文每个词经得起追问，不用边写边纠结定义；④调和="该查时查全"：九格是作者/审稿人完整性清单，日常只动两三星；⑤落地：列三词+各写一句"我指的是什么"+开场三分钟。

### Q10　落地生根：回部门词汇体检（判据综合运用）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：说"我们部门没这病" | 体检自欺——正是病二"平时不爆"的自我例证 |
| 中：列了三个词但没落到动作 | 停在"该对齐"没到"怎么对齐" |
| 好：诚实回答"最近一次对不上的词"→ 三词各写一句"我指的是什么"→ 设计开场三分钟对齐会议（谁带头/问哪句/对齐后干什么）→ 三事项各落一个动作 | 落地全中 |

**产品侧 vs IT侧**：产品组体检对象是"样机/产品/客户词"，IT 组是"验收/上线/接口词"——同一套尺子两个世界。老师把两组的三件事摆在一起对照，点出"词汇病不挑行业"。

**反转话术**：
> "章首那场会，对齐三分钟就分流了——可每个听完的人都会想：'那是别人的公司，我们没这问题。'**这正是病二'平时不爆'的自我例证：没爆过，不是没病，是还没到判定时刻。** 所以落地生根的作业要求是：①先诚实——最近一次关键会议，哪个词让大家突然发现'我们说的不是一回事'？想不起来的，本身就是警报；②列三词、各写一句'我指的是什么'——注意，写不出来的那个词，恰恰是最危险的（病一）；③设计开场三分钟对齐会议——谁带头（主持人）、问哪句（'今天核心词的所指一样吗'）、对齐后干什么（分流各归各位）。两周后回来报告：三个动作做到了几个？做不到的那个，为什么？"
**参考答案要点**（书 §3.4、§3.5、判据速查卡）：摆词→对齐→分头处理；三分钟对齐清单；"我指的是什么"句式；判据速查卡五条。
**追问链答案**：无固定答案；评讲标准=①是否诚实完成"最近一次对不上的词"体检；②三个词是否各落一句"我指的是什么"（写不出定义=病一报警）；③会议设计是否具体（谁带头/问哪句/对齐后干什么）；④三事项是否各落可操作动作；⑤与课后作业"回部门落地"衔接（两周后回来报告）。

## 4. 知识卡片

### 一页图

```
误解的三个形态（词汇病）
  说不出定义（病一）──┐
  同词异义  （病二）──┼──→ 九格尺子：定界→溯源→致用→纠误 ──→ 每章用它钉死概念
  翻译伪朋友（病三）──┘

符号 = 能指（名牌）+ 所指（名牌背后的人）      ←索绪尔
符号 → 涵义 → 指称                            ←弗雷格
语言（langue）= 社会规则系统 · 言语（parole）= 某人某次使用（漂移始于这里）
  同物异名 = 漏的根源 · 同名异物 = 吵的根源

九格四层：定界（①定义 ⑥对立 ⑦辨析 ⑨英文）
        溯源（②背景 ③历史）· 致用（④问题 ⑤场景）· 纠误（⑧误区）
规则：薄格可省，不可跳过——跳过的那格，往往是误解潜伏的地方

语言是约定不是精确编码：模糊是 feature，歧义是影子
能指任意 ≠ 随便用：约定一旦建立，个体必须遵守
术语会漂移：漂移无害，不对齐才可怕；钉死 ≠ 反对演化

认知链：发尺子(1) → 工程(2) → 三基座(3) → 需求工程(4) → 需求的完整性(5)
      → 设计开发落地(6) → 评审验证确认(7) → 架构(8) → 架构决策(9)
      → 配置管理(10) → 治理(11) → 整合(12)
```

### 金句

- **术语是名牌，概念是名牌背后的人。**
- **名词不能替你定义。**
- **例子是插图，不是定义。**（定义带判据，才是尺。）
- **同物异名是漏的根源，同名异物是吵的根源。**
- **漂移无害，不对齐才可怕。**（钉死 ≠ 反对演化；任意 ≠ 随意。）
- **拆词不是发明，是对准。**
- **平时不爆，不是没病，是还没到判定时刻。**
- **对齐的代价是三分钟，不对齐的代价是两个月。**
- **用定义说话，不用例子说话。**
