## 1. 单元导读

**主题**：术语是能指、概念是所指；误解的三个形态（词汇病）；九格尺子。这一单元发的不是内容，是**工具**——后面十一个单元量概念的尺子。

**开场破题（请对此发表意见）**：把书里章首那场会念给学员听——一家公司季度会，三个人三句话三个"架构"：老板说"我们公司的**架构**不行，管理层级太多，决策太慢"；产品总监说"我说的是产品**架构**，M3 的模块边界该重新划了"；技术总监说"你们说的都不是**架构**，系统架构是服务边界、数据所有权这些事"。吵了四十分钟，谁也没说服谁。**先让两组表态：这场会谁错了？** 不要急着给答案，让争论先发生——你会在点评 Q1 时把它收掉。

**本单元要反转的三个直觉**：

1. 「晨星和暮星是两颗不同的星」——**错**。指称相同（都是金星），只是涵义不同。
2. 「术语和概念是一回事」——**错**。术语是能指（名牌），概念是所指（名牌背后的人）。
3. 「评审就是开会 / 验证和确认差不多」——**错**。例子不是定义；评审（review）/ 验证（verification）/ 确认（validation）是翻译伪朋友。

**本轮 5 题的内在逻辑**：Q1 破题（架构吵架现场——同一个词三个所指）→ Q2 术语≠概念（晨星暮星 + 身边的同物异名/同名异物）→ Q3 词汇病三形态（自己举工作里的例子）→ Q4 九格尺子（选最容易误解的三格量一个词）→ Q5 落地（设计一次"带尺子的会议"）。

**同类分组说明**：产品组和 IT 组拿到**相同的 5 题**，各自用自己的工作语境作答。产品组容易举"样机/产品/原型"，IT 组容易举"验收/上线/发布"——表面是两组不同的词，其实是**同一种词汇病**在硬件和软件里各长一个样子。这正是"词汇病不挑行业"的证据。

## 2. 题卡（打印分发）

> **答题要求**：组内讨论 25 分钟，把答案写在便签/白板上。每题答案不超过 5 行。每组选派一人上台讲解（4–5 分钟）。允许观点不同，但必须给出理由。

**Q1（破题·先表态 + 追问链）** 一家公司季度会：老板说"我们公司的架构不行，管理层级太多，决策太慢"；产品总监说"我说的是产品架构，M3 的模块边界该重新划了"；技术总监说"你们说的都不是架构，系统架构是服务边界、数据所有权这些事"。吵了四十分钟，谁也没说服谁。有人说："三个人对'架构'理解不一样很正常，各干各的就行，何必为个词较真。"**请先表态：这句话对还是错？**然后一路推下去：①三个人用同一个词"架构"，指向了几个概念？各是什么？②如果这场会没对齐就散会、老板拍板"架构要改"——两个月后会发生什么？推到第三个月。③你们工作中"最贵的一个词"是什么？——哪个词不齐，会让两个部门扯皮最久？

**Q2（先表态 + 追问链）** 你指着清晨最亮的星说"晨星"，指着傍晚最亮的星说"暮星"——不同时间、不同方位。有人说："两个不同的名字，当然指两个不同的东西——就像'苹果'和'香蕉'。"**请先表态：这个推理对还是错？**然后：①"晨星""暮星"指同一颗星，为什么是"两个概念"？——同一个东西被几个词指、同一个词指几个东西，这两种情况各叫什么？②判一判："SRS"和"需求规格说明书"是哪种情况？"验收"在公司和医院嘴里是哪种情况？③各再造一个你们工作里的例子，并说明：哪种是"漏"的根源，哪种是"吵"的根源？

**Q3（先表态 + 追问链）** 两家公司签验收条款，谁也没定义"通过验收"是什么。半年后系统上线，医院说"验收没过——临床科室用得顺才算"，公司说"验收过了——功能测试通过"。扯了四个月。有人说："总有一方在无理取闹——要么医院耍赖，要么公司推卸责任。"**请先表态：哪方在无理取闹？**然后：①如果两方都没错，错在哪个词上？"验收"这个合同词，糊住了几个概念？各是什么？②如果你是那家公司，四个月后才查合同发现"验收"没定义——第一步该做什么？当初就把"验收"拆成"功能验收 + 临床确认"，能省下什么？③你们合同/规格/评审结论里，有没有"大家都懂、但没写清"的词？哪个最危险？

**Q4（先表态 + 当场实验 + 追问链）** 九格尺子有九个格子。有人说："理解一个概念，把它看懂就够了，何必填九个格子——这是过度工程、形式主义。"**请先表态：这句话对还是错？**然后当场做个实验：①用一句话给"需求"下定义（不许举例子）——下不出来，说明"看懂"这个标准站得住吗？②"评审就是开会"为什么不是定义？定义要带什么才算数？③请用九格的三格（①定义 / ⑦辨析 / ⑧误区）给"需求"各填一行，然后判断："需求就是用户要的东西"这句，算定义还是例子？

**Q5（先表态 + 当场实验 + 追问链）** 一场重要会议，主持人提议"开场先花三分钟，把今天要用的核心词各对齐一遍"。有人说："浪费时间，直接开会吧——大家都做了这么多年，谁还不知道'需求''质量'是什么意思？"**请先表态：这三分钟是浪费还是投资？**然后：①当场回答：你们团队的"质量"指的是什么？"验收"指的是什么？——答得上来是定义，答不上来是什么？②"大家都懂"为什么是句空话？懂到能说出定义，和懂到只能举例子，差在哪？③给下周一次真实会议选三个"开场要对齐的词"——你选的词，分别可能在哪个环节咬人（评审 / 验收 / 变更）？

## 3. 点评要点·讲师版

### Q1　架构吵架（破题）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"各干各的就行" | 正中直觉——正是本单元第一道靶心 |
| 中：说"是错的，但他们说的确实不是一回事" | 方向对了，但没给出"为什么不是一回事"的机制 |
| 好：同一个词（能指）指向三个不同的概念（所指）；"各干各的"不是解脱，是把没对齐的决定付诸执行 | 索绪尔的能指/所指到位，对齐的账算清了 |

**产品侧 vs IT侧**：产品组容易站产品总监（"模块边界当然重要"），IT 组容易站技术总监（"服务边界才是架构"）——两边都在用"架构"，指的可能真是两个不同的概念。这正是问题：**不是谁对，是先没对齐。**

**反转话术**：
> "很多人心里想的正是'各干各的就行'——吵四十分钟，各干各的，看起来最省事。"
> 落点：**'各干各的'恰恰是灾难的开始。** 老板拍板"架构要改"，产品改产品形态、技术改技术结构，两个月后系统集成不上，两边互指"你改的不对"——**没对齐的会议，四十分钟只是浪费，把错误的决定付诸执行才要命。对齐的代价是三分钟，不对齐的代价是两个月。**

**参考答案要点**（书 §1.2、§1.3、§3.4）：索绪尔"符号 = 能指 + 所指"，能指是形式、所指是实质；弗雷格"符号→涵义→指称"；同物异名是漏的根源、同名异物是吵的根源。

**追问链答案**：①三个所指——组织架构（管理）/ 产品形态（产品）/ 系统架构（技术），同一个能指挂三个所指，谁都没错；②没对齐就散会：老板拍板"架构要改"→ 产品改产品形态、技术改技术结构 → 两个月后集成不上、两边互指"你改的不对"——**没对齐的决定被执行才要命**；③"最贵的词"由学员自找，判断标准：哪个词不齐会让跨部门扯皮最久（常见：质量 / 验收 / 基线 / 需求）。

### Q2　术语 ≠ 概念（晨星暮星）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"两个名字当然指两个东西" | 正中直觉——"晨/暮"两个字的能指压过了所指 |
| 中：说"指的都是金星" | 对了，但没把"苹果/香蕉"那个推理错在哪说清 |
| 好：术语是名牌，概念是名牌背后的人；同一个指称可以有多个涵义，同一个词也可以有多个所指 | 抽象到位 |

**产品侧 vs IT侧**：产品侧"订单/order"、IT 侧"SRS/需求规格说明书"都是同物异名；"验收"一个词产品侧指验证、IT 侧可能指确认，就是同名异物。

**反转话术**：
> "如果术语 = 概念，那么'晨星''暮星'这两个词就应该是两个概念——可它们指同一颗星。反过来，'架构'一个词可以指向组织、产品、系统三个概念。所以术语不是概念：**名词不能替你定义。** 谈概念，先分清你用的是哪个所指。"

**参考答案要点**（书 §1.1~1.3）：晨星/暮星思想实验；语言是约定不是精确编码，模糊是 feature 也是歧义之源；术语漂移——"架构"从建筑学到软件到组织到数据，一次借用叠一个所指。

**追问链答案**：①同一个东西被几个词指 = **同物异名**（漏的根源）；同一个词指几个东西 = **同名异物**（吵的根源）；②"SRS = 需求规格说明书"是同物异名；"验收"在公司和医院嘴里 = 同名异物（验证 vs 确认糊在一个词上）；③学员各自举例并分类。

### Q3　词汇病三形态

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：判"公司有责"或"医院有责"，站了某一方 | 正中"必须有一方错"的直觉——本单元 Q3 的靶心 |
| 中：说"两边都没错，是词的问题" | 方向对了，但没说清是哪一种病、怎么治 |
| 好：指出"验收"一个词糊住了两个所指（验证 / 确认）；并补出另外两种病，翻译伪朋友能指出"要回英文原词才看穿" | 三病全中 |

**产品侧 vs IT侧**：产品侧容易举"样机 / 原型 / 产品"（同词异义）、IT 侧容易举"验收 / 发布 / 上线"。翻译伪朋友要引导到评审/验证/确认——**review、verification、validation 三个英文原词完全不同，中文翻译凑巧都带"评/验/认"**。

**反转话术**：
> 先让两组各站一边吵一会儿，再问："谁在无理取闹？"——等答案大概率落在"医院"或"公司"上。
> 落点：**没有恶人，也没有蠢人，只有一个没对齐的词。** "验收"一个中文词，糊住了 ISO 9000 里清清楚楚的两个概念——验证（verification，对照技术规格）和确认（validation，对照临床实际使用）。这就是病二（同词异义）；而它之所以难发现，根子在病三（翻译伪朋友）——review / verification / validation 三个英文原词，中文都带"评/验/认"。**概念不对齐的代价，平时看不见，到合同纠纷、验收分歧、需求变更时才一次性结算。**

**参考答案要点**（书 §2.1~2.4）：病一用例子代替定义，例子是插图不是定义，定义要带可检验判据；病二同词异义，平时讨论增量不显形、关键时刻定义成为判定依据才爆；病三翻译伪朋友，ISO 9000 里评审（3.11 组）和验证/确认（3.8 组）根本不同组；"验收"翻车案例（医疗公司四个月扯皮，最后把"验收"拆成功能验收+临床确认）。

**追问链答案**：①"验收"糊住了验证（verification，对照技术规格）和确认（validation，对照临床实际使用）两个概念——ISO 9000 3.8 组里两个不同的词；②第一步：把"验收"拆成"功能验收 + 临床确认"两条，各自配明确标准与记录；当初就这么拆，能省四个月扯皮；③学员找合同/规格里"没写清"的词（通过验收 / 满足要求 / 正常运行……），判断标准：写到判定依据时会不会含糊。

### Q4　九格尺子

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"看懂就够了，填格子是形式主义" | 正中直觉——但"看懂"恰恰是无法检验的标准 |
| 中：说"九格有用但不用全填" | 有判断，没把"看懂"这个标准的漏洞说出来 |
| 好："看懂就够了"站不住——当场给"需求"下定义都下不出来；九格是"该查的时候查全"的尺子，不是每次都要量全 | 把"看懂"的漏洞和九格用法都说清了 |

**产品侧 vs IT侧**：产品组爱量"质量"，IT 组爱量"架构/需求"——都行。当场实验是关键：让每个"说看懂"的人试着下定义，十有八九卡在病一（只能举例）。

**反转话术**：
> "'看懂就够了'——那请当场给'需求'下个定义。**下不出来的，不是你不懂，是'看懂'这个标准本身站不住：看得懂的例子（插图），不等于说得出的定义。** 所以九格不是每次开会都要量全，而是**该查的时候查全**：日常只用两三格——开会前对齐用①定义，审文档用⑧误区+⑦辨析，写规格用①+⑤；**薄格可省，但不可跳过**——你填不出'背景'（②），很可能你根本不知道为什么用它；填不出'误区'（⑧），很可能你正站在误区里。"
> 落点：**九格不是知识，是动作——把"我以为"变成"它定义上是什么"。**

**参考答案要点**（书 §3.1、§3.6）：九格由三类误解**反推**出来（病一→定义/对立/辨析；病二→背景/历史；病三→英文来源；乱用→问题/场景；残余→误区）；三场景（开会前对齐清单、审文档当检查单、写规格先填档案）；三层（个人/团队/组织）。

**追问链答案**：①"需求就是用户要的东西"是例子不是定义；定义要带可检验判据——ISO 9000："明示的、通常隐含的或必须履行的需要或期望"；②"评审就是开会"没有判据；判据 = 有没有得出结论、留下记录；③用三格填"需求"：定义（明示/隐含/必须履行的需要或期望）、辨析（需求 vs 需要 vs 期望）、误区（"用户要什么就记什么"——漏了隐含的和必须履行的）。

### Q5　带尺子的会议（落地）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：认同"直接开会，大家都懂" | 正中直觉——"大家都懂"恰恰是最难检验的话 |
| 中：说"有道理但没必要每次" | 没算清对不齐的账 |
| 好：当场给"质量""验收"下定义——下不出来的瞬间，就是"大家都懂"被证伪的瞬间；对齐的代价是三分钟，不对齐的代价是两个月 | 落地完整 |

**产品侧 vs IT侧**：产品组常列"需求/评审/样机"，IT 组常列"验收/基线/上线"。老师可当场演示：把两组的词放一起，追问"你们组的'验收'和另一组的'验收'是一个所指吗"——答不上来的那一刻，就是本单元最好的收尾。

**反转话术**：
> "有人说'大家都做了这么多年，谁还不知道需求质量什么意思'——好，那请当场下个定义。**下不出来的瞬间，就是'大家都懂'被证伪的瞬间。** 再把'大家都懂'和 Q3 那个'大家都懂的验收'并排放：**大家都懂的验收，让两家公司扯了四个月。对齐的代价是三分钟，不对齐的代价是两个月。**"
> 落点：**对齐的代价是三分钟，不对齐的代价是两个月。**

**参考答案要点**（书 §3.5）：三场景共用同一动作——把"我以为"变成"定义上是什么"。

**追问链答案**：①当场下不出定义 = 病一（只能举例）；②"大家都懂"不可检验——懂到能说定义 vs 懂到只能举例，后者在判定关键时刻咬人（评审结论、验收标准、需求变更）；③三个词由学员自选（质量 / 验收 / 基线 / 需求），并落到具体环节：评审结论怎么写、验收标准怎么定、需求变更怎么批。

```
  翻译伪朋友（病三）──┘

符号 = 能指（名牌）+ 所指（名牌背后的人）      ←索绪尔
符号 → 涵义 → 指称                            ←弗雷格
  同物异名 = 漏的根源 · 同名异物 = 吵的根源

九格四层：定界（①定义 ⑥对立 ⑦辨析 ⑨英文）
        溯源（②背景 ③历史）· 致用（④问题 ⑤场景）· 纠误（⑧误区）
规则：薄格可省，不可跳过——跳过的那格，往往是误解潜伏的地方

认知链：发尺子(1) → 工程(2) → 三基座(3) → 需求工程(4) → 需求的完整性(5)
      → 设计开发落地(6) → 评审验证确认(7) → 架构(8) → 架构决策(9)
      → 配置管理(10) → 治理(11) → 整合(12)
```

### 金句

- **术语是名牌，概念是名牌背后的人。**
- **例子是插图，不是定义。**
- **同物异名是漏的根源，同名异物是吵的根源。**
- **对齐的代价是三分钟，不对齐的代价是两个月。**
- **用定义说话，不用例子说话。**

## 5. 课后作业

1. 找出你最近一次会议上，两个部门用同一个词说不同事的情形——用九格尺子各填一张档案，证明他们说的是两个概念。（书第1章 练习1）
