# 单元五 需求的完整性：标尺要全

> 八步萃取分析见 [05-第5章-需求的完整性-从教材到问题分析.md](../教材书/05-第5章-需求的完整性-从教材到问题分析.md)

## 一、单元导读

### 主题

需求的"标尺"要全——产品需求要"全"，全在哪三类？为什么"样机验证通过"不等于"产品成功"？三类需求各自来自谁、为什么可实现性需求客户根本不关心？承制方为什么是需求的主导方？

### 开场破题（对应章首误解现场）

念出冰链会议室里小林的话："原理样机验证通过，**我们的产品成功了**。接下来就是放大生产。"会议室一片掌声。只有制造代表老陈皱着眉，翻着样机的零件清单问："制冷片我们买得到，但这颗控温芯片是定制料——**最小起订量五万片，交期二十周**。外壳是 CNC 一件件铣出来的，**量产用注塑，这个结构和壁厚注不出来**。还有，这个精度是靠手工校准的，**产线上没人会做**。你们管这些叫'成功'？"

让各组表态：如果你坐在冰链的会议室里，你觉得小林没错吗——样机都跑通了、还验证通过了，怎么会不是产品成功？老陈的话，是真的"太保守"，还是点到了要害？

### 本单元要反转的直觉

- **样机验证通过了 = 产品成功了**（× 原理样机只验证功能需求；环境未验、可实现没写进需求清单）
- **需求写全了 = 功能写全了**（× 功能只占三分之一；缺可实现交付物停在环境样机）
- **可实现性需求是后续工艺的事，不归需求管**（× 它是产品固有特性，必须体现在相关方需求中）
- **量产翻车是制造/采购/运维没做好**（× 每一个"不方便X"都是一条当初没写进需求的可实现性需求）
- **成本是算出来的，设计完再核算**（× 成本是需求分解分配分析的结果；降本大会=承认经济可承受性需求没写）
- **需求不够全，是客户没提清楚**（× 需求全不全是承制方责任；客户可以不知道，承制方不能说"没提所以不全"）
- **承制方就是听客户要什么就做什么**（× 承制方是主导方，引导范围、塑造需求）
- **我们组织经验很丰富，口口相传，就是在自觉积累**（× 散/隐/无法复用的资产不是资产；问题不转成资产，教训永远是教训）

### 本轮题卡的内在逻辑（10 题 2×5）

**第一组 · 概念与原理（先立概念）**：Q1 需求完整性定义（概念本身·破题）→ Q2 三类/三载体/三主人关系（概念关系）→ Q3 "谁在问"判据（同一特性两个主人）→ Q4 专属验证载体（样机≠产品）→ Q5 承制方主导（谁说了算）。由"是什么"走到"为什么"。

**第二组 · 落地与实践（用尺量）**：Q6 冰链量产翻车八条（逆向诊断）→ Q7 恒信镜照（原型/试点/正式产品）→ Q8 组织资产四步闭环（为什么经验丰富也漏）→ Q9 经济可承受性（成本是需求）→ Q10 回部门需求完整性体检（落地生根）。判据运用 + 落地动作。

### 同类分组说明

产品组与 IT 组答同一组题，答案互为镜像。冰链 M3 温控箱（硬件 × 软件）与恒信合同审批系统（流程软件）是同一个概念的两面——三类需求、三个载体、承制方主导在两边都能验：恒信没有物理样机，但"原型、试点、正式产品"就是它的"原理样机、环境样机、产品"。这正是"需求的完整性"领域中立的证据。

## 二、题卡（打印分发）

**答题要求**：组内讨论 25 分钟 / 答案 ≤5 行 / 上台讲解 4–5 分钟 / 观点不同必须给理由。

### 第一组 · 概念与原理

**Q1｜产品需求要"全"，全在哪三类？**
"小林宣布：『原理样机验证通过，我们的产品成功了。』老陈反问：『你们管这些叫成功？定制芯片买不到、注塑做不出来、精度靠手工校准。』——产品需求要'全'，全在哪三类？把'需求写全了'当成'功能写全了'，错在哪？"

追问：① 三类各自缺一项，交付物停在什么等级（缺功能→连原理样机都算不上 / 缺环境→停在原理样机 / 缺可实现→停在环境样机）？② 每一类为什么必须"及其指标"——没有指标的需求退化成什么（愿望）？③ 你们最近一次需求评审，讨论的是"功能写全没写全"，还是"三类都全没全"？

**Q2｜三类、三载体、三主人，什么关系？**
"请给出 三类需求、三个验证载体、三个主人 的对应关系（一句话）。再把'承制方主导'放进整条链——它站在哪一环？"

追问：① 功能→原理样机、环境适应性→环境样机、可实现性→真正的产品——这个三对三是巧合还是因果（需求类别→验证条件→交付物）？② 三个主人各问什么（客户问"做不做得到"、环境问"守不守规矩"、承制方问"造不造得出、造不造得起"）？③ 可实现性需求为什么是"八项 + 三对齐"——实现方案和需求是什么关系（符合性解答）？④ 三类需求各自来自谁——哪一类最依赖组织长期自觉积累的资产（供应链/工艺/设备/人员约束跨产品持续存在）？

**Q3｜同一个特性，怎么会是两个类？**
"『测试性』为什么既出现在环境适应性需求里、又出现在可实现性需求里？同一个特性，怎么会是两个类？"

追问：① 分类的判据是特性的名字，还是"谁在问"？② 可测试性在"使用环境"下被问（在役可测、维修可达）和在"承制方生产交付"里被问（产线方便测、出厂可测），各指什么？③ "测试性就是测试性（特性名字只有一个）" vs "同一个特性两个主人（谁在问决定归类）"——两个都对，靠什么判据分清？④ 你们文档里有没有一条特性同时出现在两个"类"里？当时是按名字分的，还是按谁在问分的？

**Q4｜"一台好的原理样机"精确在哪？**
"老陈说：『原理样机验证通过，只能证明它是一台好的原理样机。』——这句话精确在哪？小林把'样机验证通过'当'产品成功'，做对了一件事、漏掉了一件事，分别是什么？为什么一个载体替不了另一个？"

追问：① 老周做对了什么（原理样机验证了温控 2℃±1℃ 的功能原理成立，这一关他过得漂亮）？② 漏掉了什么（环境适应性还没验——冷链车振动、温差、-20℃ 环境曲线还平不平；可实现性根本没写进需求清单——定制料断供、注塑结构做不出、手工校准没人会）？③ 为什么"一个载体替不了另一个"——三类需求的验证条件为什么互不相容（原理验要剥离环境、环境验要真实环境、量产验要量产经济性约束）？④ "样机验证通过（功能原理成立）" vs "产品成功（三类都全）"——两个都对，靠什么判据分清？⑤ 你们的产品/系统最近一次"验证通过"，验证的是哪一类需求？

**Q5｜需求的内容，到底谁说了算？**
"需求的内容到底谁定？'客户说了算'和'承制方说了算'——两个都对，怎么分？"

追问：① 来源方/主导方/确认方三角——各是谁、干什么（原料/加工/验收）？② 客户知道要什么，但不知道哪四件事（什么技术可能/行业横向视野/标准与环境/资产沉淀）？③ 承制方引导的边界在哪——"引导可以激进"和"确认不能缺席"为什么缺一不可？④ "需求成立由相关方确认（客户说了算）" vs "内容由承制方主导、需求全不全问责承制方（承制方说了算）"——两个都对，靠什么判据分清？⑤ 你们说"需求不够全"的时候，归给谁了——客户没提清楚，还是承制方没写全？

### 第二组 · 落地与实践

**Q6｜八条"不方便"，是谁没做好？**
"老陈会后列了八条'不方便'：定制芯片最小起订量五万片、注塑结构和壁厚做不出来、手工校准没人会、电源适配器没认证、固件没有远程升级通道、备件库里没有温控模块、电池按环保新规要回收、成本超预算 40%。小林说：『这是制造/采购/运维没做好。』老陈说：『这是需求当初没写。』——谁对？"

追问：① 八条"不方便"分别对应哪八条可实现性需求（可采购性/可制造性/可测试性/可交付性/可部署性/可运维性/可回收性/经济可承受性）？② "症状在量产（执行层确实难做、团队确实尽力）" vs "根子在需求起点（当初没写、八条全是缺位需求）"——两个都对，靠什么判据分清？③ 为什么团队会犯"相关方错位"——可实现性需求的相关方是谁（承制方），团队却只访谈谁（客户）？④ 你们最近一次"量产翻车/上线翻车"，症状是哪个"不方便"？当时的需求评审为什么没人提？

**Q7｜恒信的"样机"是什么？**
"恒信没有物理样机。Ada 发现公司里反复出现'系统上线后一堆问题'。恒信的'原理样机、环境样机、真正的产品'各对应什么？'原型跑通'为什么验证不了部署、运维、成本？"

追问：① 功能需求（合同要能发起、审批、归档）→ 原型；环境适应性需求（月末 500 并发、审计留痕、内网安全合规）→ 试点；可实现性需求（可部署/可运维/可升级/成本可承受）→ 正式投产。恒信大部分"上线翻车"翻的是哪一类？② 为什么"原型跑通"那天这些全都看不出来（部署文档缺失、运维没人接、升级要停机、运维成本是预算两倍）？③ "上线成功"和"产品成功"之间差了什么（上线只验证了功能，部署/运维/成本是可实现性的验证）？

**Q8｜经验丰富的团队，为什么也会漏？**
"老周说：『我们组织经验很丰富，老师傅多，问题都是口口相传的。』小林问：『那为什么下个产品还踩同一个可实现性的坑？』——经验丰富的团队，为什么也会漏掉可实现性需求？"

追问：① "组织经验丰富（隐性资产确实多）" vs "没有资产可提（没有制度化回路）"——两个都对，靠什么判据分清？② 四步闭环（问题/经验/建议 →转化→ 资产 →复用→ 新产品需求 → 产生新问题 → 回到起点）——关键在"转化"，"转化"指什么（问题被提炼成规范性需求条目，不是照抄）？③ 判断组织自不自觉只看哪一条（有没有制度化回路：问题→分析→转需求条目→入库→新产品复用→复盘更新）？④ 没有资产库的组织捕获不到可实现性需求，是谁的责任（承制方——无资产可提是组织知识管理缺位的必然结果）？

**Q9｜成本是设计出来的，还是需求？**
"成本超预算 40%。小林说：『成本是算出来的，设计完再核算。』老周说：『成本是需求，不是结果。』——成本到底是设计出来的，还是需求？"

追问：① "成本由选型、定工艺、定测试深度决定（设计确实决定成本）" vs "没有成本需求，设计没有依据和目标（需求先于设计）"——两个都对，靠什么判据分清？② 经济可承受性的相关方为什么是市场代表，不是财务、不是客户（基于竞品/替代产品的价格成本研究给出建议）？③ 为什么说控制成本的杠杆全是设计期决策（优先标准外购件/避免定制化外包/自研核心技术模块）——等发现贵了，什么已经冻结（架构和物料清单）？④ 你们设成本需求了吗？谁提的、有没有指标、经没经市场代表确认？没有的话，降本大会是不是每隔一段时间就开一次？

**Q10｜给你们的部门做一次需求完整性体检**
"结合你们部门现状，用七把尺子（三类全 / 专属验证载体 / 谁在问 / 承制方主导 / 八项三对齐 / 资产机制 / 逆向诊断）给最近一次产品/项目做一次需求完整性体检——给出最该改进的三个事项，每个落到一个动作。"

追问：先做哪把尺子？为什么？两周后回来报告什么？

## 三、点评要点·讲师版

> 点评纪律：先表态后翻案 / 反转精确不造新误解 / 判据配机制 / 归责到可对照动作 / 教机制不教断言 / 先立尺子再翻案 / 拉开强度层次 / 每个纠正落到可操作动作 / 单一权威不另立标准 / 网搜当佐证。

### Q1 产品需求要"全"，全在哪三类？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "样机都验证通过了，不是成功是什么？功能没问题就是需求没问题。" | 正是要翻的——把一类验证当三类、把功能清单当产品需求 |
| 中 | "需求要分功能、环境、可实现三类。" 结论对，三类内容/降级后果说不全 | 概念对，机制缺 |
| 好 | 需求要全 = 功能 + 环境适应性 + 可实现性三类 + 每类"及其指标" + 缺一类交付物降一级 + "需求写全了=功能写全了"是把产品需求当功能清单（最常见的伪全） | 定义 + 机制 + 判据全到位 |

**产品侧 vs IT侧**：产品组答"M3 温控箱需求全 = 温控功能全"；IT 组答"合同审批系统需求全 = 合同发起/审批/归档功能全"。同一个伪全：功能只占三分之一。

**反转话术**（对应概念卡片·三类需求 + 章末认知反转）：小林错了一半——原理样机验证通过，只证明温控功能成立。产品需求要全 = **功能 + 环境适应性 + 可实现性三类，每类"及其指标"**。缺功能连原理样机都算不上、缺环境停在原理样机、缺可实现停在环境样机。**"需求写全了 = 功能写全了"，是把"产品需求"当成"功能清单"——最常见的伪全。** 判断需求全不全，不要问"功能写全了吗"，要问"每一类需求，都能答出用什么交付物验证它吗"——答不上来的那一类，就是欠账。

**参考答案要点**：三类需求定义见 §1.1 表；"谁在问"判据见 §1.2；"及其指标"见 §1.3 + 概念卡片·三类需求。

### Q2 三类、三载体、三主人，什么关系？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "功能→样机、环境→环境样机、产品→真产品，一一对应。" | 三对三背对了，说不出为什么是因果、承制方放不进去 |
| 中 | "三对三 + 承制方是主导方。" 结构对，因果/八项三对齐/资产来源缺 | 关系对，机制缺 |
| 好 | 三对三是因果（需求类别→验证条件→交付物）+ 三主人各问一句话 + 可实现性=八项+三对齐（实现方案是符合性解答）+ 可实现性最依赖组织资产（约束跨产品是常量） | 关系 + 机制 + 来源全到位 |

**产品侧 vs IT侧**：两组都能套同一句三对三——冰链的"原理样机/环境样机/量产产品"与恒信的"原型/试点/正式产品"。内容不同，因果链纹丝不动。

**反转话术**（对应 §2.1 因果链 + §3.3 八项三对齐）：三对三不是巧合，是因果：**需求类别 → 决定验证条件 → 决定交付物形态。** 功能需求要剥离环境单独验原理→原理样机；环境适应性需求要上真实环境→环境样机；可实现性需求要在量产经济性约束下见真章→真正的产品。三个主人各问一句话：客户问"做不做得到"、环境问"守不守规矩活不活得下去"、承制方问"造不造得出造不造得起"。承制方主导站在"加工"这一环——**来源方提供原料、承制方主导加工、相关方执行验收**。可实现性需求八项与七个生命周期过程一一对应、第八项经济可承受性是总账，**实现方案是对可实现性需求的符合性解答**——一条需求缺了，对应方案和过程就没有依据。

**参考答案要点**：三对三同构见 §2.1；因果链见 §2.1 图；八项三对齐见 §3.3 表；三角见 §4.1；资产复用见 §5.1。

### Q3 同一个特性，怎么会是两个类？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "测试性就是测试性，按标准模板放一类就行。" | 正是要翻的——按特性名字分类，踩"谁在问"误区 |
| 中 | "同一个特性可以属于两类需求。" 结论对，说不出判据 | 概念对，判据缺 |
| 好 | 分类判据是"谁在问"不是特性名字 + 使用环境问（在役可测/维修可达）=环境适应性、承制方生产问（产线方便测/出厂可测）=可实现性 + 同一个特性两个主人两种归类 | 判据 + 机制 + 例证全到位 |

**产品侧 vs IT侧**：产品组答"M3 的测试性：冷链车在役检修可达 vs 产线出厂方便测"；IT 组答"合同系统的可维护性：审计留痕可查 vs 运维方便改"。同一个双主人。

**反转话术**（对应 §1.2 "谁在问"判据）：分类的判据不是特性的名字，是**"谁在问"**。可测试性在"使用环境"下被问——在役可测、维修可达，那是环境适应性需求；在"承制方生产交付"里被问——产线方便测、出厂可测，那是可实现性需求。**同一个特性，两个主人，两种归类。** 这条判据极其有用：它解释了为什么"测试性"会同时在两个类里出现，也给了你给需求分类的动作——**分不清的那条需求，往往是两类需求的混淆点，多半是"测试性/保障性"这类双主人特性。**

**参考答案要点**：谁在问判据见 §1.2；测试性两主人见 §1.2 例；实践（附录 E 练习 5）。

### Q4 "一台好的原理样机"精确在哪？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "老陈说得对，样机不算产品。" | 表态对，说不出"精确在哪"、为什么一个载体替不了另一个 |
| 中 | "样机只验证了功能需求。" 结论对，机制缺 | 判据用了一层，机制缺 |
| 好 | 老周做对了功能原理验证（温控 2℃±1℃）+ 漏掉环境适应性（冷链车振动/温差/-20℃）+ 可实现性根本没进需求清单 + 验证条件互不相容所以一个载体替不了另一个 | 机制 + 判据 + 案例全到位 |

**产品侧 vs IT侧**：产品组答"M3 原理样机过了、冷链车真跑没跑、量产能做吗"；IT 组答"恒信原型跑通了、月末 500 并发/审计留痕/运维一年跑没跑"。同一个专属载体。

**反转话术**（对应章末认知反转）：老陈的话精确在——**原理样机只验证功能需求**。小林做对了：原理样机验证了温控 2℃±1℃ 的功能原理成立，这一关他过得漂亮；漏掉了：环境适应性还没验（真上冷链车、温差振动、-20℃ 环境，曲线还平不平），可实现性根本没写进需求清单（定制料断供、注塑结构做不出、手工校准没人会）。**为什么一个载体替不了另一个？三类需求的验证条件互不相容**：验证原理对不对，环境干扰越少越好；验证真实环境下能不能活，必须上真实环境；验证能不能经济可重复地造出来，只能在量产约束下见真章。**可实现性需求只有真正的产品——量产、交付、运维跑过一遍——才能验证。** 所以"样机通过≠产品成功"不是谨慎，是需求的完整性在验收环节的必然结算。

**参考答案要点**：三对三因果链见 §2.1；逐级完备≠专属验证见 §2.2；样机通过错在哪见 §2.3 + 概念卡片·验证载体。

### Q5 需求的内容，到底谁说了算？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "客户出钱，客户说了算，承制方照做就行。" | 正是要翻的——把确认权当全部决策权 |
| 中 | "承制方主导需求开发，客户确认。" 结论对，三角/边界说不全 | 结论对，机制缺 |
| 好 | 来源方（原料）/主导方（加工）/确认方（验收）三角 + 客户不知道四件事 + 引导可以激进确认不能缺席 + 需求全不全问责承制方 | 机制 + 判据 + 归责全到位 |

**产品侧 vs IT侧**：产品组答"M3 客户（疾控/医院）要温控，但制造成本/法规标准承制方定"；IT 组答"恒信业务方要审批流，但月末并发/审计合规/部署运维承制方定"。同一个三角。

**反转话术**（对应概念卡片·承制方主导）："客户说了算"和"承制方说了算"都对，但各管一段：**需求成立由相关方确认（客户说了算）——终审权；内容由承制方主导（承制方说了算）——加工权。** 来源方提供原料、承制方主导加工、相关方执行验收。为什么承制方更专业？客户知道"要什么"，但不知道四件事：**什么技术可能、行业横向视野、标准与环境、资产沉淀**——而这四件事都是承制方强项。**引导可以激进，确认不能缺席。** 越界替相关方做决定，需求就失去"对需要或期望的规范性陈述"的本质，退化成承制方一厢情愿。更进一步：**需求全不全、明不明确、可不可度量，是承制方的责任，不是客户的。** 客户可以说"不知道自己要什么"，那是他的本分；承制方不能说"客户没提，所以需求不全"，那是失职。

**参考答案要点**：三角见 §4.1；承制方专业四因见 §4.2；引导边界见 §4.3 + 概念卡片·承制方主导。

### Q6 八条"不方便"，是谁没做好？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "八条'不方便'是制造/采购/运维没做好，要加强执行。" | 正是要翻的——把需求缺失当执行问题 |
| 中 | "是需求当初没写，八条对应八条可实现性需求。" 结论对，为什么错位说不全 | 判据用了一层，机制缺 |
| 好 | 八条→八条可实现性需求一一对应 + 症状不是执行问题是需求起点缺位 + 相关方错位（相关方是承制方、团队只访谈客户）+ 需求评审没人提因为提需求的人不在桌上 | 机制 + 判据 + 归责全到位 |

**产品侧 vs IT侧**：产品组答"M3 定制芯片/注塑/手工校准"；IT 组答"恒信部署文档缺失/运维没人接/升级要停机/运维成本两倍"。同一个"不方便=缺失需求"。

**反转话术**（对应案例进展① + §6.1 四错位 + §6.2 逆向诊断）：老陈对。这八条没有一条是"制造没做好"，全是**"需求当初没写"**。定制芯片=可采购性、注塑做不出=可制造性、手工校准=可测试性、无认证=可交付性、无远程升级=可部署性、备件库没有=可运维性、电池回收=可回收性、成本超40%=经济可承受性。**它们不是"量产时冒出来的问题"，是"从一开始就缺位的需求"。** 为什么团队会犯？四个结构性错位——相关方错位（可实现性需求的相关方是承制方，团队却只访谈客户）、时间错位（最晚最贵，短期评估显得"不重要"）、话语权错位（采购制造运维没有在需求阶段发声的机制）、认知错位（把可实现性当后续工艺的事）。**团队每抱怨一个"不方便"，就等于在供认一条当初没写的需求——诊断方向整个反过来：不是"执行要不要改进"，而是"需求起点全不全"。**

**参考答案要点**：案例进展①；四错位见 §6.1；逆向诊断见 §6.2。

### Q7 恒信的"样机"是什么？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "恒信没有样机，这个框架不适用。" | 正是要翻的——没看到镜照同构 |
| 中 | "原型/试点/正式产品对应三载体。" 对应对了，翻车翻在哪类说不清 | 对应对，机制缺 |
| 好 | 功能→原型、环境→试点、可实现→正式投产 + 恒信大部分上线翻车翻的是第三类（部署/运维/升级/成本）+ "原型跑通那天"全都看不出来 | 机制 + 判据 + 案例全到位 |

**产品侧 vs IT侧**：这一题本身就是 IT 侧镜照；产品组答"M3 量产翻车八条"，IT 组答"恒信上线翻车一堆问题"。同一个框架，两个世界，长一个样。

**反转话术**（对应案例进展②）：恒信没有物理样机，但同一个框架照样成立。**功能需求→原型**（先做原型把流程跑通）、**环境适应性需求→试点**（月末 500 并发、审计留痕、内网安全合规，只有真实业务环境才验证）、**可实现性需求→正式投产**（可部署、可运维、可升级、成本可承受，运维跑过一年才验证）。恒信大部分"上线翻车"，翻的不是功能，是第三类——部署文档缺失、运维没人接、升级要停机、一年运维成本是预算的两倍。**这些在"原型跑通"那天，都看不出来。** "上线成功"和"产品成功"之间差了什么？上线只验证了功能，部署/运维/成本是可实现性的验证。

### Q8 经验丰富的团队，为什么也会漏？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "经验多就是资产多，老师傅最懂，问题都能解决。" | 正是要翻的——把个人经验当组织资产 |
| 中 | "组织没把经验沉淀成需求资产。" 结论对，四步闭环/卡点说不全 | 结论对，机制缺 |
| 好 | 经验丰富（隐性）≠有资产可提（显性制度化）→ 没有制度化回路就捕获不到可实现性 + 四步闭环关键在"转化" + 判断自不自觉只看一条 + 责任在承制方 | 机制 + 判据 + 归责全到位 |

**产品侧 vs IT侧**：产品组答"M3 批量返工问题只写在老师傅脑子里"；IT 组答"恒信上线事故复盘完没人把'部署文档缺失'变成一条需求"。同一个"问题不转资产"。

**反转话术**（对应 §5.1~5.3 + 章末第二反转）：经验丰富和没有资产可提，两个都对。**组织经验丰富是隐性资产**（老师傅多、口口相传），**没有资产可提是显性缺口**（没有制度化回路）。四步闭环：问题/经验/建议 →**转化**→ 可实现性需求资产 →**复用**→ 新产品需求 → 产生新问题 → 回到起点。关键在"转化"——**问题被提炼成规范性需求条目，不是照抄**（冰链"装配返工率 30%"→"关键尺寸公差 ≥ X、装配间隙 ≥ Y"）。判断组织自不自觉只看一条：**有没有制度化回路——问题→分析→转成需求条目→入库→新产品复用→复盘更新。** 没有资产库的组织，天然捕获不到全面的可实现性需求——不是承制方代表不肯说，是组织根本没有可复用的资产可以拿来提需求。**"大部分团队都不考虑可实现性需求"不是一次需求访谈的疏漏，是组织知识管理缺位的必然结果。**

**参考答案要点**：可复用性最高见 §5.1；四步闭环见 §5.2；自觉的反面见 §5.3；无资产必然缺失见 §5.3。

### Q9 成本是设计出来的，还是需求？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "成本是算出来的，超了就开降本大会换供应商压工艺。" | 正是要翻的——把成本当结果，踩经济可承受性误区 |
| 中 | "成本是需求，要设成本目标。" 结论对，相关方/为什么是设计期决策说不全 | 结论对，机制缺 |
| 好 | 成本是需求分解分配分析的结果不是设计出来的 + 相关方是市场代表 + 控制杠杆全是设计期决策（等发现贵了架构物料已冻结）+ 降本大会=承认当初没写 | 机制 + 判据 + 归责全到位 |

**产品侧 vs IT侧**：产品组答"M3 目标成本/选型冻结后超预算"；IT 组答"恒信运维成本预算两倍、升级要停机"。同一个"成本是需求不是结果"。

**反转话术**（对应 §6.3 经济可承受性）：成本是需求，不是结果。**产品的成本是相关需求及其分解、分配、分析的结果，不是设计出来的。** 没有成本相关需求，设计就没有依据和目标——每次选型、定工艺、定测试深度，都没有预算约束可以对着优化，成本自由落体。为什么相关方是市场代表？成本需求是市场代表基于对竞品/替代产品的价格成本研究提出的，不是财务、不是客户；其他人负责承接和实现。为什么控制杠杆全是设计期决策？优先标准外购件、避免定制化外包、自研核心技术模块——**等发现贵了再开降本大会换供应商、压工艺，架构和物料清单已经冻结。每次降本动作，都等于承认经济可承受性需求当初就没写过。**

**参考答案要点**：经济可承受性三特殊见 §6.3；成本是需求见 §6.3.1；专属相关方见 §6.3.2；验证最晚见 §6.3.3。

## 四、知识卡片

### 一页图（书"本章概念总图"）

```
需求要全 = 功能需求（客户问·行为·IPO·四层展开）
         + 环境适应性需求（环境问·契约·"在X环境下必须Y"）
         + 可实现性需求（承制方问·八项·过程→需求→方案三对齐）
         每类"及其指标"

三个载体：功能→原理样机  环境适应性→环境样机  可实现性→真正的产品
         需求类别 → 验证条件 → 交付物（因果同构）

谁主导：承制方主导开发（更专业·引导范围）+ 相关方确认（不能缺席）
来源：客户/环境/市场（素材）+ 组织长期自觉积累的资产（经验·建议·问题→需求条目→复用）

缺失诊断：症状（不方便X·成本大）= 缺失的需求；四个错位（相关方/时间/话语权/认知）
```

### 金句（书"本章判据"提炼）

- **需求要全 = 功能 + 环境适应性 + 可实现性，每类"及其指标"——缺一类，交付物降一级。**
- **判断需求全不全，不要问"功能写全了吗"，要问"每一类需求，都能答出用什么交付物验证它吗"。**
- 功能需求客户会要，环境需求法规会要，可实现性需求——**只有你自己会要，所以你必须自己积累、自己写、自己守住。**
- 分类的判据不是特性的名字，是"谁在问"——**同一个特性，两个主人，两种归类。**
- **"样机验证通过≠产品成功"不是谨慎，是需求的完整性在验收环节的必然结算。**
- **内容由承制方主导，成立由相关方确认——引导可以激进，确认不能缺席。**
- **需求全不全、明不明确、可不可度量，是承制方的责任，不是客户的。**
- **成本是需求，不是结果——每次降本动作，都等于承认经济可承受性需求当初就没写过。**
- 没有资产库的组织，天然捕获不到全面的可实现性需求——**问题不转成资产，教训就永远是教训，而不是护城河。**
- **团队每抱怨一个"不方便X"，就等于在供认一条当初没写的需求。**

3. **回部门落地**：结合现状，用七把尺子（三类全 / 专属验证载体 / 谁在问 / 承制方主导 / 八项三对齐 / 资产机制 / 逆向诊断）给部门最近一次产品/项目做一次需求完整性体检——给出最该改进的三个事项，每个落到一个可检查动作。**两周后回来报告**：哪一项做成了、哪一项卡住了、卡在哪把尺子上。

### 作业指南（回部门落地的步骤 + 话术）

> 照着做，2 小时内完成一次体检：
>
> 1. **查三类全（尺1）**：拿一份需求文档，每条标"谁在问"（客户/环境/承制方）——三类各有多少条？缺哪一类？最近一次"翻车"翻的是哪一类？
> 2. **查指标（尺2）**：每类挑一条——"有指标吗"（功能：吞吐/响应/精度；环境：目标值/条件/单位；可实现：目标成本/公差/交期/服务周期）？没有指标的那类退化成愿望。
> 3. **查专属载体（尺3）**：每一类问"用什么交付物验证它"——答不上来的那类，就是欠账。
> 4. **查承制方主导（尺4）**：需求全不全、明不明确，问责对象是谁？访谈对象里有没有承制方各业务代表（采购/制造/测试/交付/部署/运维/市场）在需求阶段发声？
> 5. **查八项三对齐（尺5）**：八条可实现性需求（可采购性/可制造性/可测试性/可交付性/可部署性/可运维性/可回收性/经济可承受性），每条对应方案有没有？
> 6. **查资产机制（尺6）**：组织有没有制度化回路（问题→分析→转条目→入库→复用→复盘）？最近一次事故/问题，变成一条可复用的需求条目了吗？
> 7. **查逆向诊断（尺7）**：团队最近一次"不方便X"或"降本大会"，反推出哪条需求当初没写？补写了吗？
>
> 卡住时：找到第一个"否"就能开工，不必打完全部。产出三件最该改进事项（每条 = 一个可检查动作）。
