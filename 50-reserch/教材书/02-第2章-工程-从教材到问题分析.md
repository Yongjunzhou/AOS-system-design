## 第 1 步 · 读透章，定核心与重要内容

**章问题**：我们到底在做什么——你做的到底是工程、手艺、还是伪工程。

**① 一个定义（§1，定义性核心）**
> 工程 = 科学原理 × 判断创造，在约束下，用系统方法，造出有用且安全的东西
- 四要素：**料**（科学原理×判断创造）、**框**（约束）、**路**（系统方法）、**果**（有用安全）
- 最反直觉：**约束不是敌人，是定义的一部分、是舞台——约束越多判断价值越大**；去掉约束=不需要判断=不需要工程师
- 80 年四机构收敛（ECPD 1941 / ABET 1979 / INCOSE 2019 / IEEE 610.12）证明稳定内核；出处层级：IEEE 定义的是"软件工程"不是"工程"

**② 两把尺（判据1、2，操作核心）**
- **试金石**：换个团队、换个人，同样的需求和约束能交付同等质量——能=工程，不能=手艺；交接/招聘/复盘三场合使用
- **四层结构**：工程科学→方法论→工具实践→价值伦理，四层同时在场才算工程。缺层后果：抓瞎 / 人走方法走 / 悬空 / 事故；缺前三层不专业、缺价值层会出事；敏捷+CI/CD 只覆盖第二三层

**③ 四个分界（理解性核心）**
- **三维对立面**：认识论×科学（创造vs发现）、方法论×手艺（试金石）、目标×艺术（满足用户vs表达自我）——工程没有单一对立面
- **系统化≠机械化**：systematic 有章法 / systemic 有全局 / algorithmic 确定执行；系统化本质=可检查；工程化六方面（有结构/有方法/可重复/全覆盖/受控/可验证）
- **系统工程=元工程**：整合部件、不造部件、管"缝"（接口/数据口径/时序）；**涌现属性——部件全对≠系统对**；产出隐形（接口契约/集成方案/系统级验证方案）
- **工程系统⊃技术系统**：技术系统=设备集合；工程系统含人/流程/组织/信息；生命周期实现/使用/退役；机场例子

**④ 一个落点（判据6）**
- **工程师六能力**：四层各一项（①科学素养②方法论素养③实践能力④职业伦理）+⑤工程判断（横切）+⑥可复现意识（元能力）；老周缺②⑥、李工缺①④；**头衔不定义工程师**

**⑤ 一次整合（综合应用）**
- 给恒信做工程体检六项目：试金石测可复制 / 四层测完整 / 六方面测过程 / 三问测可检查 / 元工程测整合 / 工程系统测验收参照

**重要度分层**：
- 一级（定义+操作核心）：四要素（尤其约束）/ 试金石 / 四层（尤其价值层）
- 二级（重要分界）：系统化 / 系统工程+涌现 / 工程系统⊃技术系统
- 三级（落点）：工程师六能力 / 三维对立面 / 工程化六方面 / 三大事故

**六判据**：试金石 / 四层结构 / 系统化≠机械化 / 系统工程=元工程 / 工程系统⊃技术系统 / 工程师能力

**章末认知反转**：你可能没有在做工程，而你在做的那件事，可能比工程更难被复制——不靠流程多少定义，靠四层是否同时在场。

## 第 3 步 · 反推学员常识与误解

**总根源**：人信"看得见的近端"，工程的判据全在"看不见的远端"。四机制：
**①载体误判**（用什么做=是不是）｜**②结果误判**（做成了=做得好）｜**③范围误判**（看得见的局部=全部）｜**④定义缺席**（词汇病：用头衔/名词代替定义）。

**概念层误解（完整）**：

| 概念 | 学员常识（原话） | 误解点 | 机制 | 反转 |
|---|---|---|---|---|
| 工程 | "有流程、有工具、有测试=在做工程" | 把流程当判据 | ①★ | 四层同时在场才算，流程只占两层 |
| | "工程=写代码/画图纸" | 载体当判据 | ①·③ | 载体不是判据 |

## 第 5 步 · 定纠错策略

**强化点优先级（按消除误解的杠杆排序）**：

| 优先 | 强化点 | 反制哪些误解 | 练到何种程度 |
|---|---|---|---|
| ★1 | 试金石（判据 vs 载体） | 载体+结果+定义缺席（三机制） | 肌肉记忆：听到"我们工程化了"自动问"换人还能交付吗" |
| ★2 | 四层结构·价值层管着其他三层 | 范围（价值层=管理）+载体（流程=两层） | 脱口说出"四层哪层在场/缺位"；把伦理读成结构 |
| ★3 | 判断=在约束下取舍·约束是舞台 | 约束=敌人 + AI取代 + 可复现=极致（一条机制串3陷阱） | 能解释"无限预算不需要工程师"；识别砍约束=砍舞台 |
| ★4 | 可检查·机制证明 | 结果误判（最顽固） | 评审不接受"没出事"当证据，会问三查 |
| ★5 | 工程系统⊃技术系统 | 范围（系统=设备、上线=成功） | 验收条款按行为写 |
| ★6 | 涌现·缝 | 范围（部件对=系统对、集成=最后一步） | 能指出自己系统的缝，集成从第一天开始 |

**十条纠错红线**：
1. **先表态、后翻案**——跳过踩坑，翻案不疼、记不住（误解是"信了相反"，不是不知道）
2. **反转精确，别反转过头**——约束"不是敌人"≠"越多越好"（无意义约束=官僚）；手艺"不是贬义"≠"更好"（缺可复现）；流程"不是判据"≠"没用"（是可检查载体）
3. **判据配机制**——会背试金石≠会用，每个判据配"为什么"
4. **归责落到可对照动作，不指责事故**——"先上再说"与"合理化风险"是同一动作、不同规模
5. **教机制不教断言**——防换载体再踩（纠正敏捷≠工程后，遇到平台/AI 还会踩）
6. **先立尺子再翻案**——学员无定义可依，翻完更乱（第1章发尺子→第2章用尺子）
7. **拉开强度层次**——全标★★★=无★★★，留 3~4 个最重靶子下重手
8. **每个纠正落到可操作动作**——讲完价值层给三条、可检查给三问、机制证明给三查
9. **单一权威**——训练引书不另立标准（判据权威在书+ISO/IEEE）
10. **网搜当弹药不当铁证**——事实进题面、观点进讲师版

## 第 6 步 · 产落地工具（工作检查单）

**① 随身三问（贴墙版）**
1. 试金石——换个人、换团队，同样的需求和约束，能交付同等质量吗？能=工程，不能=手艺
2. 四层在场吗——工程科学（为什么）/方法论（怎么组织）/工具实践（怎么落地）/价值伦理（守不守底线），四层齐吗？**缺价值层=会出事**
3. 判断留人了吗——"怎么做"写成规则，"怎么选"是不是还在人身上？（约束会变，规则会失效）

**② 分场景检查单**

**场景 A · 动手前（需求与方案）**
- [ ] 列出全部关键约束（预算/工期/资源/法规/物理极限/性能红线）？——不是抱怨约束，是列约束清单
- [ ] 约束里哪个定义了我们的专业性？（砍掉=没有判断舞台）
- [ ] "为什么这样能行"有依据吗？（工程科学层，不是拍脑袋）
- [ ] 有没有把约束偷偷砍掉、且没让相关方知情？（悄悄牺牲预警）
- ⚠ 失败信号：开会只说"要上"不说"约束是什么"；出现"先上再说"

**场景 B · 执行中（开发/过程）**
- [ ] 每一步有明确输入/输出吗？
- [ ] 每一步有可检验的检查点吗？
- [ ] 换个人执行，结果还稳定吗？（可复现测试）
- [ ] 关键决策有记录吗？（改了什么/为什么/影响谁/怎么验证）
- [ ] 你手里"只有你会、没写下来"的手艺，开始显性化了吗？（写成规则/文档/可检验标准）
- ⚠ 失败信号：某步靠某个人记得；改完没测旧功能；三个月后没人记得为什么这么改

**场景 C · 集成与交付前（缝与机制）**
- [ ] 跨模块的"缝"有人负责吗？（接口契约/数据口径/时序依赖）
- [ ] 每个部件都对——系统级验证方案存在吗？（涌现预警）
- [ ] "没出事"之外有机制证据吗？（接口契约写没写 / 集成方案测没测 / 追溯记录有没有）
- [ ] 集成是从第一天就在做，不是最后一步？
- ⚠ 失败信号：两个模块对一个词两套定义；集成当天第一次对数据口径

**场景 D · 上线/验收时**
- [ ] 区分了"技术系统上线"和"工程系统被用起来"吗？
- [ ] 验收条款按行为写了吗？（电子签比例≥X% / 台账迁移 / 业务走线上，不是"服务器跑起来了"）
- [ ] 人/流程/组织/数据——"技术系统不管的部分"，谁在管？
- [ ] 生命周期考虑了吗？（纸质数据怎么迁入？退役数据怎么归档？）
- ⚠ 失败信号：上线=成功宣言；"没人用"只归因产品不好用、不查变革

**场景 E · 评审/变更时（价值层门禁）**
- [ ] 这个决定相关方知情吗？
- [ ] 有评审吗？——不是走过场，签字的人真的判断了吗？
- [ ] 有记录吗？（风险登记/决策记录/反对意见留档）
- [ ] 让位的是"可让的"，还是"安全红线"？
- ⚠ 失败信号：检查点退化成走流程；反对没有正式记录（挑战者号的教训）

**场景 F · 招人/交接/复盘时（试金石场合）**
- [ ] 交接：如果我走了，这套流程还能跑吗？——答不上来=手艺
- [ ] 招人：这个人带来的是"方法"还是"经验"？（方法可传播，经验只在本人）
- [ ] 复盘：这次交付能复现吗？——复现不了=一次性手艺成功
- [ ] 六能力都考了吗？——④职业伦理考了吗？不考=最致命项不测
- ⚠ 失败信号：招人只看经验丰富；交接只说"你问老王"

**③ 判据速查卡**

| 判据 | 检查动作 | 通过标准 |
|---|---|---|
| 试金石 | 换人测 | 换个人能同等交付 |
| 四层结构 | 逐层核对 | 四层同时在场，尤其价值层 |
| 系统化 ≠ 机械化 | 系统化三问 | 有输入输出 / 有检查点 / 换人稳定 |
| 系统工程 = 元工程 | 找缝 | 跨模块接口/口径/时序有人负责 |
| 工程系统 ⊃ 技术系统 | 查验收条款 | 按行为写，不按上线写 |
| 工程师六能力 | 对照人 | 头衔不算，六项能力才算 |

**④ 每周一检（周会 5 分钟版）**
1. 这周有没有"先上再说"？——有，就补评审+记录
2. 这周哪个"只有我会"的动作被我写下来了？——没有，就写一个
3. 这周上线/交付的东西"被用起来"了吗？——没有，问题在系统还是变革？

**使用注意**：分场景触发不一次填满；每个"否"是发现不是追责；反转不过头（约束≠越多越好、手艺≠更好）。

### 题卡全文（10 题 2×5，已写入单元二）

**第一组 · 概念与原理（概念层能定义辨析、原理层能解释为什么）**

**Q1（破题 · 见树见林① 概念本身 · 工程的定义）** 恒信 IT 部季度会：双周迭代、CI/CD 全绿、自动化测试覆盖 80%。李工宣布："各位，我们敏捷转型成功了。我们已经是工程化团队了。"Ada 只问了一句："那……上个月上线那次事故，是为什么？"李工说："那是人手不够，临时赶工，跟工程化没关系。"有人替李工辩护："有流程、有工具、有测试，这不就是工程吗？出了事故也不能说它不是。"**请先表态："有流程、有工具、有测试 = 工程"站得住吗？然后给出"工程"的一句话定义，并用你自己的定义判断：李工的团队离"工程"还差什么？** 追问：①你的定义里四要素各是什么？为什么"缺一不可"——"料/框/路/果"对应哪四个词？②"科学原理 × 判断创造"——为什么是"×"不是"+"？（缺一个，整体归零）③约束在定义里是"框"——"一个没有约束的创造不叫工程，叫发明或艺术"。为什么？④反身：你给的这个定义，本身可检验吗？——还是你只能"举例说明"？（第1章：懂 ≠ 能定义）

**Q2（见树见林② 概念关系 · 工程、方法论、手艺、科学、艺术）** 有人说："工程的对立面就是科学——科学是发现，工程是应用，工程是科学的下游。"也有人说："我们用了敏捷，敏捷就是工程。"还有人说："手艺是工程的低级阶段，工程成熟了手艺就消失了。"**请给出工程、方法论、手艺、科学、艺术这五个词的关系——谁包含谁、谁和谁对立、对立在哪。然后指出上面三句话各错在哪。** 追问：①为什么"工程没有单一对立面"？——认识论、方法论、目标三个维度各得到什么？②"手艺"是工程的对立面——那手艺和工程是二选一吗？（手艺的判断力正是工程的"料"；对立的是"可复现性"维度，不是"好坏"）③这张关系图，对"判断一个团队是不是工程"有什么用？（只看流程 = 只看了方法论维度）④李工把"方法论"当"工程"、老周把"手艺"当"工程"——各犯了关系图里哪个错？

**Q3（原理 · 约束是舞台 · 判断留人）** 有人说："工程就是要摆脱约束——预算放开、工期放开、安全红线去掉，工程不就好做了吗？"另有人说："把一切流程写成文档、做成算法，完全可复现、不靠任何人——这才是工程的极致。"**约束是工程的敌人，还是舞台？"完全可复现"是工程的极致，还是工程的反面？** 追问：①一个无限预算、无限时间、无限耐心的项目——还需要判断吗？不需要判断，还需要工程师吗？②老周把"哪种工况要降额"写成对照表之后，他自己还剩什么价值？（表覆盖不到的新工况、换了供应商时的重新判断）——所以"换个人也能交付"，交付的是方法，不是判断。判断为什么不能写全成规则？（判断 = 在约束下做取舍，约束一变规则就失效）③"可复现"和"判断留人"两个方向打架吗？唯一和解是什么？（方法复现 + 判断留人 + 错误可见）④落点：你们部门最近抱怨的"约束太多"里，哪一个约束其实定义了你们的专业性？（恒信"月末高峰"就是一个——它不是麻烦，是容量评估的判断舞台）

**Q4（原理 · 价值层一票否决 · 挑战者号）** 1986 年挑战者号航天飞机升空 73 秒爆炸，7 名宇航员遇难。原因：固体火箭助推器的 O 形密封圈在低温下失效。发射前工程师明确反对——有数据证明低温下 O 形圈会失效，前一年就有低温发射后 O 形圈烧蚀的记录；但管理者为了发射窗口和进度压力，把风险"合理化"了，发射照常进行。注意：发射有完整的检查流程，工程师的反对摆在台面上。有人说："事故说明技术还不够可靠——要是 O 形圈技术再成熟些，就不会出事。"**请先表态：这句话对吗？然后回答：有流程、有检查、有反对数据还出事，工程四层里缺的是哪一层？** 追问：①"把低温不发射写进发射检查清单"能避免吗？——能，没有技术门槛。那为什么没发生？（写不写、听不听，权力不在工程师那一层——价值层的决策权失效）②"技术不够"和"没守住"怎么区分？——三大事故（泰坦尼克/挑战者/737 MAX）共同点是什么？③为进度砍容量评估（"先上再说"）和"为了发射窗口合理化风险"——同一个动作吗？怎么用三条标准区分"客观原因"和"悄悄牺牲"？（知情/评审/记录）④挑战者号工程师的反对，没有留下任何正式记录——你们团队里，反对一个"先上再说"的决定，会不会留下记录？不会的话，缺的是什么？（自我指涉）

**Q5（原理 · 系统化 ≠ 机械化）** 有人说："系统化就是把流程固化成算法、让机器自动跑——自动化程度越高，系统越安全。"也有人说："系统化就是流程繁琐，加一堆审批。"**"系统化"、"系统性"、"算法化"三个词各回答什么问题？系统化的本质是"流程更多"、"机器自动"，还是"可检查"？** 追问：①systematic（有章法）vs systemic（有全局）vs algorithmic（确定执行）——工程每一步为什么必须留判断？（算法不需要判断）②自动化不是减少判断，是把判断提纯——机器接走执行，人接住的全是最难的判断。追问：一个全自动发布系统，人剩下的是"不用判断"，还是"判断密度最高"？③悖论：737 MAX 的 MCAS 自动接管控制、设计上系统优先级高于飞行员，两次坠毁飞行员都抢不回。**自动化消灭的是事故，还是人阻止事故的能力？** 追问：单向门两层——(a)权限层：系统优先于人，物理上抢不回；(b)能力层：长期不介入失去情境意识，就算给你手动接管，你也不知道怎么接。④系统化追求的是零错误，还是错误可见？（方向相反）——你们团队哪次事故，恰恰是"错误不可见"（没记录、没检查点）才走到出事的？

**第二组 · 落地与实践（判据运用 / 场景落地 / 回部门动作）**

**Q6（判据运用 · 恒信工程体检：四层 + 试金石 + 悄悄牺牲）** 恒信合同审批系统上个月月末高峰宕机 40 分钟：新接口没做容量评估，冲刺计划里排了，但"这个功能月底要上"就砍了——砍的时候没有评审、没有风险登记、没有签字。李工在站会上说了一句"先上再说"。事后李工说："那是人手不够，临时赶工，跟工程化没关系。"**用工程四层逐层给恒信做体检：科学原理、方法论、工具实践、价值伦理——各在场还是缺位？然后回答：上个月的事故，是"工程之外的意外"，还是"不是工程的证据"？** 追问：①"先上再说"发生在第几层？——怎么用三条可检验标准区分"人手不够"（客观原因）和"悄悄牺牲"（价值层失守）？（知情/评审/记录）②用试金石测恒信 CI/CD：靠张三三条隐藏命令、李四的环境变量——换三个人运维能一样跑吗？——这算"流程完备"还是"手艺换了载体"？③如果只准整改一条，先改哪条？为什么？（为"验收参照换被用起来"埋伏笔——判据5）

**Q7（判据运用 · 系统工程 = 元工程 · 涌现）** 恒信合同审批系统：法务模块、财务模块、业务模块各自都做得很好——每个模块都有测试、都通过验收、都符合各自的需求文档。集成上线那天出事了：法务说"合同状态"是"审批到哪一步"，财务说"合同状态"是"钱到没到账"——同一份合同、同一个词、两套定义；审批流跨部门还有断点没人管。有人说："每个部件都做对了，系统凭什么出问题？一定是某个部件没做好。"**请先表态：这句话对吗？然后回答：问题出在哪个"部件"身上，还是"部件与部件之间"？系统工程"造部件"吗？它管什么？** 追问：①"合同状态"一个词、两套定义——第1章管这个叫什么？（词汇病/同词异义——系统级重演）②系统工程不造部件，它的"产品"是什么？（接口契约/集成方案/系统级验证方案——隐形产出）为什么看不见摸不着的东西决定系统能不能转？③"没出事"够不够证明系统工程有用？（结果分不清运气和工程）——不靠结果，靠什么？（三查：接口契约写没写 / 集成方案测没测 / 追溯记录有没有）④你们系统的"缝"在哪？谁拥有它？（自我指涉）

**Q8（判据运用 · 工程系统 ⊃ 技术系统）** 恒信合同审批系统上线了：服务器跑起来了、模块全部上线。李工宣布："我们成功了。"可实际情况是：法务还是线下签、财务还是手工台账、业务还是走邮件。有人辩护："系统技术上完美，没人用是人的问题、变革的问题，不能算系统的失败。"**按"技术系统"看，它上线了；按"工程系统"看，它成功了吗？"被用起来"作为验收标准，怎么设可检验的验收条款？** 追问：①缺的是"设备"还是"人/流程/组织"？——工程系统的边界画在哪？（整个运行环境，不是设备的壳；机场例子）②"上线了没人用"是产品问题（不好用）还是变革问题（没推动）？——这个区分，工程系统能独立回答吗？它还需要什么？（治理视角，预告第11章）③上线是终点还是起点？——INCOSE 生命周期：实现/使用/退役。十年前的纸质台账怎么迁入？退役时数据怎么归档？（技术系统不会问、工程系统必须答）④验收条款怎么按行为写？（电子签比例≥X% / 台账迁移 / 业务走线上——不是"服务器跑起来了"）

**Q9（判据运用 · 工程师六能力 · 能力中性）** 老周（冰链）：十五年温控产品，判断全在脑子里，请两周假产线就停，回来十分钟找到问题。李工（恒信）：流程齐全、敏捷转型成功，却为进度砍了容量评估、出事归咎"人手不够"。**直觉上谁更配得上"工程师"？先选边，不许犹豫。然后：六项能力里，老周缺哪两项？李工缺哪两项？** 追问：①"经验丰富"是能力，"可复现"是什么？（个人能力 vs 组织能力）②能力是中性的吗？——一个①③⑤顶配、④为零的工程师，是"更强"还是"更危险"？恒信"加急"功能那次：开发写一半发现审批流状态机要加状态，顺手改了状态机，没测旧审批流——上线后普通审批全卡住。他能"顺手改"，说明能力不差；没评估影响就改，说明④缺席。这样一个"最能干"的人，把系统搞挂是更快还是更慢？737 MAX 里缺的是"会算的工程师"，还是"守住底线的工程师"？③六项能力里，招聘几乎从不考哪一项？——为什么偏偏是最致命的那项不被测？④让老周和李工"合体"，第一步做什么？（老周的判断写成可检验规则 + 给李工设价值层检查点）

**Q10（落地生根 · 回部门工程体检）** 恒信工程体检六项全部不合格：试金石测可复制——不合格（CI/CD 靠隐藏命令）；四层测完整——缺两层，尤其价值层；六方面测过程——缺三个；三问测可检查——只完成一半；元工程测整合——缺位（数据口径对不齐）；工程系统测验收参照——用错（拿"上线"当"成功"）。**用同样的尺子，给你们部门最近交付的一个系统做一次体检。然后给出你们部门最应该改进的三个事项——每个事项落到一个可操作动作（一条判据/一个检查项/一句话），并说明为什么是这三件。**（提示：大多数团队体检完六项也全不合格，却觉得"我们没什么大问题"——先诚实面对体检结果，再谈改进。）
