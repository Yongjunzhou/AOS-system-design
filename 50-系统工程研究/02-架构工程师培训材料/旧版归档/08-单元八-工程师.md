## 一、单元导读

### 主题

"谁算工程师？"——**头衔、证书、年限都不定义工程师，六项能力才定义**。工程师是把四层结构背在身上的人：四层各一项能力（①科学素养②方法论素养③实践能力④职业伦理）+ 横切的工程判断（⑤）+ 元的可复现意识（⑥）。**能力不是中性的，④职业伦理定义能力的方向**——①③⑤顶配、④为零 = 有能力的坏工程师，破坏比"不会做"的人大得多。这一章不讲怎么当工程师的技术（第2章讲过工程四层），它讲的是**一个物种的解剖学**：它由什么构成（六项能力清单）、和谁像但不一样（角色边界）、怎么长出来（成长路径）、怎么死掉（失败模式）——最后给两条案例线里做工程工作的人落定判词。

### 开场破题（对应章首误解现场）

念出第8章那场招聘：

**恒信 IT 部招"高级工程师"**，Ada 面试三人。候选人甲是算法高手，笔试满分，口答流畅："会写代码的，不就是工程师吗？"候选人乙带着软考高级证书："有职称、有证书，还不算工程师？"候选人丙干了二十年："干了这么多年，经验还不够吗？"Ada 问了三个人同一个问题：**"换个人，用同样的需求，交付的东西能和你质量相当吗？"** 三个人都沉默了。旁听席上的李工，名片印着"高级工程师"，忽然意识到这个问题自己这些年也没答上来过。

让各组表态：三句话各错在哪？"工程师"到底该怎么定义？——"会写代码"和"会判断"、"有证书"和"有能力"、"干得久"和"干得对"，之间各差了什么？

### 本单元要反转的直觉

- **会写代码的人就是工程师**（× 写代码是载体不是判据；工程师判断在规则留白处）
- **有职称 / 有证书的人就是工程师**（× 证书只证明考过一次试；头衔不定义工程师）
- **干了二十年一定是好工程师**（× 二十年可能都在用手艺的壳子；可复现才是工程）
- **工程师就是照着流程做的人**（× 那是技术员；工程师在流程没覆盖的地方判断）
- **能力强就是好工程师，能力越强越可靠**（× 能力不中性，④定义方向；①③⑤顶配④为零=更危险）
- **工程师只要技术好，伦理是管理者的事**（× ④职业伦理是六项之一，缺了会出事）
- **拿到工程师头衔，就是工程师了，一辈子都是**（× 头衔是入场券；能力一项项亮起来才是成为）
- **工程师的判断不需要换个人也接得住**（× ⑥可复现意识，判断要被接住）

### 本轮题卡的内在逻辑（10 题 2×5）

**第一组 · 概念与原理（先立概念）**：Q1 工程师是什么（概念本身·破题·招聘三句话）→ Q2 工程师 × 四个相邻角色 + 六项能力的横切/元（概念关系）→ Q3 技术 vs 四层能力（真悖论）→ Q4 头衔证书年限 vs 能力（真悖论）→ Q5 能力强 vs 能力强且好·④定义方向（真悖论）。由"是什么"走到"为什么"。

**第二组 · 落地与实践（用尺量）**：Q6 老周判词（手艺极致缺②⑥·真悖论·案例进展①）→ Q7 李工判词（伪工程缺①④⑥·真悖论·案例进展②）→ Q8 失败四式·哪种最危险（判据运用）→ Q9 成长的标志·为可靠性说不（判据运用）→ Q10 回部门"工程师体检"（落地生根）。判据运用 + 落地动作。

### 同类分组说明

产品组与 IT 组答同一组题，答案互为镜像——而这一章的镜像，就是两条案例线的判词本身：**老周没头衔、手艺极致**（产品侧：十五年心里有数，判断换个人做不出来——①③⑤顶配缺②⑥），**李工有头衔、伪工程**（IT 侧：敏捷 CI/CD 方法论工具都在，容量评估被砍、为进度牺牲可靠性——有②③缺①④⑥）。六项清单是同一份，两种世界各缺各的项——**这正是"工程师是个怎样的物种"跨世界成立：头衔不定义工程师，清单一项项亮起来才算。**

## 二、题卡（打印分发）

**答题要求**：组内讨论 25 分钟 / 答案 ≤5 行 / 上台讲解 4–5 分钟 / 观点不同必须给理由。

### 第一组 · 概念与原理

**Q1｜这一章要回答什么问题？"工程师"到底是什么？**
"恒信 IT 部招'高级工程师'，Ada 面试三人。候选人甲是算法高手，笔试满分，口答流畅：'会写代码的，不就是工程师吗？'候选人乙带着软考高级证书：'有职称、有证书，还不算工程师？'候选人丙干了二十年：'干了这么多年，经验还不够吗？'Ada 问了三个人同一个问题：'换个人，用同样的需求，交付的东西能和你质量相当吗？'三个人都沉默了。旁听席上的李工，名片印着'高级工程师'，忽然意识到这个问题自己这些年也没答上来过。——这一章要回答什么问题？'工程师'到底是什么？"

追问：① 反直觉命题：头衔、证书、年限都不定义工程师——六项能力才定义？② 底座：工程师是把四层结构背在身上的人——四层各一项能力（①科学素养②方法论素养③实践能力④职业伦理）+ 横切判断（⑤）+ 元可复现（⑥）？③ 判据：Ada 那句"换个人能交付吗"问的是六项里的哪一项（⑥可复现意识）？④ 反身：你们公司名片上印着"工程师"的人，答得上这个问题吗？你呢？

**Q2｜工程师和技术员、科学家、手艺人、会写代码的人是什么关系？六项能力里哪一项是横切、哪一项是元？**
"请给出 工程师 与 技术员、科学家、手艺人、会写代码的人 的关系，再说明六项能力清单里哪一项是横切、哪一项是元能力。为什么说'判断落在人身上是工程师，交给规则是技术员'？"

追问：① 角色边界：技术员照单执行 / 科学家求真 / 手艺人依赖个人 / 会写代码只是载体——工程师在规则留白处判断、创造未存在的世界、可复现？② 试金石落点：第2章试金石在这里变成"如果你不在，交付还能不能维持"——能是工程师、不能是手艺人？③ ⑤横切 / ⑥元：工程判断横切四层（冲突里怎么选）、可复现意识是元能力（判断要被接住）——为什么这两个是工程师区别于"会做工程的人"的地方？④ 反身：你们团队那位"最牛的人"，是工程师还是手艺人？

**Q3｜工程师到底先立技术，还是先立四层能力？**
"有人问 Ada：'工程师到底该先学什么？'Ada 说：'第2章立过四层结构——工程科学、方法论、工具实践、价值伦理。工程师就是把这四层背在身上的人。'对方：'可我招人只看技术——算法、框架、架构，技术不过关凭什么叫工程师？'——工程师到底先立技术，还是先立四层能力？"

追问：① 底座原理：工程师 = 四层各一项能力 + 横切判断 + 元可复现——缺一项人就不完整？② 叠加原理：能力的自然顺序 = 先实践（③）→ 再科学（①）→ 再判断（⑤）→ 再可复现（⑥）→ 最后伦理（④）？③ 真悖论收束："工程师要技术过硬（实践能力③ + 工程判断⑤是底子——不会做一切免谈）" vs "工程师要把四层都背在身上（工程科学①给原理、职业伦理④定方向、可复现⑥给交接——只技术强缺了①④，换个上下文就错、压力下会出事）"——两个都对，靠什么判据分清？④ 反身：你们部门招"工程师"，考的是哪一项？缺的那项后来出过事吗？

**Q4｜头衔 / 证书 / 年限，到底算不算数？**
"李工有'高级工程师'头衔、有软考证书、干了十五年。他说：'我头衔、证书、年限都齐了，不是工程师是什么？'Ada 问：'头衔给你判断吗？证书给你原理吗？年限给你底线吗？'——头衔 / 证书 / 年限，到底算不算数？"

追问：① 名义原理：头衔是组织发的位置、证书是考过一次试、年资是时间的累积——都不给能力，可检验的在六项清单上？② 入场券：被任命 / 有证书只是入场券，能不能坐稳靠能力清单？③ 真悖论收束："有头衔有证书有年限就是工程师（组织认证 + 社会背书 + 时间检验——三个都齐了还要怎样）" vs "头衔证书年限都不定义工程师（位置/考试/时间都不给能力——判断悬空、原理没有、底线欠账，一样不是工程师）"——两个都对，靠什么判据分清？④ 反身：你们最近一次"评工程师 / 发头衔"，给的是什么——给头衔，还是给能力清单？

**Q5｜能力越强，是不是越值得信赖？**
"恒信那次'加急'功能，开发'写一半顺手改了审批状态机'——能'顺手改'说明能力不差，没评估影响就改，上线后普通审批全卡住。Ada 说：'能力不是中性的。'——能力越强，是不是越值得信赖？"

追问：① 能力不中性原理：能力放大的是'选择的规模'，方向由④职业伦理定义——①③⑤顶配、④为零 = 有能力的坏工程师，破坏比'不会做'的人大得多？② 737 MAX：不缺'会算的工程师'，缺'守住底线的工程师'——判断越准、方向错破坏越大？③ 真悖论收束："能力强 = 好工程师（技术最牛、判断最准、交付最稳——能力强就是值得信赖，能力本身就是价值）" vs "能力强 ≠ 好工程师（能力不中性，④定义方向——能力越强、④越缺越危险；守不住底线，能力是破坏的放大器）"——两个都对，靠什么判据分清？④ 反身：你们团队那位"最能干"的人，④的账还清了吗？

### 第二组 · 落地与实践

**Q6｜老周到底是不是工程师？**
"冰链的老周，十五年温控产品，车间里没有一份完整的测试方案，但他'心里有数'——哪个批次容易出问题、哪种工况要降额、哪家供应商不可靠，全在脑子里。按六项能力清单：老周①科学素养顶配、③实践能力顶配、⑤工程判断顶配，但缺②方法论素养（方法说不成体系）、缺⑥可复现意识（判断换个人做不出来）。——老周到底是不是工程师？"

追问：① 判词①：老周是①③⑤顶配、缺②⑥——手艺的极致，不是工程师的画像？② 可复现原理：他的手艺是最值钱的资产，但厉害不可复制——试金石一测就倒？③ 真悖论收束："老周判断全顶配，当然是最牛的工程师（①③⑤全会、每个取舍都准——能力这么强不是工程师是什么）" vs "老周缺②⑥——方法不成体系、判断不可复制（手艺依赖个人，你在质量在、你走质量走；工程师要的是换个人也能交付）"——两个都对，靠什么判据分清？④ 反身：你们团队有没有一个"老周"——能力顶配但判断换个人做不出来？

**Q7｜李工团队到底是不是工程师？**
"恒信的李工，团队上了敏捷、CI/CD、测试，方法论和工具都在。但按六项能力清单：他有②方法论素养、③实践能力，缺①科学素养（容量评估被砍，他不追问'为什么能行'）、缺④职业伦理（为进度悄悄牺牲可靠性，没让任何人知情）；更致命的是 CI/CD 依赖张三的隐藏命令、李四的环境变量，⑥可复现同样站不住。——李工团队到底是不是工程师？"

追问：① 判词②：李工团队是有②③、缺①④⑥——方法论和工具都在，四层却站不稳？② 底座原理：工程四层缺两层（工程科学 / 价值伦理）——"有组织的赌博"？③ 真悖论收束："李工团队有流程有测试有敏捷，工程化做得很成功（方法论和工具都在，这还不是工程）" vs "李工团队缺①④⑥——容量评估被砍不追问为什么、为进度悄悄牺牲可靠性、CI/CD 依赖隐藏命令（四层缺两层，'先上再说'是价值层失守）"——两个都对，靠什么判据分清？④ 反身：你们团队的 CI/CD 依赖谁？换个人能跑起来吗？

**Q8｜四种死法里，哪一宗最危险？**
"四种死法摆在面前：只会做不会说——活干得漂亮但判断全在心里，他一休假产线就停转；只会说不做——方法论讲得头头是道但落不了地，听他讲完还是不知道怎么做；守不住底线——为进度悄悄牺牲可靠性，没有评审没有记录没有人知道；能力失控——会算能做判断准，只差守住底线。Ada 问李工：'你离哪一宗最近？'——四种死法里，哪一宗最危险？"

追问：① 失败原理：只会做死于说不清（⑥缺席）、只会说死于做不了（③缺席）、守不住死于没底线（④缺席）、能力失控死于方向偏（④方向）——每种都能在六项清单找到缺的那一项？② 守不住底线为什么最普遍：症状不是"不会做"而是"做的时候没守住"——三大事故的共同点？③ 能力失控为什么最危险：他看起来最优秀——能力不中性、④定义方向？④ 反身：你或你的团队最近一次技术决策，更接近四宗死法的哪一宗？缺的是清单里的哪一项？

**Q9｜为什么成长的标志是第一次为可靠性说不？**
"'这个功能月底要上，容量评估下次再补'——说不，是工程师。'先上再说，反正没人查'——说不，是工程师。Ada 说：'第一次在压力面前护住底线，是你真正成为工程师的那一天。'——为什么成长的标志不是学会新技术，而是第一次为可靠性说不？"

追问：① 说不原理：工程师第一次真正长成，是学会对一件'做了也没人反对'的事说不——而那个'不'的第一个对象是自己的冲动？② 成长原理：判断的依据从'怎么做'升级到'守什么'（照做→会选→会取舍→守底线）——你关心的问题换了，物种就变了？③ 判据运用：用六项体检（尤其④伦理 + ⑤判断）检验一次真实决策——你最近一次'先上再说'，过得了知情/评审/记录三判据吗？④ 反身：你最近一次'说不'，拦下的是别人，还是自己？

**Q10｜给部门最像工程师的人（或自己）做一次"工程师体检"**
"结合你们部门现状，用六项能力体检（①科学素养②方法论素养③实践能力④职业伦理⑤工程判断⑥可复现意识）给'你们部门最像工程师的人'（或你自己）做一次体检——逐项打勾、指出缺项、判断在补哪一项，再给最该改进的三个事项，每个落到一个可检查动作。"

追问：先做哪一项？为什么？两周后回来报告什么？

## 三、点评要点·讲师版

> 点评纪律：先表态后翻案 / 反转精确不造新误解 / 判据配机制 / 归责到可对照动作 / 教机制不教断言 / 先立尺子再翻案 / 拉开强度层次 / 每个纠正落到可操作动作 / 单一权威不另立标准 / 网搜当佐证。

### Q1 这一章要回答什么问题？"工程师"到底是什么？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "工程师就是会写代码、技术好的人。" | 正是要翻的——把"会写代码/技术好"当工程师 |
| 中 | "工程师是懂技术、有经验的开发。" | 结论对，六项清单/能力不中性说不清 |
| 好 | 反直觉命题（头衔、证书、年限都不定义工程师）+ 底座六项（①~⑥一项不能少）+ 判据（"换个人能交付吗"=⑥可复现意识） | 命题 + 清单 + 判据全到位 |

**产品侧 vs IT侧**：产品组答"老周没有头衔但判断全顶配——①③⑤全会，可他缺⑥，换个人做不出来"；IT 组答"李工有头衔但答不上'换个人能交付吗'——三句话把工程师说成了载体/证书/年资"。同一个"头衔不定义工程师"。

**反转话术**（对应章首误解现场 + §1.1 + 判据）：三句话，三个"工程师"——这是第1章那场"架构"吵架的重演，只是这次被误解的是每个干活的人自己。候选人甲"会写代码"——**把载体当成了判据**（写代码是工程师的载体，不是工程师的判据）；候选人乙"有证书"——**把头衔当成了能力**（证书只证明考过一次试）；候选人丙"干了二十年"——**把年资当成了能力**（二十年可能都在用手艺的壳子）。Ada 那句"换个人能交付吗"问的是六项里的**⑥可复现意识**——判断要被别人接住。它们不是三个错答案，是同一个定义缺席的三个侧面：**定义在自己身上的，都不稳；定义在能力上的，才稳。**

**参考答案要点**：反直觉命题见 §1.1；六项能力清单见 §1.2；⑤⑥展开见 §1.3/§1.4；判据 1~6。

### Q2 工程师和技术员、科学家、手艺人、会写代码的人是什么关系？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "工程师就是懂技术的高级程序员。" | 正是要翻的——把工程师混进"会写代码的人" |
| 中 | "工程师和科学家、手艺人都不一样。" | 结论对，具体边界/横切元说不清 |
| 好 | 角色边界四组（技术员照单执行/科学家求真/手艺人依赖个人/会写代码只是载体）+ ⑤横切（工程判断）+ ⑥元（可复现意识）+ 试金石落点（"你不在交付还能维持吗"） | 边界 + 横切/元 + 试金石全到位 |

**产品侧 vs IT侧**：产品组答"老周=手艺人（判断顶配但依赖个人，试金石一测就倒）"；IT 组答"李工团队=会写代码的人（方法论工具都在，但缺①④⑥——判断不追问为什么、底线守不住）"。同一个"载体不是判据"。

**反转话术**：技术员照单执行、工程师在规则留白处判断——这是第一对边界。科学家研究现存世界、工程师创造未存在的世界——这是第二对。手艺人靠个人、工程师可复现——这是第三对，也是试金石落点："如果你不在，交付还能不能维持？能，你是工程师；不能，你是手艺人——哪怕你也会写代码、画图纸。"会写代码的人——**载体人人都可以拥有，判据不是人人都有**：把"会写代码"当成"工程师"，就像把"会用刀"当成"厨师"——刀人人会用，火候不是人人有。

**参考答案要点**：角色边界见 §3.1~3.4；⑤横切 §1.3；⑥元 §1.4；试金石见第2章 §2.2。

### Q3 工程师到底先立技术，还是先立四层能力？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "当然先立技术，技术不过关别的都是空谈。" | 正是要翻的——只认③实践，漏了①④⑥ |
| 中 | "技术和能力都要。" | 结论对，为什么（叠加顺序/缺项后果）说不清 |
| 好 | 底座原理（四层各一项能力，缺一项人不完整）+ 叠加原理（先实践③→再科学①→再判断⑤→再可复现⑥→最后伦理④）+ 真悖论收束（判据=能力叠加顺序与缺项后果） | 原理 + 顺序 + 收束全到位 |

**产品侧 vs IT侧**：产品组答"老周技术最强（③⑤顶配），但缺②⑥——技术强不等于工程师"；IT 组答"李工技术也强，缺①④——技术强不等于工程师"。同一个"底座缺一块，人就不完整"。

**反转话术**：技术（③实践能力）当然是底子——不会做一切免谈。但工程师不是"技术最强的人"，是"四层都背在身上的人"：①科学素养给原理（为什么能行）、②方法论素养给体系（换个人能学会）、③实践能力给落地（有想法落得了地）、④职业伦理给方向（压力下守得住）、⑤工程判断给取舍（规则留白处怎么选）、⑥可复现给交接（判断要被接住）。能力的叠加顺序决定了：先实践、再科学、再判断、再可复现、最后伦理——**为什么④放在最后？因为它最贵——它约束的不是"你会不会做"，而是"你做的方向"。判断越准、能力越强，方向错了破坏越大。**

**参考答案要点**：底座原理 §1.1~1.2；叠加原理 §4.2；判据 1~6。

### Q4 头衔 / 证书 / 年限，到底算不算数？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "头衔证书年限都齐了，肯定算。" | 正是要翻的——把名义当能力 |
| 中 | "头衔证书不完全算，还要看能力。" | 结论对，为什么（名义原理）说不清 |
| 好 | 名义原理（头衔=位置/证书=一次考试/年限=时间累积，都不给能力）+ 入场券（被任命/有证书只是入场券，坐稳靠清单）+ 真悖论收束（判据=六项清单可检验） | 名义 + 入场券 + 收束全到位 |

**产品侧 vs IT侧**：产品组答"老周没头衔（名片印着硬件工程师），但判断顶配——头衔不定义工程师"；IT 组答"李工有头衔有证书干了十五年，答不上'换个人能交付吗'——名义齐了不等于能力齐了"。同一个"名义不给能力"。

**反转话术**：头衔是组织发的位置——可以印上、也可以收走；证书是社会给的认证——只证明通过了一次考试；年资是时间的累积——干了二十年可能二十年都在用手艺的壳子。三个"名义"，都不给能力。**真正的工程师，不是名片上印着"工程师"三个字的人，而是换个人也能交付、关键时刻守得住底线的那个人。** 判断一个人是不是工程师，可检验的不在名片上，在六项能力清单上。

**参考答案要点**：名义原理 §2.2；判据 1~6。

### Q5 能力越强，是不是越值得信赖？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "能力越强当然越值得信赖，能力强就是好。" | 正是要翻的——把能力强当好，漏了④ |
| 中 | "能力强但要靠谱。" | 结论对，为什么（能力不中性/④定义方向）说不清 |
| 好 | 能力不中性原理（能力放大选择的规模，④定义方向）+ 有能力的坏工程师（①③⑤顶配④为零破坏更大）+ 737 MAX（不缺会算的工程师，缺守住底线的工程师）+ 真悖论收束（判据=④职业伦理） | 原理 + 案例 + 收束全到位 |

**产品侧 vs IT侧**：产品组答"老周能力顶配（①③⑤），但④的账还清了吗？——能力不是中性的"；IT 组答"李工团队'先上再说'——为进度悄悄牺牲可靠性，④缺席"。同一个"④定义能力的方向"。

**反转话术**：六项能力不是中性的——**能力放大的是"选择的规模"，而选择的方向由④职业伦理定义**。一个①③⑤顶配、④却为零的人，破坏比"不会做"的人大得多：他会算、能做、判断准，只差守住底线。737 MAX 里不缺"会算的工程师"，缺的是"守住底线的工程师"。恒信"加急"功能那次，开发"写一半顺手改审批状态机"——能"顺手改"说明能力不差，没评估影响就改，说明④缺席。**能力不是中性的，④定义能力的方向——头衔不定义工程师，能力也不单独定义工程师。**

**参考答案要点**：能力不中性原理 §2.1；判据 4。

| 中 | "老周技术好但有点特殊。" | 结论对，缺哪两项说不清 |

**产品侧 vs IT侧**：产品组答"老周就是'我心里有数'的人——判断全在脑子里，换个人做不出来，⑥缺"；IT 组答"老周像我们组那个'最牛但不可复制'的人——他一休假产线就停转"。同一个"手艺依赖个人"。

**参考答案要点**：判词② §6 案例进展②；底座原理 §1.1；判据 1/4/6。

### Q8 四种死法里，哪一宗最危险？

| 答案分级 | 形态 | 讲师判读 |
|---|---|---|
| 弱 | "只会做的老师傅最可惜。" | 定性偏差——四种都对应清单缺项 |
| 中 | "守不住底线最普遍。" | 结论对，为什么（能力失控最危险）说不清 |

**产品侧 vs IT侧**：产品组答"老周近'只会做'——⑥缺"；IT 组答"李工近'守不住底线'——④缺；加急那次是'能力失控'——能顺手改没评估影响"。同一个"每种死法缺清单一项"。

**反转话术**：四宗死法，四种姿态——**只会做死于说不清（⑥缺席），只会说死于做不了（③缺席），守不住死于没底线（④缺席），能力失控死于方向偏（④方向）。** 守不住底线最普遍，因为它的症状不是"不会做"而是"做的时候没守住"——泰坦尼克按"不会沉"配救生艇、挑战者在工程师反对声中升空、737 MAX 在认证压力下轻描淡写，共同点：不是不会做，是守不住。能力失控最危险，因为他看起来最优秀——**能力不是中性的，④定义方向：能力越强、④越缺，越危险。**

**参考答案要点**：失败原理 §5.1~5.4；能力不中性原理 §2.1；判据 4/5/6。

### Q9 为什么成长的标志是第一次为可靠性说不？

**金句**（书"本章判据"提炼）：

> **工程师不是一个头衔，不是一沓证书，不是一年的经验。它是把四层结构背在身上、关键时刻守得住底线的人。**

六项能力体检（工程师的六把尺子，逐项自问）：
1. **科学素养**：我做的东西，凭什么能行？换个上下文还成立吗？
2. **方法论素养**：我的方法能被别人学会吗？还是只有我会？
3. **实践能力**：我最近一次亲手落地，是什么时候？
4. **职业伦理**：压力面前，我会不会为进度悄悄牺牲可靠性？有没有让相关方知情？
5. **工程判断**：规则没有覆盖的地方，我能做对的取舍吗？
6. **可复现意识**：我的判断换个人能接住吗？我把它写成规则、文档、标准了吗？

## 五、课后作业

1. **书练习 2 题（与题卡同源）**：
   - 用六项能力，给"你们公司最像工程师的人"做一次体检——逐项打勾，指出缺项，判断他走在哪条路上。
   - 在你们团队里，找一个"被当成工程师、其实是技术员/手艺人/会写代码的人"的例子，说出他缺的是哪一项。
2. **回部门落地**：用作业指南，给"部门最像工程师的人"（或自己）做一次"工程师体检"，两周后回来报告。

**作业指南：给部门最像工程师的人（或自己）做一次"工程师体检"**

> 目标：用六项能力体检（六把尺子）给"部门最像工程师的人"（或你自己）做一次角色体检——逐项打勾、指出缺项、判断在补哪一项，产出三件可执行改进。

1. **科学素养（尺1）**：问一句"你做的东西，凭什么能行？换个上下文还成立吗？"答得出 = 有原理；答不出 = 只会套模板。产出：原理一句话 + 与同事答案对比。
2. **方法论素养（尺2）**：把他的方法写成文档，换个人能照做吗？产出：方法可复现性判定（工程 or 手艺）。
3. **实践能力（尺3）**：最近一次亲手落地是什么时候？产出：落地间隔记录（长期不碰 = 有想法落不了地）。
4. **职业伦理（尺4）**：压力面前有没有为进度悄悄牺牲可靠性？相关方知情吗？产出：知情/评审/记录三判据自检。
5. **工程判断（尺5）**：规则没覆盖的地方，能做出取舍吗？有记录吗？产出：一次取舍的依据 + 记录。
6. **可复现意识（尺6）**：判断换个人能接住吗？写成规则、文档、标准了吗？产出：可复现文档份数（没有 = 手艺型）。

**卡住怎么判断**：任一尺子打不出勾，就是该尺子说的缺口——不用全打完，找到第一个"否"就能开工。产出三件最该改进事项（每条 = 一个可检查动作）+ 一句判定（缺的是哪一项）。

**工作检查单**（配套素材）：

| 检查项 | 是/否 | 否 → 可讨论发现 |
|---|---|---|
| 一句话定义得出"工程师"吗（把四层背在身上 + 六项能力）？ | □ | 只说得出"会写代码" → 载体当判据，定义缺席 |
| 六项能力每项都能说出"我缺了会怎样"吗？ | □ | 有项说不清 → 能力清单有缺口 |
| 最近一次亲手落地是什么时候？ | □ | 长期不碰 → 实践能力悬空，③缺席 |
| 规则没覆盖的地方，我判断了吗？还是等别人？ | □ | 照单执行 → 那是技术员，⑤缺席 |
| 压力面前有没有为进度悄悄牺牲可靠性？相关方知情吗？ | □ | 悄悄牺牲 → ④职业伦理欠账（能力不中性） |
| 判断换个人能接住吗？写成文档了吗？ | □ | 只有我会 → ⑥可复现意识缺失，手艺型 |
| 我是在用能力，还是在被能力定义方向？ | □ | 能力强、方向偏 → 有能力的坏工程师 |
| 最近一次取舍，是"怎么做"还是"守什么"在主导？ | □ | 只在怎么做 → 成长还没换尺度 |
