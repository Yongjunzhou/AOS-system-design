## AI读取文档说明

本文件是业务方案（bpd-biz）架构类树形资产文档。AI 读取本文件时应按需读取，不应默认读取全部正文。

默认读取顺序：

1. 读取文档元信息和本说明，确认文档用途、状态和读取规则。
2. 读取 `0. 业务方案树画像`，建立业务域、产品路径和节点规模感知。
3. 读取 `1. 业务方案状态与处理队列`，确定本轮 bpd-biz 节点、活动锁、待资产写回队列和当前待办 ID。
4. 读取 `2. 业务方案节点索引 / 分片索引`，定位目标 bpd-biz 正文块、候选宿主块和必要追溯关系。
5. 仅读取目标 bpd-biz 正文块、来源 02 业务概要 块、相关资产候选块和本轮反馈区。

扩大读取范围仅在以下情况允许：

- bpd-biz 节点索引缺失或块 ID 无法定位。
- 与 `02` 业务概要 来源或 `23/24/25/27/28` 资产引用关系断裂。
- 业务路径存在边界冲突、业务定义冲突或资产归属争议。
- 需要执行全局一致性检查或批量迁移。
- 人类明确要求通读全文。

禁止事项：

- 不得在常规 `biz02`（wft02-biz）运行中默认全量读取正文节点块。
- 不得将旧版正文、废弃节点或未确认资产建议作为当前 bpd-biz 正式资产参与判断。
- 不得只凭对话上下文推进状态；人类反馈必须先写入节点反馈区、状态队列或转交记录。

## 3. 规则区 / 口径区

### 3.1 bpd-biz 节点口径

bpd-biz = **业务流程方案节点**（业务流程的完整态，= 02 概要 + 叶）。一个 bpd-biz 对应一个场景业务（同产品路径 + 用户角色归组），与 02 的 bph-biz 场景 1:1（见 biz02 §3.2）。每节点含**双视角**——A2（SL3~SL5 角色场景装配 + 表单使用顺序）与 Bn（逐输出文档方案 + 叶定义），两视角经"输出文档→功能表单"交汇（对② 实现）。旧 A1/A2/Bn 路径类型与 IPO 层级口径退役（L5=输出文档，见 91 §11）。

### 3.2 schema 单源与判据落点

- **schema 单源**：04 结构与节点类型 = [91 规范 §11](../../10-wfsysdev-4-eos/91-eos-biz-eng-spec.md#11-产品文档结构读写及反馈) + 本文件 + 02（来源）自身；人类方案只引用（93 §4.1）。
- **结构/领域判据**（正式/轻量、封面 DocumentCover、PL6-B 三独立、引擎权威校验）引 91 §二；**对齐判据之家 = 91 §5.3.1 + 23**（引用数据）；**覆盖检查** = "02 承接语义 ⊆ 04 叶定义之并"（20 号 §4.5 本对实例，biz02 §5.2）。
- 引擎权威值**落在 04**（biz01 候选 `[推断]` → 本任务确认/修正/推翻），对② 消费以此为准。
