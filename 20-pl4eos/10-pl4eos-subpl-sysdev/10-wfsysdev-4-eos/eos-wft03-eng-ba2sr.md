# BA(A1) → SR-F · 引擎操作页面设计
**Skill ID**: wft03-eng-ba2sr

> **概述**：接收 A1 配置单元 BA，经前置校验、材料加载和反馈处理后，将 CU 配置能力定义展开为引擎操作页面 SR-F。该 SR-F 以“操作页面”为末级节点，定义配置人员或运行支撑人员在页面上完成哪些操作、页面之间如何组织成功能架构、页面操作活动如何触发引擎处理，并将需要 PA 阶段决定的组件、接口、存储和运行机制标注为 PA 层收敛项。
>
> **输入 → 输出**：A1 BA 节点（`可以SR设计` / `待补充SR设计`）/ 有反馈的 SR-F 节点 → 操作页面 SR-F（页面清单 + 页面类型 + 操作页面组件 + 页面功能架构 + 操作活动 + PA 层收敛项）+ BA 推进为 `已SR设计` + SR-F 推进为 `待产品架构`
>
> **适用场景**：瀑布式系统设计第3步 · 平台能力系统设计路径。
>
> **设计模式参考**：[91-eos-biz-eng-spec.md](91-eos-biz-eng-spec.md)
>
> **版本**：v4.2 | **修订**：2026-07-08

## 一、职责定位

### 1.1 本 Skill 目的与目标

> **主要目的**：取信于平台开发人员——「这个 CU 应该有哪些操作页面，用户在页面上如何配置、发布、查看和触发引擎能力」。把 A1 BA 的 CU 配置能力定义转化为可进入 PA 的操作页面系统需求，不设计前后端组件。

**目标**：

1. **为 CU 推断操作页面**——基于 CU 的配置入口、配置要素、系统处理和运行期能力，确定配置页面、管理页面、运行支撑页面、治理追溯页面和必要弹窗。
2. **基于操作页面生成功能架构**——将页面按 TAB、主子关系、跳转、依赖、上下文传递、权限和状态组织成页面功能架构。
3. **为操作页面推断操作活动**——定义页面上的操作活动、入口构件、前置条件、系统处理摘要、结果状态、校验规则和异常分支。
4. **保留 CU 追溯**——每个操作页面必须追溯到来源 BA、来源 CU、CU 配置能力定义和运行期能力。
5. **传递 PA 收敛项**——将组件边界、接口契约、数据存储、运行期装载、状态处理等需要 PA 决策的事项标注为 `PA层收敛`。

本 Skill 负责：

1. **接收**——校验 BA 状态、A1 类型、CU 配置能力定义完整性、依赖链和运行期能力；缺失时退回 wft02-eng。
2. **匹配**——按 `引擎 + CU + 页面职责 + 操作活动` 匹配已有 SR-F 操作页面，判定复用、扩展或新建。
3. **页面推断**——从 CU 配置能力定义推断操作页面清单、页面类型、操作页面组件和页面职责。
4. **功能架构生成**——组织页面的 TAB、主子、跳转、上下文、状态依赖和权限依赖。
5. **操作活动设计**——定义页面操作活动、触发条件、结果状态、校验规则、异常分支和 PA 收敛项。
6. **覆盖自查**——检查每个 CU 的配置入口、配置要素、系统处理和运行期能力均被操作页面承接。
7. **推进**——人类确认后 SR-F → `待产品架构`，BA → `已SR设计`。
8. **回修**——接收 wft05-eng 退回的 `需wft03修订` SR-F，按缺失说明和人类改进方案修订；根因在 BA 时退回 wft02-eng。

本 Skill 不负责：

1. CU 配置能力定义、CU 拆分/合并和依赖链重切（→ `wft02-eng`）。
2. 业务功能表单和业务场景页面设计（→ `wft03-biz`）。
3. 前端/后端组件划分、接口详细规格、数据存储结构和实现机制（→ `wft05-eng`）。
4. NFR 量化；本 Skill 只保留需要 wft05-eng 消费的 NFR 约束引用。
5. 运行期业务页面本体编排；本 Skill 只说明 CU 运行期能力在操作页面组件/构件上的支撑关系。

### 1.2 与上下游的衔接

**上游 wft02-eng**：产出 A1 BA，包含 CU 配置能力定义、依赖链、触发追溯和变更声明。本 Skill 不重新拆 CU，只把每个 CU 的配置与运行能力翻译成操作页面需求。

**下游 wft05-eng**：消费 `待产品架构` 的操作页面 SR-F，基于操作页面、操作活动、操作页面组件/构件、NFR 和 PA 收敛项推断前端/后端组件。若 wft05-eng 发现页面职责缺失、操作活动不闭合、构件支撑不明或 PA 收敛项缺失，将 SR-F 退回为 `需wft03修订`。

## 二、操作页面 SR-F 设计基础

> 本章定义 wft03-eng 的操作对象：操作页面、页面类型、页面功能架构、操作活动、覆盖自查和 PA 层收敛项。操作页面组件与构件定义见 [91 规范 §三](91-eos-biz-eng-spec.md#三-操作页面组件与构件)，eng 路径分工见 [91 规范 §7.3](91-eos-biz-eng-spec.md#73-系统需求开发wft03-eng)。操作流程见 §三。

### 2.1 操作页面

操作页面是配置人员或运行支撑人员直接使用的页面单元，用来维护 CU 配置、触发引擎处理、查看发布/运行结果或处理异常。它不同于业务人员使用的业务功能表单；业务运行页面本体由 biz 路径设计，eng 路径只设计引擎能力所需的配置与支撑页面。

操作页面分为五类：

| 页面类别 | 用途 | 典型来源 |
|----------|------|----------|
| 配置维护页 | 维护 CU 配置要素 | 配置入口、配置要素 |
| 配置管理页 | 管理配置版本、状态、引用关系 | 系统处理、治理依赖 |
| 发布生效页 | 校验、发布、装载、回滚、停用 | 系统处理 |
| 运行支撑页 | 查看运行期能力、刷新、重试、处理异常 | 运行期能力 |
| 治理追溯页 | 审计、影响范围、引用关系、操作日志 | 横切治理依赖 |

### 2.2 页面类型与操作页面组件

页面类型与操作页面组件是两个正交维度，不能互相替代：

| 维度 | 来源 | 回答的问题 | 进入 SR-F 的字段 |
|------|------|------------|------------------|
| 页面类型 | 91 规范 §1.2 | 这个操作页面整体采用什么页面组织形态 | `页面类型` |
| 操作页面组件 | 91 规范 §3.1 | 页面内部由哪些平台页面组件承载内容和交互 | `操作页面组件清单` |

页面类型沿用 91 规范 §1.2 的六种页面类型：

| 页面类型 | eng 侧典型用途 | 候选操作页面组件 |
|----------|----------------|------------------|
| 单窗列表+辅助栏 | 配置项列表、发布记录、版本记录 | 列表页面 + 辅助栏 |
| 单窗树表+辅助栏 | 菜单树、流程节点树、权限树 | 列表页面（树表） + 辅助栏 |
| 单窗单据页 | 单个配置对象编辑 | 单据页 |
| 左窗主表+右窗子表+辅助栏 | 主配置 + 子规则/子节点 | 多级横版 + 列表/单据 + 辅助栏 |
| 全屏单据页 | 复杂设计器或大篇幅配置 | 单据页 / 多级横版 |
| 弹窗 | 选择、确认、局部参数编辑 | 弹窗页 |

上表中的“候选操作页面组件”只是提示，不能作为固定映射。每个 SR-F 必须单独给出操作页面组件清单，可选范围包括：

| 操作页面组件 | 典型用途 |
|--------------|----------|
| 多级横版 | 多层级配置对象、主从配置、流程/规则设计器 |
| 列表页面 | 配置对象集合、发布记录、版本记录、执行记录 |
| 单据页 | 单个配置对象编辑、参数维护、规则详情 |
| 辅助栏 | 详情预览、上下文摘要、引用关系、校验结果 |
| 弹窗页 | 选择、确认、局部参数编辑、冲突处理 |
| 指标页面 | 运行状态、质量指标、发布影响、异常趋势 |

### 2.3 页面功能架构

页面功能架构回答：一个 CU 或一组强依赖 CU 的操作页面如何组合使用。

要素：

- 页面清单与页面类型
- 操作页面组件与构件清单
- TAB 顺序或导航关系
- 主子页面关系
- 页面间跳转和上下文传递
- 权限、状态、版本和发布依赖
- 与来源 CU、配置能力要素的对应关系

### 2.4 操作活动

操作活动是用户在操作页面上执行的可验证动作。

每个操作活动至少包含：

| 字段 | 说明 |
|------|------|
| 活动名称 | 如新建配置、校验配置、发布配置 |
| 操作入口 | 按钮、右键、快捷键、双击、自动触发 |
| 所属页面 / 构件 | 页面 ID 和入口构件 |
| 前置条件 | 状态、权限、版本、依赖 |
| 用户动作 | 用户做什么 |
| 系统处理摘要 | 系统校验、保存、发布、装载、记录等 |
| 结果状态 | 页面状态、配置状态或运行期状态 |
| 校验规则 | 必填、唯一、依赖、权限、冲突等 |
| 异常处理 | 失败提示、回滚、重试、人工处理 |
| PA 层收敛项 | 组件/接口/存储/运行机制待 PA 决策项 |

### 2.5 CU 配置能力到操作页面的映射

| CU 配置能力要素 | 页面/活动映射 |
|----------------|---------------|
| 配置入口 | 配置维护页、配置列表、配置详情、选择弹窗 |
| 配置要素 | 字段/规则编辑区、关系维护区、辅助栏详情、选择器 |
| 系统处理 | 校验、保存、发布、装载、回滚、停用、异常处理活动，以及执行记录页 |
| 运行期能力 | 能力预览页、运行支撑页、结果查看页、异常处理页；业务运行页面本体仍由 biz 路径承接 |

### 2.6 PA 层收敛项

本 Skill 不设计组件，但必须把 wft05-eng 需要决策的事项显式传递。

| 收敛项 | 示例 | 标注 |
|--------|------|------|
| 组件边界 | 发布按钮构件是否复用公共构件 | `PA层收敛-组件边界` |
| 接口契约 | 发布动作调用同步接口还是异步任务 | `PA层收敛-接口` |
| 数据存储 | 配置版本、发布记录、审计记录的存储归属 | `PA层收敛-存储` |
| 运行机制 | 装载、缓存刷新、回滚、重试、补偿 | `PA层收敛-运行机制` |
| NFR 承接 | 性能、安全、审计、可观测性如何落组件 | `PA层收敛-NFR` |

### 2.7 覆盖自查

| 检查项 | 判据 |
|--------|------|
| CU 覆盖 | 每个非占位 CU 均有操作页面承接 |
| 配置入口覆盖 | 每类配置入口都有页面承接 |
| 配置要素覆盖 | 关键配置要素有录入、维护或选择方式 |
| 系统处理覆盖 | 校验、保存、发布、装载、回滚、异常等处理有操作活动或明确不适用理由 |
| 运行期能力覆盖 | 运行期制品、构件或功能有查看、预览、触发、支撑说明或 biz 页面承接说明 |
| 构件线索覆盖 | 页面操作入口能映射到按钮、右键、快捷键、图表、钻取等构件线索 |
| 追溯覆盖 | 页面 → CU → BA → STR-E 追溯完整 |
| PA 收敛 | 组件、接口、存储、运行机制、NFR 待定项均标注 |

### 2.8 节点生命周期与变更传播

生命周期引用 [91 规范 §8.6](91-eos-biz-eng-spec.md#86-节点生命周期模型)。本 Skill 状态映射：

| 通用态 | SR-F 状态 |
|--------|-----------|
| 待确认方案 | `待确认方案` |

变更传播引用 [91 规范 §8.7](91-eos-biz-eng-spec.md#87-变更传播协议)。wft03-eng 的变更影响判定：

### 3.4 Step 3 · 操作页面设计

#### Phase A · 页面候选生成

对每个非占位 CU：

1. 从配置入口生成配置维护页候选。
2. 从配置要素生成配置详情、子配置页或选择弹窗候选。
3. 从系统处理生成发布生效页、执行记录页或异常处理页候选。
4. 从运行期能力生成运行支撑页、能力预览页或结果查看页候选。
5. 从治理依赖生成版本、审计、影响范围等治理追溯页候选。

#### Phase B · 页面类型判定

按页面内容选择 91 规范六类页面类型：

| 判定条件 | 页面类型 |
|----------|----------|
| 多条配置对象维护 | 单窗列表+辅助栏 |
| 层级对象维护 | 单窗树表+辅助栏 |
| 单个配置对象编辑 | 单窗单据页 |
| 主配置与子规则强相关 | 左窗主表+右窗子表+辅助栏 |
| 复杂设计器、大篇幅配置 | 全屏单据页 |
| 临时选择、确认、局部编辑 | 弹窗 |

#### Phase C · 操作页面组件判定

在页面类型判定之后，独立判断页面内部需要哪些操作页面组件：

| 判定条件 | 操作页面组件 |
|----------|--------------|
| 需要展示对象集合、版本记录或执行记录 | 列表页面 |
| 需要编辑单个配置对象或参数组 | 单据页 |
| 需要并列展示多层主从对象 | 多级横版 |
| 需要上下文、详情、校验结果或引用关系 | 辅助栏 |
| 需要临时选择、确认、局部参数或冲突处理 | 弹窗页 |
| 需要展示运行指标、发布影响或异常趋势 | 指标页面 |

#### Phase D · 匹配已有 SR-F

按 `引擎 + CU + 页面类别 + 页面职责` 匹配：

| 结果 | 动作 |
|------|------|
| 复用 | 追加 BA/CU 来源 |
| 扩展 | 全量重写该页面 SR-F，保留历史引用 |
| 新建 | 新建操作页面 SR-F |
| 冲突 | 标记 `[需裁决]` |

页面 SR-F 要素：

- 页面 ID / 名称 / 页面类别 / 页面类型 / 使用角色
- 来源 BA / 来源 CU / CU 配置能力引用
- 页面职责
- 操作页面组件与构件线索
- 页面字段或配置对象摘要
- 页面操作活动清单
- 权限、状态、版本、发布约束
- PA 层收敛项
- 确认状态

### 3.5 Step 4 · 功能架构与操作活动

#### 3.5.1 页面功能架构

生成：

1. 页面 TAB / 导航顺序。
2. 主子页面关系。
3. 页面间跳转和上下文传递。
4. 权限、状态、版本、发布依赖。
5. 页面与 CU、配置能力要素、运行期能力的追溯矩阵。

#### 3.5.2 操作活动设计

活动类型：

| 活动类型 | 典型动作 |
|----------|----------|
| 配置维护 | 新建、编辑、复制、删除、导入、导出 |
| 校验处理 | 校验、预览、冲突检查、依赖检查 |
| 发布生效 | 保存、提交、发布、装载、回滚、停用 |
| 运行支撑 | 查看生效结果、刷新缓存、重试、异常处理 |
| 治理追溯 | 查看版本、审计、引用关系、影响范围 |

每个操作活动写入：活动名称、入口构件、所属页面、前置条件、用户动作、系统处理摘要、结果状态、校验规则、异常处理、PA 层收敛项。

#### 3.5.3 PA 层收敛项标注

为每个活动检查是否存在：

- 组件边界待定
- 接口契约待定
- 数据存储待定
- 运行机制待定
- NFR 承接待定

存在则写入 `PA层收敛-*` 标记，供 wft05-eng 消费。

### 3.6 Step 5 · 覆盖自查与变更声明

执行 §2.7 覆盖自查。发现缺口时：

| 缺口 | 处理 |
|------|------|
| 配置入口或配置要素未覆盖 | 补充页面或退回 wft02-eng |
| 系统处理未覆盖 | 补充操作活动或标注 PA 收敛 |
| 运行期能力未覆盖 | 补充运行支撑页面或说明由 biz 页面承接 |
| 构件线索缺失 | 补充按钮/右键/快捷键/图表/钻取等线索 |
| PA 必收敛项缺失 | 补充收敛项，不推进到可消费 |

每次新建或修订 SR-F 后写入变更影响声明；首版写“首版，无变更”。

### 3.7 Step 6 · 资产写回与落账

仅对已确认 SR-F 执行：

1. `05`：SR-F → `待产品架构`。
2. `04`：对应 BA → `已SR设计`，记录消费版本。
3. `25`：写入操作页面能力引用或待办，不固化组件设计。

资产写回与 wft05-eng 消费并行推进，写回完成与否不改变 SR-F 的可消费状态。

### 3.8 Step End · 运行结束输出

遵循 [91 规范 §8.8](91-eos-biz-eng-spec.md#88-skill-通用约定) 的三区模板。

```text
当前状态：<待确认方案 / 待产品架构>
  SR-F：新增/修订操作页面 <N> 个；操作活动 <N> 条；PA 层收敛项 <N> 条；待裁决 <N> 项。

一、方案反馈
  A. 整体确认 -> 回复「整体确认」，快捷同意全部未标注条目
  B. 局部修改 -> 在确认状态中标注 [修改]：...
  C. 驳回重做 -> 在确认状态中标注 [驳回]：...

二、下一步
  本Skill -> 存在未处理反馈 / 需wft03修订 / 新 BA 时重入
  后续    -> SR-F 状态为 待产品架构 后进入 wft05-eng
```
