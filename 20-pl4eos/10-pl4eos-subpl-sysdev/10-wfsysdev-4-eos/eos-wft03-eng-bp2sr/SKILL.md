### Step 3 · 功能概要设计

#### Phase A — 页面候选生成与宿主匹配

逐非占位 CU 按操作活动定义（配置入口 + 配置信息组操作活动定义）生成五类功能表单候选，然后按 `引擎+CU+页面类别+页面职责` 匹配已有 SR-F：

| 条件 | 路由 |
|------|------|
| 页面类别+职责落入已有 SR-F | 归入 → Phase B |
| 不满足 | 待聚合池 → Phase C |
| 页面职责冲突或同一 CU 被多个功能表单争用 | `[需裁决]` |

#### Phase B — 修订已有 SR-F

1. **要素提取**——从本轮配置信息组操作活动定义提取页面职责、页面编排线索和操作活动候选
2. **宿主匹配检查**——复用→追加来源；扩展→全量重写保留历史；冲突→`[需裁决]`
3. **重判定与关系检测**——基于全部 CU 重判页面类别与页面编排概要，比对基线判定五类关系：

| 关系 | 判定 | 处理 |
|------|------|------|
| 确认 | 页面匹配+类别一致+来源升级 | 追加 BP/CU 来源 |
| 无新增 | 页面匹配+全部已确认 | 增量合并细节 |
| 页面职责扩展 | 类别一致+操作活动清单/页面编排边界扩展 | 全量重写，保留历史 |
| 补充 | 页面不匹配 | 新增功能表单 SR-F |
| 过时 | 基线页面未被本轮覆盖 | `[过时]`+保留不删 |

4. **变更影响声明**——判定变更类型，写入 SR-F 末尾

#### Phase C — 新建 SR-F

1. **确定页面类型与类别**——页面类型固定为功能表单；按配置职责判定五类之一
2. **定义页面职责**——页面类别 + 用途 + 配置对象 + 使用角色（承接自 BP A2 上下文）
3. **定义承载关系**——来源 CU + 承载配置信息组清单
4. **承接操作活动清单**——逐活动标注承接 02 的标注入口（附录 A.5），不重复步骤
5. **组装 SR-F**——写入 `05-*.md`

### Step 4 · 页面编排与操作活动清单

**1. 页面编排概要**——区域/TAB/弹窗入口、页面间跳转与上下文传递、权限/状态/版本/发布依赖、追溯矩阵（功能表单→配置信息组→CU→操作活动定义）。组织的正是 CU 集成操作活动（CU 操作活动 = 配置信息组操作活动集成）。布局组件/构件下移 wft04-eng。

**2. 操作活动清单承接**——承接配置信息组操作活动标注操作活动清单（配置操作→配置维护、系统处理→校验/发布生效、运行期能力→运行支撑）。五类活动（附录 A.5），每活动标注承接 02 入口、不重复步骤，全量 `[推断]`。

**3. 要素机械检查**——区域/TAB/弹窗入口已定义、权限/状态/版本/发布依赖已标注、追溯矩阵完整、操作活动清单已承接（标注承接 02 入口）、所有非占位 CU 均被功能表单承接。

## 附录A：判据速查

### A.1 功能表单五类别

| 页面类别 | 用途 | 典型来源 |
|----------|------|----------|
| 配置维护页 | 维护 CU 配置要素 | 配置入口、配置操作 |
| 配置管理页 | 管理配置版本、状态、引用关系 | 系统处理、治理依赖 |
| 发布生效页 | 校验、发布、装载、回滚、停用 | 系统处理 |
| 运行支撑页 | 查看运行期能力、刷新、重试、异常 | 运行期能力 |
| 治理追溯页 | 审计、影响范围、引用关系、操作日志 | 横切治理依赖 |

> 功能表单清单含两类：配置类（来自 CU 配置入口）+ 运行类（来自运行期能力操作页面：办理单据页/待办清单/征集待办/待阅清单）。粒度=子页面即完整页面；流程设计器等=编排容器。

### A.2 页面类型/类别二维正交

| 维度 | 本 Skill 取值 | 来源 |
|------|-------------|------|
| 页面类型 | 固定为 `功能表单` | 91 规范 §1.2 |
| 页面类别 | 五类之一 | 91 规范 §8.3 |
| 页面编排概要 | 区域/TAB/弹窗入口 | 本 Skill 定义 |

> 布局组件/构件判定下移 wft04-eng（本 Skill 只到区域/TAB/弹窗入口级别）。

### A.3 页面类别判定

| 判定条件 | 页面类别 |
|----------|----------|
| 多条配置对象或版本记录维护 | 配置维护/管理页 |
| 层级对象维护 | 配置维护页 |
| 单个配置对象编辑 | 配置维护页 |
