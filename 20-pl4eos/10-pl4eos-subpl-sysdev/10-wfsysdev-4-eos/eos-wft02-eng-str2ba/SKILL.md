## 一、职责定位

### 负责与不负责

| 负责 | 不负责（路由指向） |

### Step 3 · A1/CU BA 设计

#### Phase A — STR-E 宿主匹配

逐 STR-E 按目标引擎+能力域匹配已有 BA：

| 条件 | 路由 |
|------|------|
| 同一目标引擎 + 能力域一致或互补，落入已有 BA 的 A1 路径 | 归入该 BA → Phase B |
| 不满足 | 进入待聚合池 → Phase C |
| 同一 CU 被多个主引擎争用或 A1 路径不一致 | 标记 `[需裁决]` |
| CU 属于依赖的共享 STR-E | 不进入本 BA（共享能力独立建模，消费方只记录依赖） |

待聚合池按**同一目标引擎 + 同一能力域**分组。

#### Phase B — 修订已有 BA

1. **要素提取**——从本轮 STR-E 增量合并 A2 上下文和 CU 候选。已有上下文仅追加不重建
2. **宿主匹配检查**——Q1 直接归入→追加来源；Q2 扩展归入→扩展 BA+变更声明；冲突→`[需裁决]`（详见 human spec §2.4.3）
3. **CU 收敛与关系检测**——执行七种收敛判定 + 六种关系检测：

**CU 收敛七判定**：

| 判定 | 条件 | 动作 |
|------|------|------|
| 确认既有 | BA已有CU与本轮同名同义，边界一致 | 追加来源 |
| 扩展既有 | 主体一致但新增配置要素/系统处理/运行期能力 | 修订CU配置能力 |
| 新增 CU | 无可复用CU，粒度可展开 | 新建CU |
| 拆分 CU | 候选同时承接多个不连续能力 | 输出拆分建议 `[需裁决]` |
| 合并 CU | 多个候选须同页配置、共同校验 | 合并为一个CU |
| 占位 CU | 25已有预定义但本轮未触发 | 保留名称，不进入确认范围 |
| 退回上游 | 候选缺少触发来源或能力链 | 退回 wft01-eng |

**Phase B CU 关系检测**：

| 关系 | 判定 | 处理 |
|------|------|------|
| 确认 | CU匹配+边界一致+来源非STR-E明示 | 来源升级 |
| 无新增 | CU匹配+全部已STR-E明示 | 追加引用+增量合并 |
| 配置能力扩展 | CU匹配+配置能力边界扩展 | 修订CU+变更原因 |
| 引擎归属变更 | CU匹配+目标引擎不同 | 更新引擎+变更原因 |
| 补充 | CU不匹配 | 新增到清单 |
| 过时 | 基线CU未被本轮覆盖 | `[过时]`+保留不删 |

4. **变更影响声明**——判定变更类型，写入 BA 节点末尾

#### Phase C — 新建 BA

1. **确定 A1 产品路径**——流程与 IT 域 → 引擎 → CU
2. **装配 A2 上下文**——业务配置人员→STR-E→配置活动序列→运行期能力可用
3. **收敛 CU 清单**——识别 CU 候选 + 与 25 模型线索比对 + 七种收敛判定 + 粒度判断
4. **定义 CU 配置能力**——每个 CU 四要素：

| 要素 | 回答的问题 | 设计粒度 |
|------|------------|---------|
| 配置入口 | 配置人员在哪个配置页面/子页面维护该 CU | 页面职责、配置对象、配置类别；不设计 UI 布局 |
| 配置要素 | 配置人员需要编辑哪些关键信息 | 关键配置项、关系、约束；不写字段级全量规格 |
| 系统处理 | 系统如何校验、保存、版本化、发布或装载 | 处理规则摘要、状态变化、异常处理；不写实现算法 |
| 运行期能力 | 引擎按 CU 定义生成或渲染什么制品/构件/功能 | 物理表、功能表单、菜单入口、按钮构件等 |

5. **定义引擎状态迁移**——配置草稿/已校验/已发布/已装载/已停用/已回滚等状态及触发条件
6. **校验依赖并组装 BA**——四类依赖（引擎内/跨引擎/布局组件构件/治理），写入 `04-*.md`

### Step 4 · 缺口补需与变更声明

按每个 BA 独立执行。新建 → 全量检查；修订 → 仅当 CU 拓扑变化时重验。

**1. 缺口识别**：

| 缺口类型 | 处理 |
|---------|------|
| 上游缺口（STR-E 场景边界缺失/能力链不闭合） | 退回 `需wft01修订` |
| CU 缺口（能力链段无对应 CU） | 新增候选 CU，标注 `[推断]` |
| CU 过粗/过细 | 输出拆分/合并建议，`[需裁决]` |
| 配置能力缺口（入口/要素/处理/运行期能力缺失） | 生成补充 FR-ENG |
| 依赖缺口（跨引擎无对应模型） | 形成 25 模型建议 |

**2. 要素机械检查**——A2 上下文完整、A1 路径到位、CU 清单非空且逐条标注来源和收敛判定、每个 CU 四类配置能力已定义、依赖已校验、变更影响声明已写入。

**3. 补充 FR-ENG 材料生成**——写入 `../../80-pl4eos-2-eosdata/00-origin-requirement-materials/10-raw-files/<YYYYMMDD>-<BA名称>补充原始需求材料.md`，登记到 OR 原料状态表。

## 附录A：判据速查

### A.1 CU 收敛七判定

| 判定 | 条件 | 动作 |
|------|------|------|
| 确认既有 | BA已有CU与本轮同名同义，边界一致 | 追加来源 |
| 扩展既有 | 主体一致但新增配置能力 | 修订CU |
| 新增 CU | 无可复用CU，粒度可展开 | 新建CU |
| 拆分 CU | 候选承接多个不连续能力 | 输出拆分建议 `[需裁决]` |
| 合并 CU | 多个候选须同页配置、共同校验 | 合并为一个CU |
| 占位 CU | 25已有预定义但本轮未触发 | 保留名称 |
| 退回上游 | 缺少触发来源或能力链 | 退回 wft01-eng |

### A.2 CU 配置能力四要素

| 要素 | 回答的问题 | 设计粒度 |
|------|------------|---------|
| 配置入口 | 在哪配置 | 页面职责、配置对象、配置类别 |
| 配置要素 | 配置什么 | 关键配置项、关系、约束 |
| 系统处理 | 系统怎么处理 | 校验/保存/版本/发布/装载规则摘要 |
| 运行期能力 | 产出什么 | 物理表/功能表单/菜单入口/构件等 |

### A.3 CU 来源类型（七种）

| 来源类型 | 含义 |
|---------|------|
| `STR-E明示` | STR-E CU候选清单直接列出 |
| `STR-E隐含` | 没有该CU则能力链无法闭合 |
| `构件缺口推断` | 为支撑某类页面构件扩展 |
| `布局组件缺口推断` | 为支撑某类布局组件扩展 |
| `同类引擎推断` | 同类引擎已有相似配置能力 |
| `25模型线索` | 25资产中已有CU类型定义 |
| `引擎内置` | 引擎预定义能力，本轮未触发 |

> 非 `STR-E明示` 来源均标注 `[推断]`。

### A.4 依赖关系四分类

| 依赖类型 | 示例 | 处理 |
|----------|------|------|
| 引擎内依赖 | 流转规则配置依赖流程节点配置 | BA中写明先后关系 |
| 跨引擎依赖 | 流程配置依赖实体字段、权限规则 | 引用依赖引擎/CU，不改主归属 |
| 布局组件/构件依赖 | 流程CU运行期需要按钮构件 | 说明被渲染的构件 |
| 治理依赖 | 发布、版本、审计、回滚、监控 | 缺失时生成补充FR-ENG或25模型建议 |

### A.5 Phase B CU 关系检测

| 关系 | 判定 | 处理 |
|------|------|------|
| 确认 | CU匹配+边界一致+来源非STR-E明示 | 来源升级 |
| 无新增 | CU匹配+全部已STR-E明示 | 追加引用+增量合并 |
| 配置能力扩展 | CU匹配+配置能力边界扩展 | 修订CU+变更原因 |
| 引擎归属变更 | CU匹配+目标引擎不同 | 更新引擎+变更原因 |
| 补充 | CU不匹配 | 新增到清单 |
| 过时 | 基线CU未被本轮覆盖 | `[过时]`+保留不删 |

### A.6 BA 完备性判据

| 检查项 | 判据 | 缺口处理 |
|--------|------|----------|
| CU 覆盖 | 能力链各段均有CU承接 | 补充CU或退回wft01-eng |
| 配置能力自洽 | 入口/要素能被系统处理并形成运行期制品 | 标记`[需裁决]`或补充FR-ENG |
| 依赖闭合 | CU依赖的实体/表单/权限/发布等有来源 | 形成依赖缺口 |
| 运行期可消费 | 足以让wft03-eng推断配置页面 | 不足则保持待确认方案 |
| 25关系清晰 | 已有/待确认/缺失的模型关系已标注 | 形成25建议 |
