# eos-ort02 · 切分原始需求 → 已澄清切分文档 · 模糊标注与澄清迭代

> **设计依据**：[eos-ort02-clarify.md](../eos-ort02-clarify.md)（人类方案——权威源）
> **领域规范**：[91-eos-biz-eng-spec.md](../10-wfsysdev-4-eos/91-eos-biz-eng-spec.md)

## 一、职责定位

### 负责与不负责

| 负责 | 不负责（路由指向） |
|------|-------------------|
| 读取表 B 中 `生命周期=已切分` + `人类决策=同意澄清` 的切分文件 | 原始材料文本化 → `eos-ort00-textualize` |
| 首轮全量模糊标注（五种子类型）+ 标注报告 | 语义切分 → `eos-ort01-chunk` |
| 读取正文区 `[✓已澄清]` 注释 → 生成新正文 → 三项条件评估 | OR 条目规范化/分类/编号 → `eos-ort03-norm` |
| 迭代：归档旧版正文+标注 → 新正文 + 重新评估 | 代替人类确认业务事实 |
| 维护表 B：生命周期/iteration_count/unresolved_count/frontmatter.status | — |

**五类模糊子类型**：

| 子类型 | 适用场景 | 标注格式 |
|--------|---------|---------|
| 术语模糊 | 非量化表述需明确度量 | `[⨯术语模糊: 高效→需量化处理能力指标]` |
| 主体/客体不明 | 角色或对象不可识别 | `[⨯主体不明]提出该需求` |
| 边界模糊 | 条件/范围/指标缺少边界 | `[⨯边界模糊: 实时→需明确延迟上限]` |
| 信息缺失 | 缺少来源/时间/提出方 | `[⨯信息缺失→缺来源日期和提出方]` |
| 多重模糊 | 同处存在两种以上类型 | `[⨯多重模糊: 术语+边界→非量化+缺时限]` |

**标注纪律**：标"哪里不清楚"，不标"应该怎么做"；一条只标一个点；先通读后标注。

## 二、操作流程

### Step Start · 前置校验

1. `01-eos-sysdev-status.md` 存在 → 否则提示先运行 `eos-ort00-textualize`
2. `10-raw-files/` 中有 `.chunk-*.md` 文件 → 否则提示先运行 `eos-ort01-chunk`
3. 全部就绪 → **优先检查反馈**：存在 `生命周期=澄清中` → Step 2；无 → Step 1

### Step 1 · 新增处理

读取表 B，按状态分流：

| 表 B 状态 | 处理 |
|----------|------|
| `生命周期=已切分` + `人类决策=同意澄清` | 进入首轮标注 |
| `人类决策=已终止` | 表 B→`已废弃`，frontmatter.status→`abandoned` |
| `人类决策=空` | 跳过，列入待选入澄清提醒 |

**首轮标注**：
1. 通读切分文件正文区
2. 按五种子类型标注全部模糊项
3. 写入模糊标注报告
4. 有模糊项：`status=annotated`，表 B→`澄清中`、`AI建议=需继续澄清`、`iteration_count=1`
5. 无模糊项：`status=clarified`，表 B→`已澄清`、`AI建议=可以规范化`

### Step 2 · 反馈处理

读取 `生命周期=澄清中` 的文件，检测正文区：

| 条件 | 处理 |
|------|------|
| 有 `[✓已澄清]` | 归档旧版正文+标注+注释到历史区 → 按注释生成新正文 → **三项条件评估** |
| 有 `[⨯]` 无 `[✓已澄清]` | 输出迭代报告，等待人类处理。`iteration_count >= 3` 时提示优先处理 |
| 无标记异常 | 若 `status=clarified` 跳过，否则提示数据不一致 |

**三项条件评估**：

| 条件 | 判定口径 |
|------|---------|
| 正文内容清晰完整 | 模糊表述已替换为明确内容 |
| 历史模糊项已澄清 | 所有历史 `[⨯]` 均有对应 `[✓已澄清]` |
| 无新增模糊 | 新正文通读后无新 `[⨯]` |

三项全满足 → `已澄清`、`可以规范化`、`status=clarified`。仍有未清晰项 → 追加新 `[⨯]`，保持 `澄清中`。更新 `last_size`、`iteration_count++`、`unresolved_count`。

### Step End · 运行结束输出

```text
══════════════════════════════════════════
  eos-ort02 本轮完成
══════════════════════════════════════════

当前状态：<澄清中 / 已澄清可规范化 / 已废弃>
  首轮标注：[文件]（发现 N 项模糊，澄清中）
  迭代澄清：[文件]（v{N-1}→v{N}，剩余 M 项）
  已澄清：[文件]（已澄清→可规范化）
资产落账：表 B + frontmatter.status 已同步

一、澄清反馈
  在正文区 `[⨯]` 后追加 `[✓已澄清: ...]`
  示例：[✓已澄清: 响应时间 ≤200ms]  [✓已澄清: 提出方=市场部张三]

二、下一步
  本Skill → 继续选入澄清或处理 [✓已澄清] 反馈
  后续    → 已澄清→设人类决策=同意规范化 → eos-ort03-norm
```
