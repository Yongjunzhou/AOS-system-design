## 一、职责定位

### 负责与不负责

| 负责 | 不负责（路由指向） |
|------|-------------------|
| 扫描 `10-raw-files/`，发现未文本化的原始材料 | OR 语义切分、切分方案 → `eos-ort01-chunk` |
| 执行纯格式转换（PDF/图片/文本→Markdown 工作副本） | 模糊需求澄清 → `eos-ort02-clarify` |
| 正文区全文精确查重，重复材料→软链接文档+`已废弃（重复）` | OR 条目规范化/分类/编号 → `eos-ort03-norm` |

| 输出行动清单（待选入切分清单+重复通知+下一步指引） | — |

**核心原则**：AI 在本步是"转录者"而非"理解者"——文本化只改变载体格式，不改变内容。

### 上下游衔接

| 方向 | Skill | 交接内容 |
|------|-------|---------|
| 上游 | 原始材料入库 | 人类把 PDF/图片/邮件/纪要/已有 `.md` 放入 `10-raw-files/`；wft 补充生成的材料也入此目录 |
| 下游 | `eos-ort01-chunk` | 表A 中 `人类决策=同意切分` 且正文区有纯原文（无切分方案块）的文本化文档 → 进入切分 |

## 二、操作流程

### Step Start · 前置校验

按顺序校验，首次遇缺即处理：

1. 检查 `../../../80-pl4eos-2-eosdata/00-origin-requirement-materials/` 存在
2. 检查 `10-raw-files/` 存在
3. 检查 `01-eos-sysdev-status.md` 存在——不存在则打开 [人类方案 §4.2](../eos-ort00-textualize.md#42-eos-or-预处理状态文档模板)，按模板创建 OR 阶段表 A/B/C
4. 若状态文档已存在，校验三张表（表A/B/C）的表头和字段说明；不一致时按 [人类方案 §4.2 模板](../eos-ort00-textualize.md#42-eos-or-预处理状态文档模板) 更新
5. `10-raw-files/` 为空 → 输出"请将原始材料放入后重新启动" → 结束
6. 全部就绪 → Step 1

**加载经济原则**：用 `ls`/glob 扫描 `10-raw-files/` 与状态文档表头，不 Read 整个状态文档或文件目录；查重比对仅读各既有文本化文档的**正文区**（管理区不参与比对）。

### Step 1 · 材料发现与登记

1. 用 `ls 10-raw-files/` 扫描源文件
2. 按附录 A.1 跳过判定逐文件过滤（本步产物/下游切分文档/已进流程材料/已废弃材料）
3. 表 A 无记录的新材料，登记一行：
   - `记录ID=ORT-YYYYMMDD-{seq}`（seq 为本日流水号，从 001 起）
   - `源文件=原始文件名`、`文本化文档={原始文件名}.textualized.md`
   - `生命周期=已登记`、`AI建议=可以切分`
   - `操作指引=完成文本化后由人类决定是否选入切分`
4. 无新材料 → 输出"所有材料已文本化" → 结束

### Step 2 · 文本化与查重

**1. 文本化转换**——逐源文件执行格式转换，保留原文结构；无法识别内容按 §三 转录标注速查写占位符。

**2. 查重检测**——新文本化正文区与既有文本化正文区逐字精确比对（忽略行尾空白和连续空行差异；比对范围：表A `生命周期≠已废弃（重复）` 的既有文本化文档）：

| 结果 | 处理 |
|------|------|
| 无重复 | 输出文本化文档；表A → `生命周期=已文本化`、`AI建议=可以切分` |
| 重复 | 输出软链接文档（正文区仅定向引用）；表A → `生命周期=已废弃（重复）`、`AI建议=已废弃（重复）`、`内容摘要=与[源文件名]内容完全重复` |

**3. 两区文档写入**：

| 区域 | 内容 |
|------|------|
| 管理区 | 状态摘要表（阶段/AI建议/待处理/操作指引，模板见 [人类方案 §4.1](../eos-ort00-textualize.md#41-or-文本化文档状态表模板)） |
| 正文区 | 纯原文与转录占位标注（无切分标记、方案块或分析建议块） |

**写回顺序（同步契约）**：先更新状态文档表 A（权威源），再从表 A 推导写入文本化文档管理区。写回前执行附录 B.1 冲突检查。

### Step End · 运行结束输出（含反馈等待）

按 91 规范 §A.3.2 三区模板输出：

```text
当前状态：<已文本化可切分 / 已废弃（重复）/ 无新增处理>
  本轮已文本化：[文件名] → 文本化完成，待人类选入切分
  本轮发现重复：[文件名] → 与 [原始源文件名] 完全重复，已标记 已废弃（重复）

一、方案反馈（直接回复口令，AI 代为更新状态文档表 A）
  A. 选入切分 → 回复「选入切分 [文件名]」
  B. 暂不切分 → 回复「暂不切分 [文件名]」
  C. 确认重复 → 回复「确认重复」
  D. 重复误判 → 回复「重复误判 [文件名]」

二、下一步
  本Skill → 有新增原始材料或待选入切分的文档时，重跑本步继续文本化
  后续    → 表 A 人类决策=同意切分 的文档，运行 eos-ort01-chunk 进入切分
```

**交互方式**：按 91 规范 §A.5 反馈交互协议，**AI 不结束对话**——输出本摘要后保持对话，等待人类以自然语言反馈。本轮决策回复「一、方案反馈」中的口令，AI 代为更新状态文档表 A；另有辅助口令：「继续」→ 重跑本步处理新增材料，「打开状态文档」→ 输出路径和建议关注行。

**AI 处理口令规则**：

| 人类输入 | AI 动作 |
|---------|--------|
| 「选入切分 [文件名]」 | 表A 该行 `人类决策=同意切分` |
| 「暂不切分 [文件名]」 | 表A 该行 `人类决策=暂不切分` |
| 「确认重复」 | 保留 `已废弃（重复）`，提示人类确认后删除源文件 |
| 「重复误判 [文件名]」 | 清除表A 该行生命周期值 + 删除软链接文档 + 重跑本步重新判定 |
| 「继续」 | 重跑本步，处理新增材料 |
| 「打开状态文档」 | 输出 `01-eos-sysdev-status.md` 路径和建议关注行 |

## 三、AI 标记约定

**转录占位标注**——含义是"此处需人工确认"的提示牌，不是 AI 加工结论。宁可用标注如实说明，也不凭空补全。标注写入正文区（详细规则见 [人类方案 §2.3.2](../eos-ort00-textualize.md#232-转录忠实转成-markdown)）：

| 场景 | 标注 |
|------|------|
| 图片/扫描件 | `[AI 识别，待人工确认]` |
| 录音听不清 | `[听写不清]` |
| 手写可辨识 | `[AI 推测]` |
| 手写不可辨识 | `[原文模糊]` |
| 完全无法识别的图片 | `[图片：无法识别文字内容]` |
| 文档明显不完整 | 文档开头 `[文档疑似不完整]` |
| 多语言混写 | 保留原语种，必要时标注 `[中文/英文/...]` |

**增量标记**：反馈处理中按 91 规范 §A.5 追加 `[已处理]` 作为处理记录。

## 附录A：判据速查

### A.1 跳过判定（Step 1 过滤）

| 跳过原因 | 判定条件 |
|---------|---------|
| 不是原始材料 | 文件名以 `.textualized.md` 结尾（本步产物）；或含 `.chunk-`（下游切分文档） |
| 已在处理流程中 | 表A 已有记录，生命周期非空（已登记 / 已文本化 / 切分方案待确认 / 已切分） |
| 重复关系已记录 | 表A 生命周期=`已废弃（重复）`（已通过软链接文档记录） |
| 已废弃 | 表A 生命周期=`已废弃`（如需重新启用，先清除该行生命周期值） |

> 注：`澄清中` / `已澄清` / `已规范化` 属于表B（切分文件）取值，不会出现在表A，不参与跳过判定。

### A.2 查重判定

| 结果 | 判定 | 处理 |
|------|------|------|
| 无重复 | 无任何既有文本化正文与新材料逐字完全一致 | 输出完整文档；表A → `已文本化` + `可以切分` |
| 重复 | 有既有文本化正文与新材料逐字完全一致（忽略行尾空白/连续空行） | 软链接文档；表A → `已废弃（重复）` |

### A.3 表A 生命周期与人类决策取值

| 字段 | 取值 |
|------|------|
| 生命周期 | 已登记 → 已文本化 → 切分方案待确认 → 已切分 → 已废弃（含已废弃（重复）） |
| AI建议 | `可以切分` / `已废弃（重复）` |
| 人类决策 | 空（未处理）/ `同意切分`（选入切分）/ `暂不切分`（本批不入切分）/ `已终止`（废弃） |

## 附录B：版本感知与写回

### B.1 写回前冲突检查

状态文档表 A 是人类与 AI 共同维护的表。AI 写回前执行冲突检查，防止覆盖人类手工修改：

1. **Step 1 快照**——登记/更新前，记录待写回行的 `生命周期` 与 `人类决策` 当前值。
2. **写回前复核**——写回前重新读取该行；若 `生命周期` 或 `人类决策` 与快照不符（人类在本次运行期间手工修改），标记 `[需确认]`，不覆盖，在 Step End 向人类提示。
3. **人类决策保护**——`人类决策` 是唯一由人类写入的字段：除非人类通过 Step End 口令明确指示（如「选入切分」「暂不切分」），AI 绝不覆盖非空的人类决策。

### B.2 写回顺序（同步契约）

每次写入按固定顺序执行：

1. **先更新状态文档表 A**（权威源）——登记 / 转迁生命周期 / 更新 AI建议与操作指引
2. **再从表 A 推导**写入文本化文档管理区状态表
3. 两者不一致时，以表 A 为准重建管理区

## 四、重进入规则

| 场景 | 处理 |
|------|------|
| 新增原始材料 | 无对应表 A 记录 → 进入文本化 |
| 重新文本化 | 无下游消费时清除表 A 生命周期值替换副本；已有下游消费时先输出变更影响声明再重跑 |
| 重复误判 | 清除表 A 生命周期值，删除软链接文档，重跑 |

> 重进入按 91 规范 §A.7 变更传播协议处理（详见 [人类方案 §2.4.2](../eos-ort00-textualize.md#242-重进入材料已进流程后的再处理)）：新增材料不影响既有结果；重新文本化或重复关系纠正若改变正文、来源或有效性，必须列出受影响的切分文件、OR 和已消费 STR，不得静默声明"下游不受影响"。
