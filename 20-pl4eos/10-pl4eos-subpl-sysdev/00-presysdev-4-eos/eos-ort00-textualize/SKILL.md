## 一、职责定位

### 负责与不负责

| 负责 | 不负责（路由指向） |
|------|-------------------|
| 扫描 `10-raw-files/`，发现未文本化的原始材料 | OR 语义切分、切分方案 → `eos-ort01-chunk` |
| 执行纯格式转换（PDF/图片/文本→Markdown 工作副本） | 模糊需求澄清 → `eos-ort02-clarify` |
| 正文区全文精确查重，重复材料→软链接文档+`已废弃（重复）` | OR 条目规范化/分类/编号 → `eos-ort03-norm` |
| 维护状态文档表 A（登记/文本化/废弃） | 修改/摘要/解释/补充原始需求内容 |
| 输出行动清单（待选入切分清单+重复通知+下一步指引） | — |

**核心原则**：AI 在本步是"转录者"而非"理解者"——文本化只改变载体格式，不改变内容。

### 工程化设计原则适配

| 原则 | 在本步中的体现 |
|------|--------------|
| 需求相对 | 本步不涉及需求/方案角色切换，纯格式转换步骤无需求相对性可言 |
| 详概分离 | 本步仅做格式转换和状态登记，不进行语义理解、切分分析或需求规范化 |
| 文档结对 | 本步不产生文档结对关系；文本化文档是 eos-ort01-chunk 的输入 |
| 基于资产 | 原始出处保留；文本化文档是原始文件的处理副本，不覆盖源文件 |

## 二、文本化设计基础

### 2.1 文本化文档结构

文本化文档命名为 `{原始文件名}.textualized.md`，位于 `10-raw-files/`。原始文件保持只读不动，即使源文件本身已经是 `.md`，本步也生成独立工作副本。

| 区域 | 位置 | 内容 | 写入者 |
|------|------|------|--------|
| 管理区 | 文档顶部（正文前） | 状态摘要（阶段/AI 建议/待处理/操作指引）、迭代记录 | eos-ort00 写入状态摘要；下游追加迭代记录 |
| 正文区 | 管理区之后 | 纯原文内容（仅文本化后原文，无标注、无方案块） | eos-ort00 |

**正文区纯净原则**：正文区仅包含原文。所有切分方案块、模糊标注、分析建议块均由下游步骤写入并适时清理。本步不产生任何分析产物。

**历史追溯约定**：文档不设置历史区、归档区或旧版正文；历史版本由 Git 管理（[00-doc-conventions §14.7](../../../../00-generalspec/00-doc-conventions.md#147-不保留历史区)）。需留痕的信息摘要写入管理区，不得复制旧版全文。

### 2.2 文档生命周期管理

**一句话**：状态文档 `01-eos-sysdev-status.md` 是所有 OR 预处理文档的生命周期登记表——每行记录一份文档当前所处阶段（生命周期）、AI 建议、人类决策。

**三张表管理三类对象**：

| 表 | 管理对象 | 生命周期线 |
|----|---------|-----------|
| 表 A | 原始材料 | 已登记 → 已文本化 → 切分方案待确认 → 已切分 → 已废弃 |
| 表 B | 切分文件 | 已切分 → 澄清中 → 已澄清 → 待确认规范方案 → 已规范化 → 已废弃 |
| 表 C | OR 基线条目 | 待处理 → 待确认方案 → 已分配 → 验证中 → 已验证冻结 → 已废弃 |

**一行记录三要素**：`生命周期`（所处阶段，流程唯一依据）+ `AI建议`（给人类的推荐）+ `人类决策`（人类放行与否）。模板见 §5.2。

**同步契约（本步）**：写入时**先更新表 A（权威源），再从表 A 推导写入文本化文档管理区状态表**；不一致以表 A 为准重建。

**范围**：本表只管 OR 预处理链（ort00~ort03）；wft01~05 的设计产物以各自产品文档管理区为权威源，不使用本表；wft 补充原始需求材料只登记表 A（`已登记`），仍由 ort00~ort03 处理。

## 三、操作流程

### Step Start · 前置校验

按顺序校验，首次遇缺即处理：

1. 检查 `../../../80-pl4eos-2-eosdata/00-origin-requirement-materials/` 存在
2. 检查 `10-raw-files/` 存在
3. 检查 `01-eos-sysdev-status.md` 存在——不存在则按 §五.2 模板创建 OR 阶段表 A/B/C
4. `10-raw-files/` 为空 → 输出"请将原始材料放入后重新启动" → 结束
5. 全部就绪 → Step 1

### Step 1 · 材料发现与登记

1. 扫描 `10-raw-files/` 中的文件
2. 跳过规则：

| 条件 | 动作 |
|------|------|
| 文件名以 `.textualized.md` 结尾 | 跳过（本步产物） |
| 文件名包含 `.chunk-` 且以 `.md` 结尾 | 跳过（下游切分文档） |
| 表 A 已有记录，生命周期≠空 | 跳过（已在流程中） |
| 表 A 无记录 | 登记：`生命周期=已登记`，`AI建议=可以切分` |

3. 无新材料 → 输出"所有材料已文本化" → 结束

### Step 2 · 文本化与查重

**1. 文本化转换**——逐源文件执行格式转换：

| 场景 | 处理 |
|------|------|
| PDF 表格 | 转 Markdown 表格，保留行列结构 |
| 图片/扫描件 | 识别文字内容，标注 `[AI 识别，待人工确认]` |
| 录音转写 | 标注发言人+时间戳，无法确认标 `[听写不清]` |
| 手写内容 | 可辨识标 `[AI 推测]`，不可辨识标 `[原文模糊]` |
| 完全无法识别 | 占位符 `[图片：无法识别文字内容]` |
| 文档明显不完整 | 文档开头标 `[文档疑似不完整]` |

**2. 查重检测**——新文本化正文区与既有文本化正文区逐字精确比对（忽略行尾空白和连续空行差异）：

| 结果 | 处理 |
|------|------|
| 无重复 | 输出文本化文档；表 A→`生命周期=已文本化`、`AI建议=可以切分` |
| 重复 | 输出软链接文档（正文区仅定向引用）；表 A→`生命周期=已废弃（重复）`、`AI建议=已废弃（重复）` |

**3. 两区文本化文档写入**：

| 区域 | 内容 |
|------|------|
| 管理区 | 状态摘要表（阶段/AI建议/待处理/操作指引，模板见 §五.1） |
| 正文区 | 纯原文（无标注、无方案块） |

**同步契约**：AI 每次写入时**先更新状态文档表 A（权威源），再从表 A 推导写入文本化文档管理区**。

### Step End · 运行结束输出

输出行动清单：

```text
══════════════════════════════════════════
  eos-ort00 本轮完成 · 行动清单
══════════════════════════════════════════

● 本轮已文本化：[文件名] → 文本化完成
● 本轮发现重复：[文件名] → 与 [源文件名] 完全重复

━━━ 待选入切分 ━━━
打开 状态文档 → 表A：
├─ 选入切分 → 设 人类决策=同意切分
└─ 暂不切分 → 设 人类决策=暂不切分

━━━ 下一步 ━━━
选入切分的文档运行 eos-ort01-chunk
```

## 四、重进入规则

| 场景 | 处理 |
|------|------|
| 新增原始材料 | 无对应表 A 记录 → 进入文本化 |
| 重新文本化 | 无下游消费时清除表 A 生命周期值替换副本；已有下游消费时先输出变更影响声明再重跑 |
| 重复误判 | 清除表 A 生命周期值，删除软链接文档，重跑 |

> 重进入按 [91 规范 §A.7](../../10-wfsysdev-4-eos/91-eos-biz-eng-spec.md#a7-变更传播协议) 处理：新增材料不影响既有结果；重新文本化或重复关系纠正若改变正文、来源或有效性，必须列出受影响的切分文件、OR 和已消费 STR，不得静默声明"下游不受影响"。

## 五、模板

### 5.1 OR 文本化文档状态表模板

**无重复文档**（管理区顶部写入）：

```markdown
| 阶段 | AI建议 | 待处理 | 操作指引 |
|------|--------|--------|---------|
| 文本化完成 | — | 在 状态文档 → 表A — OR原料处理建议及进展中确认入选本批材料 | 状态文档 → 表A — OR原料处理建议及进展 → 该记录 人类决策 字段设为"同意切分"（选入切分） |
```

**重复文档**（管理区顶部 + 正文区定向引用）：

```markdown
| 阶段 | AI建议 | 待处理 | 操作指引 |
|------|--------|--------|---------|
| 已废弃（重复） | 与 [原始源文件名] 内容完全重复 | 确认无误后删除源文件 | — |
```

```text
→ 本文件与 [原始源文件名] 内容完全重复，不持独立正文。
→ 原始文本化文档：[原始文本化文档文件名]
```

> 文档内状态表的 `AI建议` 与表 A 的 `AI建议` 取值不同：文档内表面向当前阶段查看，文本化是机械转换，故填 `—`；表 A 的 `AI建议=可以切分` 面向下一步选材决策。

### 5.2 EOS OR 预处理状态文档模板（首次初始化）

`01-eos-sysdev-status.md` 缺失时，按以下模板创建 OR 阶段表 A/B/C：

```markdown
# EOS OR 预处理状态文档

**用途**：OR 预处理链（`ort00-textualize` / `ort01-chunk` / `ort02-clarify` / `ort03-norm`）的状态追踪共享接口。AI 通过此表感知原始材料、文本化文档、切分子文件和 OR 基线条目的处理状态；人类通过此表做预处理阶段的批量决策。
```

## 六、与下游步骤的关系

```text
eos-ort00-textualize（本步：纯文本化）
```
