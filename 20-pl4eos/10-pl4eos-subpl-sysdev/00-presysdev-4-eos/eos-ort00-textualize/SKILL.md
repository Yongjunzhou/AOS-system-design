# eos-ort00 · 原始需求材料 → 文本化文档 · 纯文本化与原料登记

> **设计依据**：[eos-ort00-textualize.md](../eos-ort00-textualize.md)（人类方案——权威源）。本文档中「人类方案」一律指此文件（`20-pl4eos/10-pl4eos-subpl-sysdev/00-presysdev-4-eos/eos-ort00-textualize.md`）。
> **领域规范**：[91-eos-biz-eng-spec.md](../../10-wfsysdev-4-eos/91-eos-biz-eng-spec.md)（Step Start、反馈优先、输出交接（三区模板）与变更传播通用协议；本步反馈走「表 A 编辑 + git」特化，见 91 §A.5）
> **规则归属**：本文档只承载 AI 运行时执行指令（加载/写回/标注/速查）；所有设计规则、模板与字段定义以 [人类方案（eos-ort00-textualize.md）](../eos-ort00-textualize.md) 为准，命中规则冲突时以人类方案为准。

## 一、职责定位

### 负责与不负责

| 负责 | 不负责（路由指向） |
|------|-------------------|
| Step 1：扫表 A 状态条件 → 终止/重跑/确认重复（状态自终止，直接处理） | OR 语义切分、切分方案 → `eos-ort01-chunk` |
| Step 2：发现登记新材料 + 文本化 + 查重 | 模糊需求澄清 → `eos-ort02-clarify` |
| 维护状态文档表 A（登记/文本化/废弃）；Step 3 提交基线（链级不变式） | OR 条目规范化/分类/编号 → `eos-ort03-norm` |
| 输出行动清单（待选入切分清单+重复通知+下一步指引） | 修改/摘要/解释/补充原始需求内容 |

**核心原则**：AI 在本步是"转录者"而非"理解者"——文本化只改变载体格式，不改变内容；**反馈载体即表 A 状态**——人类改表 A（`人类决策`/清 `生命周期`/删源文件）即反馈，AI 扫状态条件直接处理，无需 git diff 与记录分离。

### 上下游衔接

| 方向 | Skill | 交接内容 |
|------|-------|---------|
| 上游 | 原始材料入库 | 人类把 PDF/图片/邮件/纪要/已有 `.md` 放入 `10-raw-files/`；wft 补充生成的材料也入此目录 |
| 下游 | `eos-ort01-chunk` | 表A 中 `人类决策=同意切分` 且正文区有纯原文（无切分方案块）的文本化文档 → 进入切分 |

## 二、操作流程

### Step Start · 前置校验

按顺序校验，首次遇缺即处理：

1. 检查 `../../../80-pl4eos-2-eosdata/00-origin-requirement-materials/` 存在
2. 检查 `10-raw-files/` 存在
3. 检查 `01-eos-sysdev-status.md` 存在——不存在则打开 [人类方案 §6.2](../eos-ort00-textualize.md#62-eos-or-预处理状态文档模板)，按模板创建 OR 阶段表 A/B/C
4. 若状态文档已存在，校验三张表（表A/B/C）的表头和字段说明；不一致时按 [人类方案 §6.2 模板](../eos-ort00-textualize.md#62-eos-or-预处理状态文档模板) 更新
5. 确认处于 git 仓库且 AI 基线可用：`scripts/ai-commit.sh` 存在；基线 = 状态文档 `HEAD @上次AI运行` 或最近 AI 提交（`git log --author="EOS-AI" -1`）
6. **感知前置——扫描表 A 反馈状态条件**（[人类方案 §3.4](../eos-ort00-textualize.md#34-反馈检测判据)）：`人类决策=已终止` 且 生命周期 ∈ {`已登记`,`已文本化`,`切分方案待确认`,`已切分`}（终止反馈）、`生命周期` 为空 且 有对应源文件（重跑反馈）、`生命周期=已废弃（重复）` 且 源文件不存在（确认重复反馈）——**存在任一反馈 → 即使 `10-raw-files/` 为空也进入 Step 1 先处理反馈**（目录空不代表无反馈——表 A 可能已有材料待终止/重跑/确认重复）
7. 若无表 A 待处理反馈 且 `10-raw-files/` 为空 → 输出"请将原始材料放入后重新启动" → 结束
8. 全部就绪 → Step 1

**加载经济原则**：用 `ls`/glob 扫描 `10-raw-files/` 与状态文档表头，不 Read 整个状态文档或文件目录；查重比对仅读各既有文本化文档的**正文区**（管理区不参与比对）。

### Step 1 · 反馈处理

**一句话**：扫表 A 的状态条件，发现人类反馈并直接处理——反馈载体就是状态表，处理即状态转迁，完成后条件自动失效（无需 `[已处理]` 标记）。

| 表 A / 文件系统 状态条件 | 判读 | 处理 |
|------------------------|------|------|
| `人类决策=已终止` 且 生命周期 ∈ {`已登记`,`已文本化`} | 终止 | 生命周期 → `已废弃`、AI建议 → `建议终止`，追加废弃说明 |
| `人类决策=已终止` 且 生命周期 ∈ {`切分方案待确认`,`已切分`} | 跳过（ort01 域） | 不处理；行动清单提示运行 `eos-ort01-chunk` 处理终止（含表 B 切分文件联动） |
| `生命周期` 为空 且 `10-raw-files/` 有对应文件 | 重跑 | 按原状态重跑：原软链接存在 → 删软链接+重新查重判定；原文本化文档存在 → 重新文本化（下游已消费先输出 91 §A.7 变更影响声明）；原转换失败 → 重新转换 |
| `生命周期=已废弃（重复）` 且 源文件不存在 | 确认重复 | 收尾：行动清单移除 |
| `人类决策=同意切分` | 选材 | 不处理；列入行动清单（ort01 入口） |
| `人类决策=暂不切分` | 暂不切分 | 不处理；保留行动清单 |

> 终止按生命周期段分工：`已登记`/`已文本化`（ort00 域）由本步处理；`切分方案待确认`/`已切分`（ort01 域）跳过并提示走 `eos-ort01-chunk`（含表 B 切分文件联动，级联规则唯一权威在 ort01 Step 3，见 [人类方案 §3.4](../eos-ort00-textualize.md#34-反馈检测判据)）。

处理前执行附录 B.1 竞态保护（快照/复核，命中 `[需确认]` 不覆盖）；处理后按 [人类方案 §2.2](../eos-ort00-textualize.md#22-生命周期状态模型) 同步契约推导更新文本化文档管理区。无任何反馈与新材料时输出「无待处理对象」并结束。

### Step 2 · 新增处理

**一句话**：处理新材料——发现未登记源文件、登记表 A、文本化、查重。

**1. 材料发现与登记**：

1. 用 `ls 10-raw-files/` 扫描源文件
2. 按附录 A.1 跳过判定逐文件过滤（本步产物/下游切分文档/已进流程材料/已废弃材料）
3. 表 A 无记录的新材料，登记一行：
   - `记录ID=ORT-YYYYMMDD-{seq}`（seq 为本日流水号，从 001 起）
   - `源文件=原始文件名`、`文本化文档={原始文件名}.textualized.md`
   - `生命周期=已登记`、`AI建议=可以切分`
   - `操作指引=完成文本化后由人类决定是否选入切分`
4. 无新材料 → 输出"所有材料已文本化" → 结束

**2. 文本化与查重**：

（1）**文本化转换**——逐源文件执行格式转换，保留原文结构；无法识别内容按 §三 转录标注速查写占位符。转换失败（损坏/加密/格式不受支持/报错）或部分成功时，按 §三 转换失败处理：失败材料不输出文档、在表A 登记失败（`内容摘要=转换失败：<原因>`、`AI建议=待人工处理`）、不置 `已文本化`；部分成功按 `已文本化` 处理并在正文区标 `[转换失败：<原因>]`。

（2）**查重检测**——新文本化正文区与既有文本化正文区逐字精确比对（忽略行尾空白和连续空行差异；比对范围：表A `生命周期≠已废弃（重复）` 的既有文本化文档）：

| 结果 | 处理 |
|------|------|
| 无重复 | 输出文本化文档；表A → `生命周期=已文本化`、`AI建议=可以切分` |
| 重复 | 输出软链接文档（正文区仅定向引用）；表A → `生命周期=已废弃（重复）`、`AI建议=已废弃（重复）`、`内容摘要=与[源文件名]内容完全重复` |

（3）**两区文档写入**：

| 区域 | 内容 |
|------|------|
| 管理区 | 状态摘要表（阶段/AI建议/待处理/操作指引，模板见 [人类方案 §6.1](../eos-ort00-textualize.md#61-文档内嵌状态摘要表模板)） |
| 正文区 | 纯原文与转录占位标注（无切分标记、方案块或分析建议块） |

**写回顺序（同步契约）**：先更新状态文档表 A（权威源），再从表 A 推导写入文本化文档管理区。写回前执行附录 B.1 冲突检查。

### Step 3 · 提交基线

**一句话**：AI 把本轮结果提交为 git 基线，作为下游 ort01 的 diff 基准。

把本轮 Step 1~2 的处理结果提交为 git 基线。

**为什么需要提交**：ort00 自身检测用状态扫描、不需要基线；但 ort00 的产出（新文本化文档全文 + 表 A 写入）若不落基线，会进入下游 ort01 的 git diff 视野，被误判为「正文区原文行被改」等反馈。提交基线维持「基线 = 最后 AI 提交，diff 只含人类变更」的链级不变式。

1. **提交范围**：本轮更新的表 A、文本化文档/软链接文档；人类未提交的编辑一并纳入（`git add -A`）
2. **执行提交**：`scripts/ai-commit.sh "<提交说明>"`——author=EOS-AI + `[AI]` 前缀 + Co-Authored-By，输出新基线 hash
3. **记录基线**：将新基线 hash 写入状态文档 `HEAD @上次AI运行` 字段
4. **无变更**：工作区无改动时跳过提交，基线不变

### Step End · 运行结束输出

输出行动清单（本次运行报告 + 下一步交接），**结束**——ort00 反馈全在表 A，人类直接改表 A 即反馈，无需对话收集：

```text
当前状态：<已文本化可切分 / 已废弃（重复）/ 转换失败 / 已处理反馈 / 无新增处理>
  本轮已文本化：[文件名] → 文本化完成，待人类选入切分
  本轮发现重复：[文件名] → 与 [原始源文件名] 完全重复，已标记 已废弃（重复）
  本轮转换失败：[文件名] → 转换失败：<原因>（表A 已登记，生命周期=已登记）
  处理反馈：[文件名]（终止 → 已废弃 / 重跑 → 重新转换/重新判定 / 确认重复 → 收尾）
资产落账：表 A 已同步；基线已提交（<hash>）

一、待反馈（编辑表 A 即反馈，AI 用状态扫描检测）
  A. 选材 → 表 A `人类决策=同意切分`（进入 ort01）
  B. 暂不切分 → 表 A `人类决策=暂不切分`
  C. 终止 → 表 A `人类决策=已终止`
  D. 重跑 → 表 A 清除该行「生命周期」值（转换失败重试 / 重复误判 / 重新文本化）
  E. 确认重复 → 删除源文件（软链接保留）

二、下一步
  ① 待选入切分的材料 → 表 A `人类决策=同意切分` 后运行 eos-ort01-chunk
  ② 有新原始材料 → 重跑本步继续文本化
```

## 三、AI 标记约定

**转录占位标注**——含义是"此处需人工确认"的提示牌，不是 AI 加工结论。宁可用标注如实说明，也不凭空补全。标注写入正文区（详细规则见 [人类方案 §3.2.2](../eos-ort00-textualize.md#322-转录忠实转成-markdown)）：

| 场景 | 标注 |
|------|------|
| 图片/扫描件 | `[AI 识别，待人工确认]` |
| 录音听不清 | `[听写不清]` |
| 手写可辨识 | `[AI 推测]` |
| 手写不可辨识 | `[原文模糊]` |
| 完全无法识别的图片 | `[图片：无法识别文字内容]` |
| 文档明显不完整 | 文档开头 `[文档疑似不完整]` |
| 多语言混写 | 保留原语种，必要时标注 `[中文/英文/...]` |
| 转换失败（损坏/加密/格式不支持/报错） | 不输出文档，表A 登记 `转换失败：<原因>`（`生命周期=已登记`、`AI建议=待人工处理`） |
| 部分转换成功 | 能转部分转录，未转部分正文区标 `[转换失败：<原因>]`，按 `已文本化` 处理 |

**状态自终止**：反馈处理即状态转迁、条件失效，无需 `[已处理]` 记录分离（与 ort01 的 git diff + 记录机制不同，见 [人类方案 §3.4](../eos-ort00-textualize.md#34-反馈检测判据)）。

## 附录A：判据速查

### A.1 跳过判定（Step 1 过滤）

| 跳过原因 | 判定条件 |
|---------|---------|
| 不是原始材料 | 文件名以 `.textualized.md` 结尾（本步产物）；或含 `.chunk-`（下游切分文档） |
| 已在处理流程中 | 表A 已有记录，生命周期为 `已文本化` / `切分方案待确认` / `已切分`（`已登记` 材料每轮重新进入转换：转换失败自动重试、中断材料继续处理） |
| 重复关系已记录 | 表A 生命周期=`已废弃（重复）`（已通过软链接文档记录） |
| 已废弃 | 表A 生命周期=`已废弃`（如需重新启用，先清除该行生命周期值） |

> 注：`澄清中` / `已澄清` / `已规范化` 属于表B（切分文件）取值，不会出现在表A，不参与跳过判定。

### A.2 查重判定

| 结果 | 判定 | 处理 |
|------|------|------|
| 无重复 | 无任何既有文本化正文与新材料逐字完全一致 | 输出完整文档；表A → `已文本化` + `可以切分` |
| 重复 | 有既有文本化正文与新材料逐字完全一致（忽略行尾空白/连续空行） | 软链接文档；表A → `已废弃（重复）` |

### A.3 表A 生命周期与人类决策取值

| 字段 | 取值 |
|------|------|
| 生命周期 | 已登记 → 已文本化 → 切分方案待确认 → 已切分 → 已废弃（含已废弃（重复）） |
| AI建议 | `可以切分` / `已废弃（重复）` / `待人工处理`（转换失败） |
| 人类决策 | 空（未处理）/ `同意切分`（选入切分）/ `暂不切分`（本批不入切分）/ `已终止`（废弃） |

### A.4 反馈检测（状态条件扫描）

| 表 A / 文件系统 状态条件 | 判读 | 处理 |
|------------------------|------|------|
| `人类决策=已终止` 且 生命周期 ∈ {`已登记`,`已文本化`} | 终止 | 生命周期 → `已废弃` + 说明 |
| `人类决策=已终止` 且 生命周期 ∈ {`切分方案待确认`,`已切分`} | 跳过（ort01 域） | 不处理；提示走 ort01（含表 B 联动） |
| `生命周期` 为空 且 `10-raw-files/` 有对应文件 | 重跑 | 按原状态重跑（重判 / 重文本化 / 重转换） |
| `生命周期=已废弃（重复）` 且 源文件不存在 | 确认重复 | 收尾（行动清单移除） |
| `人类决策=同意切分` | 选材 | 不处理；列入行动清单（ort01 入口） |
| `人类决策=暂不切分` | 暂不切分 | 不处理；保留行动清单 |

> 状态自终止：处理后生命周期转迁、条件不再成立，无需 `反馈：`+`[已处理]` 记录分离（与 ort01 的 git diff + 记录机制不同，见 [人类方案 §3.4](../eos-ort00-textualize.md#34-反馈检测判据)）。

## 附录B：版本感知与写回

### B.1 写回前冲突检查

状态文档表 A 是人类与 AI 共同维护的表。AI 写回前执行冲突检查，防止覆盖人类手工修改：

1. **快照**——Step 1 记录待处理行 `生命周期` 与 `人类决策` 的当前值
2. **写回前复核**——写回前重新读取该行；若与快照不符（人类在本次运行期间手工修改），标记 `[需确认]`、不覆盖，在 Step End 向人类提示
3. **人类决策保护**——`人类决策` 是唯一由人类写入的字段：AI 绝不覆盖非空的人类决策（人类编辑即反馈，AI 不代写）

### B.2 写回顺序（同步契约）

每次写入按固定顺序执行：

1. **先更新状态文档表 A**（权威源）——登记 / 转迁生命周期 / 更新 AI建议与操作指引
2. **再从表 A 推导**写入文本化文档管理区状态表
3. 两者不一致时，以表 A 为准重建管理区

## 四、重进入规则

| 场景 | 处理 |
|------|------|
| 新增原始材料 | 无对应表 A 记录 → 进入文本化 |
| 重新文本化 | 无下游消费时清除表 A 生命周期值替换副本；已有下游消费时先输出变更影响声明再重跑 |
| 重复误判 | 清除表 A 生命周期值，删除软链接文档，重跑 |
| 转换失败重试 | 人工修复/替换源文件后，清除表 A 该行生命周期值，重跑本步重新转换 |
