## 一、职责定位

### 负责与不负责

| 负责 | 不负责（路由指向） |
|------|-------------------|
| 读取表 A 中 `生命周期=已文本化` + `人类决策=同意切分` 的材料 | 原始材料文本化 → `eos-ort00-textualize` |
| 执行语义结构分析（结构识别/语义段落/体量评估/关联性分析） | 模糊需求澄清 → `eos-ort02-clarify` |
| 生成切分方案块写入正文区 + 反馈提示区，等待人类反馈 | OR 条目规范化/分类/编号 → `eos-ort03-norm` |
| 按反馈执行：[同意执行]→切分输出 / [确认不拆分]→单片 / [调整]→重生成 / [废弃]→终止 | 修改原文语义、补充需求内容 |
| 同步状态文档表 A（原料级）+ 表 B（切分文件级） | — |

**接口载体**：文本化文档正文区的切分方案块（写入=待确认，清理=已执行）+ 状态文档表 A/表 B。

## 二、操作流程

### Step Start · 前置校验

按顺序检查：

1. `10-raw-files/` 存在 → 否则提示先运行 `eos-ort00-textualize`
2. `01-eos-sysdev-status.md` 存在 → 否则同上
3. `.textualized.md` 文档存在 → 否则同上
4. 全部就绪 → **优先检查反馈**：存在 `生命周期=切分方案待确认` → Step 2；无 → Step 1

### Step 1 · 新增处理

读取表 A，按状态分流：

| 表 A 状态 | 处理 |
|----------|------|
| `生命周期=已文本化` + `人类决策=同意切分` | 进入方案生成 |
| `人类决策=已终止` | 表 A→`已废弃` |
| `人类决策=暂不切分` 或空 | 跳过，列入行动清单 |

**方案生成**：
1. 读取文本化文档正文区纯原文
2. 执行四步语义结构分析：

| # | 操作 | 说明 |
|---|------|------|
| 1 | 文档结构识别 | 章节/标题/子标题层级 |
| 2 | 语义段落识别 | 主题转换点、章节边界、段落一致性 |
| 3 | 体量评估 | 是否超过单次处理合理范围 |
| 4 | 关联性分析 | 概念定义、上下文依赖、跨段引用 |

3. 切分判断：

| 条件 | 结论 |
|------|------|
| 篇幅适中且语义单一 | 不切分 |
| 篇幅大但语义不可分 | 不切分（提示下游注意体量） |
| 篇幅大且含多个语义单元 | 切分 |
| 篇幅小但含多个独立业务域 | 切分 |

4. 在正文区写入切分方案块 + 反馈提示区
5. 表 A 更新：`生命周期=切分方案待确认`、`AI建议=审核切分方案`

### Step 2 · 反馈处理

读取 `生命周期=切分方案待确认` 的文档，检测反馈：

| 反馈 | 处理 |
|------|------|
| `[同意执行]` | 校验行号范围 → 逐片输出 `.chunk-{seq}.md`（含 YAML frontmatter）→ 清理正文区方案块 → 表 B 每片追加记录（`已切分`/`可以澄清`）→ 表 A→`已切分` |
| `[确认不拆分]` | 输出单片（seq=1, total=1）→ 清理方案块 → 表 A/B 同上 |
| `[调整]` | 解析调整意图 → 旧方案+反馈归档历史区 → 写入新版方案块 → 表 A 保持待确认 |
| `[废弃]` | 表 A→`已废弃`，管理区追加废弃记录 |
| 无反馈 | 跳过，等待人类操作 |

**切分文件 YAML frontmatter**：
```yaml
---
chunk:
  source: {原始文件名}.textualized.md
  original_source: {原始文件名}.{ext}
  seq: {序号}
  total: {总片数}
  label: {语义标签}
  range: {原文范围}
status: raw
---
```

### Step End · 运行结束输出

```text
══════════════════════════════════════════
  eos-ort01 本轮完成
══════════════════════════════════════════

当前状态：<待确认方案 / 已切分可澄清 / 已废弃>
  生成方案：[文件名]（建议切分 N 片 / 不切分，等待反馈）
  执行切分：[文件名.chunk-001.md ...]（表 B 已切分→可澄清）
  调整重生成：[文件名]（v{N-1}→v{N}）

一、方案反馈
  A. [同意执行] — 按方案切分
  B. [调整] — 描述调整内容
  C. [确认不拆分] — 输出单片
  D. [废弃] — 终止处理

二、下一步
  本Skill → 继续处理表 A 选入材料或待确认反馈
  后续    → 表 B 已切分→设人类决策=同意澄清 → eos-ort02-clarify
```

## 三、切分方案块模板

**切分场景**：
```markdown
╔═ 切分方案 ═══════════════════════╗
║ 建议：切分为 3 片                 ║
║ 001 · 市场部业务需求  L120~L340  ║
║ 002 · 研发部开发流程  L341~L480  ║
║ 003 · 售后综合需求    L481~L620  ║
╚═════════════════════════════════════╝
```

**不切分场景**：
```markdown
╔═ 切分方案 ═══════════════════════╗
║ 建议：不切分                     ║
║ 理由：文档语义单一，无需切分       ║
╚═════════════════════════════════════╝
```

**反馈提示区**：
```text
请在此处输入反馈意见：
  [同意执行] / [调整] / [确认不拆分] / [废弃]
您的反馈：
```
