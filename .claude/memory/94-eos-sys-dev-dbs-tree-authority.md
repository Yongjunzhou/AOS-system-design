## 一、全文结构（v1.16，两章）

**第一章「一、产品数据及其形态」**（总则）＝
- **§1.1 EOS 的产品数据清单**——清单表（**产品数据 × 文档（EOS 实例）× 空间 × 本文**；`…概要`＝概要态、`…方案`＝完整态，同一份数据的两个形态各占一行；`01` 不分形态；配置方案/前后端组件方案形态待裁）+ **业务树名矩阵**（见下）+ **两个空间**（业务／方案，**成对相对而言**）。
- **§1.2 本文各树凭什么成立：三个前提**——① 可以**条目化**（ISO/IEC/IEEE 29148 良构需求：单数、可验证、唯一解释；**Singular** 即"一条只讲一件事"）／② 可以**树形化**（Simon 层级 + WBS 100% 规则；**成树三条件＝判据单维 + 条目单归属 + 分组完备互斥**，不满足分别得 **格 / DAG / 缺口重叠**）／③ 可以 **N:1 分配**（公理化设计 FR↔DP；**定义域取需求叶、值域取方案枝梢、映射必须是函数**——允许多对一＝内聚、不允许一对多＝变更传播与重复实现，**两侧理由不同源**）。
- **§1.3 产品数据的两个形态**——级语义：**叶＝末级 / 枝梢＝叶上一级 / 概要＝根→枝梢 / 完整态＝根→叶**；**叶只在完整态产出**；**叶的判据**＝"可被独立解释、独立验证、可被唯一交出去"，故"树到哪一级为止"是**判断**非位置约定。
- **§1.4 形态之间的承接与已定的树间对应**——承接规则：**上游最深可用原子（叶）→ 下游能负责该语义的节点，枝干或枝梢、以语义定级**；基数**可 N:1、不可 1:N**；**两形态之间不是承接**（02↔04、05↔06 是形态轴；全链承接只有 01→02、04→05、06→07）；两条承接实例（01→02 落**枝干**场景业务；04→05 落枝梢）；**反误读注**（"叶→枝梢"只是"上游完整态、下游概要"那步的**显影**，不是通则也不是层级换算）；非承接的树间对应另列一表；末【待裁】§2.3.1 的叶由 §2.4 哪一级承接。

## 二、§2.2 的四节与树名（v1.14~v1.16 定）

业务流程有**两个视角树**——**R 树**（角色履职视角，roles & responsibilities；沿 **SL** 角色场景视角展开）与 **P 树**（产品开发视角，product or service；沿 **PL** 输出产品视角展开）。下标索引**所指产品**：`0`＝平台本身、`n≥1`＝基于平台引擎构建的各业务。

| 下标 | 所指产品 | R 树 | P 树 |
|---|---|---|---|
| 0 | 平台本身 | **R0 树**（角色＝业务配置角色） | **P0 树**（构件＝引擎，单分支只有配置单元） |
| n≥1 | 各业务 | **Rn 树**（业务运行角色按职责完成业务对象闭环） | **Pn 树**（构件经 WBS 产出构件产品数据） |

| 节 | 标题 | 树的形状 |
|---|---|---|
| §2.2.1 | **业务运行角色履职业务流程（Rn 树）** | 角色履职业务 → 业务域① → 相关方角色② → 角色职责③ → E2E场景业务④ → 业务输出文档⑤（**PL5，枝梢**） → 活动节点/正文条目⑥（**叶**） |
| §2.2.2 | **产品开发业务流程（Pn 树）**（＝引擎平台之外的产品） | 输出产品业务 → 业务域① → 产品类型② → 产品构件类型③ → 构件开发WBS④ → 构件产品数据⑤（枝梢） → 活动节点/正文条目⑥（叶） |
| §2.2.3 | **引擎平台开发业务流程（P0 树）** | BP 产品树 → 业务域① → 产品类型② → 构件③ → WBS④ → 配置单元⑤ → 配置信息组⑥ → 叶⑦（**树形待裁**，见待办 1） |
| §2.2.4 | **业务配置角色履职业务流程（R0 树）** | 角色履职业务 → 业务域①（流程与IT，单域） → 业务配置角色②（业务配置人员／平台治理角色） → 场景业务③ → 业务输出文档④（枝梢） → 活动节点/正文条目⑤（叶） |

**键口径**：**枝梢＝业务输出文档（PL5），叶＝活动节点／正文条目（PL6-A 活动 / PL6-B 条目并列两支）**；**「任务」不占树位**（一个文档 0 或 1 个任务，任务主要节点是枝梢的**分解源判据展开项**）。**两棵树**：Rn 与 Pn 是**两棵独立的树**，在**输出文档（PL5）**处对位互连、经**认亲**互指，不是一棵树的共享节点（wft 链 2026-09-10 按「两个视角＝两棵树」校正，与 biz01 试点「两条独立树」一致）。**R0 与 P0** 是同一产品（平台本身）的两棵视角树；**R0 角色层退化**（流程与IT域核心角色类型单一，bph-eng 树上无需角色层；平台治理那支角色多，保留）。
