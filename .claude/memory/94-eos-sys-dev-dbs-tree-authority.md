## 二、§2.2 四节的树形状（v1.18，**节序 Rn／Pn／R0／P0**）

R 树＝角色履职视角（↔SL）、P 树＝产品开发视角（↔PL）；下标 `0`＝平台本身、`n≥1`＝各业务。

| 节 | 标题 | 树的形状 |
|---|---|---|
| §2.2.1 | 业务运行角色履职业务流程（**Rn** 树） | 角色履职业务 → 业务域① → 相关方角色② → 角色职责③ → 场景业务④ → 业务输出文档⑤ → 活动节点/正文条目⑥ |
| §2.2.2 | 产品开发业务流程（**Pn** 树，引擎平台之外的产品） | 输出产品业务 → 业务域① → 产品类型② → 产品构件类型③ → 构件开发WBS④ → 构件产品数据（=业务输出文档）⑤ → 活动节点/正文条目⑥ |
| §2.2.3 | 业务配置角色履职业务流程（**R0** 树） | 角色履职业务 → 业务域①（流程与IT，单域） → 相关方角色②（业务配置角色：业务配置人员／平台治理角色） → 场景业务③ → 业务输出文档④ → 活动节点/正文条目⑤ |
| §2.2.4 | 引擎平台开发业务流程（**P0** 树） | 输出产品业务（单分支——只有配置单元） → 业务域① → 产品类型② → 构件③（引擎） → 配置单元④（CU） → 配置信息组⑤ |

- **节序 2026-09-10 互换**（原 P0 在 §2.2.3、R0 在 §2.2.4）——同一产品索引内 R 前 P 后。
- **R0 相对 Rn 少一级**：「角色职责」（SL4）——「相关方角色」之下直接是场景业务。§2.2.3 原有的两条防御性注已删（信息在 §1.1 矩阵、树行内联与 91 §5.4）。
- **P0 树 2026-09-10 收为五级**——删原 ④WBS 与 ⑦叶（对齐 91 §3.1「P0 无 WBS、CU 直占 PL4、配置信息组＝末级、无 PL6」）；原【待裁】注随之删。※P0 的 ⑤ 该算「叶」还是「枝梢」未明说（wft01-eng 称"业务流程概要末级节点"＝枝梢，91 称"末级"＝叶），94 未标。
- **两棵树**：Rn 与 Pn 独立，在输出文档处认亲互指；R0 与 P0 是同一产品（平台本身）的两棵视角树，bph-eng 是交汇点（此说明在 91 §5.1/§5.4，94 不载）。

**去噪与去码（v1.16 / v1.18）**：正文不留跨文档关系句／来历说明／跨节关系句／内联节号（保留清单表「本文」列＝索引、依据指针）；**v1.18 起 94 全文去 PL／SL 层码**（PL5／PL6-A／PL6-B／L1~L7），改用节点名与各树自己的 ①②③；**七棵树的「枝梢／叶」标注一律不标**（级语义由 §1.3 定义）。R↔SL、P↔PL 的**视角名别名**保留在 §1.1（是别名，不是层码）。
