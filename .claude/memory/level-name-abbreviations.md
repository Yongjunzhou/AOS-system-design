**人类 2026-09-28 定**：三份试点报告内，级名一族给简称；**每份报告首次出现处写「全称（简称：X）」，其后用简称**。

## 简称表（✓＝该报告内启用；—＝该词只作属性名出现，不动）

| 全称 | 简称 | abr | abp | cr |
|------|------|:---:|:---:|:--:|
| 文档级E2E任务 | **文档级任务** | ✓ | ✓ | ✓ |
| 岗位级E2E业务 | **岗位级业务** | ✓ | ✓ | ✓ |
| 职责级E2E业务 | **职责级业务** | ✓ | ✓ | ✓ |
| 产品级E2E业务 | **产品级业务** | — | ✓ | — |
| 构件级E2E业务 | **构件级业务** | — | ✓ | — |

abr／cr 里产品级、构件级两级**只出现在 `所属产品级E2E业务`／`所属构件级E2E业务` 两个字段名中**，字段名保留原值，故这两份不启用、也不定义。

## 只砍「E2E」、保留「级」——不取「岗位业务／职责业务／产品业务」

人类原提后者，我改在「级」上留一个字，理由是四个坑：

1. **职责业务＝R 树根节点的本名**（2026-09-17「角色履职业务」更名而来；活在三份试点的树图根行与 94 §2.2.1／§2.2.3）。取同名会使根与 ③ 同级两名。
2. **文档任务＝末三级的合称**（cr §5.2 就地定义，abr／94 同句沿用）。⑤ 的简称取同形会与它一字之差——现取「文档级任务」，差一个「级」。
3. **构件业务＝业务资产 L3 的现名**（`01-pl4eos-spec`）。「产品级业务」又紧邻「产品数据」（abp 里两者 35／48 处且同段）。
4. **94 有意让「X级E2E业务」＝端到端业务、「X业务」（WBS业务／配置单元业务／配置信息组业务）＝非端到端作业单元与配置实体**，靠收尾方式标出这条缝（见 [[chain-level-name-family]]）。简称把两端收成同形，缝就没了。

保留「级」还有一条方法上的好处：**简称放进任何一段都读得懂**（「岗位级业务」），不生造词，与 93 §2.4「每一段都要自洽」不冲突。

## 不动的地方（正位）

**树图（代码块内）、级名行（表身里以级名整格当标签的行——级语义表与级对应表）、表题「**表3-5：级名**」、以及 `所属X级E2E业务` 字段名**，一律保留全称。前三处是级名的正位、与 94 的图2-4~2-7／表2-5~2-8 对表；末一处是写进数据文件的字面量。

## 两处例外

- **abp 的「职责级E2E业务」不给简称**：全篇只剩一处非正位出现，定义一处、只用一处，不如不定义（规则：非正位出现 ≥2 次才启用）。
- **cr §5.2 补两字**：「本步做三级——用例场景、任务节点、文档级任务，**三级**合称文档任务」——「文档级任务／文档任务」一字之差，补「三级」拆开。

## 依据与登记

简称**不必登记进 94**——93 §2.4 规则七自己就写着「术语按本名写全，**缩写首次出现给全称、其后可用**」，与人类这回给的写法是同一件事。
