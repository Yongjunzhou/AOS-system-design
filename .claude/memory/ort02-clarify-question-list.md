2026-08-17 人类讨论定案：ort02（澄清步骤）AI 建议的形态 = **生成「向相关方澄清的问题」**，而非替人类补答案。

**核心设计**：
1. 标注格式 `[⨯子类型: 原文→问题：<问句>]`——AI 对每处模糊生成可问相关方的问句
2. 首轮/迭代报告新增「待向相关方确认的问题清单」段（与内联 `[⨯]` 一一对应）
3. 开发者持问题清单向相关方澄清，把相关方答案写 `[✓已澄清: <相关方确认内容>]`；确认主体=开发者（向相关方澄清），非开发替业务脑补
4. 质量诉求（实时/高效/安全等）路由识别：不量化、不给指标，问题固定标「转 NFR 路径」——由 ort03 分类 NFR → wft01-nfr 处理（对齐 ort03「不生成系统指标」+ 91 §1184）
5. 三项条件「正文清晰完整」= 内容来自相关方确认；AI 生成的问题不构成已澄清（防自问自答）
6. 标注纪律：标哪里不清楚 + 给问题，不代替相关方提供答案/数值

**Why:** AI 建议的价值在「帮人类知道该问什么」，不在「替人类补答案」——AI 注入业务/指标内容会污染 OR 基线原始性、确认主体错位（开发替业务脑补）、且在 ort02 阶段缺信息锚点（无资产上下文）。与 wft01a「提问清单 + 业务人员确认收敛」模型同构 [[wft01a-redesign-multi-or-convergence]]。

**How to apply:** ort02 人类方案 v0.20 / SKILL v2.5 已落地（登记簿同批记录）。后续审视/修改按此口径——AI 只出问题、不进内容；质量诉求转 NFR 路径不量化。链级下游（ort03 NFR 分类）接住"质量诉求路由"。
