## 一、本场落定：需求说明上 R 树

**人类定案：R 树各节点带「需求说明」——被整合上树的相关方需求正文，写在节点上、不挂指针。** 详见 [[requirement-statement-on-r-tree]]。摘要：

| 条目 | 落法 |
|---|---|
| 挂哪几级 | **只挂文档级E2E任务及其下两级**（⑤⑥⑦）；其上各级（①②③④）**不带**，其需求**由下级生成**、相对简单，只到名称、可见性与所有者 |
| 谁产出 | abr——**需求说明规则**（上树的一面＝正文；回写的一面＝承接记录留在相关方需求侧备追溯。**指针留需求侧，树上留正文**） |
| 谁消费 | cr——**需求说明分析规则**（§4.1）：取证（拿本级要素表逐栏问需求说明，取句中成分落栏——动词／数据项名词／施动者／前提从句／结果从句／状态词对／可见范围词；取证来的**不标 `[推断]`**）＋ 补足（平台侧那几栏按界面落点补，**一律标 `[推断]`**）；三个出口＝没有这句话的归补足、说的是别级的归那一级、读不出的标 `[需确认]` |
| 登记在哪 | 「推理依据与补全说明」由 ④ **下移到 ⑤⑥⑦**（取证与补足的分野要有地方可核） |
| 叶的两档 | 需求说明**有新增需求**→**新增档**（形态、出现位置、可用条件与执行结果都定义，并定义平台能力需求）；**没有新增需求、只是复用 Y 上已有功能操作项**→**复用档**（只到出现位置与可用条件，不定义执行结果，也不给配置单元与配置信息组）。**"需求"二字不可省**——省了会读成"这个叶没有新增" |

## 五、尺子（本场新增六条）

1. **破折号两侧都要以"需求"收尾**——否则读成方案（落点从"要求"变成东西或构件）。
2. **"没有新增"这类短否定必须带宾语**——读者补全时取的是**同段最近的名词**，这里最近的是"叶节点"。
3. **名换对了，错位的成分自己浮上来**——表题加了"需求定义"之后，行首的"承袭（节点的来历）"立刻显形为答错了问题。
4. **产品构件名（菜单／标签页／操作项）本身带实现味**——"需求"二字是唯一在说"这些是要求、不是图纸"的东西，不能省。
5. **引句里每见"各／逐"，数一遍实际有几级**；要素表里每见"记录／说明／依据"，问一句"这件事发生在哪一级"（本轮两处真缺项都是这么撞出来的）。
6. **退回一个命名时，别把"退回"写进正文**——正文只留分野，试验史归 git。
