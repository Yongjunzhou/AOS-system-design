## 二、本轮新立的模型（下一轮以此为准，别引中间态）

详见 [[page-menu-hierarchy-and-post-label-tab]]。要点：

- **页面层**：`场景标签页` → **一站式业务标签页**；**菜单三级**＝M0 平台 → M1 业务域 → M2 相关方角色 → M3 岗位级E2E业务（末级菜单）；**末级菜单与一站式业务标签页一对一**；其上那层菜单（业务域／相关方角色）对应菜单标签页。

- **任务间触发关系**：文档之间与同一文档内任务之间的启动关系——触发条件与启动参数；**页序归 ⑥ 的页面间流转规则、启动归 ④**。
- **两条名称不必统一**：R 树级名与菜单名／页面名可以不归一（人类定）。

## 四、可直接继承的尺子（不必重推）

**已有的**：过程／规则的判别句（"先做哪件再做哪件"＝过程，"凭什么判、判出来哪一档"＝规则）；规则名的形（名字写足限定；按过程里首次被点到的次序排；别处引名不引表号）；清单体例（节内 `1. 2. 3.`，不用圈号）；**常量不占列**（整列同值的进引题或注）；动词查归属；"定义"是加工程度；**自足**（每节读完就能照着跑）。

**本轮新增的**：

- **一段话只答一个问题**——越界处就是两份单源打架的起点（91 §1.1「菜单标签页」那段越界写了"怎么到达"，与同节注相抵）。
- **凡两处出现同一个词，先问"它主语是谁"**——主语不同就带限定（本日清了三处：`引擎化`／`任务`／`触发条件`）。
- **深度与内容是两个正交坐标**——缺口要能落地，既要"缺在哪一格"（引擎→配置单元→配置信息组），也要"缺的是什么"（输入／期望输出／业务规则／FR-BIZ 指标）。
- **"有证据≠有权改"只管权威文档**——cr 是本轮被优化的那份，不该拿这条压着自己。
