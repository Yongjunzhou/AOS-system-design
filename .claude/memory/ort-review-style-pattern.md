2026-08-17 ort01 趟出「ort01 风格」可读性审视模式并完成同链应用：**ort01 v0.53/v2.35（样板）→ ort00 v0.30/v2.5 → ort02 v0.22/v2.7 → ort03 v0.39/v2.7（均已应用，ort02 两轮+结构演进，ort03 四轮+规则章拆两章+Step 框架完全对齐）**。

**可复用审视模式清单**：
1. **逐章通览**（一~五章 + 全文收官），先列发现、用户确认后动手（先发现后修改）
2. **章首一句话 + 节首一句话**——每章/每节一句人话引导
3. **定义单源化**——同一概念只在权威处定义一次，其余引用（如反馈状态条件表只在 §2.2 定义、Step 引用；重跑子行为归 §2.4.2；22 候选线索取值口径单源化）
4. **术语瘦身**——砍冗余同义术语（ort01 15→7；ort00 统一「重跑」触发词；ort03 去「增量标记」术语）
5. **人类参与导航**——操作流程章加「人类参与」列 + 执行模式白话注，Step 补「一句话」+ AI 细则标可跳过
6. **命名约定**——产物/候选单元命名 = 主责角色 + 场景业务（ort01 适用；ort00 无切分不适用，补软链接同名区分注记；ort03 无切分不适用，改处理「模板命名」——文档内嵌状态摘要表改名）
7. **状态/反馈分块**——设计基础章拆「状态怎么追踪」与「反馈怎么收拢/检测」两子分组（ort01/ort00/ort02 §2.2、ort03 §3.2 同构；ort03 v0.37 重排后该分块随设计基础章落 §三）
8. **模板一致性**——字段取值口径补全（含两分支）；SKILL 与人类方案同字段取一致
9. **变更记录 + 双文档同步**——每次版本 bump 登记、SKILL 同步（语义不变也 bump）、登记簿 02-eos-sysdev-review.md 追加、记忆更新；**改名类修复须双向核对**——改人类方案模板名后须搜 SKILL 同名词（F48/F-j 教训：改人类方案不算完）
