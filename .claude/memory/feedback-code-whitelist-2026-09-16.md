2026-09-16 人类逐轮收紧定案：先是「01 含两棵树」这类编号当名不合适 → 再「同 ① 优先成批」的层级序号也不该出现 → 最后成条：「**可用的代号只有 X、Y，以及 R树和 P树，其他的通通不用**」。

**Why**：代号一多，读者每遇一个都要回翻或记忆——人类原话「挑战我们的智商和记忆力」。本项目的符号还普遍**多重载**：`①` 同时是「树里第几级」「需求-方案对第几号」「句内第一个」。

**How to apply**（已立为 93 号规范 §2.4「正文写法」六条，2026-09-16）：

- **代号白名单**：X＝输入文档、Y＝输出文档（本次映射的自变量与函数值）、R 树、P 树；其余给具体指代——文档写本名（相关方需求／业务流程概要／业务流程方案／系统需求概要）、资产写本名（21 相关方角色资产／23 输出产品架构／25 引擎资产）、规范与文档编号首现给文题（94 号文档《EOS 系统设计产品数据分解结构》）、任务按链上位置称呼（阶段二任务／需求预处理链）、需求类型写全称（业务功能需求／引擎能力功能需求／非功能需求）、类型代号写本名（执行类／管理类）
- **层级序号 ①…** 只留树形结构图与级语义表的「级」列——93 §2.3 本就如此要求
- **需求-方案对序号 ①②③** 不用——按两端文档称呼，如「相关方需求 → 业务流程」「业务流程 → 系统需求」。同文件里层级序号也用 ① 时尤其忌——**一个符号两种含义**，读者得先判断是哪种
- **编号不当文档名**——只留作文件名、节号引用、链上坐标图
- **状态值／节点 ID／字段名与字段值保留原值**——那是要写进数据文件的字面量，不是叙述代号

同轮另立三条（同入 93 §2.4）：

1. **引用不作主语谓语**，同一权威源全文只挂一处；内容已在本句写全的，出处一并撤掉
2. **不写元评论**——不谈本文件自身（章结构为何如此／重复命名约定／不重述什么／与哪份文档并存或互为候选）
3. **不写来历与待办**——来历归变更记录或 Git，待办与挂账归工作流

**判据（可复用）**：这句话是在讲「这件事怎么做」，还是在讲「这份文件是怎么写的」；删掉那处引用，本句是否仍完整可读。

**首发实例**：`eos-biz01-str2bph.md` v0.20 → v0.21-pilot（指向 93／94／91／20 号的引用 33 → 20 处；93／94 两类 17 → 8 处；约 45 处代号换本名）。
